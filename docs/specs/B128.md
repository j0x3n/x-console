# B128 目标和每周复盘

来源：[B127-B139 建议](B127-B139-建议.md) 第 2 条。新模块 `goals`，页面 `/goals` 和 `/goals/review`。

## 要什么

面板里习惯、训练、番茄钟、电脑时间、GitHub 都在记数据，但没有地方回答“这个季度我想做到什么，现在做到哪了”。这个模块只存目标和复盘文字，进度尽量从已有的数据自动算。

1. 季度目标。一个目标有标题、季度（年加第几季度）、备注、若干关键结果。
2. 关键结果有名称、目标值、单位、数据来源。来源是手动填，或者绑定面板里已有的数据。
3. 每个关键结果算进度百分比。目标的进度是关键结果的平均。再和“按时间应该到哪”（这个季度已经过去百分之几）对比，落后的标出来。
4. 每周复盘。每周日晚上用通知提醒一次，打开复盘页。复盘页列出每个目标这周的进度变化和偏离，下面三个固定问题让用户写几句。每周一条记录，可以改，可以回看历史。
5. 今日页有一张“目标”卡片。
6. AI 助手可以查进度、手动更新进度。

## 证据和注意事项

写进界面说明时不要夸大。

- 记录目标进度能提高达成率（Harkin 等 2016 的荟萃分析，d 约 0.40）。但纳入的研究大多是健康类目标，比如减重和锻炼。工作和学习类目标没有同样强的证据。
- “下周具体在什么时候做什么”叫执行意图。早期荟萃分析给的效应量（d 约 0.65）可能偏高，后来有研究认为存在发表偏倚。
- 每周复盘这个节奏本身没有专门的研究，来自 GTD 等方法的经验。
- 界面上不写“能提高多少”，只写怎么用。

## 数据来源调查

读别的模块的数据，不直接读它们的表。已有的 `contracts.ActivitySource`（给时间线用）够用一部分，但不够用：习惯只给“某一天打卡过”，电脑时间只给总数和前三个类别的文字，没法按习惯或类别取数。所以加一个小的新契约 `contracts.GoalMetricSource`，由四个模块各提供一份。四个提供方都只加一个新文件和 `New` 里一行，不改已有行为。

| 来源 | 提供方 | 含义 | 选项 |
| --- | --- | --- | --- |
| `habit_checkins` | habits | 某个习惯的打卡次数（`habit_logs` 的行数） | 选一个习惯 |
| `workouts` | habits | 训练记录的次数（`workout_logs`） | 无 |
| `focus_minutes` | focus | 番茄钟专注分钟数，只算已结束且不少于 1 分钟的 | 无 |
| `screen_minutes` | screentime | 电脑时间的分钟数 | 选一个分类，或全部分类 |
| `github_commits` | github | 自己的提交数 | 无 |
| `github_merged_prs` | github | 自己合并的 PR 数 | 无 |

做不了的：

- GitHub 只统计面板已经同步到缓存里的提交和 PR（每个仓库最近的一批）。季度很长或提交很多时，数字会偏少。界面上写明这一点。要精确数字需要另外调 GitHub 接口，这一版不做。
- 没有“最多不超过”类的目标（比如娱乐时间少于 10 小时）。自动来源只做“累计到目标值”。想减少的东西可以用手动来源，起点大于目标值就行。
- 身体数据、阅读、笔记数量等没有接。需要时再给对应模块加一个提供方，不用改目标模块。

## 默认做法

用户不能当场回答，下面是我选的默认做法。

- **季度**：自然季度，1 到 3 月是第 1 季度，以此类推，按服务器时区。自动来源在这个季度内累计，到今天为止。不支持自选区间。
- **手动关键结果**：记“当前值”。有可选的“起点”（默认 0）。进度 = (当前值 - 起点) / (目标值 - 起点)，所以体重这类要减少的也能用（起点 80，目标 75）。每次更新值都记一条历史，用来算“这周变了多少”。
- **自动关键结果**：起点固定是 0，值是区间内的累计。
- **进度**：每个关键结果限制在 0 到 100。超过目标值显示的值照常，进度按 100。目标整体进度是能算出进度的关键结果的平均。算不出的（来源被隐藏、来源模块不可用）不进平均，在界面上标出“没有数据”。一个都算不出时整体进度为空。
- **按时间应该到哪**：季度已过去的比例，按天线性算。季度没开始是 0，结束后是 100。不考虑周末和假期。
- **落后**：进度比应该到的低 10 个百分点以上算落后（`behind`）。进度到 100 算完成（`done`）。季度还没开始是 `upcoming`。季度结束了没到 100 是 `missed`。其余是 `on_track`。
- **目标状态**：`active`、`done`、`dropped`。用户手动改。复盘页和今日页只看 `active` 的。
- **每周复盘**：一周从周一算到周日。日期用周一的日期标识（`2026-10-05`）。周日 20:00（可设，服务器时区）发一条通知，链接 `/goals/review`。同一周只发一次。这周已经写了复盘内容就不发。没有进行中的目标也不发。服务端检查每分钟跑一次，晚于设定时间启动也会补发（只限周日当天）。
- **复盘记录**：三个固定问题，各一段文字：`wentWell`（这周哪里做得好）、`fellShort`（哪里没做到）、`nextWeek`（下周具体在什么时候做什么）。保存时把当时每个目标的进度存成快照。当前周和上一周保存时刷新快照，更早的不再刷新，历史不会随目标后来的修改而变。上一周写的“下周”显示在这周复盘页顶部，当作提醒。
- **本周的变化**：自动来源是这周内的增量。手动来源是周末的值减去周一零点之前最后一次记录的值。目标整体的变化是周末进度减周初进度，单位是百分点。
- **隐藏内容**：习惯、电脑时间、GitHub 在隐藏内容锁定时，对应关键结果标成“已隐藏”，不显示值，不进平均。
- **设置**：复盘提醒的开关和时间放在复盘页的“提醒设置”弹窗里，存设置键 `goals.options`（`reviewReminder` 默认开，`reviewTime` 默认 `20:00`）。不加设置页标签。
- **外发数据**：不调用 AI，不外发任何数据。

## 接口

文件 `api/modules/goals.yaml`。

- `GET /goals?year=&quarter=&status=`：目标列表，带关键结果和进度。返回里有 `current`（当前年和季度）。
- `POST /goals`：新建，可以带关键结果。`PUT /goals/{goalId}`：整体保存，带 `id` 的关键结果更新，没带的新建，没出现的删除。`PATCH /goals/{goalId}`：只改状态。`DELETE /goals/{goalId}`。
- `POST /goals/results/{resultId}/value`：手动关键结果更新当前值。自动来源回 400。
- `GET /goals/metrics`：能用的数据来源，以及每个来源的选项（习惯列表、电脑时间分类）。
- `GET/PUT /goals/settings`：复盘提醒。
- `GET /goals/reviews`：已保存的复盘，新的在前。
- `GET /goals/reviews/{week}`：某一周的复盘页数据。`week` 是 `current` 或任意日期（取那天所在的周一）。没保存过的周用实时进度，保存过的周用快照。不允许未来的周。
- `PUT /goals/reviews/{week}`：保存三个回答。

事件：`goal.created`、`goal.updated`、`goal.deleted`、`goal.progress`、`goal.review_saved`。通知 kind：`goals.review`。

## 动作目录

- `goals.list`（读）：进行中的目标和关键结果的名称、目标值。可选 `year`、`quarter`、`status`。
- `goals.progress`（读）：每个目标和关键结果的当前值、进度、应该到的进度、是否落后。可选 `goalId`。
- `goals.update_progress`（写）：给手动关键结果设当前值。参数 `resultId`、`value`。

## 界面

- `/goals`：概要卡片（进行中的目标数、平均进度、落后的数量、季度已过去多少），工具栏有季度切换和状态筛选，主体是目标卡片，每张有进度条、“应该到”的刻度、关键结果列表。手动关键结果有“更新”按钮。右上角“新建目标”。
- `/goals/review`：本周复盘。上面是每个目标这周的变化和偏离，下面三个问题，保存按钮。右边（窄屏在下面）是往期复盘列表，点开看那一周。
- 左栏“目标”，在“个人”组。命令面板：打开目标、新建目标、打开每周复盘。
- 今日页“目标”卡片：当前季度有进行中的目标才显示。最多 3 个，落后的标出来，链接到 `/goals`。

## 验收标准

- 进度计算：手动、各自动来源、起点大于目标值、超过目标值、目标值等于起点、来源缺失、来源被隐藏、季度边界（第一天、最后一天、没开始、已结束）。
- 季度对比：落后阈值、完成、没开始、已结束。
- 每周复盘：创建、编辑、同一周只一条、快照在当周和上一周刷新、更早的不刷新、未来的周被拒绝、上周的计划带出来。
- 提醒：周日到点发一次、重复检查不重复发、已写复盘不发、没有目标不发、关掉不发、周一不补发。
- 动作：三个动作各跑一遍，手动以外的来源更新被拒绝。
- 前端：进度和落后的文案、新建弹窗、手动更新、复盘保存、今日卡片只在有目标时显示。
- `web/src/lib/i18n.test.ts` 通过。

## 没有验证的

- 四个提供方在真实数据上的数字，只用了测试里造的数据对过。GitHub 的数字依赖缓存，没有和 GitHub 网站对过。
- 通知在 Telegram 等外部渠道的实际到达，只验证了站内通知被创建。
- 手机上的视觉效果没有截图检查（容器里没有起前端）。`npm run shots` 的页面列表加了 `/goals` 和 `/goals/review`，但没有跑。
- 端到端里加了一段“目标”流程（新建、更新数值、保存复盘、删除），没有跑过，选择器只对照了单元测试里的标签写。
- 复盘提醒的定时检查（每分钟一次）只在测试里直接调用函数验证，没有等真实的调度器。

## 实现说明

- 契约 `contracts.GoalMetricSource`（`contracts/goals.go`），键前缀 `goals.metrics.`。提供方：habits、focus、screentime、github 各一个 `goal_metrics.go`，`New` 里各加一行。GitHub 没有连接账号时返回 `ErrGoalMetricMissing`，目标页显示“来源还没设置”，不显示 0。
- 隐藏内容：关键结果按来源所属模块判断（习惯和训练是 habits，专注是 calendar，电脑时间是 screentime，GitHub 是 github）。复盘快照保存时用真实数字，读出来时再按当前的隐藏状态遮掉，目标整体进度跟着重算。
- 来源现在用不了（模块没起、被隐藏）时，已有的关键结果保存时不会被换掉来源，新选才会被拒绝。
