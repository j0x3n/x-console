# B223 设置里可以选 Jev

2026-10-15 用户说：设置里加上 Jev，让它可选。

Jev 是 TypeSafe 的分类模型。它只回答判断题，不写摘要，不抽日期。输出 token 不收费。输入大约每百万 token 0.042 美元。

## 要什么

1. 添加供应商时可以选 Jev。预设地址是 `https://api.typesafe.ai/v1`，接口类型是 `jev`。
2. 刷新模型列表时，按 TypeSafe 的返回解析（`models[].name`），不是 OpenAI 的 `data[].id`。
3. Jev 不能选成 Agent 模型或快速模型。那两个要能对话。
4. 模型设置里多一项“邮件分拣模型”，只能选 Jev。不选时，邮件分拣仍全部交给快速模型，和现在一样。
5. 选了以后，每封邮件用一次 `POST /systemone`：一个 Choice 判类别（action、notice、promo），一个 Noul 判要不要做决定。类别不是 action 时，做决定一律为否。Noul 大于 0.5 才算要做决定，刚好 0.5 算否。
6. 只有 action 的邮件再交给快速模型写摘要和日期。通知和营销可以没有摘要，界面仍用主题。
7. Jev 调用失败时，这批邮件改回原来的整封分拣，邮件仍然能分进去。
8. 删掉这个供应商时，邮件分拣模型的选择一起清掉。别的保存请求如果没带这个字段，不清掉已选的 Jev。

## 怎么做

- `ApiStyle` 加 `jev`。`AiModelSettings` 加可选的 `mailTriage`。
- 迁移把 `ai_providers.api_style` 的可选值加上 `jev`。SQLite 改不了 CHECK，换表，数据照搬。
- 用量仍记在原来的表里，用途写成 fast（这张表只允许 fast 和 agent）。来源是 mail。费用按每百万输入 token 0.042 美元估算，输出不算钱。

## 验收

- 能保存 Jev 供应商，测试时能读到模型名。
- 把 Jev 选成 Agent 或快速模型会拒绝。把对话模型选成邮件分拣模型会拒绝。
- 选了 Jev 以后，分拣的类别和“要不要做决定”来自 Jev。摘要只对 action 调原来的模型。Jev 失败时整封仍能分拣。
- 没有连真实的 TypeSafe 账号验证过。
