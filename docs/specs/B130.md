# B130 复习卡片

来源：[B127-B139 建议](B127-B139-建议.md) 第 1 条。用户在笔记或稍后阅读里选一段文字，做成一问一答的卡片。每天按 FSRS 排出该复习的卡，页面里复习，也可以在 Telegram 里一张张答。

## 范围

- 新后端模块 `backend/internal/server/modules/cards`，接口 `api/modules/cards.yaml`，迁移 `20261012040000_m33_b130_cards.sql`。
- 新前端 `web/src/features/cards`，页面 `/cards`。
- 笔记和稍后阅读各加一行，挂上“选中文字做成卡片”的公共组件。
- 早报加一段“待复习”。今日页加一张“待复习”卡片。Telegram 每天推送。
- 动作目录：`cards.create`（写）、`cards.due_count`（读）。

## 卡片

| 字段 | 说明 |
| --- | --- |
| question、answer | 问和答，Markdown 纯文本。各最多 4000 字，不能为空 |
| deck | 牌组名，字符串，默认“默认”。没有单独的牌组表，列表里按名字分组 |
| sourceTitle、sourceLink | 来源，可空。笔记写 `/notes/12`，稍后阅读写文章原链接 |
| suspended | 暂停后不进复习，也不算待复习 |
| state、stability、difficulty、due、lastReview、reps、lapses | FSRS 状态 |

state：`new` 没复习过，`learning`、`review`、`relearning` 对应 FSRS 的阶段。

## 调度

- 用开源库 `github.com/open-spaced-repetition/go-fsrs/v4`（FSRS-6，默认参数）。`go get` 成功，不用自己实现公式。
- 用库的“长期调度”（`EnableShortTerm=false`）。评分后的间隔都按天算，同一张卡一天只会出现一次。四档评分的间隔严格递增：重来 < 困难 < 良好 < 简单。
- 目标记忆保持率默认 90%，设置里可改，范围 70% 到 97%。不开随机抖动（`EnableFuzz=false`），结果可预测，测试好写。
- “待复习”按日期算，不按时刻：`due` 早于“明天零点”（服务器时区）就算今天的。
- 每天新卡上限默认 10，复习上限默认 100。已经学过多少看 `card_reviews` 表：今天 `state_before=new` 的记录数是已学新卡，其余是已复习数。队列 = 最多“复习上限 − 今天已复习”张到期的旧卡（到期早的在前），后面接最多“新卡上限 − 今天已学新卡”张新卡（先建的在前）。
- 不做撤销评分，不做自己训练参数。

## 做卡

- 笔记和稍后阅读里选中文字（6 个字以上），选区旁出现“做成卡片”按钮。点开对话框，选中的文字是上下文。
- 对话框有两种风格：问答、填空。打开时如果 AI 可用且没关，自动调 `POST /cards/generate` 出一个草稿。可以改、可以手写、可以重新生成、可以换风格再生成。
- 填空风格：问题里用 `____` 代替被挖掉的词，答案是被挖掉的词。AI 不可用时，在问题框里选中一段，点“挖空”按钮就能把它换成 `____`，选中的字进答案框。
- AI 不可用或在设置里关掉时，对话框照常能用。问答风格把选中的文字先放进答案框，填空风格把选中的文字放进问题框。
- 保存即入库。牌组名默认用上一次用的。
- 隐藏笔记（B57）不显示这个按钮。
- AI 调用走 `contracts.LLM`，用途标记 `cards`。发给供应商的只有选中的文字（最多 4000 字）和来源标题。设置里写明这一点，并有开关 `aiEnabled`。

## 复习页 `/cards`

- 三个标签：复习、卡片、设置。
- 复习：概要卡片（今日待复习、今天已复习、卡片总数、近 30 天记住率）。有待复习时主按钮“开始复习”。可以选牌组。
- 复习中：先看问题，点“显示答案”或按空格，再点四档之一。四个按钮下面写下次间隔（比如“3 天”）。快捷键：空格显示答案，答案出来后空格等于良好，1 到 4 对应重来、困难、良好、简单。
- 全部评完显示统计：张数、各档数量、用时、明天有多少张。中途可以退出，已评的不会丢。
- 卡片列表：搜索、按牌组筛选、编辑、暂停或恢复、删除（删除前确认）。可以手动新建卡片。
- 设置：每天新卡上限、复习上限、目标记忆保持率、Telegram 推送开关和时间、AI 开关和外发说明。同样的设置也挂在“设置”页的“复习卡片”标签里。

## 提醒

- 早报：新增段落 `cards`，标题“待复习的卡片”，内容一行“今天有 N 张卡待复习”。没有卡或 0 张时不出现。通过合约 `contracts.CardsDue`（键 `cards.due`）取数，卡片模块不在时跳过。已经保存过早报设置的用户，要在设置里勾上这一段，新用户默认有。
- Telegram 推送：每天固定时间（默认 20:00，可设，可关）发一条通知，类型 `card.due`，标题“今天有 N 张卡待复习”，按钮“开始”。待复习是 0 张时不发。服务器当天错过时间点后 3 小时内补发，再晚就跳过。通知走现有的通知路由，所以要在“设置 → 通知”的规则里把 `card.` 开头的类型路由到 Telegram。
- 在 Telegram 里答题，按钮回调用 `Notify.OnAction("cards.", ...)`：
  - `cards.start`：发第一张的问题，按钮“显示答案”。
  - `cards.show:<卡片>`：发答案，四个评分按钮。
  - `cards.rate:<卡片>:<已复习次数>:<评分>`：记录评分，发下一张的问题。没有下一张就发“今天复习完了”。
  - 评分按钮里带卡片当时的 `reps`。同一个按钮点两次，或者已经在网页上评过，第二次回“这张卡已经答过了”，不会重复评分。
- 现有 Telegram 通道的限制，也是这里收窄的地方：按钮回调处理完后，通道会把**原消息**改成“原文 + 已处理：按钮名”并去掉按钮，处理函数不能改原消息的内容。所以每一步都是**发一条新消息**，旧消息变成记录。问题和答案是两条消息，每张卡至少三条消息（问题、答案、下一张的问题）。没有“原地翻到下一张”。
- 这些新消息通过 `Notify.Channel("telegram").Send` 直接发，不进通知中心，也不走静默时段（是用户自己点出来的）。没配置 Telegram 时按钮回调返回错误。

## 接口

见 `api/modules/cards.yaml`。

| 接口 | 说明 |
| --- | --- |
| `GET /cards` | 列表。参数 q、deck、state、suspended、limit、cursor。游标是卡片 id，新的在前 |
| `POST /cards` | 新建，201 |
| `GET/PATCH/DELETE /cards/{id}` | 读、改、删（204） |
| `POST /cards/{id}/review` | 评分。body `rating` 1 到 4，可选 `reps` 防重复 |
| `GET /cards/queue` | 今天的队列，参数 deck、limit，每张带四档下次间隔（天） |
| `GET /cards/summary` | 概要，参数 deck |
| `GET /cards/decks` | 牌组名和数量 |
| `POST /cards/generate` | AI 出草稿。AI 没配置回 409 `ai_not_configured`，设置里关了回 409 `ai_disabled` |
| `GET/PUT /cards/settings` | 设置 |

事件：`card.created`、`card.updated`、`card.deleted`、`card.reviewed`。前端按 `card.` 刷新。

设置键：`cards.options`（一个 JSON，字段 newPerDay、reviewPerDay、retention、pushEnabled、pushTime、aiEnabled），`cards.last_push`（上次推送的日期）。

审计：新建、改、删、改设置记审计。评分不记（每天上百条，没有价值）。

## 表

迁移 `20261012040000_m33_b130_cards.sql`，只加表。

- `cards`：id、deck、question、answer、source_title、source_link、suspended、state、stability、difficulty、due、last_review、scheduled_days、reps、lapses、created_at、updated_at。索引 `(suspended, state, due)`、`(deck)`。
- `card_reviews`：id、card_id（删卡时一起删）、rating、state_before、reviewed_at、scheduled_days、stability、difficulty。索引 `(reviewed_at)`、`(card_id)`。

## 默认做法

- 牌组只是一个字符串，不单独建表。改牌组名 = 改每张卡的 deck。
- 一天的分界是服务器时区的零点，不用 Anki 的凌晨 4 点。
- 所有评分都走长期调度，没有“学习中，10 分钟后再来”这种分钟级步骤。答错的卡明天再来。
- 评分用 `reps` 防重复，只在带了 `reps` 的请求里检查。网页评分带上它。
- Telegram 推送不用新的通道，直接走通知服务。发不发到 Telegram 由通知路由决定。
- AI 草稿的用途是 `fast`，一次调用，不重试。

## 验收标准

1. 新卡评分后 due 递增：重来 < 困难 < 良好 < 简单，评良好后 due 在今天之后。
2. 已有 FSRS 状态的卡再评，稳定性按库的结果更新，lapses 在重来时加一。
3. 新卡上限 3 时，队列里只有 3 张新卡，评完后队列里没有新卡，设置改大后能再出。复习上限同理。
4. 创建卡片、AI 出草稿（假 LLM）、AI 没配置回 409、关掉 AI 回 409、手写保存。
5. 暂停的卡不在队列和待复习数里。删卡会连评分记录一起删。
6. 早报有待复习段落，数量对。0 张时没有。
7. 推送：到点发一条，同一天不发第二次；0 张不发；关掉不发；错过 3 小时以上不补。
8. Telegram 回调：`cards.start` → 问题消息；`cards.show` → 答案消息带四个评分按钮；`cards.rate` → 评分并发下一张或完成消息；同一个评分按钮点两次，第二次报错且不重复评分。
9. 页面：开始复习、空格显示答案、1 到 4 评分、结束统计、卡片列表搜索编辑暂停删除、设置保存；选中文字出现按钮，保存后卡片入库。
10. 动作 `cards.create`、`cards.due_count` 各跑一次。

## 没有验证的

- 真实 Telegram 机器人上的按钮显示和回调，只在假通道和单元测试里验证。
- 真实 AI 供应商出的卡片质量。测试里用假的 LLM。
- 手机浏览器里长按选字后按钮的位置，只在桌面浏览器逻辑和 jsdom 里测过。
