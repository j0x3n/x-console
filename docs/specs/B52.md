# B52 浏览器推送：自动同步订阅、晚到的消息带时间

用户 2026-10-01 提的：Chrome 第二次测试收不到，刷新后重新开启就好了。iPhone 想知道什么情况下推送会失效。

可能的原因：浏览器换了推送订阅，或者服务端删掉了这个订阅，但页面不会重新提交，服务端一直拿着旧的。

## 前端（已完成）

- `features/reminders/push.ts` 新增 `syncPush`，由 `PushSync` 组件在登录后调用一次（挂在 `app/GlobalPanels.tsx`）：
  - 没给通知权限、从来没注册过 service worker 时什么都不做。
  - 浏览器里有订阅：同一个订阅 1 小时内只提交一次（`localStorage` 的 `xc.push.synced`）。提交前比对服务端公钥，公钥变了就退订再重新订阅。
  - 浏览器里没有订阅、但用户开过推送（`xc.push.enabled`）：重新订阅再提交。用户在设置里关掉推送时清掉这个标记，不会自己又开回来。
- `public/sw.js`：
  - 处理 `pushsubscriptionchange`：把新订阅提交给服务端，删掉旧的。
  - 推送内容带 `sentAt` 时，作为通知的 `timestamp`。晚到 10 分钟以上的，正文后面加“（发送于 10月1日 08:30）”。
- 设置 → 通知的说明里加两条：设备断网时消息最多等 3 天；iPhone 上删掉主屏幕图标或清除 Safari 网站数据后要重新开启。

## 契约

不改接口定义。推送内容 `pushPayload` 是服务端和 `sw.js` 之间的约定，加一个字段：`sentAt`（RFC3339）。

## 后端（待做，给开发者）

都在 `backend/internal/server/modules/reminders/delivery.go`。

1. `pushPayload` 加 `SentAt string \`json:"sentAt,omitempty"\``，每次组装推送内容时填 `time.Now().UTC().Format(time.RFC3339)`。测试消息（`notify_handlers.go` 的 `TestWebPush`）也要填。
2. 测试消息的正文改成 `收到这条说明浏览器推送能用。发送时间 15:04:05`（按 `m.d.Config.Location` 时区），方便分辨是哪一次。
3. `sendOne` 里 `webpush.Options` 的 `TTL` 从 `12 * 3600` 改成 `3 * 24 * 3600`（用户确认的 3 天）。
4. 测试：推送内容里有 `sentAt`；TTL 是 3 天（可以在 `httptest` 假推送服务里看请求头 `TTL: 259200`）。

## 验收

- 在 Chrome 里开启推送，在设置里删掉这个浏览器的订阅，刷新页面后订阅自动回来，测试消息能收到。
- 在设置里关掉推送，刷新页面，不会自己又开回来。
- 手机关机 1 小时后开机，收到的通知后面写着原来的发送时间。
