# B12 两步验证改为可选

## 用户要什么

登录时不强制输入动态验证码。要不要开两步验证，在设置里自己选。

## 规则

- 初始化账号时，扫码绑定这一步可以跳过。跳过后账号没有两步验证。
- 登录：
  - 没开两步验证：用户名加密码就能登录。
  - 开了两步验证：先填用户名和密码，服务端返回 `totp_required`，页面再显示验证码输入框。
- 高危操作的再次验证：
  - 开了两步验证：输入验证码。
  - 没开：输入登录密码。
  - 有效期都是 5 分钟，还是用 `auth.RequireElevated` 判断。
- 设置里新增“安全”标签：
  - 显示两步验证是否开启。
  - 开启：显示二维码和密钥，输入一次验证码确认后生效。
  - 关闭：要输入密码和当前验证码。
  - 修改登录密码：输入旧密码和新密码，改完其他会话全部退出。
- 失败次数限制不变：同一 IP 15 分钟内失败 5 次就锁住。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/auth/status` | 加 `totpEnabled`（只在已登录时返回） |
| POST | `/auth/login` | `code` 改为可选。开了两步验证但没带 `code` 时回 401，错误码 `totp_required`，不计入失败次数 |
| POST | `/auth/setup/skip-totp` | 初始化时跳过两步验证，直接登录 |
| POST | `/auth/elevate` | 请求体 `{code}` 或 `{password}` |
| POST | `/auth/totp/enroll` | 需要提升权限。返回新的密钥和 otpauth 地址，还没生效 |
| POST | `/auth/totp/confirm` | `{code}`，确认后开启 |
| POST | `/auth/totp/disable` | `{password, code}` |
| POST | `/auth/password` | `{oldPassword, newPassword}`，新密码至少 10 位 |

## 文档

- `docs/02-architecture.md` 和 `docs/01-product.md` 的“登录”一行改成“单用户，密码登录，两步验证可选”。

## 验收

- 新装面板时跳过两步验证，只用密码能登录。
- 开启后退出，登录页先要密码，再要验证码。
- 没开两步验证时，高危操作弹出的框要求输入密码。
- 关闭两步验证时密码或验证码错了会失败。
