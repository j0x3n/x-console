# B165 修正天气降水判断

用户 2026-10-12 提供 `/weather/extra?refresh=true` 返回，要求去掉此前凭猜测添加的降雨判断。

## 问题

- 后端通过自定的 20% 和 50% 逐小时概率门槛，把分钟降水量清零，并重写摘要。用户提供的“现在是雾，未来两小时降水概率 0%，没有降水”由本地代码生成，不能当作和风原始返回。
- 前端没有排除已经结束的五分钟时段，且把未来五分钟内的降水当作正在下。
- `kind: rain` 只表示降水类型。降水量为 0 时不能判断有雨。

## 修正

- 分钟降水量和摘要保留上游返回。页面和分钟降水推送都只按有效时段内的 `precip > 0` 判断，不用实况、逐小时概率、预警或生活指数改写分钟数据。
- 仅当前五分钟时段有降水时显示正在下。未来时段显示还有几分钟开始，已结束的时段忽略。
- 停雨时间只在连续有效点中计算。数据有缺口或未覆盖未来两小时，不能断言两小时内不会停。
- 普通逐小时降水概率提醒保留，它使用用户设置的概率门槛。
- 不改接口契约和数据库，不改页面结构。

## 验收

- 用户提供的 24 个 `kind: rain, precip: 0` 点不显示降雨、不发送分钟降水提醒。
- 实况为雾且逐小时概率为 0 时，非零分钟降水不会被清零，摘要不会重写。
- 已结束的降水点不显示正在下，也不发送提醒。
- 一到五分钟后的雨显示未来降水，不显示正在下。
- 测试覆盖现在、未来、过期、雨雪、停雨及数据缺口。

字段依据：[和风分钟级降水文档](https://dev.qweather.com/docs/api/minutely/minutely-precipitation/)。`precip` 是五分钟累计降水量，`type` 是雨雪类型。
