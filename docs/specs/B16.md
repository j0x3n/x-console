# B16 日历可写：本地日历和 CalDAV 写回

用户要能在日历里直接新建和修改日程。前端和接口契约已经做好（`api/modules/calendar.yaml`），后端现在回 501。

## 要什么

- **本地日历**（`kind = local`）：事件存在自己服务器上，可以随便建、改、删。
- **CalDAV 日历**（比如 iCloud）：同步下来的事件可以改，新建和修改马上写回 CalDAV 服务器。写回失败时不保存，把错误原样告诉前端。
- **ICS 订阅**保持只读。Google 日历先用它的“iCal 格式的私密地址”订阅。

## 怎么做

1. 迁移 `m11`：`calendars.kind` 的 CHECK 加上 `local`（SQLite 要重建表）；`calendar_events` 加 `etag TEXT NOT NULL DEFAULT ''` 和 `href TEXT NOT NULL DEFAULT ''`，记 CalDAV 上这条事件的地址和版本。
2. `POST /calendars` 允许 `kind = local`，这时 `url` 可以为空，不做同步，也不参与定时同步。
3. `Calendar.writable`：`local`、`caldav` 为 true。`CalendarEvent.writable`：日历可写且不是重复事件。
4. `POST /calendar/events`、`PATCH /calendar/events/{eventId}`、`DELETE /calendar/events/{eventId}`：
   - 只能改可写日历里、不重复的事件，否则 400。
   - 全天事件用 `startDate`/`endDate`（结束不含），其余用 `start`/`end`，结束要晚于开始。
   - 本地日历：直接写表，`uid` 用新生成的 UUID。
   - CalDAV：用 `go-webdav/caldav` 生成 VEVENT 后 `PUT` 到日历集合（新建时 `If-None-Match: *`，修改时带 `If-Match: <etag>`），成功后再写本地表；删除用 `DELETE`。遇到 412 说明远端被改过，回 409“日程在别处改过了，刷新后再改”。
   - 改完发 `calendar.event_changed` 事件，前端会刷新。
5. 审计：`calendar.event.create/update/delete`。

## 验收

- 本地日历：新建、改时间、改成全天、删除，刷新后都对，今日页“下一项日程”跟着变。
- 用一个测试 CalDAV 服务（`caldav_test.go` 里已有假服务器）验证写回：新建后远端有这条 VEVENT，修改带 `If-Match`，远端改过时回 409。
- ICS 日历和重复事件改不了，接口回 400，界面上没有“编辑”按钮。
