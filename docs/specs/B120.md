# B120 密钥和令牌

用户 2026-10-10 让按《功能扩展建议》做，第 6、7、8 条都做，这是第 6 条。来源是 `/mnt/project-files/x-console-suggestions/功能扩展建议.md`。

## 为什么要加

API 密钥、访问令牌、SSH 密钥散在各台机器的配置里。某个令牌泄露时，要马上知道它用在哪几处、去哪个平台换。令牌过期没人提醒，服务会突然停。面板自己发的令牌（`mcp` 模块）已经有到期时间，这条管外部的。

## 要什么

新模块 `credentials`，页面叫“密钥台账”，地址 `/credentials`。**只记信息，不存密钥本身。**

每条记：

- 类型：API 密钥、访问令牌、SSH 密钥、签名密钥（GPG 等）、其他。
- 名称（必填）、平台（比如 GitHub、OpenAI）、账号（用哪个账号或邮箱申请的）。
- 用在哪里：一组文字，每项写一台服务器或一个项目，最多 20 项。泄露时按它查。
- 权限范围：一行文字，比如 `repo, workflow`。
- 识别尾号：最多 16 个字符，写密钥的最后几位或 SSH 指纹的前几位，用来在平台页面上认出是哪一个。
- 创建日期、上次更换日期、到期日。到期日可以不填，比如永不过期的密钥。
- 更换周期（天）：超过这么久没更换就提醒。0 或不填表示不管。
- 到期提醒提前天数，默认 30、7 天，每条可以改。
- 备注（Markdown）。

### 拒绝像密钥本身的内容

所有文字字段（名称、平台、账号、用在哪里、权限范围、尾号、备注）如果含有下面这些，整条请求回 400，提示“这看起来是密钥本身，台账里只记信息”：

- `-----BEGIN ... PRIVATE KEY-----`
- `sk-`、`pk-`、`rk-` 开头加 16 个以上字母数字的串，`ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_` 加 30 位以上，`github_pat_`，`xc_` 加 20 位以上十六进制，`AKIA` 加 16 位大写字母数字，`xox` 开头的 Slack 令牌，`AIza` 加 30 位以上，三段式 JWT（`eyJ` 开头）。
- 一个 32 位以上、只含字母数字和 `_-+/=`、同时有字母和数字的词（`SHA256:` 和 `MD5:` 开头的指纹除外）。

## 状态

| 状态 | 条件 |
| --- | --- |
| `expired` 已过期 | 到期日在今天之前 |
| `soon` 快到期 | 离到期日不超过这一条最大的提醒天数（没设提醒时 30 天） |
| `stale` 久未更换 | 设了更换周期，更换日（没有就用创建日期）加周期已经到了 |
| `ok` | 都没到 |
| `none` | 没有到期日，也没设更换周期 |

同时满足多个时按 `expired`、`soon`、`stale` 的顺序取第一个。更换周期设了但更换日和创建日期都没填，保存时回 400。

列表按“最急的一项”排：到期日和更换到期日里更近的那个，已过的在最前，两项都没有的在最后。

## 提醒

- 每小时检查一次，用服务器时区算天数。
- 到期提醒和证件档案（B115）一样：剩余天数小于等于某个提醒天数且这个天数没提醒过就发一次；一次命中多个只发最小的，其余记为已提醒；到期当天和已过期各发一次；改了到期日就清空已提醒记录；归档的不提醒。
- 久未更换：到期那天提醒一次，之后每 30 天提醒一次，直到更换。更换日、创建日期或周期改了，重新计。
- 通知标题写类型、平台和名称，正文写到期日或周期。不写尾号。链接 `/credentials`，来源 `credentials`，类型 `credentials.expiring` 和 `credentials.stale`。

## 更换

`POST /credentials/{id}/rotate`：记一次更换。更换日默认今天，可以同时给新的到期日和新的尾号。创建日期不动。到期日没给就保持原样。给了新的到期日时，已提醒记录清空。页面上“已更换”按钮打开一个小窗，新到期日默认按上一次的有效期长度推出来。

## 隐藏内容

- “密钥台账”加进可隐藏的模块（`vault.yaml` 的 `ModuleId` 加 `credentials`），默认不隐藏。隐藏内容锁着时左栏、接口、事件、通知都当作没有这个模块。

## 页面

- 概要卡片：全部、已过期、快到期、久未更换。
- 工具栏：类型下拉、搜索框（找名称、平台、账号、用在哪里、权限范围、备注）、“显示已归档”。
- 列表：类型图标、名称、平台和账号、用在哪里（前两项，多的写“等 n 处”）、状态标签和天数。点一行打开详情：各项内容，下面有“已更换”“编辑”“归档”“删除”。
- 点“用在哪里”里的一项，搜索框填上这一项，方便查“这台服务器上有哪些令牌”。
- 新建和编辑表单顶部写一行提示：“不要填密钥本身，只记信息。”
- 手机（390px）整页不横向滚动。

## 接口

见 `api/modules/credentials.yaml`。

- `GET /credentials`：全部，带 `status`、`expiresIn`、`rotateDueIn` 和概要。参数 `kind`、`q`、`archived`。
- `POST /credentials`、`GET /credentials/{id}`、`PATCH /credentials/{id}`、`POST /credentials/{id}/rotate`。
- `DELETE /credentials/{id}`：要提升权限。
- 写操作都记审计。事件 `credential.created`、`credential.updated`、`credential.deleted`。
- 动作目录：`credentials.list`（只读，参数 `q`、`kind`）。AI 能回答“这台服务器上用了哪些令牌”“哪些快过期”。

## 验收

- 新建一个到期日 20 天后的令牌，立即收到提醒（命中 30 天），再次检查不重复。改到期日再改回，会重新提醒。
- 设更换周期 90 天、更换日 100 天前，状态是 `stale`，收到一次“久未更换”，30 天内不重复。点“已更换”后状态回到 `ok`，不再提醒。
- 名称里写 `ghp_` 加 36 位字母数字，或备注里贴一段私钥，保存被拒绝。
- 搜某台服务器的名字，能找到用在这台上的令牌。
- 归档后不提醒。隐藏内容锁着时左栏没有入口，接口回 404。
- 手机（390px）不横向滚动。

## 实现记录

- 后端：`backend/internal/server/modules/credentials`。`guard.go` 是“像密钥本身”的判断，`remind.go` 是到期和久未更换提醒（每小时检查），`module.go` 里算状态和排序。迁移 `20261010000400_m20_b120_credentials.sql`。
- 前端：`web/src/features/credentials`，列表、详情（含“已更换”小窗）、新建和编辑表单。点详情里“用在”的一项，会把它填进搜索框。
- 重新提醒的规则：只有到期日变了才清空已提醒记录。更换时没给新到期日就不清。
- 识别尾号在列表右侧显示，不进通知正文。
- 没做：不检查平台上的密钥是否真的还有效，也不自动更换。
- 没验证：到期提醒和久未更换提醒只在后端测试里用固定时钟验证过，没有等真实的一小时定时跑过。

## 2026-10-10 变更：页面改名“密钥”，可以直接存密钥内容

用户让去掉“台账”两个字，并且可以直接保存密钥内容。左栏位置也从个人挪到“机器”分组，放在监控下面。上面写的“只记信息，不存密钥本身”不再成立，以这一节为准。

- 页面和命令分组叫“密钥”，地址不变。
- 新增“密钥内容”一栏，用主密钥加密后存进 `secret_enc`（迁移 `20261010000600_m22_credentials_secret.sql`）。最多 20000 个字符，SSH 私钥也放得下。
