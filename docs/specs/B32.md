# B32 AI 改为 OpenAI 兼容接口，分快速模型和 Agent 模型

用户要求（2026-09-28）：

- AI 设置去掉 Anthropic 支持，改成支持 OpenAI 兼容接口。
- 自动获取接口上的全部模型，再通过 models.dev 同步模型规格。
- 可以设置两个模型：快速模型和 Agent 模型。快速模型给笔记自动加标签、起标题。Agent 模型给 AI 浮窗、自动化、服务器 Agent 标签（B33）用。
- 可以选思考程度。
- “AI 助手”改名“AI”（界面文字，B22 里一起改）。

这个任务替换 B3 / M12 规格里“用 Anthropic 官方 SDK”的部分。改完要把 `docs/specs/M12.md` 里相关段落改掉，写明以本规格为准。

## 接口供应商

- 设置里可以加多个“供应商”：名称、Base URL（比如 `https://api.openai.com/v1`、`https://api.deepseek.com/v1`、`https://openrouter.ai/api/v1`、本地的 `http://127.0.0.1:11434/v1`）、API Key（加密存储，可以为空，本地模型不需要）。
- 每个供应商有“测试连接”。
- 调用只用 OpenAI 的 Chat Completions 接口（`POST /chat/completions`，流式 `stream: true`，工具调用 `tools`）。它是各家兼容得最好的格式。不用 Responses 接口。
- Go 端用 `github.com/openai/openai-go`（官方 SDK），设置 `option.WithBaseURL`。写代码前查它当前的用法，不要凭记忆。
- 删除 `anthropic-sdk-go` 依赖和相关代码。已有的 Anthropic 配置在迁移时丢掉，设置页提示“需要重新配置 AI”。
- 数据库迁移只加不删：旧的设置键先不读，下个版本再删。

## 模型列表

- 保存供应商后，调用它的 `GET /models` 拿到全部模型 id，存下来。设置页有“刷新模型列表”按钮。
- 从 `https://models.dev/api.json` 拉模型规格：上下文长度、最大输出、是否支持工具调用、是否支持思考（reasoning）、是否支持图片输入、价格。每天同步一次，存在本地，拉不到时用上次的。写代码前先看一次实际返回的结构。
- 匹配方法：先按“供应商 + 模型 id”精确匹配；供应商对不上（比如自建的中转）时，按模型 id 去掉前缀（`openai/gpt-x` → `gpt-x`）在所有供应商里找。都找不到就显示“规格未知”，用户可以手动填上下文长度和是否支持工具。
- 模型下拉框里每个模型显示：id、上下文长度、是否支持工具和思考（小图标）、每百万 token 的输入输出价格。可以搜索。

## 两个模型

| 用途 | 设置项 | 要求 |
| --- | --- | --- |
| 快速模型 | 供应商 + 模型 | 不需要工具调用。用于笔记自动标签、自动标题、早报润色 |
| Agent 模型 | 供应商 + 模型 + 思考程度 | 必须支持工具调用，不支持的在下拉里标灰。用于 AI 浮窗、自动化、服务器 Agent |

- 思考程度：关闭、低、中、高。对应 Chat Completions 的 `reasoning_effort`（`low`/`medium`/`high`，关闭时不传）。模型不支持思考时这一项标灰。有的兼容接口不认这个参数会报错，报错时自动去掉参数重试一次，并在设置页提示“这个接口不支持思考程度”。
- 快速模型没设置时，用 Agent 模型。

## 笔记自动标签和标题

- 笔记设置里两个开关：“自动起标题”“自动加标签”，默认开，没配 AI 时不显示。
- 触发：笔记停止编辑 10 秒后，且正文超过 50 个字，且（标题为空，或者标签为空）。每条笔记每次内容大改（变化超过 30%）最多触发一次，不反复调用。
- 标题：只在标题为空时填，不覆盖用户写的标题。
- 标签：从已有的标签里选最多 3 个，只有很确定时才新建标签。结果先作为“建议标签”显示在标签栏后面（虚线框），用户点一下才加上。设置里可以改成“直接加上”。
- 隐藏笔记不送给 AI。
- 用 `json_schema` 格式的输出（`response_format`），不支持的接口退回到在提示词里要求 JSON 再解析。

## 其他

- 每次调用记录供应商、模型、输入输出 token、耗时，设置页显示本月用量和按 models.dev 价格估算的费用。
- 更新 `api/modules/ai.yaml`：`AiSettings` 改成供应商列表和两个模型设置。

### 2. 供应商 `providers.go`

- `GET` 不返回 Key，只返回 `hasApiKey`。`modelCount` 用 `ai_provider_models` 的 `COUNT` 一次算出来。
- `POST`、`PATCH`、`DELETE` 都要 `auth.RequireElevated`（和原来的 `PutAiSettings` 一样）。前端已经用 `withElevation` 包好了。
- 校验：`name` 去首尾空格后 1 到 40 字；`baseUrl` 用 `url.Parse`，只允许 `http`、`https`，去掉末尾的 `/`。
- Key 用 `m.d.Secrets` 加密后存 `api_key_enc`。`PATCH` 里 `apiKey` 不传不改，传空字符串删掉。
- `POST` 成功后马上在后台刷新一次模型列表（不阻塞返回）。
- `DELETE`：一个事务里删供应商（模型和手动规格跟着删），如果快速模型或 Agent 模型用的是它，把那一项设置清掉。回 204。
- `test`：调 `GET {baseUrl}/models`，超时 15 秒。成功回 `{ok: true, message: "找到 N 个模型", modelCount, latencyMs}`，同时清掉 `last_error`。失败回 200 和 `{ok: false, message: 原因}`，原因写进 `last_error`。401 时写“API Key 不对”，连不上时写“连接失败”加原始错误。
- 刷新模型列表：同样调 `GET /models`，一个事务里删掉这个供应商的旧列表再插入新的，写 `models_refreshed_at`。回 `AiModel[]`（带规格，见下一步）。
- 审计：`ai.provider.create`、`ai.provider.update`、`ai.provider.delete`，内容写名称和 Base URL，不写 Key。
- 事件：写操作后发 `ai.provider_changed`。前端按 `ai.` 前缀刷新。

### 3. models.dev 规格 `modelsdev.go`

- 写代码前先下载一次 `https://models.dev/api.json` 看实际结构，把一小份存成测试夹具 `testdata/modelsdev.json`。目前是 `{供应商 id: {models: {模型 id: {name, limit: {context, output}, tool_call, reasoning, modalities: {input: [...]}, cost: {input, output}}}}}`，以实际为准。

- 匹配（`specFor(providerBaseURL, modelID)`）按顺序：
  1. `ai_model_specs` 里手动填的，`specSource: manual`。
  2. 用 Base URL 的域名认出 models.dev 的供应商（`api.openai.com` → `openai`，`api.deepseek.com` → `deepseek`，`openrouter.ai` → `openrouter`，其他的在代码里写一张小表），在它下面精确找模型 id，`specSource: exact`。

  4. 都没有：`specSource: unknown`，其他字段不返回。
- 价格是每百万 token 的美元价，models.dev 的 `cost` 本来就是这个单位（以实际为准）。
- `GET /ai/models`：所有供应商的模型加上规格，按供应商、模型 id 排序。传了 `providerId` 只返回这个供应商的。

### 4. 调用层 `modules/ai/llm/`

- 用官方 SDK `github.com/openai/openai-go`，`option.WithBaseURL(baseURL)`、`option.WithAPIKey(key)`（没有 Key 时传一个占位字符串，本地服务不校验）。写代码前查一次 SDK 当前的用法和版本，不要凭记忆。
- 对外只暴露一个接口，其他模块不直接碰 SDK：

  ```go
  type Request struct {
      Purpose  string            // "fast" 或 "agent"
      System   string
      Messages []Message         // user / assistant / tool
      Tools    []Tool            // 名字、说明、JSON Schema
      JSONSchema json.RawMessage // 要结构化输出时传
  }
  type Client interface {
      Stream(ctx context.Context, req Request) (Stream, error) // 文字增量、工具调用、结束时的 usage
      Complete(ctx context.Context, req Request) (Result, error)
  }
  ```

- 按 `Purpose` 选模型：`fast` 用快速模型，没设就用 Agent 模型；`agent` 用 Agent 模型。都没设时回 `ErrNotConfigured`，接口层转成 409 `ai_not_configured`，前端提示去设置。
- 只用 Chat Completions（`POST /chat/completions`），流式时 `stream: true` 并带 `stream_options: {include_usage: true}` 拿 token 数。不用 Responses 接口。
- 思考程度：Agent 模型且设置不是 `off` 时传 `reasoning_effort`。接口回 400 并且错误里提到 `reasoning` 时，去掉参数重试一次，把这个供应商 id 记进 `ai.reasoning_unsupported`，以后不再传。用户改了思考程度或换了模型时清掉这个标记。`GET /ai/model-settings` 的 `reasoningUnsupported` 看 Agent 模型的供应商在不在里面。
- 结构化输出：先传 `response_format: {type: "json_schema", ...}`。接口回 400 时退回到在系统提示词里写“只输出 JSON，格式如下”，再从回答里取第一个 `{` 到最后一个 `}` 解析。
- 每次调用结束（包括失败）写一行 `ai_usage`：供应商、模型、用途、token、耗时、按当时价格算的费用。
- 用测试替身：`llm` 包提供 `NewFake()`，按顺序返回预先写好的回复，给其他模块的测试用。

### 5. 改 AI 浮窗和自动化

- `polisher.go`（早报润色）改用 `Purpose: "fast"`。

### 7. 笔记自动标题和标签（`modules/notes/`）

- `contracts` 加一个接口给别的模块用，注册表键 `ai.llm`，在“接口变更记录”记一笔：

  ```go
  type LLM interface {
      Available(ctx context.Context) bool
      CompleteJSON(ctx context.Context, purpose, system, user string, schema json.RawMessage, out any) error
  }
  ```

  AI 模块在 `New` 里 `module.Provide` 它。笔记模块拿不到时自动功能全部跳过。
- 设置键：`notes.ai_auto_title`（默认 true）、`notes.ai_auto_tags`（默认 true）、`notes.ai_tag_mode`（`suggest` 或 `apply`，默认 `suggest`）。`GET /notes/ai-settings` 的 `available` 就是 `LLM.Available`。`PUT` 只改传了的字段。
- 迁移（笔记模块自己的，时间排在上面那个之后）：`ALTER TABLE notes ADD COLUMN suggested_tags TEXT;`（JSON 数组）、`ALTER TABLE notes ADD COLUMN ai_checked_hash TEXT;`。
- 触发：笔记保存后，如果不是隐藏笔记，正文去掉空白超过 50 个字，并且标题为空或者标签为空，就排一个 10 秒的延时任务（同一条笔记再保存就重新计时，用一个 `map[noteID]*time.Timer` 加锁）。
- 到点时再读一次笔记，条件不满足就算了。用正文的简单指纹（比如按行的 hash 集合）和 `ai_checked_hash` 比，变化不到 30% 就跳过，避免反复调用。调用后写 `ai_checked_hash`。（2026-09-30 加）指纹只存最小的 128 个 hash，比较时取两边合起来最小的 128 个来估算变化比例，长笔记这一列也只有两三 KB。发给模型的正文最多 4000 字。
- 调用快速模型一次，同时要标题和标签：提示词里给出已有的全部标签（最多 200 个，按使用次数），要求“标题 20 字以内，标签最多 3 个，尽量从已有标签里选，只有很确定时才新建”。
- 标题只在标题还是空的时候写（写之前再查一次，防止用户刚填了）。
- 标签：`apply` 模式直接加到 `tags`；`suggest` 模式写 `suggested_tags`，去掉已经有的。
- 改完发 `note.updated` 事件，前端会刷新。不记审计（不是用户操作）。
- `DELETE /notes/{id}/suggested-tags`：把 `suggested_tags` 清空，回 204。用户手动加上建议的标签后，`PATCH` 里顺手把它从 `suggested_tags` 去掉。
- 隐藏笔记任何时候都不送给 AI。笔记变成隐藏时取消它的延时任务。
