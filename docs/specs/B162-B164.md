# B162 到 B164：我的状态、起床后推早报、按状态推送

用户 2026-10-11 提出。原先写成 B158 到 B160，和同一天别的任务重号，改成 B162 到 B164。想让面板知道自己现在是在工作、睡觉、外出还是暂离，给各个模块用。眼前的两个用法：

- 有些通知只在工作时推送。
- 起床后推一条天气，包括和昨天的温差。

用户定的（2026-10-11）：

- 愿意在 iPhone 上配快捷指令自动化。以后也会装 Home Assistant 的手机 App。
- “工作中”只看工作电脑有没有人在用，不看前台程序是什么。
- 不在工作时攒下的通知，等回到电脑前再发。正在用手机时就发在手机上。

三个任务按顺序做。B163 和 B164 都要用 B162 的状态。B164 接在已经做完的 B127（通知合并推送）上做，用它的队列，不另起一套。

## 现在已经有的

- 电脑状态：代理上报空闲时间和锁屏，服务端算出在用、空闲、锁屏、离线（B83），接口在 `contracts/presence.go`。
- 作息：习惯模块的工作日、起床时间、睡觉时间（B83），表 `habit_schedule`。
- 带令牌的上报接口：身体数据（B119）、路由器（B114）。
- 早报和天气：`brief` 模块，和风天气。天气页已经能取昨天的实测最高、最低温（B58，`extra.go` 的 `fetchYesterday`，和风 `/v7/historical/weather`）。
- 通知路由：`reminders` 模块的路由规则、免打扰时段、静音规则。
- 推送合并（B127）：`notify.Holder` 把通知拦下放进 `notify_digest_queue`，每类通知可以选“立即”或“合并”，到时间点合成一条发。
- 电脑上弹系统通知：代理的 `notify.show`（B83）。

## 做不到的，先说清楚

- iOS 上的网页版只有打开时在运行。它不能在后台判断你在睡觉还是外出。手机的信号只能靠快捷指令自动化或 HA 手机 App 上报。
- 面板只在你打开手机上的面板时才知道你在用手机。快捷指令和 HA 都报不了“手机屏幕亮着”。
- 判断会出错。开着睡眠专注模式躺床上刷手机，面板会认为你在睡觉。所以要能手动改状态。
- 没配手机上报时，外出和睡觉分不清，都是“电脑没人用”。这时只能按作息时间猜睡觉，猜的结果在界面上标“推测”。

## B162 我的状态

### 状态

| 状态 | 键 | 意思 |
| --- | --- | --- |
| 工作中 | `working` | 任意一台工作电脑“在用” |
| 暂离 | `away` | 工作电脑 30 分钟内用过，现在空闲或锁屏，人没出门 |
| 睡觉 | `sleeping` | 手机报了开始睡觉，或者按作息推测在睡 |
| 外出 | `out` | 手机报了离开家 |
| 在家 | `home` | 手机报了在家，醒着，电脑没在用 |
| 不确定 | `unknown` | 以上都判断不了 |

按下面的顺序判断，先满足的算：

1. **手动设定**还没到期：用手动的。
2. **工作中**：任意一台工作电脑的状态是 `active`。这一条排在睡觉前面：开着睡眠模式但在用电脑，算工作中，并且结束这一段睡觉。
3. **睡觉**：手机最后一次睡眠相关的上报是“开始睡觉”，之后没有“醒来”。
4. **外出**：手机最后一次位置上报是“离开家”。
5. **暂离**：工作电脑最后一次 `active` 在 30 分钟内。
6. **推测睡觉**：开了“按作息推测睡觉”，现在在作息的睡觉时间前 1 小时到起床时间之间，工作电脑已经 30 分钟没在用，并且不是外出。
7. **在家**：手机最后一次位置上报是“到家”。
8. 其余是**不确定**。

- 工作电脑在设置里选，可以选几台。只能选有空闲时间能力（`presence`）的电脑。没选的时候，所有能报空闲时间的电脑都算。
- 状态每分钟重算一次，电脑状态变化、手机上报、手动设定时也立刻重算。
- 状态变了才记一条，`since` 是这次变化的时间。

### 起床

从“睡觉”（包括推测的）变成别的状态时，算一次起床，发事件 `me.woke`：

```json
{ "sleptAt": "2026-10-11T03:40:00+08:00", "wokeAt": "2026-10-11T11:55:00+08:00", "guessed": false }
```

- 睡了不到 3 小时的不算起床，不发事件。午睡、半夜起来上厕所都会这样，不希望因此推早报。
- 从睡觉变成工作中、外出时也算起床。比如没关睡眠模式就开了电脑。

### 手机上报

`POST /api/v1/me/report`，不需要登录会话，用 `Authorization: Bearer <令牌>` 校验。做法和 B119 一样。

```json
{ "event": "sleep.start", "at": "2026-10-11T03:40:00+08:00" }
```

| event | 快捷指令里对应的触发 |
| --- | --- |
| `sleep.start` | 睡眠专注模式开启、就寝时间开始 |
| `sleep.end` | 睡眠专注模式关闭、醒来、闹钟停止 |
| `home.arrive` | 到达家、加入家里 Wi-Fi |
| `home.leave` | 离开家、断开家里 Wi-Fi |

- `at` 可选，不填用收到的时间。不能比现在晚 5 分钟以上，不能比现在早 12 小时以上。
- 同一种事件 2 分钟内重复报只算一次。比如睡眠模式和就寝时间都配了，会连着报两次。
- 有不认识的字段或事件名，回 400。成功回 204。令牌不对回 401，不透露有没有开启。请求体最多 1 KB。
- 只收这几个事件，不收坐标。
- `POST /me/report/token` 生成令牌，要提升权限，旧令牌立即作废。令牌只在这次回复里出现，服务端只存 SHA-256。回复里带上报地址和一条 curl 示例。`DELETE /me/report` 关闭。
- 成功的上报记审计 `me.report`，不记令牌。令牌不对的请求不记。

### Home Assistant（可选）

用户以后装了 HA 手机 App 再配。设置里填两个实体，不填就不用：

- 在家：`person.xxx` 或 `device_tracker.xxx`，状态是 `home` 算到家，变成别的算离开家。
- 睡眠专注：手机 App 的专注模式传感器（`binary_sensor.xxx_focus`），变成 `on` 算开始睡觉，变成 `off` 算醒来。这个传感器只能报“开了某个专注模式”，分不出是不是睡眠模式。界面上要写清楚：如果白天也开别的专注模式，就不要填这一项，改用快捷指令。
- 用 HA 模块已有的 `WatchEntity` 和 `ha.state_changed` 事件，效果和手机上报一样。同一件事 HA 和快捷指令都报了，按 2 分钟去重。

### 手动设定

- 今日页的状态卡片上点状态，可以改成任意一种，选持续多久：1 小时、2 小时、到明天起床时间、一直到我改回来。
- 到期或点“改回自动”后恢复自动判断。
- 手动改成“睡觉”再到期，也按上面的规则算起床。

### 给别的模块用

在 `contracts` 里加一个文件 `me.go`，只加不改：

```go
const MeKey = "me.state"

type MeState struct {
    State   string    `json:"state"`   // working away sleeping out home unknown
    Since   time.Time `json:"since"`
    Guessed bool      `json:"guessed"` // 推测出来的
    Manual  bool      `json:"manual"`
    Source  string    `json:"source"`  // pc phone ha manual schedule
    AtHome  *bool     `json:"atHome,omitempty"` // 没有位置信息时为空
}

type Me interface {
    Current() MeState
    Subscribe() (<-chan MeState, func())
}
```

- 状态变化时发事件 `me.state`，起床发 `me.woke`。页面订阅 `me.state` 刷新。
- 判断推测睡觉要读作息。作息在习惯模块里，不能跨模块读表。习惯模块在 `contracts` 里加一个 `Schedule` 接口（返回工作日、起床、睡觉时间和时区），新模块通过它读。
- AI 和 MCP 可以读当前状态：加一个只读动作 `me.state`。

### 历史和睡眠时长

- 表 `me_states(id, state, source, guessed, manual, started_at, ended_at)`。存 180 天，过期的每天清一次。
- 表 `me_reports(id, event, source, at, created_at)`：手机和 HA 的上报。存 30 天，用来去重和查问题。
- `GET /me/history?days=7`：每天的状态段，加每天的睡觉、起床时间和睡了多久。
- 习惯模块订阅 `me.woke`：起床那天的身体数据里没填睡眠时，自动填进去，保留一位小数。已经填了的不改。推测出来的不填。

### 界面

- 设置里加一页“我的状态”：
  - 工作电脑多选。
  - 按作息推测睡觉的开关，默认开。旁边链接到作息设置。

  - HA 的两个实体。HA 没连上时这一块显示“先在设置里连接 Home Assistant”。
- 新模块可以加进隐藏内容，和电脑时间统计一样，默认不隐藏。

### 快捷指令的配置步骤（写进设置页）

1. 打开“快捷指令”App，点“自动化”，点右上角“+”。
2. 选触发条件。比如“睡眠”里的“就寝时间开始”，或者“专注模式”里的“睡眠 · 开启时”。

## B163 起床后推早报

### 要什么

- 早报的发送时间多一种：“起床后发”。收到 `me.woke` 就发当天的早报。
- 加一个最晚时间（默认用早报原来的发送时间）。到最晚时间还没起床就照常发，免得手机上报没配好时一天都收不到。
- 一天只发一次。起床后已经发过了，最晚时间不再发。按作息的时区算“一天”。
- 推测出来的起床也发。

### 天气这一段多的内容

不管是不是“起床后发”，早报的天气都加这几项：

- 今天最高、最低温，和昨天比高几度或低几度。比如“最高 24°，比昨天低 6°”。差 3 度以内写“和昨天差不多”。
- 现在的温度。
- 今天会不会下雨：逐小时预报里有降水的时段，比如“15 点到 18 点有雨”。没有就不写这一行。
- 正在生效的天气预警，已有的照旧。

### 怎么和昨天比

- 用天气页已有的昨天实测温度（`fetchYesterday`），和今天的预报比。它已经有当天缓存，不会多花接口次数。
- 比的是“昨天实测”和“今天预报”。今天的数到晚上可能和预报不一样。
- 取不到昨天的数（接口出错、账号不支持历史天气）就不写对比那一行，早报照常发。

### 设置

早报设置里的发送时间改成两个选项：“固定时间”和“起床后，最晚 HH:MM”。没开 B162 的手机上报或推测睡觉时，选“起床后”旁边提示“还没有起床信号，只会在最晚时间发”。

### 验收

- 假时钟：发 `me.woke`，早报马上发出。到最晚时间不再发第二次。
- 一直没有起床事件，到最晚时间照常发。
- 假和风服务器：昨天 30°/20°，今天预报 24°/18°，天气段写“比昨天低 6°”。差 2 度写“和昨天差不多”。历史接口报错时不写这一行，早报照常发。
- 逐小时预报 15 点到 17 点有降水，写“15 点到 18 点有雨”。

## B164 按状态推送

### 要什么

- B127 的推送合并里，每类通知现在可以选“立即”或“合并”。再加一种“工作时”。
- 选了“工作时”的类别：状态是工作中就马上发。不是工作中时，先放进 B127 的队列，通知中心里照常能看到。
- B127 里一律立即发的规则照旧：紧急的、`Immediate` 的、带按钮的，不管选了什么都马上发。
- “工作时”和 B127 的总开关无关。总开关关着，选了“工作时”的类别也按“工作时”处理。这样只想用这一条的时候不用打开合并。

### 攒下的什么时候发

- **回到电脑前**：状态变成工作中时，在变成在用的那台电脑上弹系统通知（代理的 `notify.show`）。攒下的只有 1 到 3 条就一条一条弹。超过 3 条合成一条：“你不在时有 5 条通知”，正文列前 3 条的标题，点开是通知中心。这台电脑没有系统通知能力时，照路由规则发到外部渠道，用 B127 的合并格式。
- **在用手机**：手机上的面板打开着（页面可见），就在手机面板上弹出“你不在电脑前时的通知”列表，并把这些清出队列。不再另外推浏览器推送或 Bark，因为你已经在看了。
  - 手机面板可见时每分钟调一次 `POST /me/seen`，带 `{"device":"phone"}`。服务端 2 分钟内收到过就算“在用手机”。这个调用放在 `web/src/features/me/`，挂到 `GlobalPanels.tsx`（只加行）。怎么算手机：屏幕宽度小于 768px，或者是添加到主屏幕的网页版。
  - 这一点也写进 B162 的状态接口：`MeState` 加一个 `PhoneActive bool`，不影响六种状态。
- **外出时**：加一个开关“外出时直接推到手机”，默认开。开着时，状态是外出就照路由规则马上发，不进队列。
- 攒了 24 小时还没发出去的，按 B127 的合并格式照路由规则发一次，然后清掉。免得一直不在电脑前，通知永远发不出去。

### 睡觉时免打扰

- 通知设置里加一个开关“睡觉时当作免打扰”，默认开。状态是睡觉（包括推测的）时，按免打扰时段处理：除了紧急的都不发外部渠道，B127 的合并到点也顺延。
- 原来固定的免打扰时段（默认 23:00 到 07:30）保留，两个条件满足一个就算免打扰。你作息是凌晨三四点睡，可以把固定时段关掉，只用这一条。

### 模块和文件

- 改 `reminders` 模块：`digest.go` 加模式 `working`，`channels.go` 的免打扰判断加睡觉状态。迁移给 `notify_digest_queue` 加一列 `hold_for`（`digest` 或 `working`，默认 `digest`），只加不删。到时间点的合并只发 `digest` 的，`working` 的按上面的规则发。
- 通过 `contracts.Me` 读状态和订阅变化，不读 `me` 模块的表。
- `notify` 包不动，用 B127 已有的 `Holder`。
- 设置页“推送合并”卡片里每类的选项加“工作时”。“外出时直接推到手机”放在同一张卡片里。“睡觉时当作免打扰”放在“免打扰时段”卡片里。

### 验收

- 选了“工作时”的类别：不是工作中时进队列，通知中心有记录，假 Telegram 没收到。变成工作中后，在那台电脑上弹系统通知。
- 攒了 5 条，回到电脑前只弹一条合并的。
- 那台电脑没有系统通知能力时，发到外部渠道。
- 手机面板可见时，攒下的显示在手机面板上并清出队列，不推外部渠道。
- 外出且开关开着，马上发。开关关着，进队列。
- 紧急的、带按钮的不进队列。
- B127 总开关关着时，“工作时”照样生效。到合并时间点不会把 `working` 的发出去。
- 攒了 24 小时发一次合并的，然后清掉。
- 睡觉时普通通知不发，紧急的照发。B127 的合并到点顺延到醒来以后。
- 端到端（第一部分）：把一类通知改成“工作时”，在不是工作中时发一条，确认没推出去；手动设成工作中后，确认推出去了。
