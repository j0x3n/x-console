# B48 二次验证改成设置里可选

用户 2026-09-30 提出：后台很多操作都要再输一次密码（或两步验证码），改成设置里可以选。

## 现状

- 50 多处操作调用 `auth.RequireElevated`：开终端、执行命令、服务和容器的启停、SSH 主机、文件传输、云盘删除和分享、备份和恢复、存储切换、AI 供应商和模型设置、GitHub 和 Linear 令牌、HA、自动化、推送渠道、代理配对和吊销、Agent 任务的推送和开 PR 等。
- 验证一次后 5 分钟内不用再输（`elevationTTL`）。开了两步验证的要输验证码，没开的输密码。
- 前端遇到 `elevation_required` 会弹出验证框（`withElevation`），验证后自动重试。

## 要什么

设置 → 安全 加一项“敏感操作二次验证”，四选一：

| 选项 | 效果 |
| --- | --- |
| 每次（5 分钟内免验证） | 现在的做法，默认值 |
| 30 分钟内免验证 | 验证一次，30 分钟内不再问 |
| 本次登录内免验证 | 验证一次，退出登录或会话过期前不再问 |
| 关闭 | 除了下面“始终要验证”的几项，都不问 |

**始终要验证，不受这个设置影响**：

- 修改密码、开关两步验证、修改这个设置本身。
- 创建 API 令牌（B43）、新建和修改 Git 连接（B47）、把 Agent 的权限改成 `full`（B47）。
- 从备份恢复（会覆盖整个数据库）。
- 保险库有自己单独的解锁，不在这个设置里，不变。

这几项的验证窗口固定 5 分钟。

## 怎么做

- 设置键 `security.elevation_mode`：`always`、`30m`、`session`、`off`。
- `auth.Service.Authenticate` 读取设置，算出这个会话当前是否算“已验证”：
  - `off`：一律算已验证。
  - `session`：只要这个会话验证过一次，就算已验证。（实现时没有加列：`elevated_until` 是“上次验证 + 5 分钟”，会话结束前不会清空，不为空就说明验证过。）
  - `30m`、`always`：按验证时间加 30 分钟或 5 分钟算。
- 新增 `auth.RequireStrictElevated`：只看最近 5 分钟内有没有验证过，不管设置。上面“始终要验证”的几处改用它。
- `RequireElevated` 的函数签名不变，已有的调用方都不用改。这是基础代码改动，记到“接口变更记录”。
- 用 API 令牌（B43）来的请求，两个函数都一律失败，不受设置影响。
- 设置读取加缓存，改设置时刷新，不要每个请求查一次库。
- 修改这个设置写审计日志，记下改之前和改之后的值。
- 选“关闭”时，设置页在选项下面用 `warning` 颜色写明后果：“登录状态被别人拿到（比如手机没锁屏、Cookie 泄露）时，对方可以直接开终端、删文件、删备份，不会再要求输入密码。”

## 验收

- 四种模式各有测试：`always` 5 分钟后要求验证；`30m` 29 分钟不要、31 分钟要；`session` 验证一次后同一会话一直不要，换会话要；`off` 普通操作不要。
- “始终要验证”的操作在 `off` 模式下仍然要求验证。
- 令牌请求在 `off` 模式下仍然失败。
- 改设置本身要求验证，并写审计日志。
- 前端：设置页能选、能保存；选“关闭”时显示警告。截图 1360px 和 390px 自查。
