# B56 AI 润色做成公共功能

用户 2026-10-01 提的：站内所有的编辑器都要支持 AI 润色，和笔记一样。不同功能区的提示词要有区别：笔记的润色是更好读，卡片的润色除了好读还要更专业简洁。

## 做法（前后端都已完成）

### 后端

- 新接口 `POST /ai/polish`（`api/modules/ai.yaml`，`modules/ai/polish.go`）。请求 `{text, scene, prompt?}`，返回 `{text}`。只返回结果，不保存。
- `scene` 决定提示词。所有场景共用一段基础要求：改错字和不通的句子，保留原意和全部信息，不编造；中文像母语者写的，一句一个意思，不用破折号插入语，不用比喻；代码、链接、图片原样保留。各场景再加：

  | 场景 | 用在哪 | 额外要求 |
  | --- | --- | --- |
  | `note` | 笔记 | 整理标题层级、列表、段落，可以调整顺序 |
  | `card` | 卡片描述、新建卡片、项目描述 | 专业、简洁，去掉口语和重复，步骤写成有序列表，待办写成清单，不加原文没有的需求 |
  | `comment` | 卡片评论 | 简洁专业，语气平和，不扩写 |
  | `task` | Agent 任务、分配给 Agent 的说明 | 整理成“目标、要改什么、验收标准”三段，没提到的写“未说明” |
  | `reminder` | 提醒备注 | 一两句说清楚 |
  | `event` | 日程备注 | 列出时间地点和要带的东西 |
  | `general` | Agent 的说明等其他地方 | 通顺、清楚、简洁 |

- 用快速模型（`fast`），超时 90 秒。最多 20000 字。没配置模型时回 409 `ai_not_configured`。用量记在来源 `polish`，`ref` 是场景名，设置 → AI 用量里显示为“AI 润色”。
- 测试：`modules/ai/polish_test.go`，每个场景都有提示词、卡片和笔记的提示词不同、用户要求附在最后、空内容和超长和未知场景回 400、没配置模型回 409。

### 前端

- 润色弹窗从笔记挪到公共组件 `components/markdown/PolishDialog.tsx`，调用 `components/markdown/polish.ts` 的 `polishText`。
- `MarkdownEditor` 加 `polish` 属性（场景名）。传了就在工具栏右边、预览按钮前面多一个“AI 润色”按钮。内容为空时提示“先写点内容”。弹窗挂到 `body`，按键不冒泡到外层，避免按 Esc 时关掉外层弹窗或放弃卡片描述的修改。
- 各处用的场景：笔记 `note`；卡片描述、新建卡片、项目描述 `card`；评论 `comment`；新建 Agent 任务、分配给 Agent `task`；提醒 `reminder`；日程 `event`；Agent 的说明 `general`。
- 笔记改用 `/ai/polish`（`scene: note`）。笔记原来的 `/notes/ai/polish` 接口留着不删，下个版本再删。

## 验收

- 在卡片描述里写一段口语化的需求，点润色，结果更简洁，有列表。同一段文字放到笔记里润色，结果保留更多原文的说法。
- 在新建卡片弹窗里打开润色，按 Esc 只关掉润色弹窗，新建卡片的弹窗还在。
