# B109 仓库页显示本月 CI 时长额度

用户 2026-10-05 提的。账号是 GitHub 免费套餐，仓库是私有的，免费额度每月 2000 分钟（Linux 计 1 倍，Windows 2 倍，macOS 10 倍）。要在仓库页看到本月已用多少、还剩多少。

## 要什么

- 仓库页顶部的统计条里，“API 额度”旁边加一张卡片“本月 CI 时长”。
- 大字显示已用分钟数，下面一行写“共 2000 分钟 · 已用 37%”，再下面一行写“按系统：Linux 120 · Windows 30 · macOS 0”（用的是折算后的分钟数）。
- 已用达到 80% 时卡片变黄，达到 100% 变红。
- 没有读账单的权限时，卡片显示“未授权”，下面写“令牌需要账单读权限”，不报错。
- 每月 1 号 0 点（UTC）自动重新计，页面不用改。

## 接口

`api/modules/github.yaml` 加：

- `GET /github/actions-usage?refresh=`：
  `{month: "2026-10", usedMinutes, includedMinutes, byOS: {linux, windows, macos}, fetchedAt}`。
  `includedMinutes` 为 0 或接口没给时，用设置里的 `github.ci_included_minutes`，默认 2000。
- 没有令牌回 412 `github_not_configured`。令牌没有账单权限回 403 `github_billing_forbidden`。
- 设置里加 `ci_included_minutes`（整数，默认 2000），放在设置 → GitHub，用户升级套餐后自己改。

## 后端

都在 `modules/github/`，新文件 `usage.go`。

- 用现有的 `restClient`。先调新的计费接口 `GET /users/{login}/settings/billing/usage?year=&month=`，按 `product=actions` 过滤，把 `quantity` 按 `sku` 里的系统分到 `byOS`。`{login}` 用 `GET /user` 取，取到后缓存。
- 新接口返回 404 或 410 时，退回旧接口 `GET /users/{login}/settings/billing/actions`（`total_minutes_used`、`included_minutes`、`minutes_used_breakdown`）。
- 实际返回的字段名以用户账号为准。写实现时先用真实令牌调一次，把响应样例存到 `testdata/`，测试用它。
- 结果缓存在内存 10 分钟，`refresh=true` 不看缓存。令牌改了清缓存。
- 计费数据有延迟，不要在 CI 刚跑完就期望数字变化。
- 用量达到 80% 和 100% 时各发一次通知，走现有 `notify` 和仓库通知设置里的开关。每个月每个阈值只发一次，记在 `github_notify_windows` 里（`event = ci_quota_80` 或 `ci_quota_100`，`repo` 填账号名）。每 30 分钟检查一次，调度用 `Scheduler.Every`。
- 只读，不需要 `auth.RequireElevated`。令牌不要写进日志。

## 前端

`web/src/features/github/GitHubPage.tsx` 的统计条里加卡片，用现有 `StatCard`，样式见 `docs/07-design.md`。

- 接口 404、501 时不显示这张卡片。
- 设置 → GitHub 加“每月免费 CI 分钟数”输入框，默认 2000。
- 新增的中文词条放进 `features/github/i18n.ts`，同一个英文键不能和别的模块冲突。

## 验收标准

- 假 GitHub 服务器返回新接口的样例时，卡片显示正确的已用、总额和按系统的分钟数。
- 新接口回 404 时，退回旧接口，结果一致。
- 回 403 时，卡片显示“未授权”，页面其他部分正常。
- 用量从 79% 到 80% 只发一次通知，下个月重新发。
- 缓存 10 分钟内不重复请求，`refresh=true` 会请求。
- 全部后端和前端检查通过，1360px 和 390px 截图没有横向溢出。
