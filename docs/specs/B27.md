### 1. 代理上报累计字节数

  - Windows 排除：名字里有 `Loopback`、`vEthernet`、`VirtualBox`、`VMware`、`Hyper-V` 的。
  - 规则写成一个函数 `countedInterface(name string) bool`，加单元测试。
- 概要（30 秒）和详情模式都带这两个字段。

### 2. 服务端算增量

- `modules/hosts` 在内存里记每台机器上一个样本的 `(at, rxTotal, txTotal)`。
- 收到新样本：
  - 有累计值：`drx = rxTotal - last.rxTotal`，`dtx` 同理。任何一个是负数（重启、计数器归零、换了网卡），这一段按 0 算，只更新 `last`。
  - 没有累计值（老代理）：`drx = netRx * 秒数`，秒数是和上一个样本的时间差，最多按 60 秒算（断线太久不估算）。这一段标记为估算。
  - 单个样本的增量超过“10 Gbit/s × 秒数”视为异常，丢掉。
- 增量先加到内存里当前小时的累加器，每分钟和整点落库（用调度器，别在收样本的地方写库）。
- 服务重启后第一个样本只记 `last`，不算增量。

### 4. 统计周期

写一个纯函数，放在 `modules/hosts/traffic.go`：

```go
// cycleAt 返回包含 day 的统计周期 [start, end]（含两端），日期按服务器时区。
func cycleAt(day time.Time, startDay, periodMonths int) (start, end time.Time)
```

- 周期从某年某月的 `startDay` 号开始，长度 `periodMonths` 个月。那个月没有 `startDay`（比如 31 号遇到 2 月）时用当月最后一天。
- 多个月的周期以 2000-01 为基准对齐：`(年*12+月 - 2000*12) % periodMonths == 0` 的月份才是周期起点，这样不管哪天打开，算出来的周期都一样。
- `end` 是下一个周期开始的前一天。
- 表格测试：每月 4 号开始 1 个月；31 号开始遇到 2 月和闰年 2 月；3 个月周期跨年；day 正好等于开始日；day 是开始日前一天。

### 5. 接口

- `GET /hosts/{hostId}/traffic`：
  - 没有计划时用默认 `{startDay:1, periodMonths:1, limitBytes:0, countMode:"both", alertPercent:80}`。
  - `cycle=current`：`cycleAt(今天)`；`previous`：`cycleAt(当前周期开始日的前一天)`。
  - `days`：从周期开始到 `min(今天, 周期结束)` 的每一天，没数据的天给 0。今天的数据要加上内存里还没落库的部分。
  - `rx`、`tx` 是 `days` 求和；`usedBytes` 按 `countMode` 算（`max` 是 `max(rx总, tx总)`）。
  - `projectedBytes`：只给 current。`usedBytes / 已过天数 × 周期总天数`，已过不足 1 天时按 1 天算。
  - `estimated`：周期里任何一天 `estimated=1` 就是 true。
- `PUT /hosts/{hostId}/traffic/plan`：校验 `startDay` 1 到 31、`periodMonths` 只能是 1、3、6、12、`alertPercent` 0 到 100、`limitBytes` ≥ 0。存进 `host_traffic_plans`，改了开始日或周期时把 `alerted_cycle`、`alerted_level` 清掉。回新的 `HostTraffic`（current）。审计 `host.traffic_plan`。发事件 `host.traffic_plan_changed`。
- `GET /hosts` 的 `HostListItem.traffic`：有计划且 `limitBytes > 0` 时带上当前周期的 `usedBytes` 和 `limitBytes`。结果按机器缓存 1 分钟，不要每次列表都扫库。

### 6. 提醒

- 每 5 分钟检查一次有上限的计划：
  - 用量 ≥ `alertPercent`% 且这个周期还没到 level 1：发通知 `host.traffic_alert`（普通优先级），标题“<机器名> 流量已用 80%”，正文写已用、上限、剩余天数，链接到这台机器。记 level 1。
  - 用量 ≥ 100% 且还没到 level 2：发高优先级通知“<机器名> 流量已用完”，记 level 2。
  - 周期变了（`alerted_cycle` 不是当前周期开始日）：重置为 0。
- `alertPercent = 0` 时只在用完时提醒。

### 7. 测试

- 增量：正常增长、计数器归零、断线 5 分钟后重连、老代理按速率估算、异常大的增量被丢掉。
- 落库：跨小时、跨天（服务器时区）。
- 周期：见上面第 4 条。
- 接口：用测试数据造 30 天，`current` 和 `previous` 的日期范围和合计都对；`max` 模式按累计取大。
- 提醒：上限 10 GB、提醒 80%，造 8 GB 发一条，10 GB 再发一条，同一周期不重复；改了开始日以后重新提醒。
