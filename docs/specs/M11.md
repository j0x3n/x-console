# M11 个人生活：日历、早报、番茄钟

状态：已完成。早报依赖多个 contracts，取不到的部分就跳过。

## 日历

| 表 | 列 |
| --- | --- |
| `calendars` | id、name、kind（ics/caldav）、url、username、secret（加密）、color、enabled、last_synced_at、last_error |
| `calendar_events` | id、calendar_id、uid、title、start、end、all_day、location、description、rrule、recurrence_id |

- 每 15 分钟同步一次。ICS 用 `github.com/arran4/golang-ical` 解析，重复事件在查询时按范围展开（rrule-go）。
- CalDAV 用 `github.com/emersion/go-webdav/caldav`，先只读。
- 接口：`/calendars` CRUD，`POST /calendars/{id}/sync`，`GET /calendar/events?from=&to=`。
- 提供 `contracts.Calendar`，动作 `calendar.events`（read）。
- 前端 `features/calendar`：日视图和周视图，手机默认日视图。

## 每日早报

- 设置：`brief.time`（默认 `08:00`）、`brief.channels`（走哪些渠道，默认按路由规则）、`brief.location`（天气城市的经纬度）、`brief.sections`（启用哪些部分）。
- 内容：天气（Open-Meteo，无需密钥）、今日日程、今天和逾期的 Issue、今天的提醒、昨天的服务器告警、习惯昨天的完成情况和今天目标、续费提醒（M10 有的话）。
- 每部分由一个函数生成，拿不到数据（contracts 取不到或出错）就跳过这部分，不影响其他部分。
- 生成的内容存表 `briefs`（date、content Markdown、sent_at），面板里能看历史。
- 发送用 `notify.Send`，kind `brief.daily`。
- 可选：设置里打开“用 AI 润色”后，把原始内容交给 Claude 生成一段简短的中文总结放在最前面（用 M12 的 Claude 客户端；M12 未完成时隐藏这个开关）。
- 接口：`GET /briefs`、`GET /briefs/{date}`、`POST /briefs/generate`（立即生成一份预览）、`GET/PUT /briefs/settings`。
- 天气单独提供 `GET /weather`，M1 首页用。

## 番茄钟

| 表 | 列 |
| --- | --- |
| `focus_sessions` | id、issue_key、started_at、ended_at、planned_minutes、actual_seconds、completed、note |

- 服务端只记录。计时在前端，但开始和结束都要调接口，这样换设备也能看到正在进行的番茄钟。
- 结束时间到了由服务端发通知（kind `focus.done`），防止页面关掉后收不到。
- 接口：`POST /focus/start`、`POST /focus/{id}/stop`、`GET /focus/current`、`GET /focus/stats?days=`。
- 前端：页头按钮（`app/TopbarActions.tsx` 加一行），显示剩余时间；点开可选关联 Issue。Issue 详情页也能开始番茄钟（给 M5 页面加一个按钮，改动尽量小）。

## 验收

- ICS 测试文件含重复事件，周视图展开正确，时区正确。
- 早报在所有依赖模块都缺失时仍能生成（只有天气和日期）。
- 番茄钟开始后关闭页面，到点收到通知。

## 实现说明

和上面规格不同或补充的地方：

- **后端分成三个模块**：`modules/calendar`（日历，提供 `contracts.Calendar`）、`modules/brief`（早报和天气）、`modules/focus`（番茄钟）。接口契约分别是 `api/modules/calendar.yaml`、`brief.yaml`、`focus.yaml`。前端都在 `features/calendar`。
- **迁移**：`20260927220000_m11_calendar.sql`、`20260927220100_m11_briefs.sql`、`20260927220200_m11_focus.sql`。
- **日历表**：`start`、`end` 是 SQL 关键字，列名改成 `starts_at`、`ends_at`。另加 `tzid`、`rdates`、`exdates`（JSON）、`created_at`。
  - 事件时间存“墙上时间”加时区名，查询时在事件自己的时区展开，所以跨夏令时的重复事件时间不漂移。没有时区的浮动时间和全天事件按用户时区（`Config.Location`）理解。
  - 支持 RRULE、EXDATE、RDATE、DURATION、改过的单次发生（RECURRENCE-ID），取消的单次发生变成 EXDATE。Windows 时区名（Outlook）和 `X-WR-TIMEZONE` 也能识别。
  - 按秒或按分钟重复的规则（SECONDLY、MINUTELY）不展开，只显示第一次。
  - 同步失败时保留上次的事件，错误写在 `lastError`，错误信息里不带地址（订阅链接常含私密 token）。
  - 密码用 `secrets.Box` 加密存在 `calendars.secret`，接口只返回 `hasPassword`。
  - CalDAV 的地址可以是日历集合、日历主目录或服务器根地址，找不到日历时按 current-user-principal 自动发现。只读，只取 VEVENT 日历。
  - 新建或改了地址后在后台同步一次，完成时发 `calendar.synced` 事件。`POST /calendars/{id}/sync` 同步完再返回。
  - `GET /calendar/events` 范围最长 100 天。接口还有 `GET /calendars/{id}`。
- **早报**
  - 设置每项一个键：`brief.enabled`（默认开）、`brief.time`、`brief.channels`、`brief.location`（`{lat, lon, name}`）、`brief.sections`、`brief.ai_polish`、`brief.weather_api_base`（默认 `https://api.open-meteo.com`，测试指向假服务器）。
  - 定时：每分钟检查一次（发送时间是设置项，不用固定 cron）。到点后 3 小时内还没发就补发，超过就等明天。判断逻辑是纯函数 `shouldSend`。
  - `brief.channels` 为空时按通知路由规则发。选了渠道时，通知以 low 优先级发出（默认规则只把 normal 以上推到外部，所以只留站内），再直接发给选中的渠道。如果路由规则里有匹配 `brief.daily` 且接受 low 的规则，可能会重复。
  - `POST /briefs/generate`：`{send: false}` 只预览不保存；`{send: true}` 保存为今天的早报并发送。
  - 表 `briefs` 另存 `sections`（JSON），前端和测试可以按部分查看。通知正文是去掉 Markdown 标题的纯文本，链接 `/calendar/briefs?date=<日期>`。
  - 习惯部分只有今天的目标、已完成和连续天数：`contracts.Habits` 没有“昨天”的数据。
  - 服务器告警取从昨天 0 点到现在的，包含夜里的告警。
  - `GET /weather` 结果缓存 10 分钟。没设置位置且没传经纬度时返回 412。
  - **续费**：早报通过 `contracts.RenewalsKey` 查找运维监控模块提供的 `contracts.Renewals`。`Upcoming(ctx, until)` 返回未归档且在截止日期前续费的订阅，包含尚未处理的逾期订阅。
  - **AI 润色**（M12 未完成）：早报查找注册表键 `ai.brief_polisher`，值实现 `Polish(ctx, markdown string) (string, error)`。有它时设置接口返回 `aiAvailable: true`，前端才显示开关；打开后总结放在最前面（部分 key 为 `summary`）。
- **番茄钟**
  - 同时只能有一个进行中，再开始返回 409（`focus_running`）。已经到点但没人点结束的，开始新的时自动算作完成。
  - 到点通知靠内存定时器准时发出，每分钟的扫描兜底（比如重启后）。通知只发一次（`notified_at`），带“再来一个”按钮（`focus.again:<id>`）。
  - 到点 1 小时后还没结束的自动结束并算完成。计划时间之后的时间不计入时长。
  - 暂停没有做，前端只有“提前完成”和“放弃”。
  - `GET /focus/current` 返回 `{session}`，没有时 `session` 不出现。`GET /focus/stats` 还返回按 Issue 的时长和最近 10 次。
- **动作**：`calendar.events`（read）、`brief.preview`（read）、`focus.start`（write）、`focus.stop`（write）、`focus.current`（read）。
- **事件**：`calendar.created/updated/deleted/synced`、`brief.sent`、`brief.settings_updated`、`focus.started/stopped/done`。
- **前端**
  - `/calendar` 日程（日视图、周视图，宽度 640px 以下默认日视图），`/calendar/briefs` 早报历史，`/calendar/focus` 专注统计，`/calendar/calendars` 日历管理。
  - 设置页“早报”标签（`/settings/brief`）。
  - 页头番茄钟按钮显示剩余时间，点开可以选时长和关联 Issue。Issue 详情页右栏有“开始专注”按钮。
