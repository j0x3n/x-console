# B31 云盘文件操作

用户要求（2026-09-28）：

- 除了文件夹和二进制文件，都能当纯文本编辑，能保存，并自动保存历史版本。
- 多选，复制、移动、压缩、解压、外链分享等基本操作。（用户原话是“外链分析”，按“外链分享”理解，验收时确认。）
- 日志这类文件要能高性能地实时滚动。
- 浏览器能显示的文件都能在弹窗里预览，并且可以全屏。

## 文本编辑

- 判断能不能编辑：读文件前 8 KB，没有 `\0` 且能按 UTF-8 解码（允许末尾截断的字符）就算文本。大小超过 10 MB 的不能编辑，只能用下面的日志查看方式看。
- 编辑器：用 CodeMirror 6（按需加载，不进主包），按扩展名高亮（常见的 json、yaml、md、js、ts、go、py、sh、ini、conf、nginx、sql、html、css、xml、csv、log）。显示行号，支持搜索替换。
- 保存：`⌘S` / `Ctrl+S` 或按钮。接口 `PUT /drive/files/{id}/content`，带上打开时的版本号（`If-Match`），别处改过时回 409，界面提示“文件在别处改过了”，可以选“看对比”或“覆盖”。
- 关闭时有没保存的改动要提示。
- 编码：只支持 UTF-8。打开 GBK 等编码的文件时提示“不是 UTF-8，编辑后会改成 UTF-8”，可以选只读查看。

## 历史版本

- 每次保存前，把旧内容存一份到 B24 的 `drive-versions/`。
- 新表 `drive_file_versions(id, file_id, size, sha256, created_at, key)`。内容一样（sha256 相同）时不重复存。
- 默认每个文件保留最近 50 个版本、最多 30 天，设置里可以改。超出的每天清理一次。
- 文件菜单里“历史版本”：列出时间、大小；点一个版本看内容和与当前版本的对比（行级 diff）；可以“恢复这个版本”（恢复本身也会产生一个新版本）。
- 删除文件时版本一起进回收站，彻底删除时一起删。

## 多选和批量操作

- 已有多选。选中后顶栏（B20）显示：下载（多个文件打包成 zip）、复制到、移动到、压缩、删除、取消选择。
- 复制、移动：弹窗选目标文件夹（树形，可以新建文件夹）。重名时问：跳过、覆盖、保留两个（加“ (1)”）。
- 大批量操作在后台做，界面显示进度，完成后提示。操作可以取消。

## 压缩和解压

- 压缩：选中的文件和文件夹打成 `zip`（默认）或 `tar.gz`，名字默认用第一个文件名，可以改。
- 解压：支持 `zip`、`tar`、`tar.gz`、`tgz`。解压到同名文件夹，或者选目标文件夹。
- 安全：拒绝路径里有 `..` 或绝对路径的条目；解压后总大小超过 10 GB 或文件数超过 10 万时停止并提示（防止压缩炸弹）；不跟随符号链接。
- 在后台做，显示进度。

## 外链分享

- 文件或文件夹菜单里“分享”：生成链接 `https://<面板>/s/<随机 22 位>`。
- 选项：有效期（1 天、7 天、30 天、永久）、提取码（可选，4 到 8 位）、允许下载次数上限（可选）。
- 打开链接的页面不需要登录，只能看和下载这一个文件或这一个文件夹里的内容，不能看别的。文件夹分享可以下载单个文件或整体打包。
- 公开入口要：校验链接和提取码（提取码错 5 次锁 10 分钟）；按 IP 限流；隐藏空间里的文件不能分享；文件删除或移到回收站后链接失效。
- 设置里（或云盘页的一个标签）“分享管理”：列出所有链接、访问次数、下载次数，可以随时取消。
- 审计：创建、取消、每次下载都记。

## 预览

- 点文件打开预览弹窗（现在已有预览，改成统一的弹窗）。支持：
  - 图片（png、jpg、gif、webp、svg、avif、bmp、ico）：可以缩放、拖动、上一张下一张。
  - 视频、音频：浏览器原生播放器，支持 Range 请求拖动进度。
  - PDF：浏览器内置查看器（`<iframe>` 或 `<embed>`）。
  - 文本和代码：B31 的编辑器只读模式，有“编辑”按钮。
  - Markdown：渲染后显示，可以切到源码。
  - 其他：显示文件信息和“下载”按钮。
- 弹窗右上角有“全屏”按钮（`requestFullscreen`），`Esc` 退出。键盘左右键切换同一个文件夹里的文件。
- 手机上弹窗直接全屏。

## 日志文件

- 扩展名是 `.log`，或者大于 10 MB 的文本文件，用 B29 的 `LogViewer` 打开，不用编辑器。
- 按需读：先读最后 1 MB；往上滚时用 Range 请求再往前读 1 MB。不一次读整个文件。
- “实时”开关：打开后通过 WebSocket 订阅这个文件的追加内容（服务端每秒检查一次文件大小，变大就推新增的部分），新内容追加到底部并自动滚动。文件变小时（被轮转）从头开始。
- 关键字过滤和高亮。
- 服务器“文件”标签打开远端日志文件时也用同一个查看器，代理那边用 `files.tail`（没有就在代理里加），逻辑一样。

## 验收

- 编辑一个 yaml 文件并保存，历史里多一个版本；恢复旧版本后内容对；同时在两个标签页编辑同一个文件，后保存的收到 409。
- 二进制文件（比如 png、zip）没有“编辑”入口。
- 多选 3 个文件移动到另一个文件夹，重名时三个选项都对。
- 压缩 → 下载 → 在本地解压，内容一致；上传一个带 `../` 条目的 zip，解压被拒绝。
- 分享链接在无痕窗口能打开和下载；提取码错 5 次被锁；过期后回 404；取消后回 404；隐藏空间的文件没有“分享”入口。
- 500 MB 的日志文件打开不超过 1 秒，滚动流畅；实时模式下往文件追加一行，1 秒内显示。
- 预览：图片、视频、PDF、文本、Markdown 各一个，全屏和退出都正常；390px 下预览是全屏。
- 分享页面、压缩、解压都有后端测试。

## 后端（待做，给开发者）

按下面的顺序做，每一步都能单独测。新代码放在 `modules/drive/` 下，按功能分文件：`zip.go`、`tasks.go`、`transfer.go`、`archive.go`、`versions.go`、`share.go`、`follow.go`。

### 1. 打包下载 `GET /drive/zip`

- 每个 id 用现有的 `visibleRow` 取（隐藏的没解锁回 404），回收站里的回 404。
- 用 `archive/zip` 直接写进 `ResponseWriter`，不落盘。`Content-Type: application/zip`，`Content-Disposition` 用 `mime.FormatMediaType` 写文件名（中文名要能下）。
- 文件夹递归，zip 里的路径从选中条目的名字开始。空文件夹也写一个目录条目。跳过回收站里的子条目。
- 已经开始写响应后出错，只能断开连接，记日志。
- 审计 `drive.zip`，记条目数。

### 2. 后台任务 `tasks.go`

- 任务只存内存：`map[string]*task`，一把锁。`id` 用 `secrets.RandomID()`。
- 结构对应 `api.DriveTask`，另外带一个 `context.CancelFunc`。任务的 context 从模块 `Start` 的 ctx 派生，不用请求的 ctx（请求结束任务不能停）。
- 同时最多跑 2 个任务，多的排队（排队时 `state` 仍是 `running`，`current` 写“等待中”）。
- 进度通过 `Bus.Publish("drive_task.updated", dto)` 推送：状态变化时马上推，进度变化时最多每 300ms 推一次。
- 结束 10 分钟后从 map 里删掉，由现有的 `Scheduler` 每分钟清一次。
- `GET /drive/tasks`：正在跑的加最近 10 分钟结束的，按 `createdAt` 倒序。
- `POST /drive/tasks/{id}/cancel`：调 `CancelFunc`，状态改 `canceled`。不存在回 404，已结束原样返回。
- 任务结束时（任何状态）再推一次 `drive_item.batch`，前端按 `drive_item.` 前缀刷新列表。不要每个文件推一次。
- `title` 服务端写好中文，比如“复制 3 项到 /照片”“压缩 12 项为 日志.zip”“解压 备份.tar.gz”。

### 3. 复制和移动 `transfer.go`

- 请求校验（同步做，出错直接回 4xx，不建任务）：
  - `ids` 每个都用 `visibleRow`，不能在回收站。
  - `targetId` 为 0 是根目录；否则必须是文件夹、不在回收站、调用方能看到。
  - 目标是某个被选文件夹自己或它的子孙：400 `invalid_target`（用现有的 `descendant`）。
  - 隐藏规则和 `PATCH` 移动一致：普通条目不能放进隐藏空间，隐藏条目不能放到普通目录，不一致回 400 `hidden_mismatch`。
- 重名只看选中的最上层条目和目标里已有的条目：
  - `skip`：跳过，`skipped++`。
  - `overwrite`：把目标里的旧条目移到回收站（走现有的删除逻辑），再放新的。类型不同（文件对文件夹）时按 `rename` 处理。
  - `rename`：用现有的 `freeName` 取“名字 (1)”。
- 复制文件只插一行新记录，`sha256` 和原来一样，不复制文件内容（blob 按内容存，已经是共享的）。`doneBytes` 按文件大小累加，给界面一个进度。
- 复制文件夹：先建文件夹，再递归复制里面的东西（新建的文件夹里不会重名）。每 200 个条目提交一次事务，避免长事务锁库。
- 移动：每个条目一个事务改 `parent_id`。
- 取消：已经复制的保留，停在当前条目。
- 审计 `drive.copy`、`drive.move`，内容写条目数和目标。

### 4. 压缩 `archive.go`

- 先遍历一遍算 `totalItems` 和 `totalBytes`，再写。
- 写到 `<drive 根目录>/tmp/` 下的临时文件，同时用 `io.MultiWriter` 算 sha256。写完 `os.Rename` 到 `blobPath(hash)`（已存在就删临时文件）。
- zip 用 `archive/zip`（Deflate）；tar.gz 用 `archive/tar` 加 `compress/gzip`。条目路径用 `/`，保留修改时间。
- `name` 没有 `.zip`、`.tar.gz` 时补上。放在 `parentId`（隐藏规则同上），重名用 `freeName`。mime 分别是 `application/zip`、`application/gzip`。
- `resultId` 是新文件，`targetId` 是它所在的文件夹。
- 取消或失败时删掉临时文件，不留半个压缩包。

### 5. 解压 `archive.go`

- 支持 `.zip`、`.tar`、`.tar.gz`、`.tgz`，按扩展名判断，再用开头几个字节核对（zip 是 `PK\x03\x04`，gzip 是 `\x1f\x8b`）。对不上回 400 `archive_unsupported`。
- **先检查，再写**：第一遍只读目录（zip 读中央目录；tar 顺序扫一遍），检查：
  - 路径：统一成 `/`，`path.Clean` 后以 `/` 开头、含 `..`、含盘符（`C:`）的，任务失败，`errorCode = archive_unsafe_path`，一个文件都不写。
  - 总大小超过 10 GB 或条目超过 10 万：失败，`errorCode = archive_too_large`。
- 第二遍真正解压：
  - 每个文件用 `io.LimitReader` 按声明的大小读，实际读到的总量超过 10 GB 也停止（压缩包里写的大小可能是假的）。
  - 符号链接、硬链接、设备文件、FIFO 跳过，`skipped++`。
  - 文件内容同样先写临时文件算 sha256，再挪进 blob。
  - 文件夹按路径建，用一个 `map[路径]id` 记住。
  - zip 里没有 UTF-8 标记的文件名，按 GBK 解码（`golang.org/x/text/encoding/simplifiedchinese`，已经是依赖）。
- 位置：
  - 不传 `targetId`：在压缩包旁边建“去掉扩展名的名字”的文件夹，重名加“ (1)”，解压到里面。`resultId` 是这个文件夹。
  - 传了 `targetId`：直接解压进去。文件重名按 `conflict` 处理，文件夹同名就合并。
- 取消或失败：删掉这次新建的所有条目（记一个列表），用 `permanentDelete`。
- 隐藏：压缩包在隐藏空间里，解压出来的也是隐藏的。

### 6. 历史版本 `versions.go`

迁移（比如 `20260929000200_b31_drive_versions_shares.sql`，时间要晚于最新的迁移）：

```sql
CREATE TABLE drive_file_versions (
    id         INTEGER PRIMARY KEY,
    item_id    INTEGER NOT NULL REFERENCES drive_items (id) ON DELETE CASCADE,
    size       INTEGER NOT NULL,
    sha256     TEXT    NOT NULL,
    created_at DATETIME NOT NULL
);
CREATE INDEX drive_file_versions_item ON drive_file_versions (item_id, created_at DESC);
CREATE INDEX drive_file_versions_hash ON drive_file_versions (sha256);
```

- 和规格开头写的 `drive-versions/` 目录不同：版本内容直接用现有的 blob（按 sha256 存，同样内容只存一份），表里只记 sha256。这样不用复制文件，也自动去重。B24 挪目录时 blob 一起挪。
- **blob 引用计数要算上版本**：`CountBlobReferences` 改成 `drive_items` 和 `drive_file_versions` 里引用数之和。不改的话，旧版本的内容会在保存后被删掉。这一条必须有测试。
- 什么时候存版本：内容要被替换时（`SaveDriveItemContent`、`actionWriteText`、恢复版本、复制/解压时 `overwrite` 不算，那是进回收站）。旧 sha256 为空或和新的一样时不存；和最近一个版本一样时也不存。
- `GET .../versions`：按 `created_at` 倒序。文件夹回 400。
- `GET .../versions/{vid}/content`：`http.ServeContent`，支持 Range。版本不属于这个条目回 404。
- `POST .../restore`：一个事务里先把当前内容存成版本，再把条目的 `sha256`、`size`、`updated_at` 改成这个版本的。版本本身不删。回 200 和条目，响应头 `ETag`。发 `drive_item.updated`，S3 同步状态改成待同步。审计 `drive.version.restore`。
- 保留规则：设置键 `drive.versions`，值 `{"keepCount":50,"keepDays":30}`，没存过用默认值。`PUT` 校验范围（1–500、1–3650），不对回 400。
- 清理：`Scheduler.Every("drive.versions.prune", 24*time.Hour, ...)`，每个文件只留最近 `keepCount` 个，并删掉早于 `keepDays` 天的。删行之后对每个 sha256 调 `dropBlob`。`PUT` 设置后也异步跑一次。
- 彻底删除条目时：先查出它所有版本的 sha256，删掉条目（版本跟着级联删），再逐个 `dropBlob`。进回收站时版本不动。

### 7. 外链分享 `share.go`

迁移（和版本放同一个文件）：

```sql
CREATE TABLE drive_shares (
    id             INTEGER PRIMARY KEY,
    item_id        INTEGER NOT NULL REFERENCES drive_items (id) ON DELETE CASCADE,
    token          TEXT    NOT NULL UNIQUE,
    code_sealed    TEXT,              -- 提取码，用 Deps.Secrets（secrets.Box）加密；没有提取码为 NULL
    expires_at     DATETIME,          -- NULL 表示永久
    max_downloads  INTEGER,
    visits         INTEGER NOT NULL DEFAULT 0,
    downloads      INTEGER NOT NULL DEFAULT 0,
    created_at     DATETIME NOT NULL,
    last_access_at DATETIME
);
CREATE INDEX drive_shares_item ON drive_shares (item_id);
```

主人这边：

- `POST /drive/shares`：条目用 `visibleRow`。条目隐藏（自己或任何上级隐藏）、在回收站：400 `share_not_allowed`。
  - `token`：16 字节 `crypto/rand`，base62 编码成 22 位。
  - `expiresIn` 换成 `expires_at`（`never` 为 NULL）。`code` 按契约校验后加密存。
  - `url`：`Config.PublicURL + "/s/" + token`。`PublicURL` 没配时用请求的 `Host` 和 `X-Forwarded-Proto` 拼。
  - 回 201，带明文 `code`。审计 `drive.share.create`。发 `drive_share.changed`。
- `GET /drive/shares`：`JOIN drive_items` 拿名字。`active` 在查询时算：没过期、没到下载上限、条目不在回收站、不是隐藏。`shared`（`DriveItem` 上的字段）用 `EXISTS` 子查询算有没有生效的链接。
- `DELETE /drive/shares/{id}`：删行。审计 `drive.share.delete`。发 `drive_share.changed`。
- 清理：每天删掉失效超过 7 天的链接。

公开入口（安全要求，逐条做）：

- `PublicPaths()` 返回 `/public/shares`（现在在 `pending.go`，挪到 `share.go`）。这些接口没有会话，自己校验。
- **限流**：按 IP（和 `auth` 一样取 `X-Forwarded-For` 第一段）每分钟 60 次，超出回 429 `rate_limited`，带 `Retry-After`。用内存里的计数器，定时清掉旧的。
- **找分享** `resolve(token)`：token 不存在、过期、条目在回收站、条目或任何上级是隐藏的，一律 404 `share_not_found`。不同原因不要回不同的错误，防止试探。
- **提取码**：
  - 有提取码时，除了 `unlock`，其他接口都要带 `t`。`t` 是无状态的签名令牌：`<分享 id>.<过期时间戳>.<HMAC-SHA256>`，1 小时有效，签名密钥用 `secrets.Box` 派生一个（或者在设置里存一个随机密钥）。取消分享后令牌自然失效（`resolve` 先找不到分享）。
  - `unlock`：用 `subtle.ConstantTimeCompare` 比较。同一个 IP 对同一条链接错 5 次，锁 10 分钟：锁住时回 429 `share_locked`，message 写“试错太多次，10 分钟后再试”。错了回 403 `share_code_wrong`，message 写“提取码不对，还能试 N 次”。计数存内存。
  - 没带或带了无效的 `t`：401 `share_code_required`。
- **只能访问分享的范围**：文件夹分享时，`folder` 和 `item` 参数要沿 `parent_id` 往上找，能找到分享的那个文件夹才行（最多找 64 层），否则 404。隐藏的、在回收站的子条目当作不存在。
- **下载计数**：不带 `Range`、或者 `Range` 从 0 开始的请求才算一次下载。用 `UPDATE ... SET downloads = downloads + 1 WHERE id = ? AND (max_downloads IS NULL OR downloads < max_downloads)`，影响行数为 0 就回 410 `share_limit_reached`。打包下载算一次。`GET /public/shares/{token}` 成功时 `visits + 1`，更新 `last_access_at`。
- **防止在面板域名下跑脚本**：分享的文件和面板在同一个域名。响应一律带 `X-Content-Type-Options: nosniff` 和 `Content-Security-Policy: default-src 'none'; sandbox`。`inline=1` 只对图片（png、jpeg、gif、webp、avif、bmp）、视频、音频、PDF 生效，其他类型（包括 svg、html）一律 `attachment`。
- 审计：每次下载记 `drive.share.download`，actor 写 `share:<id>`，内容带 IP 和文件 id。
- `/s/<token>` 页面：服务端现有的 SPA 回退（`app.go` 的 `spa`）已经会返回 `index.html`，不用改。

### 8. 日志实时 `follow.go`

- 用 `coder/websocket`，写的时候不要传会被取消的 context（AGENTS.md）。参考 `hosts/terminal.go` 的写法。
- 云盘的文件内容按 sha256 存，文件“变大”只会发生在保存或上传覆盖以后，也就是条目的 `sha256` 变了。所以每秒查一次条目：
  - `sha256` 没变：什么都不做。
  - 变了且新大小 ≥ 已发位置：把 `[位置, 新大小)` 从新 blob 读出来发。
  - 变了且新大小 < 已发位置：先发 `{"type":"reset"}`，再从 0 开始发。
  - 条目被删或进回收站：正常关闭（1000）。
- 每帧最多 256 KB，多的分几帧。末尾不完整的 UTF-8 字节留到下一帧，`offset` 按实际发出的字节算。
- 连接超过 1 小时自动关闭（前端会显示断开，用户可以再打开）。

### 9. 测试

放在 `drive` 的外部测试包里，和现有的 `drive_test.go` 一样起真实的 app。

- 打包下载：两个文件和一个文件夹，解开后内容和路径都对；隐藏条目没解锁时 404。
- 复制：同名三种处理各一条；复制文件夹后子条目数量对；复制到自己的子文件夹回 400。
- 移动：批量移动 3 个，重名时三种处理都对。
- 任务：取消后状态是 `canceled`；10 分钟后从列表消失（替换时间函数）。
- 压缩：zip 和 tar.gz 各一个，解开后和原来一样。
- 解压：正常的 zip、tar.gz；带 `../x` 的 zip 被拒绝且一个文件都没写；声明 20 GB 的 zip 被拒绝；带符号链接的 tar 跳过链接；GBK 文件名的 zip 解出中文名。
- 版本：保存两次后有 2 个版本；恢复后内容对且多一个版本；**保存后旧 blob 还在**；超过 `keepCount` 的被清掉且 blob 被删；彻底删除文件后版本和 blob 都没了。

- 日志实时：连上后保存一次更长的内容，收到新增部分；保存更短的内容，收到 `reset`。
