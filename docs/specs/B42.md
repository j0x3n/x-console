# B42 AI 用量：缓存命中率、历史记录

用户 2026-09-30 提出：AI 用量统计要显示缓存率，历史记录也能查看。

## 现状

- `ai_usage` 每次调用记一行：输入、输出 token、耗时、估算费用。只有 `GET /ai/usage?month=` 返回某个月的汇总。
- 调用层只读了 `prompt_tokens` / `input_tokens`，没读缓存相关的字段。费用按原价算，用了缓存的部分算多了。
- Agent 任务（Claude Code、Codex CLI 在代理上跑的）用的 token 完全没记。

## 1. 记录缓存

- 迁移给 `ai_usage` 加列（只加不删）：
  - `cached_input_tokens`：命中缓存的输入 token。
  - `cache_write_tokens`：写入缓存的输入 token（Anthropic 这类要单独收费的才有）。
  - `reasoning_tokens`：思考用的输出 token。
  - `source`：从哪里调的，`assistant`、`notes`、`brief`、`host_agent`、`coding`、`mcp`（B43），默认空串。
  - `ref`：关联对象，比如对话 id、笔记 id、Agent 任务 id，默认空串。
  - `status`：`ok` 或 `error`；`error` 列存报错信息，最多 500 字。
- 缓存价从 models.dev 的 `cost.cache_read`、`cost.cache_write` 读（每百万 token 的美元价格），和输入输出价一样放在内存里的目录中，接口 `AiModel` 加 `cacheReadPrice`、`cacheWritePrice`。（实现时发现价格本来就不存在 `ai_model_specs` 里，所以没有加列。）
- 调用层读这些字段：
  - Chat Completions：`usage.prompt_tokens_details.cached_tokens`、`usage.completion_tokens_details.reasoning_tokens`。
  - Responses：`usage.input_tokens_details.cached_tokens`、`usage.output_tokens_details.reasoning_tokens`。
  - 兼容 Anthropic 格式的供应商会回 `cache_read_input_tokens`、`cache_creation_input_tokens`，读到了也记下。
- 统一口径：`input_tokens` 存全部输入，包括命中缓存和写入缓存的部分。Anthropic 格式的输入不包括缓存，入库前加回去。缓存命中率 = `cached_input_tokens / input_tokens`。
- 费用 = 未命中缓存的输入 × 输入价 + 命中的 × 缓存读价 + 写入的 × 缓存写价 + 输出 × 输出价。缺缓存价时命中部分按输入价算，界面上标“估算”。
- 报错的调用也记一行，token 为 0，方便看失败率。

## 2. Agent 任务的用量

- 代理把执行器输出里的用量上报，服务端记进 `ai_usage`，`source` 为 `coding`，`ref` 为任务 id：
  - Claude Code（`--output-format stream-json`）：最后的 `result` 事件里的 `usage` 和 `total_cost_usd`。有 `total_cost_usd` 时直接用它做费用。
  - Codex CLI（`exec --json`）：`turn.completed` 事件里的 `usage`（`input_tokens`、`cached_input_tokens`、`output_tokens`）。
- 读不到用量时不记，任务详情里写“未提供用量”。

## 3. 接口

- `GET /ai/usage` 保留，返回里加 `cachedInputTokens`、`cacheWriteTokens`、`cacheHitRate`。
- `GET /ai/usage/summary?from=&to=&groupBy=`：`from`、`to` 是日期（服务器时区，包含两端），最多跨 366 天。`groupBy` 是 `day`、`model`、`source`、`provider`。每组返回：次数、失败次数、输入、命中缓存、写入缓存、输出、思考、费用、平均耗时、命中率。
- `GET /ai/usage/records?from=&to=&model=&source=&status=&cursor=&limit=`：按时间倒序的明细，每页默认 50 条，最多 200 条。
- `GET /ai/usage/records.csv`：同样的条件导出 CSV。
- 记录保留 400 天，每天清理一次。

## 4. 界面

在 设置 → AI 里，原来的“本月用量”卡片改成“用量”页签：

- 顶部选时间范围：今天、7 天、30 天、本月、上月、自定义。
- 一行数字：调用次数、输入、输出、缓存命中率、估算费用。和上一个同样长度的时间段比，显示升降。
- 按天的柱状图：输入分成“命中缓存”和“未命中”两段叠在一起。命中率放在悬停提示和顶部数字里，不在同一张图上再画一条折线（两个量纲不同，放一张图会变成双纵轴）。两种颜色按 `dataviz` 的校验脚本选过，浅色和深色各一套。
- 两张表：按模型、按来源。列：次数、输入、输出、命中率、费用。点一行就用它过滤下面的明细。
- 明细列表：时间、来源、模型、输入 / 命中 / 输出、耗时、费用、状态。点一行展开看关联对象（能跳过去，比如跳到那条对话或那个 Agent 任务）和报错信息。滚到底自动加载下一页。
- “导出 CSV”按钮。
- 手机上表格改成卡片列表，图表可以横向滑动。

## 验收

- 用假服务器分别回三种格式的 `usage`，入库的数字和命中率正确，Anthropic 格式的输入加回了缓存部分。
- 费用计算有单元测试，覆盖有缓存价和没有缓存价两种情况。
- Claude Code 和 Codex 的样例输出（放 `testdata`）能解析出用量。
- `summary` 按天分组时没有调用的日子也返回 0，前端图表不断档。
- 跨月、跨年的时间范围正确。
- 截图 1360px 和 390px 自查。
