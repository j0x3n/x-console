# B19 部署前自动备份，出错自动回退

用户要求（2026-09-27）：项目越来越大，每次部署都直接改线上，要能保住数据、出错能退回去。后端这一轮会加很多数据库迁移，所以排在最前面做。

## 现在的情况

- `deploy/remote-deploy.sh`：改 `.env` 里的 `XC_IMAGE`，`docker compose up -d`，等 `/api/v1/health` 60 秒。没就绪就打印日志、退出，**但不回退**，线上会停在坏掉的版本。
- 服务器上保留本次和上一次的镜像，可以手动回退。数据库没有自动备份，`docs/06-deploy.md` 里只写了手动复制的命令。
- 数据库在启动时自动跑迁移。迁移跑了一半或者新版本改坏了数据，退回旧镜像也救不回来。

## 要什么

1. **部署前备份数据库**：每次部署前，在服务器上生成一份一致的数据库备份，保留最近 10 份，放在部署目录的 `backups/` 下。文件名带时间和旧版本号，比如 `x-console-20260927-1530-sha-8fed186.db`。
2. **出错自动回退**：新版本 60 秒内健康检查没过，自动：
   - 停掉新容器；
   - 用部署前的备份替换数据库（新版本可能已经跑了迁移）；
   - `.env` 的 `XC_IMAGE` 改回旧镜像，重新启动；
   - 等旧版本健康检查通过；
   - 脚本以非零退出码结束，GitHub Actions 显示失败，用户能看到。
3. **手动回退**：`remote-deploy.sh rollback` 退回上一个版本并恢复部署前的备份；`remote-deploy.sh restore <备份文件>` 只恢复数据库。都写进 `docs/06-deploy.md`。

## 怎么做

- 服务端加子命令 `x-console backup <路径>`：打开数据库，执行 `VACUUM INTO '<路径>'`，得到一致的副本。服务运行时也能用，不用停服务（SQLite 的 WAL 模式下安全）。
- `remote-deploy.sh` 部署前：旧容器在运行时，`docker compose exec -T x-console x-console backup /data/backups/<文件名>`；第一次部署没有旧容器时跳过。`/data/backups` 在数据卷里，脚本再把超过 10 份的旧文件删掉。
- 回退时恢复：`docker compose stop x-console`，用一个临时容器挂同一个卷，把备份复制成 `/data/x-console.db`，同时删掉 `-wal`、`-shm` 文件，再启动旧镜像。
- 迁移本身保持“只加不删”：删列、改列要分两次部署做（先停止使用，下个版本再删），写进 `docs/03-backend.md`。

## 验收

- 本地用 docker compose 演练：正常部署会多一份备份；故意推一个启动就崩的镜像，脚本自动退回旧版本，数据和部署前一样，退出码非零。
- `rollback`、`restore` 两个命令都演练一遍。
- `x-console backup` 有单元测试：备份出来的文件能打开，表和数据都在。
