## AI 助手

- 工具来自 `d.Actions.List()`：每个动作是一个工具，name 把 `.` 换成 `__`，description 和 input_schema 直接用。
- 执行规则（2026-09-27 用户调整：助手要能按请求自动读写删）：
  - `read`：直接执行，结果回给模型。
  - `write`：新建和修改直接执行。删除类动作（动作名以 `.delete` 结尾或在动作上标了 `Destructive`）先暂停等确认。设置里有“所有写操作都先确认”开关，默认关。
  - `dangerous`：暂停，把“要执行的动作和参数”推给前端，用户点确认后执行，确认接口要求提升权限。拒绝时给模型返回“用户拒绝了”。
- 隐藏内容（B13）对助手不可见，就算当前会话已解锁。
- 对话存库，前端断线重连后能接着看。

| 表 | 列 |
| --- | --- |
| `ai_conversations` | id、title、created_at、updated_at |
| `ai_messages` | id、conversation_id、seq、role、content（JSON，原样保存 API 的 content blocks）、created_at |
| `ai_pending_actions` | id、conversation_id、tool_use_id、action、input、status（pending/approved/rejected/done/failed）、result |

接口：

| 方法 | 路径 |
| --- | --- |
| GET/POST | `/ai/conversations` |
| GET/DELETE | `/ai/conversations/{id}` |
| POST | `/ai/conversations/{id}/messages`（发送后立即返回，回复通过事件流推送） |
| POST | `/ai/conversations/{id}/stop`（停止生成，待确认的动作当作拒绝） |
| POST | `/ai/actions/{id}/approve`、`/ai/actions/{id}/reject` |
| GET | `/ai/tools`（动作的中文名和风险等级，前端显示用） |
| GET/PUT | `/ai/settings` |

事件：`ai.delta`（`{conversationId, text}`，文本增量）、`ai.message_saved`（存了一条新消息，前端重新拉对话）、`ai.action_pending`、`ai.message_done`、`ai.error`。完整契约见 `api/modules/ai.yaml` 和 `automations.yaml`。

系统提示词里写上：当前时间和时区、用户是这个面板的唯一主人、已连接的设备列表概况。保持提示词稳定，时间这种变化的内容放在最后以便缓存。

## 助手能操作的内容

所有非隐藏内容都要能读、写、删。缺的动作在各模块补上，每个动作都有测试：

| 模块 | 读 | 写 | 删 |
| --- | --- | --- | --- |
| 项目 | `projects.list`、`projects.get`、`issues.list`、`issues.get` | `projects.create`、`projects.update`、`issues.create`、`issues.update`、`issues.move`、`issues.comment`、`milestones.create` | `issues.delete`、`projects.archive` |
| 笔记 | `notes.search`、`notes.get` | `notes.create`、`notes.update`、`notes.append` | `notes.delete` |
| 提醒 | `reminders.list` | `reminders.create`、`reminders.update`、`reminders.done` | `reminders.delete` |
| 习惯 | `habits.today`、`habits.stats` | `habits.create`、`habits.checkin` | `habits.delete` |
| 日历 | `calendar.events` | | |
| 云盘 | 见 B14 | 见 B14 | 见 B14 |
| 服务器、监控、编码任务、智能家居、GitHub | 各模块已有的动作 | | |

批量需求（比如“给这个项目排好期，拆成 Issue”）靠模型连续调用多个动作完成。系统提示词里写明：

- 先读现有数据再改，避免重复创建。
- 排期按用户时区，从今天开始，跳过周末，除非用户另有要求。
- 做完后用一段简短的中文列出改了什么，带上链接（比如 `/projects/XC/12`）。

## 自动化

| 表 | 列 |
| --- | --- |
| `automations` | id、name、enabled、trigger（JSON）、conditions（JSON）、actions（JSON）、cooldown_seconds、created_at、updated_at |
| `automation_runs` | id、automation_id、started_at、finished_at、trigger_data（JSON）、steps（JSON：每步的动作、输入、结果、错误）、status |

触发器：

| 类型 | 配置 |
| --- | --- |
| `schedule` | cron 表达式 |
| `event` | 事件主题前缀，可选字段匹配（如 `data.hostId == "abc"`） |
| `metric` | 就是 `event` 订阅 `host.metrics` 加阈值条件的快捷方式 |
| `ha_state` | 实体 id、目标状态（会调用 HA 的 WatchEntity） |
| `webhook` | 生成随机路径 `/hooks/<token>`（公开路径，token 即密钥） |

条件：简单比较列表，全部满足才执行（字段路径、运算符、值）。字段来自触发数据。

动作：

- 任意已注册动作，输入里可以用 `{{trigger.data.xxx}}` 引用触发数据。
- `ai.ask`：把一段提示词和触发数据交给 Claude，结果作为下一步的输入（比如让 AI 总结告警再发通知）。

执行规则：

- 自动化以 actor `automation:<id>` 运行，写审计日志。
- `dangerous` 动作要在保存规则时提升权限，规则上记下“已授权”。之后改规则要重新授权。
- 冷却时间内不重复触发。
- 每一步的结果都记录。一步失败后停止，发通知。

接口：`/automations` CRUD，`POST /automations/{id}/run`（手动运行），`GET /automations/{id}/runs`，`GET /automations/catalog`（可用的触发器、事件主题、动作及其 schema）。

## 前端

- 助手不放在侧边栏的“集成”里（2026-09-27 用户要求）。入口是全局的：
  - 所有页面右下角一个圆形按钮，点击弹出浮窗。快捷键 `⌘J`。组件放在 `app/GlobalPanels.tsx`。
  - 浮窗 400×600，可拖动、可放大成右侧整列。手机上是全屏的底部弹层。
  - 浮窗里：顶部是对话标题、历史对话下拉、新对话按钮、关闭按钮。中间是消息。底部是输入框，回车发送，Shift+回车换行。
  - 打开时带上当前页面（路径和标题）作为上下文，比如在某个项目页说“帮我排期”，助手知道是哪个项目。
- 对话里每次动作执行显示成一行小卡片：动作的中文名、参数摘要、结果（成功、失败）。点开看详细参数和结果。
- 待确认的动作显示成卡片：动作名、参数（可读的形式）、确认和拒绝按钮。
- 助手改了数据后，相关页面通过事件自动刷新。
- 设置里有“AI 助手”标签：API Key、模型、“所有写操作都先确认”开关。
- `features/automations`：规则列表、编辑器（触发器、条件、动作三段表单，动作的输入表单根据 JSON Schema 生成简单表单，复杂的退回 JSON 编辑框）、运行记录。
