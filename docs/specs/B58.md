# B58 和风天气：预警、分钟降水、空气、指数、天文、历史对比，地震速报

用户 2026-10-01 提的：想尽快收到降雨、降雪、冰雹等预警，最好能对接国内的灾害预警。用户注册了和风天气（免费每天 5 万次），开通了 GeoAPI、分钟降水、空气质量、时光机、天气预报、天气预警、天气指数、天文。key 由用户在设置里填。地震也要。

现在的情况：天气来自 Open-Meteo，当前天气每 15 分钟更新，预报每小时更新，没有官方预警。降雨提醒每 30 分钟看一次（`modules/brief/rain.go`），按小时降水概率。

## 后端（待做，给开发者）

都在 `backend/internal/server/modules/brief/`。新文件 `qweather.go`（和风天气客户端）、`extra.go`（`/weather/extra`）、`quake.go`（地震）、`weather_notify.go`（推送）。做完把 `pending.go` 里对应的函数删掉。

### 1. 配置

- 设置键 `brief.qweather`，用 `m.d.Settings.SetSecret` 加密存：`{"apiHost": "...", "apiKey": "...", "checkedAt": "..."}`。
- `GET`：返回 `apiHost`、`keySet`（key 非空）、`checkedAt`。不返回 key。
- `PUT`：`apiHost` 去掉 `https://` 和结尾的 `/`，只允许域名字符，不对就 400。`apiKey` 为空时保留原来的。`clearKey` 为 true 时删掉 key。保存前用新配置调一次 GeoAPI（见下），失败回 400，文字写“和风天气验证失败：<原因>”，原因按和风天气的 `code` 翻译（`401` key 不对，`402` 超过额度，`403` 没有权限或 Host 不对，`404` 地点不对）。成功才保存，`checkedAt` 写当前时间。记审计 `brief.qweather`，不记 key。

### 2. 和风天气客户端

- 地址 `https://<apiHost>`，请求头 `X-QW-Api-Key: <key>`。响应是 gzip 压缩的，用 Go 默认的 `http.Client`（不要自己设 `Accept-Encoding`）会自动解压。超时 10 秒，响应体最多读 1 MB。
- 返回 JSON 里 `code` 不是 `"200"` 时当错误，带上 code。
- 位置用早报设置的经纬度（`cfg.Location`）。`location` 参数写成 `经度,纬度`，保留两位小数。新版接口（路径里带 `/{latitude}/{longitude}`）按路径写。
- 下面每个接口的返回字段以和风天气官方文档为准（https://dev.qweather.com/docs/api/ ），实现前先用自己的 key 调一次看实际返回。

| 用途 | 接口 | 用到的字段 |
| --- | --- | --- |
| 地点 ID | `GET /geo/v2/city/lookup?location=经度,纬度` | `location[0].id`、`name` |
| 分钟降水 | `GET /v7/minutely/5m?location=经度,纬度` | `summary`、`minutely[].fxTime`、`precip`、`type`（rain / snow） |
| 天气预警 | 新版 `GET /weatheralert/v1/current/{纬度}/{经度}`；不可用时退回 `GET /v7/warning/now?location=经度,纬度` | 新版 `alerts[]`：`id`、`headline`、`eventType.name`、`color.code`、`senderName`、`issuedTime`、`effectiveTime`、`expireTime`、`description`、`instruction`、`messageType.code`（cancel 表示解除）。旧版 `warning[]`：`id`、`title`、`typeName`、`severityColor`、`sender`、`pubTime`、`startTime`、`endTime`、`text` |
| 空气质量 | 新版 `GET /airquality/v1/current/{纬度}/{经度}`；不可用时退回 `GET /v7/air/now?location=地点 ID` | 新版取 `indexes` 里 `code` 为 `cn-mee` 的那条：`aqi`、`level`、`category`、`primaryPollutant.name`；`pollutants` 里 `pm2p5`、`pm10` 的 `concentration.value` |
| 生活指数 | `GET /v7/indices/1d?type=1,2,3,5,8,9&location=经度,纬度` | `daily[]`：`type`、`name`、`category`、`text` |
| 日出日落 | `GET /v7/astronomy/sun?location=地点 ID&date=yyyyMMdd` | `sunrise`、`sunset`（取 `HH:MM`） |
| 月相 | `GET /v7/astronomy/moon?location=地点 ID&date=yyyyMMdd` | `moonrise`、`moonset`、`moonPhase[0].name` |
| 昨天（时光机） | `GET /v7/historical/weather?location=地点 ID&date=昨天 yyyyMMdd` | `weatherDaily.tempMax`、`tempMin` |

- 地点 ID 按经纬度缓存在设置里（`brief.qweather_location`：`{"lat":..,"lon":..,"id":".."}`），位置变了再查。
- 日期按早报位置所在的时区（`m.d.Config.Location`）算。
- 预警颜色转成 `WarningLevel`：`red`、`orange`、`yellow`、`blue`，其他 `unknown`。新版 `messageType.code` 为 `cancel` 的不算生效。

### 3. `GET /weather/extra`

- 没设置位置时回 412，和 `/weather` 一样。
- 没配和风天气：`configured: false`，`warnings`、`indices` 是空数组，只有 `earthquakes`。
- 配了：并发调上面几个接口，单个失败只让那一项缺省（`minutely`、`air` 这些不返回），记一条日志，整体照常返回。全部失败时回 502，文字带第一个错误。
- 整体结果缓存 5 分钟。`refresh=true` 时跳过缓存，1 分钟内最多真拉一次（和 `/weather` 的做法一样）。日出日落、昨天、生活指数这类一天只变一次的，缓存到当天结束。
- `warnings` 颜色重的在前。`earthquakes` 见下。

### 4. 地震

- 数据源先用中国地震台网的速报列表：`GET https://news.ceic.ac.cn/ajax/google?rand=1`，返回 JSON 数组，字段 `CATA_ID`（id）、`M`（震级）、`O_TIME`（北京时间 `2006-01-02 15:04:05`）、`EPI_LAT`、`EPI_LON`、`EPI_DEPTH`、`LOCATION_C`（地点）。这是网页用的接口，没有文档，字段以实际返回为准。
- 中国地震台网取不到时，用美国地质调查局的公开数据：`GET https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/2.5_day.geojson`，`features[]` 的 `id`、`properties.mag`、`properties.place`、`properties.time`（毫秒）、`geometry.coordinates`（经度、纬度、深度）。
- 两个地址都可以在设置里覆盖（`brief.quake_cenc_url`、`brief.quake_usgs_url`），测试时指向假服务。
- 按早报位置算距离（球面距离公式）。`/weather/extra` 返回最近 3 天、在推送设置的半径内、达到推送设置震级的，新的在前，最多 10 条。推送没开时用默认的 M4.5、500 km。
- 地震列表缓存 2 分钟。

### 5. 推送

- 设置键 `brief.weather_notify`，默认：全关，`rainLeadMinutes` 30，`warningMinLevel` yellow，`quakeMinMagnitude` 4.5，`quakeRadiusKm` 500。`PUT` 时按 yaml 里的范围校验。
- 定时任务（`module.go` 里 `m.d.Scheduler.Every`）：
  - `brief.weather_minutely`，每 5 分钟：`rainSoon` 开着并且配了和风天气时，查分钟降水。从现在起 `rainLeadMinutes` 分钟内第一次 `precip > 0` 时推送“20 分钟后有雨（杭州）”，正文写和风天气的 `summary`。推过以后 2 小时内不再推，除非中间停过（连续 30 分钟没有降水）。
  - `brief.weather_alerts`，每 5 分钟：`warnings` 开着时，查天气预警。新的预警、颜色升级的、解除的各推一次，低于 `warningMinLevel` 的不推（解除时按原来的颜色判断）。用设置键 `brief.weather_alerts_seen` 记已推过的 `id → 颜色`，解除后删掉。红色和橙色用 `notify.PriorityUrgent`，其他用普通。标题用预警的标题，正文用前 200 字。冰雹、暴雪这类都在天气预警里，不用另外处理。
  - `brief.quakes`，每 2 分钟：`earthquakes` 开着时，查地震。新出现的、在半径内、达到震级的推一次，标题“M5.2 四川雅安市芦山县”，正文“距离 236 公里，深度 10 公里，北京时间 08:12”。用设置键 `brief.quakes_seen` 记最近 3 天推过的 id。
  - 每次查到的预警或地震和上次不同时，发事件 `weather.updated`（`m.d.Bus.Publish`），前端会自动刷新。
- 发通知用 `m.d.Notify.Send`，`Kind` 分别是 `weather.rain_soon`、`weather.warning`、`weather.quake`，`Source: "brief"`，`Link: "/"`。
- 调用量：两个 5 分钟任务每天约 576 次，加上页面打开时的查询，远低于每天 5 万次。

### 6. 测试

- 用 `httptest` 起假的和风天气（检查请求头带了 key）和假的地震接口。
- 保存配置：key 不对时回 400 且不保存；`apiKey` 为空时保留旧的；`GET` 不返回 key。
- `/weather/extra`：没配和风天气时只有地震；某个接口回错误时其他字段照常；预警颜色转换和排序；新版预警接口 404 时退回旧版。
- 地震：中国地震台网失败时用美国地质调查局；距离和半径过滤；只返回 3 天内的。
- 推送：同一条预警只推一次，升级再推，解除推一次；低于最低级别的不推；快下雨在冷却期内不重复推；地震同一个 id 只推一次。
