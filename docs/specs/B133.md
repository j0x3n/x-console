# B133 自我实验

2026-10-11 用户要求做。来源是 [B127-B139-建议](B127-B139-建议.md) 第 3 条。

## 要什么

定义一个实验：改什么、看哪些指标、哪几天照常、哪几天改变。到时间后，面板用已有的数据比较两段，给出平均值的差、95% 区间，并明说样本够不够、差异是不是在随机波动之内。

## 局限（写进界面）

- 自己做、不设盲，结果会受预期影响。主观打分（打卡的精力、压力）尤其容易偏。所以指标选择里，客观数据（手环睡眠、静息心率、步数、电脑时间、专注分钟）和主观数据（状态打卡）分开标注，选了主观指标会显示提示。
- 天数少、波动大时，差异很可能只是随机波动。结果必须先说“够不够下结论”，再给数字。不写“提升 12%”这种只有百分比的结论。
- 两段不是随机分配的（前后对比），同期的季节、工作量变化也会影响结果。界面上写一句。

## 做法

- 新模块 `experiments`。
- 一个实验：名称、改了什么（文字）、基线开始日、改变开始日、结束日、备注、结论（用户自己写）、是否已停止。日期按服务端时区，基线 `[基线开始日, 改变开始日)`，改变期 `[改变开始日, 结束日]`。每段至少 3 天，总长最多 180 天。开始日可以在过去，这时是用已有数据做回头对比，界面标“回头对比”。
- 一个实验最多 6 个指标。指标来源：
  - 状态打卡的每个问题（B132，`contracts.CheckinSeries`），主观。
  - 身体数据：体重、腰围、睡眠、静息心率、步数（习惯模块提供 `contracts.BodySeries`），客观。
  - 习惯打卡次数、专注分钟、电脑时间（可选分类），用 B128 已有的 `contracts.GoalMetricSource`，逐日取数。GitHub 来源不用（读缓存，不准确）。电脑时间某天为 0 当作没有记录，其他来源的 0 是真值。
- 分析（`analysis.go`，纯函数）：每个指标分别算基线和改变期的天数 n、平均值、标准差，两段平均值之差，Welch 法 95% 区间，Cohen d。判断：
  - `too_few`：任一段有数据的天数少于 5。只给数字，不下结论。
  - `inconclusive`：区间包含 0。
  - `higher` 或 `lower`：区间不含 0。
  - 另外标出“改变期还没结束”和“数据覆盖的天数占比”。
- 页面 `/experiments`：实验列表（状态：未开始、基线期、改变期、已结束、已停止），详情里每个指标一张结果卡：两段平均值、差、区间、判断、折线图（两段用底色分开）。可写结论。
- 动作目录：`experiments.list`（读）、`experiments.result`（读，带分析）。

## 默认做法

- 状态打卡指标取每天的平均分。
- 没有数据的日子不参与平均，不当 0。
- 结果每次打开页面时现算，不存快照。
- 不做多重比较校正。一个实验选的指标不超过 6 个，界面写一句“指标越多越容易碰巧出现差异”。

## 没有验证的

- 统计公式用单元测试对照手算值。没有用真实数据长期跑过。

## 验收

- 新建实验、选指标、看到结果卡；样本太少时只给数字并提示。
- 区间包含 0 时写“在随机波动范围内”。
- 主观指标有提示。
- 隐藏模块的数据不参与（锁定时指标不可选、结果显示“没有数据”）。
