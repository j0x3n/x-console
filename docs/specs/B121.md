# B121 AI 编码工具配置统一下发

用户 2026-10-10 让按《功能扩展建议》做，第 6、7、8 条都做，这是第 7 条。来源是 `/mnt/project-files/x-console-suggestions/功能扩展建议.md`。

## 为什么要加

Windows 和几台服务器上都跑 Claude Code 或 Codex。每台机器的全局规则、权限设置、MCP 服务器各改各的。某台漏了一条规则，Agent 在那台上的行为就和别的机器不一样，排查时很难想到是配置的问题。

## 要什么

- 在面板里写一份通用配置，分 Claude Code 和 Codex 两部分。
- 代理把它写到所选机器上这两个工具各自的配置位置。
- 面板显示每台机器和面板是否一致，不一致在哪。
- **只管面板写的那部分。** 机器上原有的私有配置不读出来展示，不覆盖，不删。

## 面板里的配置

| 工具 | 项目 | 内容 |
| --- | --- | --- |
| Claude Code | 规则 | 全局规则文本（Markdown），最多 64 KB |
| Claude Code | 权限 | 允许、询问、禁止三组规则，每行一条，各最多 100 条，每条最多 200 个字符，比如 `Bash(git status)` |
| Claude Code | MCP 服务器 | 最多 20 个 |
| Codex | 规则 | 全局规则文本（Markdown），最多 64 KB |
| Codex | MCP 服务器 | 最多 20 个 |

MCP 服务器每个有：名称、传输方式、命令和参数（本机进程）或地址（远程）。

- 名称只能用字母、数字、`_`、`-`，最多 40 个字符，同一个工具里不能重名。
- 传输方式 `stdio` 要填命令，参数每个最多 200 个字符、最多 20 个。传输方式 `http` 要填 `http://` 或 `https://` 开头的地址。
- 所有文字不能含换行和其他控制字符（规则文本除外）。
- 这一版不支持给 MCP 服务器配环境变量和请求头，因为它们常带令牌，面板不存。需要的话在机器上自己配。

另外选“下发到哪些机器”：只列已配对并支持这个功能的机器，默认一台都不选。没选的机器不检查也不写。

## 机器上写到哪里

| 工具 | 项目 | 文件 | 写法 |
| --- | --- | --- | --- |
| Claude Code | 规则 | `<配置目录>/CLAUDE.md` | 文件里一段带标记的区块 |
| Claude Code | 权限 | `<配置目录>/settings.json` 的 `permissions.allow`、`ask`、`deny` | 往数组里加面板的条目 |
| Claude Code | MCP | `.claude.json` 的 `mcpServers` | 按名称写入 |
| Codex | 规则 | `<配置目录>/AGENTS.md` | 带标记的区块 |
| Codex | MCP | `<配置目录>/config.toml` | 文件末尾一段带标记的区块，里面是 `[mcp_servers.名称]` |

- Claude Code 配置目录：环境变量 `CLAUDE_CONFIG_DIR`，没有就是家目录下的 `.claude`。`.claude.json` 在家目录（设了 `CLAUDE_CONFIG_DIR` 时在那个目录里）。
- Codex 配置目录：环境变量 `CODEX_HOME`，没有就是家目录下的 `.codex`。
- 这个工具在机器上没装（配置目录不存在，PATH 里也没有命令），整个工具的状态是“没安装”，不检查也不写。

### 带标记的区块

规则文件的区块：

```
<!-- x-console:begin 以下内容由 X Console 管理，请在面板里修改 -->
……面板写的规则……
<!-- x-console:end -->
```

`config.toml` 的区块用 `# x-console:begin` 和 `# x-console:end`，每个服务器一个表：

```
[mcp_servers.名称]
command = "npx"
args = ["-y", "某个包"]
```

远程服务器写 `url = "https://……"`。

- 区块外的内容原样保留。区块不存在就加在文件末尾，前面空一行。面板的规则为空，区块也不存在，就什么都不写。
- 面板的规则清空后，下次下发把区块删掉。
- 有 `begin` 没有 `end`，或者出现不止一对标记，状态是“冲突”，不动这个文件。

### settings.json 和 .claude.json

- 只改 JSON 里的这几个位置，其他内容原样保留。文件里的键会按字母顺序重排，缩进变成两个空格。
- 文件不存在就新建（权限 0600）。不是合法 JSON，或者顶层不是对象，状态是“冲突”，不动。
- 代理在自己的状态文件里记下“哪些条目是面板加的”。状态文件放在代理配置文件所在目录，叫 `aiconfig-state.json`，只有代理读写。
- 权限：下发时，面板里有而机器上没有的条目加到数组末尾，已有的不动顺序。以前是面板加的、现在面板里删了的条目，从数组里去掉。机器上本来就有的同名条目不算面板加的，面板以后删了它，机器上的不动。
- MCP：面板里的服务器按名称写进 `mcpServers`。**机器上已经有同名、内容不同、而且不是面板以前写的服务器，状态是“冲突”，不覆盖。** 以前是面板写的、现在面板里删了的，从 `mcpServers` 里去掉。面板写的服务器内容和机器上的不同（比如被改过），下发时覆盖回来。
- Codex 的 `config.toml` 同理：区块外已经有同名的 `[mcp_servers.名称]` 表，状态是“冲突”，不写整个区块。
- 第一次修改某个文件之前，在同目录复制一份 `<文件名>.x-console.bak`，已经有就不再复制。写文件先写临时文件再改名，保留原来的权限。

## 状态

每台机器每个工具每个项目有一个状态：

| 状态 | 条件 |
| --- | --- |
| `ok` 一致 | 面板写的内容都在，该删的都不在。面板这一项为空而且机器上没有面板写过的东西，也是一致 |
| `drift` 不一致 | 缺内容、多了该删的、内容和面板不同。原因 `missing`、`extra`、`different` |
| `conflict` 冲突 | 见上面几条。原因 `exists`（同名已存在）、`invalid`（文件格式不对）、`markers`（标记不成对） |
| `absent` 没安装 | 这个工具在机器上没装 |

一台机器的总状态：有冲突就是冲突，没有冲突有不一致就是不一致，其他是一致。机器不在线、不支持这个功能（旧代理）、调用失败，分别是 `offline`、`unsupported`、`error`。

- 下发后每个项目再检查一次，把结果返回。
- 面板里的内容改了以后，机器状态要重新检查才更新。页面打开时自动检查一次，再提供“检查”按钮。检查不写任何东西。

## 下发

- 只有点“下发”才写。不自动下发，不定时下发。
- 下发要提升权限，因为 MCP 命令会在机器上执行。
- 下发用的是**已保存**的配置。页面上有没保存的修改时，下发按钮不可用。
- 一次可以下发到一台，也可以下发到所有选中的机器。各台机器之间互不影响，一台失败不影响别的。
- 一台机器上，某个项目是冲突，这个项目不写，别的项目照常写。
- 写入记审计 `aiconfig.apply`，记机器和每个项目的结果，不记规则全文。事件 `aiconfig.updated`。

## 协议

代理新增能力 `aiconfig`（这台机器有 Claude Code 或 Codex 才上报），方法 `aiconfig.sync`：

- 参数 `{ config, apply }`。`config` 是上面那份配置，`apply` 为 `false` 时只检查。
- 结果 `{ items: [{ tool, item, state, reason, names, error }] }`。`tool` 是 `claude` 或 `codex`，`item` 是 `rules`、`permissions`、`mcp`。`names` 是受影响的 MCP 名称或权限条目，最多 20 个。
- 代理自己再校验一遍参数（名称、控制字符、数量），因为它会写文件。
- 详细写在 `docs/04-agent-protocol.md`。

## 页面

- 地址 `/coding/config`，页面名“配置下发”，在左栏“Agent”的二级菜单里加一项。
- 上面是机器卡片：每台支持的机器一行，复选框选是否下发，右边是总状态标签和“下发”按钮，展开能看每个项目的状态和原因。顶部有“检查”和“全部下发”。
- 下面是 Claude Code 和 Codex 两个区域：规则用等宽文本框，权限三个文本框（每行一条），MCP 服务器一行一个，可以增删。
- “保存”按钮在页面顶部，有没保存的修改时显示提示。
- 手机（390px）整页不横向滚动。

## 接口

见 `api/modules/aiconfig.yaml`。

- `GET /aiconfig`：配置、已选机器、可选机器（含在线和是否支持）。
- `PUT /aiconfig`：保存配置和已选机器。不需要提升权限。
- `GET /aiconfig/status`：检查所有已选机器。
- `POST /aiconfig/apply`：下发，body 可选 `hostIds`（不填就是所有已选机器）。要提升权限。
- 动作目录：`aiconfig.status`（只读，返回哪些机器不一致）。
- 属于“Agent”这个可隐藏的模块，隐藏内容锁着时接口回 404、动作不可用。

## 数据

配置存在设置表里（键 `aiconfig.doc`），不加迁移。

## 验收

- 保存一份配置，选两台机器。页面显示两台都“不一致”，原因是缺内容。
- 下发后两台都“一致”。机器上 `CLAUDE.md` 原有的内容还在，区块在末尾。`settings.json` 里原有的权限条目还在。
- 机器上 `.claude.json` 里已有同名、内容不同的 MCP 服务器，状态是“冲突”，文件没被改。
- 面板里删掉一条权限和一个 MCP 服务器，下发后机器上这两个被去掉，机器上原有的不受影响。
- 把规则清空再下发，`CLAUDE.md` 里的区块被删掉，区块外的内容还在。
- 在机器上手动改区块里的一个字，页面检查后显示“不一致”，下发后恢复。
- 没装 Claude Code 的机器，Claude Code 部分显示“没安装”，不创建任何文件。
- 机器不在线显示“离线”，别的机器照常。
- 没提升权限下发回 403。
- 手机（390px）不横向滚动。

## 没做

- 不支持 MCP 服务器的环境变量和请求头。
- 不管 Claude Code 的 `defaultMode`、钩子、插件，也不管 Codex 的 `approval_policy`、`sandbox_mode`。这几项要写在 `config.toml` 顶层，和区块写法不兼容，以后单独做。
- 不读也不展示机器上原有的私有配置。
- 不定时检查，不在不一致时发通知。

## 实现记录

- 协议和校验：`backend/pkg/protocol/methods_aiconfig.go`。`Normalize` 和 `Validate` 服务端和代理共用，服务端保存时检查一遍，代理收到后再检查一遍。
- 代理：`backend/internal/agent/aiconfig`。`blocks.go` 管规则文件和 `config.toml` 的区块，`jsonfiles.go` 管 `settings.json` 的权限和 `.claude.json` 的 MCP，`fsutil.go` 管备份、临时文件改名和符号链接。测试在 `aiconfig_test.go`，用临时目录，不碰真实的家目录。
- 服务端：`backend/internal/server/modules/aiconfig`。配置存在设置表（键 `aiconfig.doc`），没有迁移。检查和下发对所选机器同时调用，每台最多等 20 秒。
- 前端：`web/src/features/aiconfig`，页面 `/coding/config`。草稿和已保存的内容比较，有没保存的修改时下发按钮不可用。
- 没有改的约定：下发用已保存的配置，不是页面上的草稿。
- 没做：见上面“没做”一节。另外 Windows 上没有真机验证，只做了交叉编译和 `go vet`。
- 没验证：真实的 Claude Code 和 Codex 读这些文件的效果（比如 `.claude.json` 里 `type: "http"` 的服务器在当前版本是否生效），只验证了文件内容。
