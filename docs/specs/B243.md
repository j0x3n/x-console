# B243 分享链接可以允许编辑

用户 2026-10-17 提出。现在笔记的分享链接（B72）只能看。要加一个设置，让打开链接的人也能改这篇笔记。

## 现在的情况

- 每篇笔记最多一个分享链接，存在 `note_shares`：令牌、密码（bcrypt）、有效期、打开次数。
- 分享页地址 `/n/<令牌>`，接口 `GET /public/notes/{token}`。有密码时先 `POST .../unlock` 换一个 12 小时的访问码。
- 改分享设置（`PUT /notes/{noteId}/share`）要二次验证（`auth.RequireElevated`）。
- 隐藏笔记不能分享。隐藏块（`:::hidden`）的内容分享页里能点开看到。
- 笔记没有历史版本。自己改笔记是直接覆盖，不检查别人有没有改过。

## 要什么

### 设置

- 分享弹窗里加勾选框“打开链接的人可以编辑”，默认不勾。改这个也要二次验证，和现在改密码一样。
- 不强制设密码（用户 2026-10-17 定的）。勾选编辑但没设密码时，勾选框下面提示“没设密码，拿到链接的人都能改”。

### 访客那边

- 允许编辑时，分享页右上角多一个“编辑”按钮。
- 访客能改标题和正文。不能改标签、颜色、置顶、隐藏，不能删除，不能上传图片和附件（用户 2026-10-17 定的，第一版不做上传）。
- 编辑器是一个 Markdown 输入框，加“编辑 / 预览”切换。不复用自己用的 `NoteEditor`，因为它调用的都是登录后的接口。
- 点“保存”才保存，不自动保存。有没保存的改动时，离开页面浏览器会提示。
- 第一次保存时可以填一个称呼（可以不填），存在浏览器本地，记进审计日志和通知。
- 保存时带上开始编辑时的 `updatedAt`。笔记在这期间被改过，服务端拒绝，页面提示“这篇笔记刚被改过”，给两个按钮：“载入最新内容”（自己的草稿放在下面一个只读框里，方便复制）和“取消”。

### 修改记录

- 不做（用户 2026-10-17 定的）。笔记没有历史版本，访客改坏了找不回来。只记审计日志：时间、称呼、IP、改前改后的字数。

### 通知

- 访客保存后通知自己，走已有的通知渠道。通知写“某某改了笔记《标题》”，没填称呼写“访客”。同一篇笔记 10 分钟内多次保存只通知一次（用户 2026-10-17 定的）。

### 自己正打开这篇笔记时

- 收到“访客改了这篇”的事件后：本地没有没保存的改动，就直接载入新内容；有没保存的改动，顶部提示“访客刚改了这篇笔记”，给“载入最新内容”按钮，不自动覆盖。

## 怎么做

### 接口（`api/modules/notes.yaml`）

- `NoteShare` 加 `allowEdit: boolean`。
- `NoteShareInput` 加可选的 `allowEdit: boolean`。不传就不变。
- `PublicNote` 加 `canEdit: boolean`。
- 新增 `PUT /public/notes/{token}`：请求 `{ title, body, baseUpdatedAt, editorName? }`，查询参数 `t`（访问码）。成功返回新的 `PublicNote`。笔记被改过返回 409 `note_changed`。没开编辑返回 403 `note_edit_disabled`。

### 后端（`modules/notes`）

- 迁移：`note_shares` 加 `allow_edit INTEGER NOT NULL DEFAULT 0`。
- 公开写接口：
  - 走和读接口一样的限流（`noteShareRateLimit`），每次都重新查 `allow_edit`、有效期、密码。
  - 标题、正文长度用笔记已有的上限。称呼最多 20 个字。
  - 在一个事务里比对 `updated_at` 再更新笔记。
  - 走和自己改笔记一样的更新逻辑，保证搜索索引、事件（`note.updated`）都更新。事件里加 `source: "share"`。
  - 正文里的附件地址：读的时候换成了分享页的地址（`rewriteNoteAttachments`），保存前要换回原来的地址，不然自己那边的图片会坏。要写测试覆盖。
  - 写审计 `note.share.edit`，带称呼、IP、改前改后的字数。
  - 通知走已有的通知渠道，10 分钟合并只在内存里记，重启后重新算。
- 关掉编辑后，已经打开编辑器的访客保存时拿到 403。

### 前端

- `features/notes/components/ShareDialog.tsx`：勾选框和没设密码的提示。
- `features/notes/share/NoteSharePage.tsx`：编辑按钮、编辑器、保存和冲突提示。
- `features/notes/components/NoteEditor.tsx`：收到访客修改事件时的处理。

### 分工

按 AGENTS.md：后端由 Sonnet 5.5 写，前端由 Opus 5.5 写。先定好 `notes.yaml`，再分开写。后端写完由 Opus 5.5 审查。

## 不做

- 多人同时编辑、实时看到对方光标。
- 访客上传附件。
- 修改记录和恢复。
- 每个访客单独的链接和权限。还是一篇笔记一个链接。

## 验收

- 后端集成测试：
  - 没开编辑时公开写接口返回 403；开了编辑、有密码时，不带访问码返回 401。
  - `baseUpdatedAt` 不对返回 409，笔记不变。
  - 保存后笔记内容变了，搜索能搜到新内容，写了审计。
  - 带附件的正文保存后，附件地址还是原来的格式。
  - 10 分钟内保存两次只发一条通知。
  - 改 `allowEdit` 没有二次验证时被拒。
- 前端组件测试：分享页没开编辑时没有“编辑”按钮；409 时显示冲突提示和自己的草稿。
- 端到端（第一部分）：开启允许编辑 → 用另一个没登录的页面打开链接、改正文、保存 → 回到自己的笔记看到新内容。
