# B233 代理自动更新

2026-10-15 用户提的：加入自动更新代理功能。用户定了两点：
- 默认自动更新，每台机器可以在设备页单独关掉。设备页也有“立即更新”按钮。
- 换之前先校验和试运行，不对就不换。不做“新版本连不上面板就自动退回”。

## 现在的情况

- 每次部署，镜像里会带上同一版本的代理程序（`deploy/Dockerfile` 用同一个 `VERSION` 编译面板和代理），放在 `XC_AGENTS_DIR/<系统>-<架构>/`，有 linux 和 windows 两种系统，amd64 和 arm64 两种架构。
- 面板的版本是 `core.Version`，代理连上时在 Hello 里报自己的 `AgentVersion`。两个都是 `dev` 时说明是开发环境编译的。
- 升级代理要用户在机器上再执行一次安装命令（B30 的已知问题）。

## 要什么

1. 代理连上面板时，如果它的版本和面板带的代理版本不一样，面板就让它更新。下面几种情况不更新：
   - 这台机器关了自动更新。
   - 面板版本是 `dev`。
   - 代理不支持更新，也就是没报 `update` 能力。
   - 同一台机器、同一个目标版本，1 小时内已经试过一次。
2. 设备页每台机器显示版本号。版本不是最新时标“可更新”，旁边有“更新”按钮，点了马上更新，要二次验证。更新中显示“正在更新”。失败时显示原因，比如“校验不对”“新程序跑不起来”“没有权限写程序文件”。
3. 设备页每台机器有“自动更新”开关，默认开。
4. 代理的配置文件里写 `"disableUpdate": true`，这台机器就拒绝更新，也不报 `update` 能力。面板分不清它是关了更新还是版本太旧，设备页统一写“这台代理不能自己更新：版本太旧，或者配置里关了更新”。
5. 更新过程：
   1. 面板把新程序经已有的连接发给代理，同时给出版本号、大小和 sha256。
   2. 代理把新程序写到程序所在目录的临时文件里，校验大小和 sha256。
   3. 代理运行一次 `<临时文件> version`，输出的版本号要和面板给的一样。不一样就删掉临时文件，报错，不换。
   4. 把旧程序改名为 `<程序名>.old` 留作备份，把临时文件改名成程序名。
   5. 重启成新版本：
      - Linux：用 `syscall.Exec` 换成新程序，参数和原来一样，进程号不变，systemd 不会把它当成退出。
      - Windows：运行中的 exe 不能覆盖，但能改名，所以上一步照样能做。之后用原来的参数启动新程序，方式和 `setup.Background` 一样，脱离当前进程、不弹窗。新程序起来以后旧进程退出。
   6. 代理启动时如果看到 `<程序名>.old`，就删掉它（Windows 上旧进程退出后才删得掉）。
6. 新版本连上以后，面板看到版本对了，就标成“已更新”。
7. 同时最多 2 台机器在更新。

## 怎么做

### 协议（`pkg/protocol`）

- 新能力 `update`。
- 新流方法 `agent.update`，参数 `AgentUpdateParams{Version string, Size int64, SHA256 string}`。面板把程序分块写进流里，写完关闭发送方向。代理校验和试运行都通过后回一个空数据帧，然后开始重启。出错就用流的错误结束，错误信息是中文。

### 代理

- 新包 `internal/agent/selfupdate`：
  - 接收程序、校验、试运行、改名，重启分 Linux 和 Windows 两个文件。
  - 写临时文件、改名、重启这几步，在测试里能换成假的，这样不用真的重启测试进程。
  - 试运行要用 `nowindow.Hide`，否则 Windows 上会闪黑窗口。
  - 程序路径用 `os.Executable()`，要处理符号链接。
- `config.Config` 加 `DisableUpdate bool json:"disableUpdate,omitempty"`。
- `cmd/agent/main.go` 只加行：注册 `agent.update`，按配置报不报 `update` 能力，启动时清掉 `.old`。

### 面板（新模块 `modules/agentupdate`）

- 监听 `agent.online` 事件，按“要什么”第 1 条判断，要更新就在后台更新。
- 新程序取 `XC_AGENTS_DIR/<os>-<arch>/`，`os` 和 `arch` 用代理 Hello 里报的。没有对应的文件就记“面板没有这个系统的代理程序”。
- 每台机器的更新状态只存在内存里：`idle`、`updating`、`failed`（带原因和时间）。面板重启后状态清空。
- 自动更新开关存在设置里，键名 `agentupdate.disabled`，值是关掉的机器 id 列表。
- 机器被吊销或删除后，从列表里去掉它。

### 接口（新文件 `api/modules/agentupdate.yaml`）

- `GET /agent-updates`：返回面板带的代理版本 `latest`，以及每台机器的 `agentId`、`version`、`autoUpdate`、`canUpdate`（有没有 `update` 能力）、`state`、`error`、`updatedAt`。
- `POST /agent-updates/{agentId}`：马上更新，要二次验证，回 202。机器不在线回 409，不支持更新回 409，已经是最新回 409，正在更新回 409。
- `PUT /agent-updates/{agentId}/auto`，body `{ "on": bool }`：开关自动更新，回 204。打开要二次验证，因为打开以后面板能往这台机器推新程序。关掉不用。
- 状态变化时发事件 `agentupdate.changed`，设备页跟着刷新。

### 前端（`features/settings/DevicesTab.tsx`）

- 版本那一列加“可更新”标记和“更新”按钮。更新中显示“正在更新”，失败显示原因。
- 每行加“自动更新”开关。
- 机器没有 `update` 能力、版本又不是最新时，写“这台代理不能自己更新：版本太旧，或者配置里关了更新。要手动更新一次”，自动更新开关不能点。原来的更新说明保留，手动更新时还用得上。
- 手机宽度下这几样要能放得下。

## 验收

- 代理单元测试：
  - 校验不对时不换，临时文件删掉。
  - 试运行版本不对时不换。
  - 正常时旧程序变成 `.old`，新程序就位，调用了重启。
  - `disableUpdate` 时拒绝更新，也不报能力。
  - 启动时清掉 `.old`。
- 面板集成测试（用测试里的代理，重启用假的）：
  - 版本不一样、开着自动更新时，上线后会更新。关了自动更新不会。面板版本是 dev 时不会。没有 `update` 能力时不会。
  - 1 小时内同一个版本不重复试。
  - 手动更新要二次验证，几种 409 都有。
  - 代理报错时状态是 failed，带原因。
  - 同时最多 2 台在更新。
- 前端测试：可更新标记、点更新调接口、开关调接口、太旧时的提示。
- 端到端：第二部分代理配对以后，设备页能看到版本和自动更新开关（端到端里面板和代理都是 dev，不会真的更新）。

## 没法在开发环境验证的

- Windows 上改名、启动新进程、旧进程退出这一套，只能交叉编译加单元测试，要上线后在真机看。
- 现在已经装好的代理都是旧版本，没有 `update` 能力。这次上线后，每台机器还要最后手动更新一次，以后才能自动更新。
