# B211 菜谱第三批：AI 联网按口味找新菜谱

用户 2026-10-14 提的：根据胃口搜索互联网扩展菜谱。B209 做了菜谱，B210 做了打分和推荐，这一批让 AI 上网找新菜。

用户用的是 OpenAI，要求两种搜索都支持：OpenAI 自带的联网搜索和 Brave Search API。

## 先说清楚的限制

- 每次找菜都要花 AI 额度，联网搜索本身也可能另外收费。只在用户点按钮时找，不定时自动找。
- 网上菜谱很多是互相抄的，用量也常常不全。找回来的先放进“待确认”，用户看过、点了“收进菜单”才保存。
- AI 整理时可能把几个网页的内容混在一起，也可能编出原文没有的用量。每个候选都带来源链接，页面上提醒用户对照原文看。

## 一、AI 模块：联网研究（公共能力）

这一块是基础能力，以后别的模块也能用。改动记进 `docs/api-changes.md`。

### 设置

`GET/PUT /ai/web-search`：

| 字段 | 说明 |
| --- | --- |
| `mode` | `off` 关闭（默认）、`openai` 用 OpenAI 自带的联网搜索、`brave` 用 Brave Search API |
| `braveKey` | 只写。Brave 的密钥，用 `Settings.SetSecret` 加密存。读的时候只返回 `braveKeySet` |
| `braveKeySet` | 只读，存过密钥就是 true |

- 选 `openai` 时，“主模型”（`agent`）那家服务商的接口风格要是 `responses`（OpenAI 官方的接口）。不是的话保存时回 400，提示“OpenAI 自带的联网搜索要用 Responses 接口的服务商”。
- 选 `brave` 时要已经存过密钥，或者这次一起给了密钥。
- 改设置要提升权限（`auth.RequireElevated`），因为里面有密钥。
- `POST /ai/web-search/test`：用当前设置搜一次“西红柿炒鸡蛋 做法”，返回前 3 条的标题和地址，用来确认设置能用。

### 契约

新文件 `contracts/websearch.go`：

```go
const WebSearchKey = "ai.web_search"

var ErrWebSearchOff = errors.New("还没有打开联网搜索，去 设置 → AI 里打开")

type WebSource struct{ Title, URL string }

type WebResearch struct {
	Purpose    string          // 用量记录的用途，比如 "recipes.discover"
	System     string          // 给模型的要求
	Task       string          // 这次要找什么
	Schema     json.RawMessage // 要返回的 JSON
	MaxSources int             // 最多读几个网页，默认 4，最多 8
}

type WebSearch interface {
	// Mode 返回 off、openai 或 brave。
	Mode(ctx context.Context) string
	// Research 上网查资料，按 Schema 把结果写进 out，返回用到的来源。关着时返回 ErrWebSearchOff。
	Research(ctx context.Context, in WebResearch, out any) ([]WebSource, error)
}
```

### 两种做法

- **openai**：一次 Responses 调用，`tools` 里加 `{"type": "web_search"}`，同时要求按 Schema 返回 JSON。来源从回答里的 `url_citation` 标注收集，去重。模型不支持在用联网搜索时按 Schema 返回，就不带 Schema 再请求一次，在说明里要求只输出 JSON，再按 JSON 解析（参照现有的 `fallbackJSON` 做法）。
- **brave**：
  1. 用快速模型（`fast`）按任务写 2 到 3 个搜索词。
  2. 每个词调一次 Brave Search（`GET https://api.search.brave.com/res/v1/web/search?q=...&count=5`，请求头 `X-Subscription-Token`），合并去重。
  3. 读前 `MaxSources` 个网页的正文。网页由稍后读模块读，见下面的 `PageReader`。读不到的跳过。每页正文最多取 6000 字。稍后读模块不存在时只用搜索结果的摘要。
  4. 把搜索结果和网页正文交给主模型（`agent`），按 Schema 返回 JSON。来源是读成功的那些网页。
- Brave 的地址写成可以在测试里换掉的变量，测试用 `httptest` 假服务器。
- 外部请求超时 15 秒。Brave 回 401、403 时报“Brave 的密钥不对或者过期了”。回 429 时报“Brave 搜索次数用完了”。

### 稍后读：开放网页读取

稍后读模块已经有 `fetchPage`，会拦住本机和内网地址。新契约 `contracts.PageReader`：

```go
const PageReaderKey = "readlater.page_reader"

type WebPage struct{ Title, Text string }

type PageReader interface {
	Read(ctx context.Context, url string) (WebPage, error)
}
```

稍后读模块注册它，`Text` 用 `fetchPage` 抽出来的正文。不存进稍后读的列表。

## 二、菜谱：找新菜谱

### 按什么找

- 口味画像：自己做过的、打分 4 分以上的菜谱里，出现最多的 5 个标签和营养分类。还有饮食目标。没有任何记录时用全部菜谱的标签。
- 用户这次的要求（可选），比如“想吃清淡的汤”“用土豆做的”。
- 已经有的菜名和还在待确认里的菜名，告诉 AI 不要重复。

### 接口

- `POST /recipes/discover`：参数 `hint`（可选，最多 100 字）、`count`（1 到 5，默认 3）。调 `WebSearch.Research`，`MaxSources` 等于 `count` 加 1。每个候选用 B209 的 `repair` 和 `validate` 修正，不合法的扔掉，菜名和已有的、待确认的重复的也扔掉。存进候选表，返回这次新加的候选。
  - 联网搜索关着回 501，信息用 `ErrWebSearchOff` 的文字。
  - 每天最多找 10 次（服务器时区，按调用次数算，失败也算），超了回 429“今天已经找了 10 次，明天再找”。
  - 一个候选都没留下时回 200 和空列表，页面提示“这次没找到合适的，换个说法试试”。
- `GET /recipe-candidates`：返回待确认的候选（新的在前），加上 `profile`：口味标签、营养分类、饮食目标、联网搜索的方式（`off`、`openai`、`brave`）、今天还能找几次。
- `PATCH /recipe-candidates/{id}`：`status` 改成 `accepted` 或 `dismissed`，`accepted` 时可以带 `recipeId`。改过的不再出现在列表里。
- 收进菜单的流程：前端把候选的草稿放进新建表单（带上来源地址），用户保存后再 PATCH 成 `accepted`。
- 超过 30 天的 `dismissed` 和 `accepted` 候选在启动时和每天清理一次。
- 事件 `recipe_candidate.created`、`recipe_candidate.updated`。审计 `recipe.discover`、`recipe_candidate.update`。

### 候选

| 字段 | 说明 |
| --- | --- |
| `draft` | 和 `RecipeInput` 一样，`sourceUrl` 是这个菜谱主要参考的网页 |
| `reason` | 为什么推荐，比如“你常做辣的鲁菜，这道是辣的家常菜”，最多 100 字 |
| `sources` | 这次搜索用到的全部来源（标题和地址） |
| `status` | `pending`、`accepted`、`dismissed` |
| `createdAt` | |

### 给 AI 的要求（菜谱模块写）

- 只找家常能做的菜，按网页原文整理，不编用量。原文没写用量的写“适量”。
- 每道菜的 `sourceUrl` 必须是真的读到的网页地址。
- `reason` 用一句话说为什么符合用户的口味或要求。
- 食材、步骤、计时、营养分类的格式和 B209、B210 的转换一样。

## 三、页面

### AI 设置（设置 → AI）

加一张卡片“联网搜索”：方式（关闭 / OpenAI 自带 / Brave Search），选 Brave 时有密钥输入框（显示“已保存”），“测试”按钮显示搜到的前 3 条。说明写清楚：OpenAI 自带的要用 Responses 接口的服务商；每次搜索都会花额度。

### 找新菜谱 `/recipes/discover`

- 二级菜单加“找新菜谱”，有待确认的候选时显示数量。
- 上面：按你的口味（标签和营养分类）、饮食目标；输入框“这次想吃什么（可以不填）”；数量 1 到 5；“帮我找”按钮。找的时候按钮显示“正在找…”，可能要一分钟。显示今天还能找几次。
- 联网搜索关着时，整块换成说明和“去设置”。
- 下面：待确认的候选卡片：菜名、简介、推荐理由、食材数和步骤数、标签和营养分类、来源链接（新窗口打开）。展开能看食材和步骤。按钮“收进菜单”和“不要”。
- 页面上一行提示：“网上的菜谱可能有错，收进来之前对照来源看一下用量。”

## 不做

- 不定时自动找。
- 不抓下厨房等网站的私有接口，只用搜索和公开网页。
- 不在 AI 助手里加联网搜索工具（以后可以用这个契约加）。

## 验收

- AI 设置：三种方式能存；选 `openai` 但服务商不是 Responses 风格回 400；选 `brave` 没有密钥回 400；密钥加密存，读的时候不返回；没提升权限回 403；测试接口在 Brave 假服务器下返回 3 条。
- `Research`：openai 方式下请求体里有 `web_search` 工具，来源从 `url_citation` 收集（假服务器）；brave 方式下按步骤调假的 Brave 和假的 `PageReader`，401 和 429 的报错文字对。
- 稍后读的 `PageReader` 拦住内网地址。
- 找菜：关着回 501；第 11 次回 429；和已有菜名重复的扔掉；候选能接受和不要；接受后不再出现。用假的 `WebSearch` 测。
- 端到端：没开联网搜索时找新菜谱页显示“去设置”。（真联网的部分端到端不跑。）
- 1360px 和 390px 截图：找新菜谱页（有候选和没开联网两种）、AI 设置的联网搜索卡片。

## 实现记录

后端部分（2026-10-14）：

- 新契约 `contracts/websearch.go`：`WebSearch`、`PageReader`，和规格一致。
- AI 模块：`websearch.go` 放设置、测试接口和两种做法，`WebSearch` 在 `module.go` 里注册。设置键 `ai.web_search_mode`，Brave 密钥 `ai.brave_key` 用 `SetSecret` 加密存，审计里不记密钥。
- 选 `openai` 只在这次请求带了 `mode` 时检查主模型的服务商，只改密钥时不检查。主模型没选也回 400。
- `llm.Request` 加 `WebSearch`，`llm.Result` 加 `Sources`。`WebSearch` 为 false 时请求和结果和以前完全一样。chat 风格的服务商用联网搜索会直接报错，不发请求。
- 联网搜索带 Schema 时，供应商回任何 400 都会去掉 Schema 重试一次，因为不同服务商的报错文字不一样。
- 用量记录：来源用调用方在上下文里设的来源，没设就写 `web_search`。参考写 `Purpose`，菜谱找菜是 `recipes.discover`。
- Brave 方式搜索词最多 3 个，每个词取 5 条。搜索词模型没给出可用的词时，直接拿任务文字去搜。
- 读网页是并行读的。一个网页都读不到时，回答只依据摘要，来源是全部搜索结果。
- 测试接口：Brave 方式只调 Brave，不花模型额度。OpenAI 方式调一次 Responses，返回引用的前 3 个网页。
- 生成的 `ReasoningEffort` 常量改了名（`api.Off` 变成 `api.ReasoningEffortOff`），因为新枚举也有 `off`。只有 ai 模块里引用了，已一起改。
- 稍后读：`pagereader.go` 实现 `PageReader`，走 `fetchPage`，正文没有就用摘要。不存进列表。
- 菜谱：迁移 `20261014060000_m51_b211_recipe_candidates.sql`，新表 `recipe_candidates` 和 `recipe_discover_runs`。每天次数用一条带上限的 upsert 记在 `recipe_discover_runs` 里，日期按服务器时区，先记再搜，失败也算。
- `discover.go`：口味画像取做过且打分 4 分以上的菜谱，标签和营养分类各取最多 5 个。没有这样的记录就用全部菜谱。
- 每个候选先 `repair` 再 `validate`，没有菜名或者步骤和食材都空的扔掉。菜名去空格、不分大小写后，和已有菜谱、待确认候选、同一批里的重复的也扔掉。
- 候选的 `sourceUrl` 不在这次搜索用到的网页里时清空，比较时不看协议、`www`、参数和结尾的斜杠。搜索没返回来源时不检查。
- 候选最多留下 `count` 个。关着或者没有 `WebSearch` 回 501，不记次数。次数用完回 429。搜索出错回 502。
- 清理：`Start` 里清一次，之后每 24 小时一次。按处理时间删 30 天前的 `accepted`、`dismissed`，同时删 30 天前的次数记录。
- `api/modules/ai.yaml`、`api/modules/recipes.yaml` 没有改。
