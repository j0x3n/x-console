# B220 邮件分拣结果推到今日页

2026-10-15 用户提的：AI 分拣出的待办和需要我决定的邮件，自动出现在今日页对应的卡片里。今日页邮件卡片的每封邮件后面也标上分拣类别。

## 规则变了

B136 原来定的是“AI 只分拣，不因为邮件内容自动做任何事”。用户 2026-10-15 改了：分拣出的“要处理”邮件自动推到今日页。

推到今日页只是显示，不建提醒、不建卡片、不回信、不删信。邮件里写的要求仍然当数据，不当指令。

## 要什么

1. AI 分拣时，给“要处理”（action）的邮件多判断一项：是不是需要我做决定。比如批准、选方案、答应或拒绝邀请、确认报价。
2. 今日页“今天要做”卡片多一类来源：要处理、不用做决定的邮件。“需要你决定”卡片多一类来源：要处理、要做决定的邮件。
   - 每行显示 AI 总结（没有就用主题），下面一行是发件人和邮件里的日期（没有日期就写收到时间）。
   - 点这一行打开那封邮件。
   - 行尾有“标成已处理”的按钮，点了就不再出现在今日页。
   - 只列今天收到、还没标成已处理的，最多 20 封。昨天和更早的不进今日页。
3. 今日页“邮件”卡片：每封邮件的主题后面标上分拣类别（要处理、待决定、通知、营销），没分拣过的不标。
4. 邮件页的列表和阅读区：要做决定的邮件标“待决定”，不标“要处理”。

## 怎么做

### 数据库

迁移只加不删。`mail_triage.category` 有 CHECK 约束，不能加新类别，所以加两列：

- `decision INTEGER NOT NULL DEFAULT 0`：要做决定。
- `done_at DATETIME`：标成已处理的时间。

重新分拣一封邮件时，`done_at` 保留不动。

### 接口（`api/modules/mail.yaml`）

- `MailTriage` 加 `decision`（必有）和 `doneAt`（可选）。
- `GET /mail/todo`：返回 `MailPage`，每封带 triage。
- `PUT /mail/messages/{id}/done`，body `{done}`：设置或清掉 `done_at`。没分拣过的回 404。标成已处理时如果还是未读，同时在邮箱服务器上标成已读。取消不改已读状态。服务器没存上已读时回 502，本地也不标成已处理。
- `GET /mail/summary` 的 `latest` 带上 triage。

### AI

- 分拣的提示词和 JSON schema 加 `decision`（布尔）。category 不是 action 时强制为 false。
- 标成已处理或取消后发 `mail.updated`，今日页跟着刷新。

### 前端

- `features/overview/components/MainCards.tsx` 的 `TodosCard` 和 `DecisionsCard` 加邮件的行，`ExtraCards.tsx` 的 `MailCard` 加类别标签。
- `features/mail/triage.ts` 加“待决定”的显示。

## 验收

- 后端测试：分拣结果带 decision；`/mail/todo` 只返回 action、没处理、今天收到的；标成已处理后不再返回，并且这封变成已读，取消已处理不把它改回未读；重新分拣不清掉 done_at；没分拣过的邮件标已处理回 404；`/mail/summary` 的 latest 带 triage。
- 前端测试：今日页两张卡片显示邮件的行，点“标成已处理”调接口；邮件卡片显示类别标签。
- 没有真实模型验证 decision 判断得准不准。
