# B28 进程合并、终端里跑脚本、容器排序和日志过滤

用户要求（2026-09-28）：

- 进程标签里很多重名进程，加一个“合并”勾选框，默认勾上。
- 终端里加一个面板，列出和这台机器关联的监控脚本，可以一键运行。
- 容器可以按 CPU、内存排序。镜像默认展开，并且可以删除。日志可以按类型过滤。

## 进程合并

- 进程标签的工具栏加 `<label className="xc-check">合并同名进程</label>`，默认勾选，选择存在 `localStorage`（`xc.hosts.mergeProcs`）。
- 合并时按进程名分组，一组一行：名称、进程数（`×12`）、CPU 之和、内存之和、最早的启动时间。排序按合并后的值。
- 点一行展开这一组的每个进程，展开后每个进程的操作（结束进程等）照旧。
- 在前端合并，不改接口。`GET /hosts/{hostId}/processes` 的 `limit` 现在是 300，合并时改成请求 1000，保证同名进程不被截断。
- “结束这一组”放在展开后的“更多”菜单里，要二次确认（B21），确认框里写清楚会结束几个进程。

## 终端里的脚本

- 终端标签右侧加一个可以收起的面板“脚本”，宽 260px。手机上从底部弹出。
- 列出监控模块里目标包含这台机器的脚本（`GET /scripts`，前端按 `hostIds` 过滤；接口能按主机过滤的话就加 `hostId` 参数）。每行：名称、类型（bash、sh、powershell）、上次运行结果。
- 每行两个按钮：
  - “在终端运行”：把脚本送进当前终端执行，输出直接显示在终端里。bash 和 sh 用 heredoc 包起来（`bash <<'XC_EOF' ... XC_EOF`），避免脚本里的特殊字符被当前 shell 解释。PowerShell 用 `-EncodedCommand`。
  - “后台运行”：调用已有的 `POST /scripts/{scriptId}/run`，只对这台机器，结果在监控的运行记录里，面板里显示状态。
- 权限和监控页运行脚本一样。脚本里有 `rm -rf`、`shutdown`、`reboot`、`mkfs`、`dd` 这类字样时，运行前二次确认。
- 面板底部“管理脚本”链接到监控页的脚本标签。

## 容器

- 容器列表加排序：名称、状态、CPU、内存。点表头切换，手机上用下拉。CPU 和内存来自 `docker stats --no-stream`，代理已经有的话直接用，没有的话在代理的 `docker` 包里加（每次列表请求取一次，不常驻）。
- 镜像区块默认展开，去掉“显示/隐藏”按钮，改成可以折叠的标题。
- 镜像每行加“删除”（`docker image rm`），要二次确认。镜像被容器使用时，确认框里列出用它的容器，删除按钮不可点，提示“先删除使用它的容器”。另加“清理未使用的镜像”（`docker image prune -a`），显示能释放多少空间，二次确认。
- 容器日志加过滤：
  - 来源：全部、标准输出、错误输出（用 Docker 日志的流类型区分，代理要把流类型带上）。
  - 级别：全部、ERROR、WARN、INFO、DEBUG。按每行里的关键字判断（不区分大小写，匹配 `error`/`err`/`fatal`/`panic` 等；`warn`/`warning`；`info`；`debug`/`trace`），判断不出来的算“其他”。
  - 关键字搜索框，匹配的字高亮。
  - 过滤在前端做，日志区块最多保留最近 5000 行。
- 删除容器、停止、重启都要二次确认（B21）。

## 验收

- 一台跑了 30 个 `php-fpm` 的机器，合并后只有一行 `php-fpm ×30`，CPU 和内存是总和；取消勾选后是 30 行。
- 终端面板里点“在终端运行”，多行 bash 脚本（含 `$`、引号、反引号）原样执行，输出和直接跑一致。
- 按内存排序后第一行内存最大。删除一个没被使用的镜像成功；删除被使用的镜像时按钮不可点。
- 日志选“错误输出”只显示 stderr 的行；选 ERROR 只显示含错误关键字的行。
- 代理改动带单元测试，Windows 交叉编译和 vet 通过。
