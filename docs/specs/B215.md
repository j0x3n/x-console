# B215 Google 日历双向同步

用户 2026-10-15 提出：日程要和 Google 账户双向同步。

现在 Google 日历只能用“iCal 格式的私密地址”订阅，只读（B16）。Apple 日历已经能用 CalDAV 双向同步（B16、B192）。

## 先说清楚的几件事

- **Google 的 CalDAV 只认 OAuth，不能填密码。** 所以要走和云盘 Google Drive 一样的授权流程（B63、B69）。用户在 Google Cloud 里自己建 OAuth 客户端，可以用云盘那个客户端，但要多启用两个接口：“CalDAV API”和“Google Calendar API”。
- **同意屏幕要发布成正式版。** “测试”状态下 refresh token 7 天就过期。这一点和 B63 一样，页面上要提示。
- **授权后走现有的 CalDAV 代码。** 同步、ETag、`If-Match` 写回、409 冲突都已经有了（B16、B192），只是请求头从用户名密码换成 `Authorization: Bearer <access token>`。
- **重复日程还是改不了。** 这是现在所有日历的限制，B215 不改。Google 日历里重复日程多，界面上没有“编辑”按钮的日程会比 Apple 日历多。
- **没有真实账号测过。** Google CalDAV 对 REPORT 的具体返回格式，只能照文档写假服务器。上线后要用户授权一次，看同步和写回对不对。

## 要什么

- 日历管理页“添加日历”多一种：“Google 日历”。
- 选了以后填客户端 ID 和密钥，页面上显示要填进 Google 控制台的重定向地址，点“授权”跳到 Google。
- 授权回来后列出这个账号下的全部日历（主日历、自己建的、订阅的节假日等），用户勾选要同步哪些，每个勾选的日历变成一个日历条目，颜色默认用 Google 上的颜色。
- 同步和写回和 Apple 日历一样：每 15 分钟同步，新建、修改、删除马上写回 Google。只读的日历（比如订阅的节假日、别人共享给你只读的）显示为不可写。
- 同一个 Google 账号可以以后再加日历，不用重新授权。
- 撤销授权：删掉这个账号，同时删掉它下面的日历条目（本地的同步数据，不动 Google 上的日程）。
- 授权过期（refresh token 失效）时，日历上显示“Google 授权过期，请重新授权”，发一条通知，一天最多一次。重新授权后恢复，日程不用重新导入。

## 怎么做

### 数据

迁移 `m11_b215`，只加不删：

- 新表 `calendar_accounts`：id、provider（目前只有 `google`）、email、client_id、created_at、updated_at。
- `calendars` 加两列：`account_id INTEGER`（可空，引用 `calendar_accounts.id`）和 `remote_id TEXT NOT NULL DEFAULT ''`（Google 的日历 ID）。
- Google 的日历条目 `kind` 仍是 `caldav`，`url` 是 `https://apidata.googleusercontent.com/caldav/v2/<日历 ID>/events/`，`username` 为空。这样不用改 `kind` 的 CHECK，也不用重建表。
- client secret 和 refresh token 用 `Settings.SetSecret` 加密存，键 `calendar.account.<id>.client_secret`、`calendar.account.<id>.refresh_token`。接口只返回 `secretSet`、`authorized`。

### 授权

照 `modules/storage/remote_gdrive.go` 的写法，放在 calendar 模块里，不跨模块调用：

- `POST /calendar/accounts`（提升权限）：建账号，填客户端 ID 和密钥。
- `GET /calendar/accounts/{id}/auth`（提升权限）：返回 `{url, redirectUri}`。权限范围 `https://www.googleapis.com/auth/calendar`，`access_type=offline`，`prompt=consent`。state 一次性，10 分钟过期。
- `GET /calendar/accounts/google/callback`：公开路径，靠 state 校验，state 必须是当前登录用户刚生成的。换到 refresh token 后跳回 `/calendar/calendars?google=ok&account=<id>`，失败带 `message`。
- `GET /calendar/accounts`、`DELETE /calendar/accounts/{id}`（提升权限，调 Google 的 revoke，删 token 和它下面的日历）。
- 授权地址和换 token 用 `files.GoogleEndpoints`、`postToken` 的同一套地址。`files` 是基础代码，只加一个按 scope 生成授权地址的函数，原函数不动，记进 `docs/api-changes.md`。

### 列出日历

- `GET /calendar/accounts/{id}/calendars`：调 Calendar API 的 `GET https://www.googleapis.com/calendar/v3/users/me/calendarList`，返回 ID、名字、颜色、`accessRole`、是否已添加。
- 主日历的 ID 就是账号邮箱，授权后用它填 `calendar_accounts.email`，不用另外申请 `email` 权限。
- `POST /calendar/accounts/{id}/calendars`：传要添加的日历 ID 列表，每个建一个日历条目，建完后台同步一次。`accessRole` 是 `reader` 或 `freeBusyReader` 的标成只读。

### 同步和写回

- `fetchCalDAV` 和写回用的 `remoteClient` 按日历有没有 `account_id` 选认证方式：有就用 Bearer，没有照旧用用户名密码。
- access token 缓存在内存里，过期前 1 分钟刷新。刷新返回 `invalid_grant` 时记成授权过期，同步报错写进 `lastError`。
- 只读日历的 `writable` 为 false。

### 前端

- 日历管理页“添加日历”的类型里加“Google 日历”。按 `docs/07-design.md`，复制 设置 → 存储 里 Google Drive 账号的填写和授权界面。
- 授权回来后弹出日历勾选列表。
- 日历条目上显示所属的 Google 账号邮箱。账号单独一组，有“添加更多日历”“重新授权”“删除账号”。

## 验收

- 用假的 Google 授权服务器、假的 calendarList 和假的 CalDAV 服务器测：授权、列出日历、添加、同步、新建、修改、删除、`If-Match` 冲突回 409、只读日历拒绝写、token 过期刷新、`invalid_grant` 记成授权过期并通知一次。
- 回调的 state 不对、过期、不是当前用户生成的，都拒绝。
- client secret 和 refresh token 不出现在接口返回、日志和审计里。
- Apple 日历和 ICS 订阅不受影响，现有日历测试全过。
- 端到端补一条：添加 Google 日历（假服务器）、勾选、看到日程、新建一条。
- 上线后用户用真实账号授权一次，结果写进 `docs/qa/B215.md`。
