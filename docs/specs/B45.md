# B45 Safari 工具栏：内容要能滚到状态栏和底部菜单栏下面

用户 2026-09-30 反馈：在 iPhone 的 Safari 里，别的网站往下滚时，文字会显示到状态栏下面，底部的玻璃菜单栏悬浮在网页上。X Console 的状态栏和菜单栏各自占了一块高度，页面在它们中间就结束了。B38 改了很久没解决。

用户的设备：iPhone 16 Pro Max，iOS 27，从 Safari 打开（不是主屏幕图标），顶部和底部栏在别的网站上都是透明的。

参考网站：`https://wenxue88.com/`，效果符合用户要求。

## B38 为什么没解决

B38 的验收全部在 Playwright 的 WebKit 里跑。Playwright 的 WebKit 没有 Safari 的状态栏和菜单栏，“是否透明”根本测不到。以后这类问题只以用户真机的结果为准。

## 参考网站和我们的差别

参考网站 `<head>` 里和显示相关的只有一行：

```html
<meta content="width=device-width, initial-scale=1.0, minimum-scale=1.0" name="viewport">
```

没有 `viewport-fit=cover`、没有 `theme-color`、没有 `color-scheme`、没有 `apple-mobile-web-app-*`、没有 `manifest`。页面是普通的文档滚动，没有全屏高度的外壳。

我们多出来的东西，每一条都可能让 Safari 把状态栏或菜单栏画成实心：

| 编号 | 我们有、参考网站没有 | 在哪 |
| --- | --- | --- |
| A | `viewport-fit=cover`、`interactive-widget=resizes-content` | `index.html` |
| B | `theme-color`（首屏脚本和 `usePreferenceEffects` 会改它）、`color-scheme` | `index.html`、`hooks/usePreferenceEffects.ts` |
| C | 手机上侧边栏关着时仍然是一个 `position: fixed`、上下贴边的元素，只是移到了屏幕外面。新版 Safari 会根据贴着上下边缘的固定元素给栏上色 | `styles/styles.css`、`styles/browser.css` |
| D | 贴底的固定元素：AI 按钮、提示框、云盘传输面板 | 同上 |
| E | `.app-shell` 按安全区加了上下内边距，最小高度是整屏 `100dvh` | `styles/browser.css` |
| F | 宽度大于 720px 的触屏设备（手机横屏、iPad）还是内部滚动 | `styles/browser.css` |

没有真机没法确定是哪一条。所以一次上线全部可以单独开关的改法，用户在手机上切换开关，当场就能看出结果，不用改一次部署一次。

## 第一步：做成可以切换的开关，部署一次让用户测

- 网址参数 `?safari=` 控制，值用逗号分开：`A`、`B`、`C`、`D`、`E`、`F`，或者 `all`（全部打开）、`off`（全部关闭，恢复原样）。
- 首屏脚本（`index.html` 里那段）读参数，存进 `sessionStorage`，切到别的页面仍然有效，关掉标签页恢复原样。A 和 B 要在首屏脚本里直接改 `meta` 标签，不能等 React 加载。
- 每个开关做的事：
  - A：`viewport` 改成和参考网站一样的 `width=device-width, initial-scale=1.0`。
  - B：删掉 `theme-color` 和 `color-scheme` 两个 `meta`，`usePreferenceEffects` 不再写 `theme-color`。
  - C：手机上侧边栏关着时 `display: none`，打开时才显示；遮罩层关着时不渲染。
  - D：隐藏 AI 按钮、提示框、云盘传输面板（只用来判断原因，不是最终方案）。
  - E：去掉 `.app-shell` 的上下内边距和最小高度，页面高度由内容决定。顶栏上面留出 `env(safe-area-inset-top)` 的距离，放在顶栏自己的内边距里。
  - F：判断手机改用 `(pointer: coarse)`，不只看宽度，横屏也走文档滚动。
- 页面右下角显示一个小标签，写着当前打开了哪些开关，点它可以复制 `innerHeight`、`visualViewport.height`、四个安全区的值和当前开关。
- 这一步不需要单独的诊断页，也不需要对照页。

## 第二步：用户在手机上测

在 iPhone 的 Safari 里依次打开下面的地址，每个地址都在“今日”页往下滚一下，看状态栏和底部菜单栏是不是透明、文字能不能滚到栏下面：

1. `/?safari=all`：全部打开。如果还不透明，把角上小标签复制的内容发回来，审查者再查。
2. 如果第 1 步透明了，再分别打开 `/?safari=A`、`/?safari=B`、`/?safari=C`、`/?safari=D`、`/?safari=E`，记下哪几个单独打开就能透明。

## 第三步：按结果定稿

- 用户测出来有效的那几条变成默认做法，去掉开关和小标签。
- D 有效时，不能直接隐藏 AI 按钮。改成不贴底：按钮离底边留出菜单栏的高度，或者在往下滚时收起、往上滚时出现。具体做法按测试结果再定。
- 其余没用的开关删掉，代码恢复原样。
- 修改集中在 `index.html`、`styles/browser.css`、`useBrowserViewport`、`usePreferenceEffects`，记到“接口变更记录”。

## 结果（2026-10-01 真机）

用户在 iPhone 上测过：`?safari=all` 和 `?safari=off` 都可以，A 到 F 单独开不行。没有单独有效的一条，所以不改页面。测试开关和小标签已删。

## 验收

- 用户在真机上确认：从 Safari 打开，今日、笔记、项目、云盘四个页面往下滚时，文字能滚到状态栏和底部菜单栏下面，两个栏都是透明的。以用户的确认为准，不以模拟器为准。
- 从主屏幕图标打开的应用还能正常用（没有 Safari 栏，内容不被刘海挡住）。
- 桌面三个浏览器的截图和改之前一致。
