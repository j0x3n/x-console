# B45 Safari 工具栏：先在真机上查原因，再改

用户 2026-09-30 反馈：别的网站在 Safari 里，底部导航栏是半透明的，页面内容能滚到它下面。X Console 的 Safari 导航栏单独占了一块高度，页面在它上面就结束了。B38 改了很久没解决。

## B38 为什么没解决

B38 的验收全部在 Playwright 的 WebKit 里跑。Playwright 的 WebKit 没有 Safari 的地址栏和标签栏，所以“工具栏是否透明”这件事根本测不到。B38 的验收里也写了“实际 iOS 工具栏透明效果需要真机复核”，这一步一直没做。继续在模拟环境里改 CSS 没有意义，要先拿到真机数据。

## 已知会让 Safari 工具栏变成实心的情况

下面几条是 Safari 的已知行为，要在真机上逐条排除：

1. 页面不是整个文档在滚动，而是某个 `div` 在里面滚动。Safari 只在文档滚动时才让内容穿过工具栏，并在往下滚时收起工具栏。现在只有宽度 ≤ 720px 时改成了文档滚动，手机横屏（宽度 844px 以上）还是内部滚动。还有笔记、项目看板等页面自己设了固定高度加内部滚动。
2. 页面高度刚好等于可见高度（用了 `100dvh` 或 `100svh` 做高度）。内容在工具栏上沿就结束了，工具栏下面只有背景色。
3. 靠近屏幕底边的 `position: fixed` 元素（AI 按钮、提示框、底部弹层）。iOS 26 的 Safari 会根据贴边的固定元素给工具栏区域上色。
4. `html` 和 `body` 背景色和页面主体颜色不一致，工具栏下面露出的是另一种颜色，看上去像一块单独的区域。
5. 用户的 Safari 设置（标签栏布局是“紧凑”“底部”还是“顶部”）和是否从主屏幕图标打开。从主屏幕打开时根本没有 Safari 工具栏。

## 第一步：诊断页（先做这个，做完让用户在手机上打开）

- 新增一个要登录才能看的页面 `/debug/viewport`，不进侧边栏导航，在 设置 → 关于 里放入口。页面显示并可以一键复制：
  - `navigator.userAgent`、显示模式（`browser`、`standalone`、`fullscreen`）。
  - `innerHeight`、`outerHeight`、`visualViewport.height`、`visualViewport.offsetTop`、`screen.height`。
  - 实际量出来的 `100vh`、`100svh`、`100lvh`、`100dvh` 各是多少像素（放一个隐藏元素量）。
  - 四个 `env(safe-area-inset-*)` 的值。
  - 当前滚动的是谁：`document.scrollingElement` 的 `scrollHeight` 和 `clientHeight`；页面滚动时记录收到 `scroll` 事件的元素，列出选择器。
  - 当前页面里所有 `position: fixed` 和 `sticky` 且离上下边缘 120px 以内的元素，列出选择器和位置。
  - `html`、`body`、`.app-shell`、`.main-scroll` 的计算后背景色、`overflow`、`height`。
- 页面上有几个开关，打开后对整个应用生效（存 `sessionStorage`，关掉标签页就恢复），用户可以切到别的页面看效果：
  - 隐藏 AI 按钮和所有贴底的固定元素。
  - 强制文档滚动（不管宽度）。
  - 去掉 `.app-shell` 的 `min-height` 和 `height`。
  - `html`、`body` 背景色改成和主体一样。
- 另外放一个对照页 `web/public/safari-test.html`：纯静态，只有和 `index.html` 一样的 `meta` 标签和一长段文字，没有任何应用样式。

## 第二步：用户在真机上测，把结果发回来

请用户在 iPhone 上：

1. 打开 `/safari-test.html`，往下滚，截图。看工具栏是不是透明的。
2. 打开 `/debug/viewport`，点“复制全部”，发回来。
3. 在诊断页上逐个打开开关，每开一个回到“今日”页滚动一下，记下哪一个开关打开后工具栏变透明。
4. 告诉我们：iPhone 型号、iOS 版本、Safari 设置里标签栏布局选的是哪一种、是从 Safari 打开还是从主屏幕图标打开。

判断：
- 对照页也不透明：原因在 `meta` 标签、`manifest` 或手机设置，不在应用样式。
- 对照页透明、应用不透明，某个开关打开后变透明：原因就是那一条，按第三步改。
- 所有开关都没用：把诊断页数据发回来，审查者再定下一步。

## 第三步：按结果修

- 修改集中在 `styles/browser.css` 和 `useBrowserViewport`，改动记到“接口变更记录”。
- 横屏手机和平板也要走文档滚动的，一起改（判断条件改成“触屏设备”，不只看宽度：`(pointer: coarse)`）。

## 验收

- 用户在真机上确认：从 Safari 打开，今日、笔记、项目、云盘四个页面往下滚时，内容能滚到工具栏下面，工具栏是半透明的。审查者以用户的截图为准，不以模拟器为准。
- 桌面三个浏览器的截图和改之前一致。
- 诊断页保留，以后遇到手机显示问题先让用户发诊断数据。
