# B62 Git 账号统一：设置里一个“Git 与 GitHub”

用户 2026-10-01 提的：Agent 的 Git 连接、集成下的 GitHub、设置里的 GitHub，三处统一一下。

前后端都待做。

## 现状

- **设置 → GitHub**（`web/src/features/github/GitHubSettingsTab.tsx`，接口 `api/modules/github.yaml` 的 `/github/config`）：填 GitHub 令牌（存在设置键 `github.token`，加密）和 API 地址，选关注的仓库（`RepoPicker.tsx`）。
- **集成 → GitHub**（`/github`，`GitHubPage.tsx`）：看关注仓库的 PR、CI、Issue，只读。
- **Agent → Git 连接**（`web/src/features/aiagents/ConnectionsPage.tsx`，接口 `api/modules/aiagents.yaml` 的 `/git-connections`）：GitHub 或 Forgejo 的连接，各自填令牌；GitHub 的可以勾 `useGithubModule`，借用 GitHub 模块的令牌（`contracts.GitHubCredentials`）。Agent 按连接登记仓库。

同一个 GitHub 令牌要在两处填，Forgejo 只能在 Agent 里填，用户找不到。

## 做法

以 Agent 的 Git 连接为准，改名叫“Git 账号”，所有地方都从这里取令牌。

### 1. 设置里合成一个标签

- 设置标签 `github` 改成 `git`，标题“Git 与 GitHub”（`features/settings/tabs.tsx` 改那一行的 id、label、组件）。旧地址 `/settings/github` 跳到 `/settings/git`。Linear 标签不动。
- 新组件 `features/github/GitSettingsTab.tsx`，两张卡片：
  1. **Git 账号**：列出全部连接（`GET /git-connections`）。每行：类型图标（GitHub、Forgejo）、名称、地址、用户名、状态（`lastError` 有值时红字）。可以新建、编辑、删除（删除前 `confirmAction`，有 Agent 仓库在用时后端会拒绝，把原因显示出来）。新建弹窗就是现在 `ConnectionsPage.tsx` 里的那个，挪过来用，去掉“使用 GitHub 模块的令牌”这个勾选。
  2. **GitHub 页面**：下拉选“用哪个 GitHub 账号”（只列 kind 为 github 的连接），下面是现在的关注仓库选择（`RepoPicker`），同步状态和间隔照旧。没有 GitHub 账号时显示“先在上面添加一个 GitHub 账号”。
- 原来的 `GitHubSettingsTab.tsx` 删掉，它的测试改到新组件上。

### 2. Agent 页面

- Agent 的“Git 连接”标签页（`AgentTabs.tsx` 里那一项）改成一个链接“Git 账号在设置里管理”，跳到 `/settings/git`。`ConnectionsPage.tsx` 删掉，弹窗组件挪到 `features/github` 或公共位置（两个模块都用，放 `features/github/GitAccountDialog.tsx`，aiagents 从那里引用）。
- 登记仓库时的“连接”下拉框不变，名字改叫“Git 账号”。

### 3. 集成 → GitHub

- 页面不变。没配好时的“去设置”链接改到 `/settings/git`。

## 契约（待改）

- `api/modules/aiagents.yaml`：`GitConnection` 和创建、修改的请求里的 `useGithubModule` 标成 `deprecated: true`，说明“B62 起不用，下个版本删”。界面名称改成“Git 账号”，接口路径不变。
- `api/modules/github.yaml`：`/github/config` 的 GET 和 PUT 加 `connectionId`（int64，可选）：GitHub 页面用哪个 Git 账号。PUT 里的 `token`、`clearToken`、`apiUrl` 标成 `deprecated`，前端不再传。

## 后端（待做）

1. aiagents 提供令牌：在 `contracts` 里加

   ```go
   // GitAccounts gives other modules the token of a Git connection.
   type GitAccounts interface {
       // Credentials returns the API base and token of a connection.
       Credentials(ctx context.Context, connectionID int64) (base, token string, err error)
   }
   ```

   aiagents 实现并注册。“接口变更记录”里记一笔。

2. github 模块：
   - 设置键加 `github.connection_id`。有值时，API 地址和令牌都从 `GitAccounts.Credentials` 取；没值时退回原来的 `github.token`（兼容还没迁移的数据）。
   - `GET /github/config` 返回 `connectionId`；PUT 收到 `connectionId` 时校验它存在并且是 github 类型，保存。

3. 数据迁移（写在 github 模块启动时，做一次，做完写设置键 `github.migrated_b62 = true`）：
   - 有 `github.token`、没有 `github.connection_id` 时：新建一个 Git 连接（kind github，名称“GitHub”，地址取原来的 API 地址，令牌用原来的，用户名取原来的 `github.login`），把它的 id 写进 `github.connection_id`。
   - 已有的 `use_github_module = 1` 的连接：把令牌复制进去（`token_enc`），`use_github_module` 改成 0。
   - 原来的 `github.token` 不删（迁移只加不删），下个版本再删。
   - aiagents 里 `useGithubModule` 那段读令牌的代码保留，只是不会再走到。
4. 测试：
   - 只有旧的 `github.token` 时，启动后多了一个 GitHub 连接，`github.connection_id` 指向它，GitHub 页面照常同步。
   - 用 `connectionId` 配置后，GitHub 模块请求带的是这个连接的令牌（假 GitHub 服务检查请求头）。
   - 迁移只做一次：重启不会再建连接。
   - `connectionId` 指向 forgejo 连接时回 400。

## 验收

- 设置里只有一个“Git 与 GitHub”标签。在这里加一个 GitHub 账号和一个 Forgejo 账号。
- “GitHub 页面”选了这个 GitHub 账号后，集成 → GitHub 能看到关注仓库的 PR。
- Agent 页面没有单独的 Git 连接页了，登记仓库时能选上面两个账号。
- 老用户升级后，原来填过的 GitHub 令牌自动变成一个 Git 账号，不用重填。
