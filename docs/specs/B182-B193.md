## B182 AI 统一会话列表（后端）

AI 窗口要把三种会话放进一个列表：面板 AI 的普通对话、服务器 Agent 会话、Agent 页的执行记录。现在服务器会话只能按单台机器查，前端拼不出全局列表。

接口 `GET /ai/sessions`，在 `api/modules/ai.yaml` 里定义，参数 `limit`（默认 100，最多 300）。返回 `AiSession` 数组，排序：状态是 working 或 waiting 的在前，其余按 `updatedAt` 倒序。

`AiSession` 字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 字符串，`chat:<会话 id>`、`host:<会话 id>`、`run:<执行 id>` |
| `kind` | `chat` 面板对话，`host` 服务器 Agent，`agent` Agent 执行记录 |
| `refId` | 会话 id 或执行 id |
| `title` | 对话标题；执行记录用卡片编号加标题，没有卡片时用执行摘要的开头 |
| `sourceName` | 机器名或 Agent 名，面板对话为空 |
| `hostId` | 只有 host |
| `agentId`、`agentKind`、`agentAvatar`、`agentColor`、`issueKey`、`taskId` | 只有 agent |
| `status` | `working` 正在生成或执行；`waiting` 有待确认的操作或等你决定；`idle` 对话空闲；`done`、`failed`、`canceled` 执行记录结束 |
| `pendingCount` | 等你确认的数量 |
| `updatedAt` | 最后变化时间 |

规则：

- 对话的 working 看内存里正在生成（`m.running`），waiting 看有没有待确认的动作。
- 执行记录的状态按 `AiAgentRunStatus` 对应：queued、running 算 working；waiting 算 waiting；pr_opened、done 算 done；failed、canceled 照原样。
- 读执行记录要通过 `contracts` 里的接口拿，不要在 ai 模块里直接查 aiagents 的表。没有合适的接口就在 contracts 加一个，aiagents 模块实现。
- 机器名从 `d.Agents` 拿。机器已删除时 `sourceName` 用机器 id。
- 状态变化要能让前端知道：对话已经有 `ai.message_done`、`ai.action_pending`，执行记录已经有 `ai_agent.changed`、`ai_agent.run_event`、`ai_agent.decision`。生成开始时补发一个 `ai.message_started`（带 `conversationId`），前端收到这些事件就刷新列表。
- 隐藏空间：锁定时不能返回隐藏内容相关的东西，和现有对话列表的处理一致。
- 测试：三种来源都出现、排序、状态对应、limit。

## B184 服务器 Agent 权限不再丢失

原因：前端离开 Agent 标签时把“全部自动”改回“每步确认”；没发消息前选的权限只存在组件里；后端权限只存在内存里，重启就丢。

- 后端：权限存进 `ai_conversations`（新加列，迁移只加不删），重启后还在。“全部自动”仍然要二次验证，2 小时没有新消息自动退回“每步确认”，到期时间也存库。`Conversation.permission` 返回存下的值。`createHostAgentConversation` 的请求体可选带 `mode`，带 `all_auto` 时要二次验证。
- 前端：去掉离开页面就重置的逻辑。没发消息前选的权限记在全局状态里，按机器记。

## B186 curl 安装的服务器没有国旗（后端）

国家按公网 IP 查（`modules/hosts/host_addresses.go`）。先找出 curl 安装的代理为什么拿不到国家，再修。可能的原因：网卡上只有内网 IP；`SourceIP` 拿到的是反向代理的地址；只有公网 IPv6 而国家库查不到；国家库没下载成功。修完要有测试覆盖找到的那个原因。

## B192 Apple 日历同步报错（后端）

iCloud 同步时报“读取日历失败: property <urn:ietf:params:xml:ns:caldav calendar-data>: 404 Not Found”。iCloud 的 REPORT 返回里，有些条目的 `calendar-data` 在 404 的 propstat 里（比如已删除或不是日程的资源），go-webdav 解析整个列表时直接报错。改成跳过这些条目，必要时改用先列地址再 multiget 的方式。测试里用一段带 404 propstat 的返回复现。

## B193 AI 缓存命中优化（后端）

尽量让每次请求的开头部分不变，提高供应商的提示缓存命中。

- 先看现状：用量记录里按用途算缓存命中率，找出命中低的用途和原因，结果写进 `docs/qa/B193-cache.md`。
- 工具列表顺序固定。隐藏空间锁定和解锁时工具列表不要变。
- 系统提示里不放会变的内容。服务器 Agent 的系统提示每一轮都去取机器信息，要确认取到的内容不变，能力列表要排序。
- 请求带 `prompt_cache_key`（chat 和 responses 两种格式都带），用会话 id 或用途。供应商不支持这个字段时自动去掉重试，和现有的不支持字段处理一样。
- 其他用途（笔记、早报、分类等）的固定说明放在系统提示，变化的内容放在用户消息。
- 每一项改动有测试，能证明连续两轮请求的开头部分完全一样。
