# B98 到 B102 音乐播放器

用户 2026-10-10 要求：全局能播放音乐，通过云盘上传，歌词和封面缺了就在线匹配并写回文件，有播放列表，有定时暂停，能和专注状态同步。

2026-10-10 用户确认的三个决定：

1. 在线匹配用 LRCLIB、网易云、QQ 音乐、iTunes Search、MusicBrainz 的 Cover Art Archive，全部做成可开关的来源。
2. 匹配成功后默认写回文件，不保留旧版本。
3. 五个任务全部做。

## 拆分

| 编号 | 内容 | 依赖 |
| --- | --- | --- |
| B98 | 曲库：音乐目录、入库扫描、读标签、播放接口、播放列表、收藏、最近播放 | 云盘 |
| B99 | 全局播放器和音乐页：迷你条、全屏页、队列、歌词、Media Session | B98 |
| B100 | 在线匹配歌词和封面、待确认列表、写回文件 | B98 |

| B102 | 专注同步、播放统计、今日页迷你卡片 | B99，番茄钟 |

按这个顺序做，一个任务一个提交。每个任务做完都要有后端集成测试，B99 之后每个任务在端到端测试里补主流程。

## 范围外（第一版不做）

- 声纹识别。文件名和标签都乱的歌，只做文件名拆分，不行就进“待确认”。
- 转码。浏览器不能直接解码的格式（APE、WMA 等）不入库。
- 响度标准化（ReplayGain）。
- 多设备接力播放。同一时间只在用户点了播放的那个标签页出声，换设备要在那台设备上点播放。
- 让 AI 控制播放、暂停、切歌。播放在浏览器里，服务端不能替它出声。AI 上传歌、搜索、匹配、整理播放列表的 MCP 动作见 [B103](B103.md)。

## 模块和文件

- 新后端模块 `backend/internal/server/modules/music`，接口 `api/modules/music.yaml`。
- 新前端 `web/src/features/music`。全局播放器挂在 `web/src/app/GlobalPanels.tsx`，只加一行。
- 迁移只加表，文件名 `YYYYMMDDHHMMSS_m<编号>_music_<说明>.sql`。
- 读写云盘文件需要云盘提供的接口。`contracts` 里没有就加一个小的契约（读文件路径、改文件后刷新大小和哈希、列目录变更），不改云盘模块现有行为，记入 `docs/tasks.md` 的“接口变更记录”。
- 隐藏内容（B57）：锁定状态下的隐藏目录里的音乐不入库。已入库的歌所在目录被设为隐藏时，锁定后接口回 404，事件、通知里不出现。

## B98 曲库和播放接口

### 做什么

- 设置里指定音乐目录，可以多个，默认没有。目录以云盘的目录 ID 保存，设置键 `music.folders`。
- 目录里的音频文件自动入库。触发时机：
  - 云盘上传、移动、重命名、删除的事件（`drive_item.*`）。
  - 服务端启动时和每天一次全量对账，补漏和清理已不存在的文件。
  - 设置里“重新扫描”按钮。
- 支持扩展名：mp3、flac、m4a、aac、ogg、opus、wav。
- 入库时读：标题、歌手、专辑、专辑歌手、曲目号、碟号、年份、时长、码率、内嵌封面（有无）、内嵌歌词（有无，是否带时间轴）。读不到标题时用文件名，读不到歌手时用上级目录名。
- 封面缩略图生成 3 个尺寸（96、256、640，WebP），存在数据目录，不放进云盘。
- 同目录同名 `.lrc` 和 `cover.jpg`、`folder.jpg`、`front.jpg` 也在入库时读取，只存入库表，不改文件。
- 播放接口：返回云盘文件内容，必须支持 Range 请求（拖进度条）。云盘现有的文件内容接口用 `http.ServeContent`，已支持 Range，复用即可。
- 播放列表：新建、改名、删除、加歌、移除、拖动排序。播放列表里的歌引用 `music_tracks.id`，文件删除后从列表里自动移除。
- 收藏：布尔值，自动有一个“我喜欢的”视图，不当作普通播放列表存。
- 最近播放和播放次数：前端播放超过 30 秒或超过一半时上报一次。

### 表

| 表 | 列 |
| --- | --- |
| `music_tracks` | id、drive_item_id（唯一）、title、artist、album、album_artist、track_no、disc_no、year、duration_ms、bitrate、format、has_cover、cover_source（embedded、folder、online、none）、lyrics_source（embedded、lrc、online、none）、lyrics_synced（布尔）、lyrics_text、favorite、play_count、last_played_at、match_state（none、matched、pending、failed、skipped）、created_at、updated_at |
| `music_playlists` | id、name、created_at、updated_at |
| `music_playlist_items` | playlist_id、track_id、position，主键 (playlist_id, track_id) |

- 歌词全文放在 `lyrics_text`，用于搜索歌词内容。
- 搜索：歌名、歌手、专辑、歌词内容，用 SQLite FTS5 或 `LIKE`，选哪个由实现决定，要有 5000 首歌的性能测试（查询小于 100 毫秒）。

### 接口

- `GET /music/tracks?q=&artist=&album=&favorite=&cursor=&limit=`
- `GET /music/tracks/{id}`
- `GET /music/tracks/{id}/stream`（Range）
- `GET /music/tracks/{id}/cover?size=96|256|640`
- `GET /music/tracks/{id}/lyrics`：返回已解析的行，每行 `timeMs` 和 `text`，没有时间轴时只有 `text`。
- `PATCH /music/tracks/{id}`：改收藏、手动改标题歌手专辑。
- `POST /music/tracks/{id}/played`：上报一次播放，带 `seconds`。
- `GET /music/albums`、`GET /music/artists`
- 播放列表：`GET/POST /music/playlists`，`GET/PATCH/DELETE /music/playlists/{id}`，`PUT /music/playlists/{id}/items`（整体设置顺序）。
- `GET/PUT /music/settings`：音乐目录、来源开关、是否写回。
- `POST /music/scan`

### 读写标签的库（先做 spike）

后端是纯 Go，镜像是 alpine，没有 CGO。动手前先验证：

- 方案 A：`go.senan.xyz/taglib`（用 WebAssembly 跑 TagLib，不需要 CGO）。要验证能在 `CGO_ENABLED=0` 下编译，能读写 mp3、flac、m4a、ogg 的封面和歌词，二进制增加多少。
- 方案 B：A 不行就在 `deploy/Dockerfile` 里 `apk add ffmpeg`，读写标签和封面都用它。

spike 的结论写进本文件。A 和 B 选哪个，要在一个小的 Go 程序里用真实的 mp3、flac、m4a 测试文件验证过才定。

## B99 全局播放器和音乐页

页面样式先读 `docs/07-design.md`，复制最像的现有页面再改，用现成的公共组件。

### 全局播放器

- 音频元素和播放状态放在布局最外层（`GlobalPanels`），切换页面不中断。
- 迷你条在页面底部：封面、歌名和歌手、上一首、播放暂停、下一首、进度条、音量、打开全屏。没有在播放时不显示。手机端迷你条在底部导航上方，只显示封面、歌名、播放暂停和下一首。
- 全屏页：大封面、滚动歌词（当前行高亮并跟随）、播放队列（可拖动排序、移除）、播放模式（顺序、列表循环、单曲循环、随机）、倍速（0.75、1、1.25、1.5、2）、收藏、定时（B101）。
- 没有时间轴的歌词按普通文本显示，不滚动。
- 点歌词的某一行跳到那一行的时间。
- 歌词和封面缺失时显示默认封面，不报错。
- 队列和播放位置存在 `localStorage`，刷新页面后能恢复到暂停状态，不自动出声。读取失败时按没有处理。
- Media Session：标题、歌手、专辑、封面、上一首、下一首、拖进度、暂停播放。锁屏和耳机按键可控制。
- 键盘：空格播放暂停（焦点不在输入框时）。

### 音乐页（`/music`）

- 左栏加一级菜单“音乐”，二级：全部歌曲、专辑、歌手、播放列表、我喜欢的、最近播放、待确认（B100）。
- 歌曲列表：封面缩略图、歌名、歌手、专辑、时长、收藏。双击播放。右键菜单：播放、下一首播放、加入队列、加入播放列表、收藏、重新匹配、编辑信息、在云盘中显示。
- 搜索框同时搜歌名、歌手、专辑、歌词。
- 没设音乐目录时，空状态里有“选择音乐目录”的入口，指向设置。
- 云盘里点音频文件，用全局播放器播放，不再另开预览窗口。

### 浏览器限制（要在界面和文档里说明）

- 浏览器要求用户点一下页面才允许自动播放。B102 的自动播放遇到被拒绝时，显示“点一下开始播放”。
- iOS 要把页面加到主屏幕，锁屏后才能继续播放。这一点要用户真机验证。

## B100 在线匹配和写回

### 来源

做成统一接口 `Provider`：搜索候选（带歌名、歌手、专辑、时长、来源 ID），取歌词，取封面。每个来源有开关，设置键 `music.providers`。

| 来源 | 歌词 | 封面 | 说明 |
| --- | --- | --- | --- |
| LRCLIB | 是，带时间轴 | 否 | 开放接口，免 key |
| 网易云 | 是 | 是 | 非官方接口，可能失效或限制境外 IP |
| QQ 音乐 | 是 | 是 | 非官方接口，可能失效 |
| iTunes Search | 否 | 是 | 官方公开接口 |
| MusicBrainz + Cover Art Archive | 否 | 是 | 开放接口，限速 1 次每秒，请求要带 User-Agent |

- 来源出错、超时、返回格式不对时，跳过这个来源，记一条日志，不让整个匹配失败。
- 每个来源 8 秒超时，并发最多 2 个请求，匹配任务串行，避免被封。
- 搜索关键字：先“歌名 歌手”，没结果时只用歌名。
- 请求要带统一的 User-Agent，不伪造成官方客户端。

### 匹配规则

对每个候选打分，全部满足才自动采用：

1. 标题相同。比较前统一大小写、全角半角、繁简，去掉括号里的版本说明（Live、Remix、伴奏除外，这几个必须一致）。
2. 歌手有交集（按 `/`、`,`、`&`、`、` 拆开比较）。
3. 时长相差不超过 2 秒。来源没给时长的候选，不自动采用，放进待确认。

有多个候选满足时，歌词优先选带逐行时间轴的，其次按来源顺序（LRCLIB、网易云、QQ 音乐）。封面优先选尺寸大的，并且短边至少 500 像素。

没有候选满足时，`match_state = pending`，把最多 5 个候选存起来，让用户在“待确认”里手选。

### 什么时候匹配

- 入库后，对缺歌词或缺封面的歌排队匹配。顺序是：内嵌、同目录文件、在线。
- 已经有内嵌歌词和封面的歌不请求网络。
- 设置里有“自动匹配”开关，默认开。关掉后只在用户手动点“匹配”时运行。
- 每首歌只自动匹配一次。失败的记 `failed`，用户手动点才再试。

### 写回

设置键 `music.write_back`，默认开，不保留旧版本（用户 2026-10-10 决定）。

- 流程：复制原文件到同目录的临时文件，写标签，重新读一遍确认封面和歌词确实在里面，且音频部分的数据没变，然后原子替换原文件。任何一步失败就删掉临时文件，原文件不动。
- 写完后更新云盘记录的大小、哈希、修改时间，发 `drive_item.updated` 事件，已有的云盘同步照常工作。
- 只写本地存储里的文件。在 S3 或 WebDAV 上的文件，只存数据库，`match_state` 仍记 `matched`，在音乐页提示“未写入文件”。
- 隐藏目录里的文件不处理。
- 只补缺的：已有内嵌封面不覆盖，已有内嵌歌词不覆盖。用户在“重新匹配”里选“覆盖”才改。
- 歌词写入：有时间轴的写 LRC 文本到歌词字段（ID3 的 USLT，Vorbis 的 LYRICS，MP4 的 ©lyr）。
- 封面写入：JPEG 或 PNG，最长边缩到 1200 像素以内。
- 同目录的 `.lrc` 和封面图文件：只读，不删除。

### 接口

- `GET /music/pending`：待确认的歌和候选。
- `POST /music/tracks/{id}/match`：手动匹配。带可选的 `candidate`（来源和来源 ID）和 `overwrite`。
- `POST /music/match`：批量匹配所有缺歌词或封面的歌，返回任务 ID。
- `PUT /music/tracks/{id}/lyrics`：手动编辑歌词（纯文本或 LRC），可选写回。
- `POST /music/tracks/{id}/cover`：上传封面图，可选写回。
- 匹配进度用现有事件通道发 `music.match_progress`。

### 界面

- “待确认”页：每首歌显示候选列表（封面、歌名、歌手、专辑、时长、来源），选中后点“采用”。有“都不对，跳过”。
- 歌曲右键菜单“重新匹配”。
- 设置 → 音乐：音乐目录、自动匹配、各来源开关、写回开关、重新扫描、批量匹配和进度。

### 风险写进设置页文案

- 网易云和 QQ 音乐的接口是非官方的，可能随时不可用。
- 写回会直接修改云盘里的原文件，不保留旧版本。

## B101 定时暂停和播放列表分享

### 定时暂停

- 选项：15、30、45、60 分钟、自定义分钟数、播完当前这首、播完 N 首（N 从 2 到 20）。
- 到时前 10 秒音量渐小，到点暂停并把音量恢复。“播完当前这首”到下一首开始前暂停，不渐小。
- 定时放在服务端（设置键 `music.sleep`，含 `endsAt` 或剩余首数），换页面和设备都能看到。到点服务端发事件 `music.sleep_fired`，所有打开的页面收到后暂停。页面本地也有一个定时器兜底，服务端事件晚到时不会多播。
- 取消定时、延长 15 分钟。
- 全屏页和迷你条显示剩余时间。
- 手动暂停不取消定时。

### 播放列表分享

做法照 [B75](B75.md) 的云盘分享页。

| 表 | 列 |
| --- | --- |
| `music_playlist_shares` | id、playlist_id、token_hash、password_hash（可空）、expires_at（可空）、created_at、view_count |

- 公开入口 `/s/music/{token}`，需要校验密钥，有密码时先校验密码。
- 公开页只能播放这个播放列表里的歌，不能访问其他歌和云盘文件。流接口也校验 token 和歌曲是否在列表里。
- 公开页：封面、歌名、歌手、播放列表。播放器是简化版，没有收藏和歌词编辑。
- 撤销分享后链接立即失效。删除播放列表时一并删除分享。
- 访问次数记在 `view_count`，每次打开页面加一。

## B102 专注同步、统计和今日页卡片

### 专注同步

当前番茄钟只有“开始”和“结束”（到点或手动停止），没有“休息”状态，所以只同步这两个点。

设置键 `music.focus`：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `autoPlay` | 关 | 专注开始时自动播放指定播放列表 |
| `playlistId` | 无 | 自动播放用的播放列表，没设时用当前队列 |
| `autoPause` | 关 | 专注结束或手动停止时暂停 |
| `onlyFocusList` | 关 | 专注期间队列只用指定播放列表，专注结束后恢复原队列 |

- 番茄钟模块加两个事件：`focus.started`、`focus.stopped`（现有只有 `focus.done`）。改动要小，向后兼容，记入“接口变更记录”。
- 多个页面同时打开时，只有当前可见且有焦点的页面执行自动播放，其他页面不出声。
- 浏览器拒绝自动播放时，在页面里显示“点一下开始播放”，不重试。
- 手动暂停后，同一次专注里不再自动播放。
- 用户在专注期间手动换了歌，不改回。

### 播放统计

| 表 | 列 |
| --- | --- |
| `music_plays` | id、track_id、started_at、seconds、focus_session_id（可空） |

- 一次播放：超过 30 秒或超过一半时长才记。
- `GET /music/stats?days=`：总播放时长、播放最多的歌和歌手、专注期间播放时长和专注期间最多的歌。
- 页面只展示数字，不下结论。

### 今日页迷你卡片

- 今日页加一个“正在播放”卡片：封面、歌名、播放暂停。没在播放时不显示。样式照今日页现有卡片，布局列号用现有机制（B88）。

## 测试

- 后端集成测试放外部测试包。覆盖：入库、更新、删除对账、隐藏目录、Range、播放列表增删排序、搜索、统计、定时事件、分享的密码和失效、专注事件。
- 匹配规则做单元测试：标题归一化、歌手拆分、时长误差、多个候选的选择、全部不满足时进待确认。来源用 `httptest` 的假服务器，不访问真实网络。每个来源各有一份成功、错误格式、超时的测试。
- 标签读写用真实的小型 mp3、flac、m4a、ogg 文件做往返测试：写入歌词和封面，再读出来一致，音频数据不变。写入中途失败时原文件不变。
- 前端测试：歌词解析（LRC 多时间戳、偏移、无时间轴）、队列和播放模式、定时计算、专注同步的判断。
- 端到端：上传一首歌到音乐目录，出现在曲库，播放，匹配并写回（来源用假服务器），创建播放列表并分享，开专注自动播放。
- 手机 390px 和桌面 1360px 的截图都要看，深浅主题都要看。
- 做完后要用户验证的项目：iOS 主屏幕应用锁屏后继续播放、网易云和 QQ 音乐的真实接口。

## 验收

- 上传到音乐目录的 mp3、flac、m4a、ogg、opus、wav 都入库，字段正确，拖进度条能跳。
- 缺封面和歌词的歌，匹配成功后文件里有内嵌封面和歌词，用别的播放器打开能看到。
- 匹配不确定的歌进“待确认”，不会被错误写入。
- 写回失败时原文件完全不变。
- 切换页面播放不中断，手机锁屏能控制。
- 定时暂停到点所有页面暂停。
- 公开播放列表链接能听，撤销后立刻失效，不能听列表外的歌。
- 专注开始和结束按设置播放和暂停。
- 所有新增的界面文字用日常中文，不出现生僻词。
- 全部后端和前端检查通过，`git diff` 生成文件为空。
