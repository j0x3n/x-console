# B226 网站自动化的浏览器看起来更像普通浏览器

2026-10-15 用户提的：浏览器特征能优化的都优化。起因见 [B208](B208.md)，江苏政务服务网登录后被拦。

## 现在的情况

浏览器是 `chromedp/headless-shell`，只把 User-Agent 里的 `HeadlessChrome` 换成了 `Chrome`（`browser/session.go`）。网站还能从下面这些地方看出是自动化程序：

- `navigator.webdriver` 是 true。
- 请求头 `Sec-CH-UA` 和 `navigator.userAgentData` 里还有 `HeadlessChrome`。
- `navigator.plugins` 是空的，普通 Chrome 有 5 个 PDF 插件。
- 没有 `window.chrome`。
- `Notification.permission` 是 denied，可 `navigator.permissions.query` 查通知又说 prompt，普通浏览器两个对得上。
- `window.outerWidth`、`outerHeight` 是 0，或者和窗口内部一样大。
- 屏幕大小是默认的 800×600，比窗口还小。
- WebGL 的显卡名是 SwiftShader（软件渲染），普通电脑上不会是这个。
- 点击是直接在目标位置按下，没有鼠标移动过去的过程。输入是一次把整段文字塞进去。

## 要什么

全部改在 `backend/internal/server/browser` 里，不改镜像和部署文件。

1. 改 User-Agent 时同时传 `userAgentMetadata`：品牌用 `Chromium` 和 `Google Chrome`，加一个 `Not.A/Brand`，版本照 `Browser.getVersion` 的主版本号，平台照 UA 里写的系统（现在是 Linux），不是手机。
2. 新页面加载前跑一段脚本（`Page.addScriptToEvaluateOnNewDocument`，放进新文件 `stealth.js`，用 `go:embed`）：
   - `navigator.webdriver` 返回 false，改在 `Navigator.prototype` 上。
   - `navigator.plugins` 和 `navigator.mimeTypes` 照普通 Chrome 给 5 个 PDF 插件，类型要对（`PluginArray`、`Plugin`）。
   - `navigator.languages` 照任务的语言，比如 `["zh-CN","zh"]`。
   - 没有 `window.chrome` 时补上，带 `runtime`、`app`、`csi`、`loadTimes`。
   - `Notification.permission` 是 denied 时，`permissions.query` 查通知也回 denied。两边对得上就行，不改成 granted。
   - `outerWidth`、`outerHeight` 等于窗口内部大小加上浏览器边框（宽加 0，高加 85）。
   - WebGL 和 WebGL2 的 `getParameter` 在查 `UNMASKED_VENDOR_WEBGL`、`UNMASKED_RENDERER_WEBGL` 时，回一套和 Linux 对得上的 Intel 显卡名。别的参数照原样。
   - 改过的函数调用 `toString()` 时显示成原生函数（`function xxx() { [native code] }`）。
   - 脚本出错不能影响页面，每一项单独 try。
3. 屏幕大小用 `Emulation.setDeviceMetricsOverride` 的 `screenWidth`、`screenHeight` 设成 1920×1080。窗口大小仍是 1280×900。
4. AI 点击时，鼠标先从上一次的位置分几步移到目标，每步间隔 10 到 30 毫秒，落点在元素里稍微偏一点，然后再按下、松开，按下和松开之间隔 50 到 120 毫秒。
5. AI 输入文字时，一个字一个字输入，每个字间隔 30 到 120 毫秒。超过 200 个字的还是整段塞进去，免得太慢。接管页面里用户自己输入的不改。
6. 这些都对每个新会话生效，不用配置。

## 不做的

- 不换浏览器镜像，不加启动参数。`--disable-blink-features=AutomationControlled` 要改容器启动方式，没法在开发环境验证，记进已知问题，等这次上线看效果再说。
- 不把系统改成 Windows。改了 UA 以后字体、平台这些也得一起改，对不上反而更容易被认出来。
- Chrome 调试协议本身（比如 `Runtime.enable`）有办法被网页检测到，这次不处理。

## 验收

- 用真实 Chrome 的测试（`browsertest`）：打开本地测试页，读到
  - `navigator.webdriver === false`，
  - `navigator.plugins.length === 5`，
  - `navigator.userAgentData.brands` 里没有 `HeadlessChrome`，请求头 `Sec-CH-UA` 里也没有，
  - `window.chrome` 存在，
  - `outerHeight > innerHeight`，`screen.width === 1920`，
  - WebGL 显卡名不含 SwiftShader（这台测试机没有 WebGL 时跳过这一项），
  - `Function.prototype.toString.call(Object.getOwnPropertyDescriptor(Navigator.prototype, "webdriver").get)` 含 `[native code]`。
- 点击测试：测试页记录 `mousemove` 事件，点一次至少收到 3 次移动，然后才是 `mousedown`。
- 输入测试：测试页记录 `keydown`，输入 5 个字收到 5 次。现有的点击、输入、接管测试都要还能过。

## 效果没法保证

这些只能挡住简单的检测。政务网站常用的商业防护会查更多东西，挡不挡得住要上线试。如果 B208 换了出口还是被拦，再看要不要换成完整版 Chrome。
