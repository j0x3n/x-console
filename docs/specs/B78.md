# B78 CI 提速

## 实际用时（2026-10-02，PR #29 第一次跑新流程）

- `web`（生成检查、typecheck、格式、字号、单元测试）：1 分 27 秒。
- `e2e`（编译服务端和代理、打包、端到端）：2 分 25 秒，和 `web` 同时跑。
- 原来一个 `web` 任务要六七分钟。
- 和规格不同的地方：没用 `dorny/paths-filter`，改成在 `changes` 任务里用 `git diff HEAD^1 HEAD` 比较 PR 的合并提交，免得被 deploy.yml 调用时多要 `pull-requests` 权限。改了 `api/`、`.github/` 时前后端都跑。

用户 2026-10-01 提的：部署又慢了，前端那个检查要六七分钟，能跳过的测试跳过。

## 现在前端检查（`ci.yml` 的 `web` 任务）做了什么

按顺序：`npm ci` → 生成接口类型并比较 → `typecheck` → 格式检查 → 字号检查 → 单元测试 → `npm run build`（里面又跑一次 `typecheck`）→ 装 Go → `playwright-core install --with-deps chromium`（要用 apt 装系统库，一两分钟）→ 端到端测试（先编译服务端和代理，再跑浏览器）。

## 改法

1. **拆成两个并行的任务**：
   - `web`：生成检查、typecheck、格式、字号、单元测试。
   - `e2e`：只做构建和端到端。两个同时跑，总时间取较长的那个。
2. **不装浏览器**：GitHub 的 `ubuntu-latest` 已经装好了 Google Chrome。端到端和截图脚本本来就支持 `XC_SHOTS_BROWSER`，指向 `/usr/bin/google-chrome`，去掉 `playwright-core install --with-deps`。
3. **构建不再重复 typecheck**：`e2e` 任务里直接 `npx vite build`，不跑 `npm run build`（`web` 任务已经 typecheck 过了）。
4. **单元测试用多线程**：`vitest run` 默认按 CPU 数开线程，配置里限制过 worker（`vite.config.ts`）。CI 上放开到 CPU 数（Runner 是 4 核）。
5. **Go 编译缓存**：`e2e` 任务的 `setup-go` 开缓存（已经开了），编译服务端用 `go build -trimpath`，和 `backend` 任务共用缓存键。
6. **只改了后端或只改了前端时**：PR 上用 `dorny/paths-filter` 判断改了哪边。只改 `backend/` 时跳过 `web`；只改 `web/` 时跳过 `backend`。端到端两边都要跑（两边的改动都可能弄坏它）。部署时（`workflow_call`）全部都跑，不跳过。
7. 端到端失败时照旧上传截图和日志。

## 不跳过的

- 单元测试、类型检查、端到端都不跳过。它们抓到过真问题。
- 部署前的测试全部要跑。

## 验收

- PR 上前端相关的两个任务都在 4 分钟内跑完（以改完后第一次 PR 的实际用时为准，写进这一节）。
- 只改文档的推送不跑 CI（原来就是）。
