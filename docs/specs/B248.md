# B248 仓库管理搬到仓库页，仓库页能启动 Action

用户 2026-10-18 在 X Console 看板提出（XC-59）：设置里的 Git 仓库绑定挪到仓库模块，设置只留账号绑定和通知设置，仓库模块要能启动 Action。

## 现在的情况

- 设置 → Git（`web/src/features/github/GitSettingsTab.tsx`）有五块：Git 账号、同步状态、关注的仓库、仓库通知、CI 额度。
- 仓库页（`/github`，`GitHubPage.tsx`）只读：PR、提交、Action 运行记录、Issue、CI 用量。没关注仓库时显示 `SetupGuide`，叫人去设置里加。
- 后端 `modules/github` 只读 GitHub 的 `actions/runs` 和 `jobs`，不会触发运行。
- 项目看板绑定仓库（B84，`BindRepoDialog`）用的是 aiagents 的 Git 账号，和这次无关，不动。

## 要什么

### 设置里只留两块

- 留下：Git 账号（加、改令牌、Webhook、删除）、仓库通知。
- 挪走：关注的仓库、同步状态、CI 额度。设置里原来的位置放一行字“关注哪些仓库在仓库页里改”，带链接到 `/github?manage=1`。

### 仓库页

- 顶栏加“管理仓库”按钮，打开弹窗。弹窗内容就是原来设置里的“关注的仓库”（从账号里选、去掉、属于已删账号的提示），代码直接搬过去，不重写。
- 没关注仓库时，`SetupGuide` 里的按钮直接打开这个弹窗。没有 Git 账号时，按钮还是去设置加账号。
- 同步状态和每月免费 CI 分钟数也放进这个弹窗，排在关注的仓库下面。三块都是从设置页原样搬过来的（`ManageRepos.tsx`），弹窗里去掉卡片外框，用分隔线隔开。设置里原来的位置换成一行说明和“管理仓库”链接（`/github?manage=1`）。

### 启动 Action

- 仓库页“运行记录”视图，选中一个仓库时，上面多一个“运行工作流”按钮。只对 GitHub 账号显示。Forgejo 先不做，按钮不出现。
- 点了弹窗：选工作流（只列有 `workflow_dispatch` 触发的），选分支（默认仓库默认分支），工作流定义了输入参数时按类型列出（文字、选项、勾选），带默认值。
- 点“运行”要二次验证（`auth.RequireElevated`），因为工作流可能部署线上。提交后提示“已提交，运行记录里一会儿就能看到”，并刷新运行记录。
- 失败的运行在记录里多一个“重新运行失败的任务”（GitHub `rerun-failed-jobs`），同样要二次验证。
- 令牌没有权限时，把 GitHub 的原话显示出来，并提示：经典令牌要 `repo` 和 `workflow`，细粒度令牌要 Actions 读写。
- 审计日志记：仓库、工作流、分支、输入参数（参数值只记前 200 字）。

## 怎么做

- 后端 `modules/github` 加三个接口，写进 `api/modules/github.yaml`：
  - `GET /github/repos/{owner}/{repo}/workflows`：列出工作流。GitHub 的列表接口不带触发方式和输入参数，要再读每个工作流文件（`contents` 接口），解析 YAML 里的 `on.workflow_dispatch.inputs`。结果缓存 5 分钟。
  - `POST /github/repos/{owner}/{repo}/workflows/{workflowId}/dispatches`：body 是 `ref` 和 `inputs`。
  - `POST /github/repos/{owner}/{repo}/runs/{runId}/rerun-failed`。
  - 三个都只接受关注列表里的仓库，别的仓库返回 404。两个写接口调用 `auth.RequireElevated`。
- 解析 YAML 用 `go.yaml.in/yaml/v3`。它已经是间接依赖（`go.sum` 里有 v3.0.5），改成直接依赖，不引入新的库。
- 前端只改 `web/src/features/github/`，设置页的登记 `settings/tabs.tsx` 不用改（还是同一个 Git 标签）。

## 验收

- 设置 → Git 只有账号和仓库通知两块，加一行链接到仓库页。
- 仓库页能打开“管理仓库”，加、去掉仓库后列表马上变。没关注仓库时引导能直接打开弹窗。
- 用假 GitHub 服务器的后端测试：列出工作流时只留有 `workflow_dispatch` 的，输入参数解析正确（文字、选项、勾选、默认值）；触发时请求体对；没二次验证返回 403；不在关注列表的仓库返回 404；GitHub 回 403 时原话带出来。
- 前端测试：运行弹窗按参数类型出控件，提交的参数对；Forgejo 仓库不显示按钮。
- 端到端第一部分加一步：打开仓库页的“管理仓库”弹窗。
- 截图 `/github` 和设置 → Git 的 1360 和 390 宽，按 `docs/07-design.md` 自查。

## 没验证的

- 开发环境连不上 GitHub，触发和重跑只用假服务器测。上线后拿一个不会部署的工作流先试。
