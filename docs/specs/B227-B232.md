# B227 到 B232：路由器设备流量、上下线通知、日志、页面密度、一行命令安装、新设备通知

2026-10-15 用户提的。六个任务都只用在“路由器主动上报”（B114）模式下，直连和代理转发模式不做，页面上提示“改成主动上报才有”。

## 用户定的（2026-10-15）

- 用户的路由器是 Lean 或 ImmortalWrt 一类的固件，在“Turbo ACC 网络加速”里开着 Shortcut-FE 流量分载、全锥型 NAT 和 BBR。分载不关。
- 路由器上有“带宽监控”（nlbwmon）。每台设备的流量从它读。
- Wi-Fi 设备上下线要及时发现，不等 5 分钟。同一台设备多久能再通知一次，可以设置。
- 通知有总开关，每台设备也有自己的开关。
- 日志有两部分：路由器自己的系统日志（`logread` 能看到的那些），和面板记的事件（设备上下线、WAN 掉线和恢复、路由器停止上报、重启命令）。保存天数在 1 到 15 天里选，默认 7 天。
- 先写规格，用户看过再开发。
- 加上 B232：新设备第一次接入时通知。
- 分工：前端（`web/` 下的代码和界面）Opus 5.5 写，其他（迁移、`api/modules/router.yaml`、后端、上报脚本、测试）Sonnet 5.5 子代理写。每个任务先做后端，前端接在后面。B231 只有前端。

## 做不到的，先说清楚

- **Shortcut-FE 开着时，防火墙计数不准。** 一个连接只有开头几个包走防火墙，后面的包直接转发。所以不用 nftables 或 iptables 计数，改读 nlbwmon。nlbwmon 读的是连接跟踪表的计数，Shortcut-FE 会把转发的字节数定期写回这张表。写回这一点没在用户的路由器上验证过，做完后要对数（见 B229 验收）。
- **“及时”最快也只能到上报间隔。** 脚本每隔几秒上报一次，面板在下一次上报时才知道设备变了。要及时就把上报间隔设成 3 或 5 秒。
- **有线设备没法马上知道离线。** 网线拔掉后，路由器的邻居表要过一阵才变。有线设备还是连续 5 分钟看不到才算离线。
- **手机锁屏可能断开 Wi-Fi。** 有的安卓手机锁屏后会断开几分钟再连上。Wi-Fi 设备按“及时”判断，就会频繁上下线。这正是“再次通知间隔”要解决的事，日志里每次都会记。

## B227 安装改成下载脚本

### 要什么

现在“生成上报令牌”后要复制一大段脚本粘贴到路由器上。改成复制一行命令，路由器自己下载安装脚本。

### 怎么做

- `POST /router/push/token` 的回复多两个字段：`installUrl` 和 `command`。`script` 字段保留，给手动安装用。
- `command` 长这样：

  ```sh
  wget -qO /tmp/xc-install.sh 'https://面板地址/api/v1/router/install/<下载码>' && sh /tmp/xc-install.sh
  ```

  OpenWrt 的 `wget` 就是 `uclient-fetch`。先存成文件再执行，下载到一半断了也不会执行半个脚本。
- 新接口 `GET /router/install/{code}`，不需要登录，加进 `PublicPaths`。
  - 下载码是 32 字节随机数，存在内存里，只存 sha256。
  - 15 分钟内有效，下载一次就作废。重新生成令牌后，旧的下载码马上作废。面板重启也作废。
  - 有效时回 `text/plain` 的安装脚本，内容和现在的 `script` 一样，令牌已经填好。
  - 无效时回 404，正文是“安装链接失效了，回面板重新生成”。`wget` 拿到 404 会失败，后面的 `sh` 不会执行。
  - 审计记 `router.install.download`，带对方 IP。
- 安装脚本在 B228 到 B230 里会多做几件事（配置 nlbwmon、记日志位置），都写在这个脚本里，不另外让用户执行。
- 以后升级脚本也是这一个办法：回设置页重新生成，再执行一行命令。旧令牌马上失效。

### 界面

设置 → 路由器 的令牌区域：

- 生成后最上面是这一行命令，旁边一个复制按钮。下面一行灰字：“15 分钟内有效，只能用一次。在路由器的 SSH 里执行。”
- 再下面一个折叠的“手动安装”，展开是现在那段完整脚本。路由器下载不了的时候用它。
- 面板地址是 https 时加一行提示：路由器没装 `ca-bundle` 会下载失败，失败就用手动安装。

### 验收

- 生成令牌，在路由器上执行那一行命令，最后显示“已上报一次”。
- 同一个链接再下载一次，返回 404。等 15 分钟再下载，也是 404。
- 重新生成令牌后，旧链接 404，旧脚本上报返回 401。
- 测试：下载码只能用一次、过期、重新生成后作废、不带登录也能下载、审计有记录。

## B228 设备列表、备注和上下线通知

### 要什么

- 面板记住见过的每台设备，不管现在在不在线。
- 每台设备可以写备注。备注替代主机名显示，通知里也用备注。
- 设备上线、离线时推送通知。总开关加单台开关，同一台设备可以设多久才能再通知。

### 在线怎么判断

现在的“在线设备”是 DHCP 租约和 ARP 表合起来的。租约没到期的设备就算在线，其实可能早就走了。这次改成下面的规则。

脚本每次上报多带两段：

- `#xc:wifi`：Wi-Fi 上连着的终端。先用 `ubus call hostapd.<接口> get_clients`，路由器没有 hostapd 的 ubus 对象时，用 `iwinfo <接口> assoclist`。每行写“接口名 MAC”。
- `#xc:neigh`：`ip neigh show` 的输出。没有 `ip` 命令时不带这段，面板退回读 `#xc:arp`。

判断规则：

| 设备 | 算上线 | 算离线 |
| --- | --- | --- |
| Wi-Fi 设备（出现在 `#xc:wifi` 里） | 出现在列表里的那次上报 | 从列表里消失的那次上报 |
| 有线设备 | 邻居表里是 REACHABLE、DELAY、PROBE 或 PERMANENT，或者它在 nlbwmon 里的字节数在涨（B229） | 连续 5 分钟以上都不满足上线条件 |

- 一台设备从 Wi-Fi 换到网线，只要有一边满足就算在线，不记一次下线。
- 只有 DHCP 租约、别的都没有的设备，不算在线。
- 路由器停止上报时，不给设备记离线。那时记的是“路由器停止上报”。恢复上报后按新的上报重新判断。
- 设备状态存数据库。面板重启后不会把所有设备当成刚上线。

### 数据

迁移 `m58`，新表：

```sql
CREATE TABLE router_devices (
  mac TEXT PRIMARY KEY,           -- 大写，冒号分隔
  note TEXT NOT NULL DEFAULT '',  -- 备注，最多 40 个字
  notify INTEGER NOT NULL DEFAULT 0,
  cooldown_minutes INTEGER,       -- NULL 表示跟随默认
  conn TEXT NOT NULL DEFAULT '',  -- wifi、wired，没判断出来是空
  last_name TEXT NOT NULL DEFAULT '',
  last_ip TEXT NOT NULL DEFAULT '',
  online INTEGER NOT NULL DEFAULT 0,
  online_since INTEGER,           -- 这次上线的时间
  first_seen INTEGER NOT NULL,
  last_seen INTEGER NOT NULL,
  notified_at INTEGER,            -- 上一次推送的时间
  notified_online INTEGER         -- 上一次推送的是上线还是离线
);
```

- 30 天没出现、也没写备注的设备，每天清理一次。
- 设置表加三个键：`router.device_notify`（总开关，默认关）、`router.notify_cooldown`（默认再次通知间隔，分钟，默认 15）、`router.log_days`（B230 用）。

### 通知

- 只有总开关开着、这台设备的开关也开着，才推送。默认都关。
- 标题“{名字} 上线了”或“{名字} 离线了”。正文写 IP、Wi-Fi 还是有线、这次在线了多久（离线时）或离开了多久（上线时）。
- 名字按这个顺序取：备注、主机名、MAC。
- 再次通知间隔可选 0（每次都推）、5、15、30、60 分钟。每台设备可以单独选，也可以跟随默认。
- 间隔怎么算：推送过一次后，这台设备在间隔内再变化，不推送，只记日志。间隔到了，如果设备现在的状态和上一次推送的不一样，补推一条，比如“手机现在离线了，过去 15 分钟上下线 4 次”。一样就不推。
- 通知类型 `router.device_online` 和 `router.device_offline`，普通优先级。走 B127 的合并推送设置，默认“立即”。

### 接口

- `GET /router/devices`：所有记住的设备。每台带备注、通知开关、间隔、Wi-Fi 还是有线、在线状态、上线时间、最后出现时间、IP、主机名，加上 B229 的速率和今天的流量。在线的排前面。
- `PATCH /router/devices/{mac}`：改 `note`、`notify`、`cooldownMinutes`（`null` 表示跟随默认）。不需要提升权限。
- `DELETE /router/devices/{mac}`：忘掉这台设备，删掉备注和它的流量记录。它再出现时当新设备。
- `GET /router/options`、`PUT /router/options`：`deviceNotify`、`notifyCooldownMinutes`、`logDays` 三项。
- 现有的 `GET /router/clients` 保留，AI 动作在用。改成只返回在线的设备，每台多带 `note`。

### 界面

- 设置 → 路由器 加一张“设备通知”卡片：总开关、默认再次通知间隔。
- 路由器页点一台设备，右边打开详情面板：备注输入框、通知开关、再次通知间隔、MAC、IP、IPv6、租约到期、第一次见到的时间，加上 B229 的流量。底部“忘掉这台设备”。
- 设备表里开了通知的设备，名字后面显示一个小铃铛。

### 验收

- 手机关掉 Wi-Fi，下一次上报（间隔 3 秒时 3 秒左右）收到“手机离线了”。打开 Wi-Fi 收到“上线了”。
- 再次通知间隔设成 15 分钟，15 分钟内反复开关 Wi-Fi，只收到第一条。间隔到了收到一条补推，写着变了几次。
- 拔掉一台有线电脑的网线，5 分钟后收到离线通知。
- 写了备注的设备，页面和通知都显示备注。
- 面板重启后，没有一批“上线了”的通知。
- 测试：Wi-Fi 及时判断、有线 5 分钟、Wi-Fi 换有线不记下线、路由器停止上报不记设备离线、再次通知间隔和补推、总开关和单台开关、重启后状态还在。

## B229 每台设备的实时流量

### 要什么

设备表里每台设备显示当前的下载、上传速率和今天用了多少。详情面板里有这台设备最近 24 小时和 7 天的曲线。

### 怎么做

- 脚本每次上报多带一段 `#xc:nlbw`，内容是 `nlbw -c json -g mac` 的输出。没装 nlbwmon 时不带这段。
- nlbwmon 默认 30 秒才刷新一次计数，速率会一跳一跳的。安装脚本把它改成 5 秒：`refresh_interval` 大于 5 秒时改成 `5s`，然后重启 nlbwmon。改之前的值写进 `/etc/xc-report.nlbw.bak`，卸载时恢复。会多占一点路由器 CPU。
- nlbwmon 的数是从统计周期开始累计的（默认每月一号清零，nlbwmon 重启也清零）。面板按相邻两次上报算每台设备的增量。数变小了就当作清零，按新值算，和 WAN 口的规则一样。
- `rx` 算下载，`tx` 算上传。这一点按 nlbwmon 的网页界面推的，要用真机确认一次。
- 速率按最近 10 秒的平均算。nlbwmon 每 5 秒刷新，直接用相邻两次上报会一会儿 0 一会儿翻倍。
- 存储：新表 `router_device_traffic(mac, hour, rx, tx)`，主键 `(mac, hour)`，每小时一行，和 WAN 流量一样存 30 天。和 B228 放在同一个迁移里。
- `GET /router/devices` 的每台设备多 `rxRate`、`txRate`、`todayRx`、`todayTx`。
- `GET /router/devices/{mac}/traffic?range=24h|7d`：24 小时按小时，7 天也按小时。

### 怎么知道数准不准

- 流量页签里 WAN 曲线下面加一行：“今天设备合计 ↓ X ↑ Y，WAN ↓ A ↑ B”。
- 设备合计不到 WAN 的 70%，并且 WAN 今天超过 500 MB 时，显示一行提示：“设备流量比 WAN 少很多。可能是分载没有把计数写回，设备流量只能参考。”
- 没装 nlbwmon 时，设备表的流量列显示“—”，表格上方提示“在路由器上装 nlbwmon（带宽监控）后显示每台设备的流量”。

### 验收

- 一台电脑下载一个大文件，设备表里这台的下载速率几秒内跟上，和电脑上看到的速度差不多。
- 用一天以后看流量页签，设备合计和 WAN 差不到三成。差太多就记进“已知问题”，再看要不要换做法。
- 测试：增量计算、清零、10 秒平均、按小时累加、没有 nlbw 段时不报错。

## B230 路由器日志

### 要什么

路由器页加一个“日志”页签，里面两部分：

- **事件**：面板自己记的。设备上线和离线、WAN 掉线和恢复、路由器停止上报和恢复、重启接口和重启路由器（谁在什么时候下发的）。
- **系统日志**：路由器的 `logread`，和在 LuCI 的“系统日志”里看到的一样。

保存天数在设置里选，1 到 15 天，默认 7 天。

### 系统日志怎么收

- 脚本每次上报带一段 `#xc:log`，只放上次发过之后的新行。
- 脚本把发过的最后一行存在 `/tmp/xc-report.logpos`。下次在 `logread` 的输出里找到这一行，只发它后面的。找不到（路由器重启了，或者日志缓冲区满了被覆盖）就整份发。
- 一次最多 500 行，多的下次再发。
- 面板按 `logread` 的格式拆出时间、来源（`daemon.info` 这种）、程序名和内容。时间用路由器的时钟。拆不出来的行原样存。

### 数据

和 B228 放在同一个迁移里：

```sql
CREATE TABLE router_events (
  id INTEGER PRIMARY KEY,
  at INTEGER NOT NULL,
  kind TEXT NOT NULL,      -- device_new、device_online、device_offline、wan_down、wan_up、report_lost、report_back、interface_restart、reboot
  mac TEXT,                -- 设备事件才有
  title TEXT NOT NULL,
  detail TEXT NOT NULL DEFAULT ''
);
CREATE INDEX router_events_at ON router_events(at);

CREATE TABLE router_logs (
  id INTEGER PRIMARY KEY,
  at INTEGER NOT NULL,
  level TEXT NOT NULL DEFAULT '',     -- emerg、alert、crit、err、warn、notice、info、debug
  facility TEXT NOT NULL DEFAULT '',
  program TEXT NOT NULL DEFAULT '',
  message TEXT NOT NULL
);
CREATE INDEX router_logs_at ON router_logs(at);
```

- 每小时清一次，超过保存天数的删掉。
- 系统日志另外最多存 20 万行，超了删最旧的。dnsmasq 每次 DHCP 续租都会写几行，设备多时一天能有几万行。

### 接口

- `GET /router/events?kind=&mac=&before=&limit=`：新的在前，`before` 是上一页最后一条的 id，一页最多 200 条。
- `GET /router/logs?q=&level=&program=&before=&limit=`：`level` 表示“这个级别及以上”，`q` 搜内容。
- 保存天数用 B228 的 `PUT /router/options` 的 `logDays`，只能是 1 到 15。改小以后下一次清理时删掉多出来的。

### 界面

- 页签顺序：设备、流量、日志。
- 日志页签里上面一个分段切换：事件、系统日志。
- 事件：按类型筛选（全部、设备、WAN、上报、命令），按设备筛选。每行是时间、类型标签、标题。设备事件点一下打开 B228 的设备详情。
- 系统日志：级别筛选（全部、警告及以上、错误及以上）、程序名下拉、搜索框。每行是时间、级别、程序名、内容，等宽字体，错误红色，警告黄色。长内容折行，不横向滚动。
- 停在最上面时跟着页面的刷新频率自动刷新。往下翻过就不自动刷新，顶上显示“有新日志”，点一下回到最上面。
- 底部“加载更多”。
- 设置 → 路由器 加一张“日志”卡片：保存天数下拉，1 到 15 天。

### 验收

- 在路由器上执行 `logger -t xc-test hello`，几秒后在系统日志里搜到 hello。
- 重启路由器，日志不丢、不重复（重启前的一段可能收不到，路由器的日志在内存里，重启就没了）。
- 保存天数改成 1 天，第二天只剩最近 1 天的。
- 测试：只发新行、找不到上次的行时整份发、500 行上限、`logread` 格式拆分、按天清理、20 万行上限、各种事件都记了。

## B231 路由器页提高信息密度

### 要什么

一屏能看到更多有用的东西，但不挤，字不变小。按 [07-design](../07-design.md) 做。

### 改什么

- **概要卡片**改成 5 张：
  - WAN：状态、IP、连了多久。
  - 设备：在线几台、记住几台，下面一行 Wi-Fi 几台、有线几台。
  - 当前速率：下载、上传。
  - 负载和内存：1 分钟负载、内存用了百分之几。这两个数现在接口里就有，页面没显示。
  - 运行时长。
- **接口卡片**默认收起成一行：“接口 7 个，全部正常”，后面每个接口一个小圆点加名字。点开是现在的列表。有接口断开时默认展开，断开的排前面。
- **设备表**：
  - 行高 36px，一行一台设备，不换行。
  - 列：状态点、名字（备注加粗，主机名灰字跟在后面）、Wi-Fi 或有线图标、IP、↓ 速率、↑ 速率、今天、在线时长（离线的写“3 分钟前离线”）。数字右对齐，等宽数字。
  - MAC 和租约到期从表里拿掉，放进详情面板。鼠标停在名字上显示 MAC。
  - 表格上面：在线、全部的分段切换，搜索框（搜名字、备注、IP、MAC）。默认看在线的。
  - 默认按下载速率排，点表头可以按名字、IP、速率、今天的流量排。排序方式记在本机。
  - 速率是 0 的显示灰色的“0”，不显示“—”。
- **手机（390px）**：设备每台两行。第一行名字和下载速率，第二行 IP、Wi-Fi 或有线、今天的流量。点一下打开详情。
- 截图检查 1360px 和 390px 两种宽度，没有横向溢出。

### 验收

- 1360px 宽时，一屏能看到概要、收起的接口、至少 15 台设备。
- 390px 宽时没有横向滚动。
- 深浅两个主题都能看清。

## B232 新设备第一次接入时通知

### 要什么

一台面板从没见过的设备连上家里的网络，马上推一条通知。用来发现陌生设备蹭网。

### 怎么做

- “新设备”指 `router_devices` 里没有这个 MAC。B228 判断它上线、往表里插新行的那一刻推送。
- 只看“在线”，不看 DHCP 租约。只有租约、没上线的不算。
- 设置 → 路由器 的“设备通知”卡片加一个开关“新设备接入时通知”，设置键 `router.notify_new_device`，默认开。和设备上下线的总开关互不影响。
- 每台新设备只推一次，不受再次通知间隔影响。
- 标题“新设备连上了：{主机名或 MAC}”。正文写 IP、MAC、Wi-Fi 还是有线、连在哪个 Wi-Fi 接口上。
- 通知类型 `router.device_new`，高优先级，走 B127 的合并推送设置，默认“立即”。
- 点通知打开路由器页，并打开这台设备的详情面板，可以马上写备注。
- 事件日志记一条 `device_new`（B230 的 `kind` 多这一种，类型筛选归到“设备”）。

### 不该推的时候

- **第一次上报不推。** 刚装好脚本时，家里所有设备对面板都是新的。安装后的第一次上报，把在线的设备全部存进表里，不推送，只在事件日志里记一条“第一次上报，记下了 N 台设备”。
- 升级到 B228 以后的第一次上报也一样。以前的版本没有设备表。
- 路由器停止上报一段时间又恢复，不算第一次。
- 在详情面板里“忘掉这台设备”后，它再出现会当新设备推送。

### 要知道的

- 手机的“私有 Wi-Fi 地址”如果设成“轮换”（iOS 18 以后有这个选项），同一台手机过一阵会换一个 MAC，面板会当新设备再推一次。设成“固定”就不会。
- 访客网络上的设备也会推送。

### 验收

- 一台从没连过的手机连上 Wi-Fi，几秒内收到“新设备连上了”。
- 关掉开关后，再连一台新设备不推送，事件日志里照样有记录。
- 重新安装脚本后的第一次上报，不会一下推一堆通知。
- 测试：新设备推送一次、第一次上报不推、开关、忘掉后再出现会推、停止上报后恢复不推。

## 做的顺序和脚本升级

- 按 B227、B228、B232、B229、B230、B231 的顺序做。B232 紧接 B228，它就是在 B228 的设备表上加几行判断。
- 一个任务一个提交。后端和前端分开写的任务，各一个提交，提交信息写“B228: 后端……”“B228: 前端……”。
- B228 到 B230 都改上报脚本。每个任务做完脚本都能单独用，新段面板认不出时忽略。
- 全部做完后，用户回设置页重新生成一次令牌，用 B227 的一行命令装新脚本。老脚本不带新段，面板照常显示状态，只是没有设备流量、Wi-Fi 及时判断和系统日志。

## 没做的

- 直连和代理转发模式下的设备流量、上下线通知和日志。
- 按设备限速、拉黑。这要改路由器配置，风险大，不做。

## 没在真机验证的（做完后写进“已知问题”）

- Shortcut-FE 把计数写回连接跟踪表，nlbwmon 的数是否接近真实。
- 用户固件的 Wi-Fi 驱动有没有 hostapd 的 ubus 对象，`iwinfo assoclist` 能不能列出终端。
- nlbwmon 的 `rx`、`tx` 是不是下载、上传。
- `logread` 的时间格式。不同固件可能不一样。

## 实现（2026-10-15）

后端 Claude Sonnet 5.5 写，前端 Claude Opus 5.5 写并审查后端。和上面写的不一样或补充的地方：

**接口和数据**

- 迁移 m58 建了四张表。`router_devices` 比上面多两列：`wifi_iface`（连在哪个 Wi-Fi 接口）、`offline_since`（这次离线的时间）。
- 路径里的 MAC 不分大小写，冒号、横杠、不带分隔都认。前端传不带分隔的写法，省得转义。
- `RouterDevice` 的可空字段没有值时是省略，不是 `null`。`cooldownMinutes` 例外，没设时是 `null`。
- `GET /router/events`、`GET /router/logs` 不检查模式，直连时回空列表。只有 `GET /router/devices` 在非主动上报模式回 409 `router_not_push`。
- 事件多一种 `devices_seeded`：第一次上报记下了几台设备。
- 脚本多发一段 `#xc:tz`（`date +%z`），日志时间按路由器时区解释，再用 `#xc:time` 和面板时钟的差校正。

**在线判断**

- 邻居表里只有 STALE 的设备不建记录。WAN 口上的邻居不算设备。
- Wi-Fi 设备从关联列表消失的那次上报就算离线。如果邻居表里它还是 REACHABLE 一类，等 60 秒：60 秒内一直在，就当换成了网线，不记离线。所以手机刚走时，离线通知最多可能晚 15 到 45 秒。
- nlbwmon 的字节数在涨，只对有线设备和新设备算在线。Wi-Fi 设备走了以后路由器上还会有一阵残留流量，算进去会拖住离线。
- `#xc:wifi` 里有一段 JSON 读不出来时，这一次的 Wi-Fi 列表整个不用，不会把所有 Wi-Fi 设备判成离线。
- 老脚本（没有 `#xc:wifi`、`#xc:neigh`）只看 ARP 表的完整条目，全部按有线的 5 分钟算。

**通知**

- 设备上下线事件对所有设备都记，不管通知开关。新设备只记 `device_new`，不另记上线。
- 补推里的“上下线 N 次”从事件表里数。
- 总开关或单台开关从关改成开时，清掉这台设备的通知历史，免得拿很久以前的状态补推。

**流量**

- 设备流量先在内存里累加，30 秒或每分钟轮询时写一次库。“今天”的数会加上还没写库的部分。
- 当前这个小时的速率按已经过去的秒数算，整点后头几秒会偏大。

**界面**

- 设备和日志页签的筛选和页签放在同一行，不再另起一行工具栏。
- 日志翻过页以后不自动刷新，顶上显示“正在看旧日志，已暂停自动刷新”和“回到最新”按钮，没有做“有新日志”的提示。
- 手机上设备表只留名字和下载速率两列，IP、连接方式、今天的流量写在名字下面一行。
