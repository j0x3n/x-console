# B241 资讯：在面板里看 AI 新闻和 X 推文

用户 2026-10-17 提出。用户在内网虚拟机（192.168.1.2）上用 Hermes Agent 跑了两个服务，现在只推到 Telegram。用户想在面板里有一个页面，能翻看和搜索这些新闻和推文。

## 现在的情况

两个仓库都在用户自己的 Git 上：`https://git.xcc.im/agent/ai-news`、`https://git.xcc.im/agent/x-assistant`。2026-10-17 看过代码。

**ai-news**（Python，目录 `/root/.hermes/scripts/ai-news`）：

- 数据在 SQLite `ai_intel.db` 里，开了 WAL。
- `items` 是新闻主表：`id`、`title`、`url`、`source`、`category`、`published_at`、`fetched_at`、`summary`，AI 补的 `title_cn`、`summary_cn`、`tags`（JSON 数组）、`importance`，以及 `pushed`（推过 Telegram 是 1）。时间都是 UTC 的 ISO 字符串。
- `items_fts` 是 FTS5 全文索引，列有 `item_id`、`title`、`title_cn`、`summary`、`summary_cn`、`tags`、`source`、`category`。SQLite 不带 FTS5 时这张表不存在。
- `article_contents` 存正文：`markdown_zstd`、`content_cn_zstd` 是 zstd 压缩的 Markdown，`status` 是抓取状态。`article_media` 存配图，`public_url` 是 S3 的公开地址。
- 推 Telegram 之后才补正文、标签和翻译，所以最新的几条可能还没有这些字段。

**x-assistant**（Node，目录 `/root/.hermes/remote-chrome`）：

- `collect.js` 通过 CDP 连上已经登录的 Chromium，打开一个私有列表，取最多 25 条推文：`id`、`author`、`time`、`url`、`text`。
- 推文不存在任何地方。`seen.json` 只记见过的编号，最多 2000 个。新推文打印到标准输出，Hermes 读了以后发 Telegram。
- **疑似 bug**：没有新推文时，第 55 行输出的是 `state.last_payload`，也就是上一批推文，不是 `NO_NEW_TWEETS`。Hermes 如果不自己去重，会重复推送上一批。

面板里已经有 B207 的“盯 X”，用 Cookie 调 X 接口，不支持列表。用户 2026-10-17 选了推文从 x-assistant 读，不扩展 B207。

## 要什么

- 新页面“资讯”，地址 `/feeds`，放在左栏“个人”分组里，排在“稍后读”后面。两个标签页：“新闻”和“推文”。
- 数据不复制到面板。每次打开页面，面板经过虚拟机上的面板代理，去请求虚拟机本机的一个只读小接口。
- 新闻列表：
  - 按抓取时间倒序，一页 50 条，往下滚动加载更多。
  - 每条显示：中文标题（没有就用原标题）、中文摘要（没有就用原摘要，最多 3 行）、来源、分类、重要度、标签、时间、有没有推过 Telegram。
  - 筛选：关键词、标签、分类、时间（今天、7 天、30 天、全部）、只看重要的（`importance` ≥ 4）、只看推过的。筛选条件写进地址栏，刷新后还在。
- 新闻详情：照“稍后读”的做法，桌面上列表旁边显示详情，手机上进单独一页。
  - 显示标题、来源、原文链接、标签。
  - 有正文时显示正文，有译文时可以切换“译文 / 原文”，默认显示译文。配图按 `public_url` 显示。
  - 正文还没抓到时，显示“正文还没抓取”，只给原文链接。
  - 按钮“存进稍后读”：调用面板已有的稍后读接口，存原文链接。
- 推文列表：
  - 按时间倒序，一页 50 条，往下滚动加载更多。
  - 每条显示：作者、时间、正文（保留换行，引用推文按原样显示）、“在 X 上打开”的链接。
  - 筛选：关键词、作者。
  - 推文也能“存进稍后读”。
- 设置页加“资讯”标签：
  - 选哪台机器（下拉框，列出已配对的代理）。
  - 接口地址，默认 `http://127.0.0.1:8790`。
  - 接口令牌，只能写不能读，加密存储。
  - “测试连接”按钮：显示新闻和推文的条数，以及最后一条的时间。
- 出错时页面要说清楚：
  - 没配置：提示去设置里选机器。
  - 机器不在线：显示“虚拟机不在线”和机器名字。
  - 接口没响应、令牌不对：分别给出提示。接口没响应时，提示用户检查 `x-console-feeds` 服务。

这次不做：首页卡片、早报里的新闻段、同步 Telegram 里 `/save` 的待研究列表、在面板里改新闻数据。

## 怎么做

### 虚拟机上的小接口（新目录 `deploy/feeds-api/`）

放在 x-console 仓库里。接口格式归面板管，用户的两个仓库只改最少的地方。

- `feeds_api.py`：只用 Python 标准库，再加 ai-news 已经装好的 `zstandard`。用 ai-news 的 `.venv/bin/python3` 运行。
- 只监听 `127.0.0.1`，端口默认 8790，用参数 `--listen` 可以改。
- 每个请求都要带 `Authorization: Bearer <令牌>`。令牌从环境变量 `XC_FEEDS_TOKEN` 读，用常数时间比较。令牌不对回 401。
- 新闻库用只读方式打开：`file:<路径>?mode=ro`，`busy_timeout` 设 5 秒。每个请求单独开连接。
- 有 `items_fts` 就用 FTS5 搜索，没有就退回 `LIKE`。关键词里的 FTS 特殊字符要转义，不能让用户输入改变查询语法。
- 推文：`collect.js` 把新推文追加写进 `tweets.jsonl`。小接口每次收到推文请求时，从上次读到的位置接着把新行导入自己的 `tweets.db`。`tweets.db` 放在 x-assistant 目录下，主键是推文编号，重复的跳过，表上建 FTS5 索引。坏掉的行跳过并记日志。
- 接口（都是 GET，返回 JSON）：

| 地址 | 参数 | 返回 |
| --- | --- | --- |
| `/v1/health` | 无 | `{news: {count, lastFetchedAt}, tweets: {count, lastAt}}` |
| `/v1/news` | `q`、`tag`、`category`、`days`、`minImportance`、`pushed`、`before`（上一页最后一条的 id）、`limit`（默认 50，最大 100） | `{items: [NewsItem], next}`，`next` 没有更多时为空 |
| `/v1/news/facets` | 无 | `{categories: [...], tags: [{tag, count}]}`，标签取最近 30 天最多的 50 个 |
| `/v1/news/{id}` | 无 | `NewsItem` 加上 `content: {status, markdown, markdownCn}` 和 `media: [{url, type, width, height}]` |
| `/v1/tweets` | `q`、`author`、`before`、`limit` | `{items: [Tweet], next}` |

- `NewsItem`：`id`、`title`、`titleCn`、`summary`、`summaryCn`、`url`、`source`、`category`、`tags`（数组）、`importance`、`pushed`（布尔）、`publishedAt`、`fetchedAt`。
- `Tweet`：`id`、`author`、`time`、`url`、`text`、`collectedAt`。
- 单个响应不超过 2 MB。正文太长时截断，并带上 `truncated: true`。代理的 `http.proxy` 上限是 8 MB。
- `x-console-feeds.service`：systemd 单元，`Restart=always`，令牌放在 `EnvironmentFile=/etc/x-console-feeds.env` 里，这个文件权限设成 0600。
- `README.md`：写清楚安装的几步，以及要给两个仓库做的改动。
- `collect.js.patch`：给 x-assistant 的补丁，改两处：
  1. 有新推文时，每条加上 `collectedAt`，追加写进 `tweets.jsonl`。
  2. 没有新推文时输出 `NO_NEW_TWEETS`，不再输出 `last_payload`。

  补丁由用户自己提交到 x-assistant。ai-news 不用改。
- 测试 `test_feeds_api.py`：用标准库 `unittest`，造一个和 ai-news 结构一样的临时库来测，包括没有 FTS5 的情况。CI 里加一步跑它。

### 服务端（新模块 `modules/feeds`）

- 设置存在模块自己的表里：`agent_id`、`base_url`、`token_enc`（用主密钥加密）。
- 照 `modules/homeassistant/agent.go` 的写法，用 `hub.Call` 发 `protocol.MethodHTTPProxy`，超时 15 秒。
- 浏览器请求面板的 `/api/v1/feeds/...`，面板转成对小接口的请求。只转发上面表里的那几个地址和参数。参数由面板自己按白名单拼，不把浏览器传来的地址原样转出去。
- 错误对应：
  - 没配置：409 `not_configured`。
  - 代理不在线：503 `agent_offline`，沿用现有的错误。
  - 小接口连不上：502 `feeds_unreachable`。
  - 小接口回 401：502 `feeds_unauthorized`。
- 改设置要二次验证（`auth.RequireElevated`），因为设置决定了面板通过代理访问哪个内网地址。`base_url` 只接受 `http://` 或 `https://` 开头的地址。代理那边本来就只允许私有地址。
- 测试用假代理和假小接口：正常翻页、筛选参数白名单、各种错误、令牌不回传给浏览器。

### 接口（新文件 `api/modules/feeds.yaml`）

- `GET /feeds/settings`、`PUT /feeds/settings`（令牌只写不读，返回 `hasToken`）、`POST /feeds/settings/test`。
- `GET /feeds/news`、`GET /feeds/news/facets`、`GET /feeds/news/{id}`、`GET /feeds/tweets`，参数和返回照上面的表。

### 数据库

- 一个迁移，只建 `feeds_settings` 表，单行。

### 前端（新目录 `features/feeds`）

- 复制“稍后读”的页面来改：列表照 `ReadLaterPage.tsx`，详情照 `ReadDetail.tsx` 和 `ReadingBody.tsx`。空状态和出错用 `components/ui/States.tsx`，按 `docs/07-design.md` 做。
- 正文用 `components/markdown/Markdown.tsx` 渲染。外链都在新标签页打开。图片懒加载。
- 设置标签加在 `features/settings/tabs.tsx`，只加行。

## 做成的样子（2026-10-17）

和上面写的不一样的地方：

- 页面没有“新闻”“推文”两个页签。设计规范要求二级菜单里有的，页面里不再放一份。新闻在 `/feeds`，推文在 `/feeds/tweets`，从二级菜单切换。二级菜单还列出最近 30 天最多的 20 个标签，只在新闻页显示。
- 新闻详情照稍后读做成宽弹窗，地址里带 `?item=<编号>`，手机上按返回能关掉。
- 搜索：只由字母和数字组成的词走 FTS5，按词首匹配；含汉字或标点的词用 LIKE 找子串。FTS5 默认分词不会切开连着的汉字，搜“模型”找不到“大模型发布”。FTS 查询出错时自动退回 LIKE。用户输入始终当字面量。
- 新闻按 `id` 倒序翻页，ai-news 里 `id` 的顺序就是抓取顺序。推文按推文编号倒序，编号就是发布顺序。“今天”是最近 24 小时。
- 测试连接用已经保存的设置，所以要先保存再测试，测试不用二次验证。保存时必须有令牌。
- `collect.js.patch` 在 `--baseline` 模式下也写 `tweets.jsonl`。打补丁之前见过的推文不会补进来。
- CI 加了单独的 `feeds-api` 任务跑小接口的测试。`scripts/ci-scope.sh` 里只改 `deploy/feeds-api/` 时不跑后端和前端检查，`scripts/check-quick.sh` 改了它时跑 Python 测试。
