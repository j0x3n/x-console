# B30 一条命令添加服务器，“本机”改名“电脑”，Windows 客户端

用户要求（2026-09-28）：

- 服务器怎么通过一条命令添加内网的服务器？
- 监听脚本（代理）资源占用够低吗？
- “本机”改为“电脑”，也是运行一个 Windows 客户端就自动连上面板。

## 现在的情况

- 加一台服务器要：在设置里生成配对码，自己编译代理，复制到服务器，手动 `pair`，再装 systemd 服务。步骤多，要有 Go 环境。
- 代理是**主动连面板**的（WebSocket）。内网机器只要能访问面板地址就能接入，不用开端口，不用内网穿透。
- Windows 有 `deploy/install-agent-windows.ps1`，同样要自己编译。
- 镜像里只有面板所在平台的一个代理（B1 自动安装本机代理用）。
- 代理资源占用：设计上平时 30 秒采一次概要，没人看详情时不传详细数据。没有实测过。

## 前端（已完成，提交 B30）

- “本机”改名“电脑”：侧边栏、左上角标题、空状态。英文键从 `This PC` 换成 `Computer`。路由 `/pc` 不变。电脑详情的左上角显示“电脑 / <电脑名>”，去掉了副标题。多台电脑时仍用顶栏里的下拉切换。
- 设置 → 设备与代理的“添加设备”弹窗（`features/settings/DevicesTab.tsx`）：
  - 填名称、选“Linux 服务器”或“Windows 电脑”，生成配对码（要提升权限，沿用现有接口）。
  - Linux 显示一条命令：`curl -fsSL "<面板>/api/v1/agent/install.sh?code=XXXX" | sudo sh`，带“复制”按钮，下面有卸载命令。
  - Windows 显示 PowerShell 命令 `irm "<面板>/api/v1/agent/install.ps1?code=XXXX" | iex`，和“下载安装程序”（`/api/v1/agent/setup.exe?code=XXXX`）。
  - “手动安装”展开后是原来的 `pair` 命令，给不能用一键脚本的情况。
  - 弹窗开着时每 3 秒刷新设备列表，出现新设备就显示“<名字> 已连接”和“打开”按钮。
  - 服务器页顶栏的“添加服务器”、电脑页和 Agent 任务的空状态都带 `?add=server` 或 `?add=desktop` 跳过来，直接打开弹窗并选好类型。
- 前端用到的地址都在契约里；后端没做之前，命令会拿到 501。手动安装一直能用。

## 契约

`api/modules/core.yaml`：`/agent/install.sh`、`/agent/install.ps1`、`/agent/uninstall.sh`、`/agent/download/{os}/{arch}`、`/agent/setup.exe`。现在由 `core/pending.go` 回 501。

## 后端（待做，给开发者）

### 1. 镜像里带上各平台的代理

- `deploy/Dockerfile` 编译 4 个代理：`linux/amd64`、`linux/arm64`、`windows/amd64`、`windows/arm64`（`CGO_ENABLED=0`，`-trimpath`，`-ldflags "-s -w -X main.version=<版本>"`），放在镜像的 `/usr/share/x-console/agents/<os>-<arch>/x-console-agent[.exe]`，同目录写 `SHA256SUMS`。
- 服务端配置加 `XC_AGENTS_DIR`，默认 `/usr/share/x-console/agents`；开发时没有这个目录，接口回 404“这个面板没有打包代理”。
- 构建时间会变长，可以用 `docker buildx` 的缓存（CI 里已经缓存了 Go 模块）。

### 2. 公开接口

- 这 5 个路径加到 `internal/server/app/app.go` 的 `corePublic`（`/agent/download/` 要按前缀匹配）。其余接口不变。
- 配对码校验：用现有的配对码表，只检查“存在、没过期、没用过”，**不要**在这里把码标记为用过（用过是在 `/agent/pair` 里）。无效时一律回 404，不说明原因。
- 限流：按 IP 每分钟 10 次，超出回 429。沿用登录接口的限流写法。
- `install.sh`：用 `text/template` 生成，写入面板地址（`d.Config.PublicURL`，没配置时用请求的 `Host` 和 `X-Forwarded-Proto`）和配对码。模板放在 `internal/server/core/agentinstall/install.sh.tmpl`，用 `embed` 打包。脚本内容：
  1. `set -eu`；不是 root 时提示用 `sudo` 并退出。
  2. `uname -m` 判断架构（`x86_64 → amd64`、`aarch64|arm64 → arm64`，其他报错退出）。
  3. 用 `curl -fsSL` 下载 `/api/v1/agent/download/linux/<arch>?code=...` 到临时文件，用响应头或 `SHA256SUMS` 校验。
  4. `install -m 0755` 到 `/usr/local/bin/x-console-agent`。
  5. 已有 `/etc/x-console-agent/config.json` 时跳过配对（升级场景），除非带 `--repair`；否则 `x-console-agent pair --server <面板> --code <码> --config /etc/x-console-agent/config.json`，配置文件权限 600。
  6. 写 `/etc/systemd/system/x-console-agent.service`（内容和 `deploy/x-console-agent.service` 一致，并加 `MemoryMax=128M`、`CPUQuota=20%`、`Nice=10`），`systemctl daemon-reload && systemctl enable --now x-console-agent`。没有 systemd 时打印手动启动命令并以非零退出。
  7. 等 10 秒内 `systemctl is-active` 为 active，打印“已连接到面板”。
- `uninstall.sh`：停止并删除服务、删 `/usr/local/bin/x-console-agent` 和 `/etc/x-console-agent/`。
- `install.ps1`：和 `deploy/install-agent-windows.ps1` 的逻辑一样，只是改成从面板下载代理，写好面板地址和配对码。安装到 `%LOCALAPPDATA%\x-console-agent\`，用任务计划程序登录时启动。
- `download/{os}/{arch}`：带有效配对码或者已登录才能下。`Content-Disposition: attachment`，响应头 `X-Checksum-Sha256`。
- `setup.exe`：返回 windows/amd64 的代理，文件名 `x-console-agent-setup-<码>.exe`。在文件末尾追加一段数据：`\nXC-SETUP:` 加 JSON `{"server":"<面板地址>"}`（PE 文件末尾追加数据不影响运行）。

### 3. 代理的安装模式（Windows）

- 代理启动时如果没有子命令，并且自己的文件名匹配 `x-console-agent-setup-([A-Z0-9-]+)\.exe`，进入安装模式：从文件名取配对码，从文件末尾读 `XC-SETUP:` 后的面板地址；复制自己到 `%LOCALAPPDATA%\x-console-agent\x-console-agent.exe`，配对，注册任务计划，启动，弹一个系统消息框说“已连接到面板”。
- 文件名里没有配对码时，弹一个输入框（用 PowerShell 的 `Read-Host` 或 Windows API 的简单对话框）让用户填面板地址和配对码。
- 托盘图标、自动更新放到后面单独的任务（记到 `docs/tasks.md` 的“已知问题”），这次先保证一键装好能连上。

### 4. 资源占用

- 在一台 1 核 1 GB 的 Linux 机器上实测，写进 `docs/06-deploy.md`：代理空闲（没人看详情）时的常驻内存和平均 CPU，打开详情 1 秒刷新时的平均 CPU。
- 目标：空闲常驻内存不超过 30 MB，平均 CPU 不超过 0.5%（单核）；1 秒刷新时不超过 2%。达不到就查原因（比如每次采样都重新读 `/proc` 下的大文件、没复用缓冲区）。

### 5. 测试

- 公开接口：无效码 404、过期码 404、有效码 200 且脚本里有面板地址和码；第 11 次请求 429；这些路径不登录也能访问，其他接口仍然要登录。
- `install.sh` 用 `shellcheck` 检查，加进 CI。
- 代理：`setup` 文件名解析、末尾数据读取的单元测试（Windows 专用的部分只做交叉编译）。

## 验收

- 一台干净的 Debian（amd64）和一台 arm64 机器，各执行一条命令，1 分钟内出现在服务器列表，添加弹窗里显示“已连接”。
- 重复执行命令只升级，不产生第二条记录。用过的配对码再执行，回 404。
- 在一台 Windows 上分别用 PowerShell 命令和安装程序各装一次，重启后自动连上。Windows 部分 CI 测不了，用户验收时在自己电脑上试。
