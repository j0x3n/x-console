# B91 网页推送的图标

用户 2026-10-02 提的：

- 网页推送自定义图标，只针对 Windows 和 Android 上的 Chrome/Edge：按通知类型显示图标；提醒和习惯可以按条目设图标，比如喝水显示水滴；Android 用单色 badge；以及服务端动态生成图标，比如喝水进度环。

## 现状

`web/public/sw.js` 里所有推送都用同一个 `icon-192.png` 做 `icon` 和 `badge`。Android 的 badge 只看透明度，所以现在状态栏里是一个白色方块。

## 怎么做

### 推送内容（后端）

Web Push 的内容加三个字段，旧的 sw 不认识也不影响：

| 字段 | 意思 |
| --- | --- |
| `icon` | 大图标地址。按下面的顺序选 |
| `badge` | Android 状态栏的单色小图标地址 |
| `image` | 可选，大图（暂时不用） |

`icon` 的选择顺序：

1. 条目自己的图标：习惯和提醒有 `icon`（emoji 或图标名），服务端把它画成 192×192 的 PNG（彩色底、白色图案）。
2. 动态图标：习惯的提醒画成进度环（今天完成了几成，比如喝水 3/8），中间是习惯的图标。
3. 通知类型的图标：按 kind 前缀选一张固定的图，例如 `host.alert` 服务器、`monitor.` 监控、`mail.` 邮件、`github.`/`repo.` 仓库、`ai_agent.` Agent、`weather.` 天气、`reminder.` 提醒、`habit.` 习惯、`brief.` 早报。
4. 都没有时用应用图标。

`badge` 按通知类型选单色图（白色图案、透明底，96×96）。

### 图标地址

- 推送通知的图片是浏览器在后台取的，可能不带登录状态。所以图标接口不要求登录，地址里带签名：`/api/v1/notify/icons/<名字>.png?sig=<HMAC>`，名字是 `kind-server`、`emoji-1f4a7`、`habit-12-progress-3-8` 这一类，签名用服务端密钥算，防止被人拿来随便画图。
- 生成的 PNG 按名字缓存在内存里（最多几百张），响应头 `Cache-Control: public, max-age=86400`。
- 固定的类型图标和 badge 可以直接放在 `web/public/icons/notify/` 下，不用签名。

### sw.js（前端）

- `icon` 用推送里的 `icon`，没有时用应用图标；`badge` 用推送里的 `badge`，没有时用新加的单色 `badge-96.png`。
- 只在 Windows 和 Android 上用自定义图标（`navigator.userAgent` 判断）。macOS、iOS 的通知不显示这个图，不要去取，省流量。
