# B46 项目改成多看板：参照 Planka 和 Trello

用户 2026-09-30 提出：B36 的“二级分类”理解错了。用户要的是 Planka 那样的结构：一个项目里有多个看板（截图里项目“台球厅经理”下面有“开发进程”“游戏设计”两个看板页签），每个看板有自己的列表和卡片。功能参照 Trello 补全。虽然不是多人协作平台，但要配合多个 Agent 一起干活（B47），卡片的“成员”就是 Agent。

## 和现在的区别

| | 现在 | 改成 |
| --- | --- | --- |
| 层级 | 项目 → Issue | 项目 → 看板 → 列表 → 卡片 |
| 看板的列 | 固定 6 个状态（待规划、待办、进行中……） | 每个看板自己建列表，名字、数量、顺序随意 |
| 分类 | B36 的两级分类 | 不要了，用看板和标签代替 |
| 成员 | 没有 | “我”和 Agent（B47） |

界面上 “Issue” 改叫“卡片”，编号 `XC-12` 保留。接口和代码里仍叫 `issue`，不改名（和“编码任务”改名“Agent 任务”的做法一样）。

## 1. 数据

- 新表 `project_boards(id, project_id, name, icon, position, starred, archived_at, created_at, updated_at)`。`icon` 存一个 emoji。
- 新表 `board_lists(id, board_id, name, position, status, color, wip_limit, collapsed, archived_at, created_at)`：
  - `status` 可以为空，也可以是原来 6 个状态之一。卡片拖进这个列表时，卡片的 `status` 改成它。空表示不改状态。
  - `wip_limit` 为 0 表示不限。超过时列表标题变 `warning` 颜色，不阻止拖入。
- `issues` 加列 `board_id`、`list_id`、`archived_at`、`cover_file_id`。`sort_order` 继续表示列表内顺序。
- 新表 `issue_members(issue_id, member_kind, member_id)`：`member_kind` 是 `me` 或 `agent`（B47 的 Agent id）。
- 新表 `issue_activity(id, issue_id, at, actor, kind, data)`：移动、改标题、改截止时间、加减成员、勾清单、Agent 开始和结束任务都记一条。`actor` 是 `me`、`agent:<id>`、`token:<名字>`（B43）、`automation:<id>`。
- 迁移：每个项目建一个默认看板“看板”，按原来 6 个状态建 6 个列表（名字用原来的中文名，`status` 对应），已有的 Issue 按状态放进对应列表。迁移只加不删。
- B36 的分类：`project_categories` 和 `issues.category_id` 保留，接口和界面不再使用，下个版本删。

### 状态和列表的关系

- 拖卡片到有 `status` 的列表：改状态。
- 从外面改状态（Linear 同步、PR 合并、Agent、MCP 调 `update_issue`）：如果卡片当前列表的 `status` 和新状态不一样，把卡片移到同一个看板里第一个 `status` 等于新状态的列表的底部。没有这样的列表就不动。
- 完成率、到期提醒、早报、提醒页汇总（B37）照旧按 `status` 算，不用改。

## 2. 接口

在 `api/modules/projects.yaml` 加：

- 看板：`GET/POST /projects/{id}/boards`，`PATCH/DELETE /boards/{id}`，`POST /boards/{id}/move`（排序），`POST /boards/{id}/copy`（复制结构，可选带卡片）。
- 列表：`GET/POST /boards/{id}/lists`，`PATCH/DELETE /lists/{id}`，`POST /lists/{id}/move`，`POST /lists/{id}/archive-cards`（归档列表里全部卡片）。
- 看板数据：`GET /boards/{id}/full` 一次返回列表、卡片摘要（标题、编号、标签、成员、截止时间、清单进度、评论数、附件数、封面）、标签，用于首屏。
- 卡片：`POST /issues/{id}/move`（`boardId`、`listId`、`beforeId`、`afterId`，可以跨看板、跨项目，跨项目时换编号），`POST /issues/{id}/copy`，`POST /issues/{id}/archive`、`/restore`，`PUT /issues/{id}/members`，`GET /issues/{id}/activity`。
- 归档：`GET /boards/{id}/archive` 列出归档的卡片和列表，可以恢复或彻底删除（`useConfirm`）。
- 原来的 `GET /projects/{id}/issues` 保留，加 `boardId` 过滤。
- 动作注册表（给 AI 和 B43 用）补上：`projects.list_boards`、`projects.get_board`、`projects.create_card`（按看板和列表名建）、`projects.move_card`、`projects.comment`、`projects.add_checklist_item`、`projects.check_item`。`create_issue` 和 `update_issue` 加 `boardId`、`listId`。
- 事件：`board.changed`、`issue.moved`，前端据此刷新。

## 3. 界面

按截图的布局：

- 项目页顶部：返回、项目名。下面一行是看板页签，每个页签前面是 emoji 图标，最后一个是“+”新建看板。页签可以拖动排序，右键或长按有改名、换图标、复制、归档。
- 看板工具栏（一行，手机上可以横向滑动）：
  - 星标按钮：标星的看板出现在侧边栏“项目”下面（替换 B36 的分类子菜单，`registerNavChildren`，最多 8 条）。
  - 成员头像：“我”加上被分配到这个看板卡片上的 Agent。后面是“添加成员”按钮，从 B47 的 Agent 里选（B47 没做之前只有“我”，按钮不显示）。
  - 成员筛选、“只看我的”、标签筛选、搜索框、截止时间筛选（今天、7 天内、已过期、没有截止时间）。筛选条件写进网址，刷新后保留。
  - 右边“更多”：归档内容、看板设置（列表对应的状态）、复制看板。
- 列表：横向排列，宽 272px。标题可以直接点击改名。标题右边是卡片数量，有 WIP 上限时显示 `3/5`。“更多”菜单：改颜色、设 WIP 上限、对应状态、折叠、把全部卡片移到别的列表、归档全部卡片、归档列表。最右边是“添加列表”。
- 卡片（在看板上）：封面图、标签色条、标题、编号，下面一行小图标：截止时间、描述、评论数、附件数、清单进度、Agent 头像。Agent 正在处理时头像上有一个转圈的小标记。
- 列表底部“添加卡片”：输入标题回车就建，连续输入可以连续建。
- 卡片详情（弹窗，手机上全屏）：标题、所在看板和列表（可以点击改）、成员、标签、截止时间、描述（`MarkdownEditor`，可以贴图）、检查清单（B36 已有）、附件（上传、设为封面、删除）、关联（PR、Agent 任务、笔记）、评论和活动记录（一个时间线，可以切“只看评论”）。右边一列操作：移动、复制、归档、分配给 Agent（B47）、删除。
- 拖动：卡片可以在列表内、列表间、拖到页签上换看板；列表可以左右拖。手机上长按 300ms 开始拖动（去掉“已知问题”里“看板拖动只支持桌面”这一条）。
- 快捷键（桌面）：`N` 在第一个列表新建卡片，`F` 聚焦搜索，`Q` 只看我的，在卡片上按 `E` 编辑、`L` 改标签、`D` 改截止时间、`C` 归档、`Space` 分配给自己。已有的 `useShortcuts` 上加。
- 原来的“列表视图”保留，作为看板页签右边的一个切换按钮，按列表分组显示同一批卡片。
- B36 做的分类选择、分类筛选、按分类分组都去掉。

## 验收

- 迁移测试：旧数据库迁移后，每个项目有一个看板、6 个列表，Issue 都在对应列表里，数量不变。
- 拖到有状态的列表会改状态；外部改状态会移动卡片；没有对应列表时不动。
- 跨项目移动卡片换编号，原项目的编号不复用。
- 归档的卡片不出现在看板上，也不出现在提醒页汇总里；恢复后回到原列表（原列表删了就回第一个列表）。
- 活动记录：每种操作都有一条，actor 正确。
- 动作注册表的新动作有测试。端到端测试补一条：新建看板、建两个列表、建卡片、拖到另一个列表、打开详情加清单。
