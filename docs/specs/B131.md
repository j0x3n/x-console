# B131 专注时屏蔽分心网站和程序

2026-10-11 用户要求做。来源是 [B127-B139-建议](B127-B139-建议.md) 第 8 条。

## 要什么

番茄钟开始专注时，让选定的电脑：

- 把名单里的网站在 hosts 文件里指向本机。
- 把名单里的程序结束，专注期间每隔几秒检查，又启动了就再结束。

专注结束、被停止或超时后，恢复原状。

## 怎么做

- 服务端模块 `focusblock` 订阅番茄钟事件（`focus.started`、`focus.stopped`、`focus.done`），告诉每台选中的代理现在该屏蔽什么。代理自己改 hosts 和结束程序。
- 协议在 `pkg/protocol/methods_focusblock.go`：`focusblock.apply`（开始或续期）、`focusblock.clear`、`focusblock.status`。能力名 `focusblock`。
- 代理包 `internal/agent/focusblock`：
  - hosts 只改自己的标记块，原内容保留，先写临时文件再替换。
  - 状态存在代理本地文件里，代理重启后继续按截止时间执行，已过期就清理。
  - 清理失败会每 30 秒重试。
  - 服务端给的截止时间是专注预定结束时间。代理在截止时间后 5 分钟仍没收到停止指令，自己恢复。
- 设置键 `focusblock.settings`：总开关、选哪些电脑、网址名单、程序名单、是否屏蔽 IPv6、休息时是否也屏蔽（默认不屏蔽）、专注开始和结束时要触发的 Home Assistant 场景或脚本（可选）。
- 电脑时间里分成“娱乐”类的应用可以一键导入程序名单（`GET /focus-block/suggestions`，数据来自 `screentime`）。
- 设置 → 专注屏蔽页签配置；番茄钟页上显示“屏蔽中”的小标，每台电脑显示状态：已生效、权限不足、离线。
- 改设置要先验证密码（`auth.RequireElevated`）。

## 安全

- 程序名单只匹配进程名，不匹配路径。内置一份拒绝名单，名单里的系统关键进程（Windows 的 System、csrss、winlogon、explorer 等，Linux 的 init、systemd 等）永远不会被结束，写进设置也会被拒绝。
- 面板自己的地址、代理连的服务器地址不会被屏蔽，避免把代理自己断掉。
- 名单有上限：200 个网址、100 个程序、一次最长 6 小时。
- 没有管理员或 root 权限时 hosts 写不进去。代理明确报告“权限不足”，设置页显示，不静默失败。程序结束不需要管理员权限，权限不够时只对自己能结束的进程生效。

## 默认做法

- 休息期间放开屏蔽。
- 默认只处理 IPv4（127.0.0.1），IPv6（::1）要手动打开。
- Home Assistant 场景是可选项，没配就不触发。

## 没有验证的

- 没在真实 Windows 机器上跑过。Windows 构建和 `go vet` 通过，hosts 编辑逻辑用临时文件测试。
- 浏览器开了“安全 DNS”（DoH）时可能绕过 hosts，屏蔽不生效。设置页有说明，要用户在浏览器里关掉。
- 只管电脑，管不到手机。
- 刷新 DNS 缓存的命令（Windows 的 `ipconfig /flushdns`）没在真机验证。

## 验收

- 开始番茄钟后，选中的电脑 hosts 里出现标记块，名单里的程序被结束。结束番茄钟后标记块消失。
- 代理重启、服务端宕机后，到截止时间加 5 分钟，hosts 自己恢复。
- 拒绝名单里的程序不能加进名单。
- 全部相关后端和前端测试通过，Windows 构建通过。
