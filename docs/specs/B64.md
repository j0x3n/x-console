# B64 服务器支持 Unraid

用户 2026-10-01 问：服务器怎么支持 Unraid。

**开工前和用户确认**：按“服务器的一种安装方式”做（本文的方案）。用户还没回复，2026-10-01 Claude 的建议是这样。

前后端都待做，以后端和安装脚本为主。

## 问题

- Unraid 是 Linux（基于 Slackware），代理程序本身能跑。
- 现在的安装脚本 `backend/internal/server/core/agentinstall/install.sh.tmpl` 要求 systemd（第 66 行检查 `/run/systemd/system`），Unraid 没有 systemd，脚本会停在“请自己启动代理”。
- Unraid 的系统盘在内存里，每次开机都重置。只有 U 盘上的 `/boot` 会保留。装在 `/usr/local/bin` 的代理重启后就没了。

## 做法

### 1. 安装脚本识别 Unraid

在 `install.sh.tmpl` 里，检查 systemd 之前先判断是不是 Unraid：存在 `/etc/unraid-version` 就走 Unraid 分支。

Unraid 分支：

1. 代理和配置放在 U 盘上：`/boot/config/plugins/x-console-agent/`（`x-console-agent` 程序和 `agent.json` 配置）。配对时用 `--config /boot/config/plugins/x-console-agent/agent.json`。
2. 开机启动：在 `/boot/config/go`（Unraid 开机时执行的脚本）末尾加一段，用标记包起来，重复安装时先删掉旧的那段再加：

   ```sh
   # >>> x-console-agent >>>
   cp /boot/config/plugins/x-console-agent/x-console-agent /usr/local/bin/x-console-agent
   chmod 755 /usr/local/bin/x-console-agent
   nohup /usr/local/bin/x-console-agent run --config /boot/config/plugins/x-console-agent/agent.json \
     >> /var/log/x-console-agent.log 2>&1 &
   # <<< x-console-agent <<<
   ```

   U 盘是 FAT32，不能直接执行，所以开机时复制到 `/usr/local/bin` 再运行。
3. 安装完立刻按上面的命令启动一次，并检查进程起来了。
4. 卸载脚本（`uninstall.sh`）同样认 Unraid：结束进程，删掉 `/boot/config/go` 里那一段和 `/boot/config/plugins/x-console-agent/`。
5. 代理以 root 运行（Unraid 默认就是 root）。

### 2. 代理在 Unraid 上的差异

- 服务管理：Unraid 没有 systemd，代理的服务列表和启停功能在这台机器上不可用。代理启动时检测到没有 systemd，就不上报 `services` 能力（看 `internal/agent` 里能力上报的地方），前端的“服务”标签会自动不显示。
- 系统日志：没有 journald，读 `/var/log/syslog`。`internal/agent/syslog` 里已经有 `textlog.go`，检测时（`detect_linux.go`）没有 journal 就用它，确认 Unraid 上走得到。
- Docker：Unraid 的 Docker 是标准的，现有的容器功能直接能用。
- 额外信息（可选，第二步做）：读 `/var/local/emhttp/disks.ini` 和 `/var/local/emhttp/var.ini`，上报阵列状态（启动、停止、校验中）和每块盘的温度、状态。协议里加一个可选的 `unraid` 字段，旧服务端忽略。前端服务器详情的概览里，有这个字段时多一张“阵列”卡片。

### 3. 面板上的提示

- 设置 → 设备与代理 → 添加服务器的说明里加一句：“Unraid 也用同一条命令，在 Unraid 的终端里运行。代理装在 U 盘上，重启后自动启动。”

## 测试

- 安装脚本：用 shellcheck 检查；在一个没有 systemd、有 `/etc/unraid-version` 的容器里跑一遍（可以用 `slackware` 或普通 Alpine 镜像假装），检查 `/boot/config/go` 里加了那一段、重复跑只有一段。
- 代理：没有 systemd 时不报 `services` 能力的单元测试。

## 验收

- 在 Unraid 的终端里运行面板给的安装命令，服务器页出现这台机器，能看监控、进终端、看 Docker。
- 重启 Unraid 后自动连回面板。

## 实现时的调整（2026-10-01）

用户 2026-10-01 让直接做，按本文方案。

- 开机启动用一个启动脚本 `/boot/config/plugins/x-console-agent/run.sh`，`/boot/config/go` 里那一段只调它：`nohup sh '/boot/config/plugins/x-console-agent/run.sh' >/dev/null 2>&1 &`。启动脚本把程序复制到 `/usr/local/bin`，代理退出后 5 秒重启，退出码 3（被吊销）时不再重启。没有 systemd 时这样代替 `Restart=always`。
- 日志写 `/var/log/x-console-agent.log`。Unraid 的 `/var/log` 在内存里，空间小，每次重启代理前超过 1 MB 就换成 `.log.1`。
- Unraid 没有 sudo，设置里添加服务器时多给一条不带 sudo 的命令。
- 代理这边不用改逻辑：没有 `/run/systemd/system` 时本来就不报 `services` 能力，没有 journalctl 时本来就读 `/var/log/syslog`。补了这两条的单元测试。
- 安装脚本测试：`agentinstall/unraid_test.go` 在临时目录里假装 Unraid（环境变量 `XC_UNRAID_ROOT` 把 Unraid 的路径放到临时目录下，只给测试用），用假的 curl 和假的代理跑两遍安装、一遍卸载。
- 阵列状态和硬盘温度（可选的第二步）没做。
