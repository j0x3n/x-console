## 后端（待做，给开发者）

### 1. 天气强制刷新

契约：`api/modules/brief.yaml` 的 `/weather` 新增 `refresh` 参数（已生成，`api.GetWeatherParams.Refresh *bool`）。

- `modules/brief/weather.go` 的 `fetchWeather` 加一个参数 `force bool`。
- `force` 为 true 时：如果缓存里这个 key 的 `at` 在 1 分钟以内，仍然返回缓存（防止连点把 Open-Meteo 刷爆）；否则跳过缓存直接请求，成功后更新缓存。
- `GetWeather` 里把 `params.Refresh != nil && *params.Refresh` 传进去。别的调用（早报、降雨提醒）传 false。
- 测试：用现有的假天气服务器，连续两次 `refresh=true` 间隔小于 1 分钟只请求一次；把时间函数调过 1 分钟后再请求一次。现在模块里没有可替换的时间函数的话，加一个 `now func() time.Time`。

### 2. 订阅分类

契约：`api/modules/monitoring.yaml` 的 `/subscription-categories`、`/subscription-categories/{categoryId}`、`SubscriptionCategoryItem`、`SubscriptionCategoryInput`。现在由 `modules/monitoring/pending.go` 回 501。

迁移（新文件，比如 `20260929000100_b23_subscription_categories.sql`，时间要晚于最新迁移）：

```sql
CREATE TABLE subscription_categories (
    id         INTEGER PRIMARY KEY,
    name       TEXT    NOT NULL,
    builtin    TEXT,               -- server、domain、saas、other；用户自己加的为 NULL
    position   INTEGER NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL
);
CREATE UNIQUE INDEX subscription_categories_name ON subscription_categories (name);
CREATE UNIQUE INDEX subscription_categories_builtin ON subscription_categories (builtin) WHERE builtin IS NOT NULL;
INSERT INTO subscription_categories (name, builtin, position, created_at) VALUES
    ('服务器', 'server', 0, CURRENT_TIMESTAMP),
    ('域名',   'domain', 1, CURRENT_TIMESTAMP),
    ('软件',   'saas',   2, CURRENT_TIMESTAMP),
    ('其他',   'other',  3, CURRENT_TIMESTAMP);

ALTER TABLE subscriptions ADD COLUMN category_id INTEGER REFERENCES subscription_categories (id);
UPDATE subscriptions SET category_id = (SELECT id FROM subscription_categories c WHERE c.builtin = subscriptions.category);
```

- 旧列 `category` 保留（迁移只加不删），写入时继续写：分类有 `builtin` 就写它，没有写 `other`。
- 接口：
  - `GET`：按 `position, id` 排序，`count` 是这个分类下未归档的订阅数（一条 `LEFT JOIN ... GROUP BY`）。
  - `POST`：`name` 去掉首尾空格后 1 到 30 个字，重名回 409（`httpx.ErrConflict`，消息“已经有这个分类了”）。`position` 不传时放最后。
  - `PATCH`：可以改 `name` 和 `position`。默认分类也能改名（前端显示时，默认分类按 `builtin` 显示翻译后的名字，所以改名只影响英文界面以外的场景；这一点可以接受）。
  - `DELETE`：`builtin = 'other'` 的回 400“‘其他’不能删除”。其他分类：在一个事务里把这个分类下的订阅改到“其他”（`category_id` 和 `category` 都改），再删分类。
  - 增删改都发事件 `subscription.category_changed`（前端已经对 `subscription.` 前缀刷新）。
  - 审计：`subscription.category.create/update/delete`。
- `Subscription` 返回值加上 `categoryId` 和 `categoryName`（`JOIN subscription_categories`）。
- `SubscriptionInput`、`SubscriptionPatch` 带 `categoryId` 时以它为准，同时把 `category` 写成对应的 `builtin` 或 `other`；分类不存在回 400。只带旧的 `category` 时，按 `builtin` 找到 `category_id`。
- `CategorySpend` 加上 `categoryId`、`categoryName`，汇总按 `category_id` 分组。

### 3. 周期：每 N 个单位

契约：`Subscription`、`SubscriptionInput`、`SubscriptionPatch` 的 `cycleCount`、`cycleUnit`（`minute`、`hour`、`day`、`week`、`month`、`year`）。

迁移（和上面放同一个文件）：

```sql
ALTER TABLE subscriptions ADD COLUMN cycle_count INTEGER NOT NULL DEFAULT 1;
ALTER TABLE subscriptions ADD COLUMN cycle_unit  TEXT    NOT NULL DEFAULT 'month';
UPDATE subscriptions SET cycle_count = 1, cycle_unit = 'year' WHERE cycle = 'yearly';
UPDATE subscriptions SET cycle_count = cycle_days, cycle_unit = 'day' WHERE cycle = 'custom_days';
```

- 读：`cycleCount`、`cycleUnit` 直接返回。旧字段 `cycle`、`cycleDays` 也照样返回，由新字段换算：`1 month → monthly`，`1 year → yearly`，天和周换成 `custom_days` 加天数，其他组合返回 `custom_days` 和近似天数（月按 30 天，年按 365 天，分钟和小时按 1 天）。
- 写：请求里同时有 `cycleCount` 和 `cycleUnit` 时以它们为准，`cycleCount` 1 到 1000。只有旧字段时按上面的规则反推。
- 自动续期和“下一个续费日”的计算改用新字段。和前端 `lib.ts` 的 `addCycle` 保持一致：
  - 月、年按日历加，日子超过当月天数时取月末（1 月 31 日加 1 个月是 2 月 28 日或 29 日）。
  - 周是 7 天，天是 1 天。
  - 分钟、小时：`next_renewal` 只是日期，所以向上取整成天，至少 1 天。
- `monthlyCost` 按新字段折算：月 `amount / count`，年 `amount / (12 * count)`，周 `amount * 30.4375 / (7 * count)`，天 `amount * 30.4375 / count`，小时 `amount * 730.5 / count`，分钟 `amount * 43830 / count`。
- 续费提醒（`remind_days_before`）逻辑不变。

### 4. 测试

- 迁移测试：旧数据的 `monthly`、`yearly`、`custom_days 14` 迁移后 `cycleCount/cycleUnit` 分别是 `1 month`、`1 year`、`14 day`，`category_id` 对应上。
- 周期计算的表格测试，至少包括前端 `lib.test.ts` 里的那些用例，结果要一致。

- 旧前端兼容：只发 `cycle: monthly` 和 `category: server` 仍然能创建，返回里新旧字段都对。
