# B34 浏览器推送自检和后台通知

需求见 `docs/tasks.md` 的“B34 浏览器推送自检和后台通知”。这里写做法。

## 前端（已完成）

2026-09-29 做完，分支 `claude/project-thread-o3tsew`。都在 `features/reminders/NotificationsTab.tsx` 的“浏览器推送”卡片里。

- 订阅列表：每个浏览器一行，写设备名（前端从 User-Agent 看出浏览器和系统，比如“Edge · Windows”）、推送服务、上次送达时间、上次的错误。现在这个浏览器有“这个浏览器”标记。每行可以删除，删除前确认。后端没上线时还是只显示订阅数量。
- 有谷歌推送服务的订阅（或者现在这个浏览器用的是谷歌）时，显示一句“国内网络可能收不到，可以换 Edge 或 Safari”。
- “发测试消息”分两步显示：
  1. 本机检查：页面直接调 `registration.showNotification` 弹一条本地通知，不经过服务器。浏览器拦截、还没开启、不支持时各写一句原因。弹了的话，再按系统（Windows、macOS、Android、iPhone）写一句怎么在系统里打开通知，因为系统关了通知时浏览器也不知道。
  2. 服务器推送：调 `POST /notify/webpush/test`，每个订阅一行，写推送服务和结果。接口没上线时退回旧的渠道测试，只写“测试消息已发出”。
- 可以展开的说明“关掉面板还能收到吗”：浏览器要在后台运行；iPhone 要 iOS 16.4 以上并从主屏幕打开；安卓 Chrome 要谷歌服务；想更稳可以同时开 Bark 或 Telegram。
- `public/sw.js` 的通知图标和角标从 `favicon.svg` 改成 `/icons/icon-192.png`。

## 契约

`api/modules/reminders.yaml`：

- `GET /notify/webpush/subscriptions`：`WebPushSubscriptionInfo[]`，字段 `id`、`endpoint`、`service`（`google | microsoft | mozilla | apple | other`）、`userAgent`、`createdAt`、`lastOkAt`、`lastError`、`lastErrorAt`。
- `DELETE /notify/webpush/subscriptions/{subscriptionId}`：按 id 删除。原来按 `endpoint` 删除的接口保留，页面“关闭推送”还在用。
- `POST /notify/webpush/test`：`WebPushTestResult[]`，每个订阅一条：`id`、`service`、`ok`、`status`（推送服务的 HTTP 状态码）、`error`。
- `modules/reminders/pending.go`：这三个先回 501。

## 后端（待做，给开发者）

都在 `modules/reminders/`。

### 1. 迁移

```sql
-- +goose Up
ALTER TABLE webpush_subscriptions ADD COLUMN last_ok_at DATETIME;
ALTER TABLE webpush_subscriptions ADD COLUMN last_error TEXT;
ALTER TABLE webpush_subscriptions ADD COLUMN last_error_at DATETIME;
```

文件名 `YYYYMMDDHHMMSS_m7_b34_webpush_status.sql`，时间晚于当时最新的迁移。

### 2. 记录每次推送的结果

- `delivery.go` 的 `sendOne` 改成返回 `(status int, err error)`。推送服务回 2xx 时写 `last_ok_at = now`，清空 `last_error`。失败时写 `last_error`（状态码和原因，比如 `403 Forbidden`、`连接 fcm.googleapis.com 超时`，最长 200 字）和 `last_error_at`。404 和 410 照旧删除订阅。
- 连接错误把 `url.Error` 里的原因写成中文短句：超时写“连接 <域名> 超时”，DNS 失败写“解析不了 <域名>”，连接被拒写“<域名> 拒绝连接”。其他写原始错误。
- 写库用 `context.WithoutCancel`，推送成功了但请求被取消时也要记下来。

### 3. 接口

- `service` 按 `endpoint` 的域名判断，写一个纯函数 `pushService(endpoint)`，规则和前端 `push.ts` 的一样：`fcm.googleapis.com` 和 `*.googleapis.com` 是 google，`*.notify.windows.com` 是 microsoft，`*.mozilla.com`、`*.mozaws.net` 是 mozilla，`*.push.apple.com` 是 apple。
- `GET` 列表按 `created_at` 倒序。
- `DELETE` 按 id：不存在回 404。审计 `notify.webpush.unsubscribe`，发 `notify.channel_updated`。
- `POST /notify/webpush/test`：对每个订阅并发发一条测试推送（最多 5 个一起），每个 15 秒超时，按上面的规则更新状态，返回每个的结果。没有订阅时回空数组。这个接口不走通知路由和免打扰，直接发。审计 `notify.webpush.test`。

### 4. 测试

- 用 `httptest` 起一个假的推送服务：回 201 时 `last_ok_at` 有值；回 403 时 `last_error` 是 `403 Forbidden`；回 410 时订阅被删除。
- `pushService` 表驱动测试，和前端的用例一样。
- 测试接口返回每个订阅的结果，一个成功一个失败时两个都在。
