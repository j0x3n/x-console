# B143 稍后阅读：读取 X 推文和完整图文保存

用户 2026-10-10 提出。在 B117（稍后读）上加两件事：

1. 存 X（Twitter）推文链接时，能读到推文内容。可以用用户提供的 Cookie，也可以用别的办法。
2. 页面存档要带图片。网页和推文都是，原链接失效以后还能完整地看。

## 现状和问题

- B117 抓取用 `go-readability`，只存纯文本（`content`），不存图片和排版。
- X 的页面要执行脚本才有内容，直接 GET 只拿到空壳。现在存推文链接会得到“抓取失败”或只有站点名。
- 纯文本里的图片全丢了。推文几乎都是图。

## 要什么

### A. 读取推文

识别 `x.com`、`twitter.com`、`mobile.twitter.com` 下的 `/用户名/status/数字` 和 `/i/status/数字`。网址整理时对这几个站点额外去掉 `s`、`t` 参数（分享时 X 自己加的）。

读取按下面的顺序，前一个成功就不再往下：

1. **公开接口**（不用登录）：`cdn.syndication.twimg.com/tweet-result?id=…&token=…`。能拿到作者、发布时间、文字、图片、视频封面、引用的推文。
   - 限制：很长的推文（长文）可能被截断。受保护账号、年龄限制内容拿不到。这个接口不是 X 的正式接口，随时可能改。
2. **用户的 X 登录 Cookie**（设置里填 `auth_token` 和 `ct0`）：调网页端用的 GraphQL 接口 `TweetResultByRestId`，拿到完整长文和需要登录才能看的内容。同一作者的串推用 `TweetDetail` 补全。
   - 限制：接口的 `queryId` 和 `features` 经常变，放进设置里可改，不写死。违反 X 的服务条款，账号有被限制的可能，建议用小号。
   - 只有公开接口失败或内容被截断时才用，减少用到 Cookie 的次数。
3. **第三方转换服务**（`api.fxtwitter.com`）：默认关闭。打开后第 1、2 步失败时才用。推文链接会发给这个第三方。

三步都失败，状态是“抓取失败”，原因里写是哪一步、为什么（比如 Cookie 过期、推文已删除、账号受保护）。

### B. Cookie 的保存

- 在“设置 → 稍后读”填 `auth_token` 和 `ct0`。用 `Secrets` 加密存储，接口不返回明文，只返回“已配置”和最后一次验证的时间。
- 保存和清除都要 `auth.RequireElevated`，记审计（不记 Cookie 内容）。
- Cookie 只发往 `x.com` 和 `api.x.com`。不写日志，不进错误信息，重定向到别的域名时不带。
- 有“测试”按钮：用 Cookie 读一条固定的公开推文，成功就记下验证时间，失败显示原因（401、403、接口改版）。
- 抓取时遇到 401 或 403，把设置里的状态改成“Cookie 可能过期”，并发一条通知（最多一天一次）。

### C. 完整图文保存

对所有网页都做，不只推文：

- 抽取正文时同时保存清理过的 HTML（`content_html`），保留段落、标题、列表、引用、代码块、表格、图片、链接。去掉脚本、样式、事件属性、`iframe`、表单。服务端清理一次，前端显示前再用 DOMPurify 清理一次。
- 抓取时下载正文里的图片，存进 `Files.For("readlater")`，键为 `{条目id}/{图片内容的哈希}`。HTML 里的 `img` 地址改成 `/api/v1/readlater/{id}/assets/{哈希}`，需要登录才能看。
  - 用同一个防内网的客户端下载。单张最多 10 MB，一个条目最多 50 张、合计 50 MB，超过的保留原图地址。
  - 只收 `image/*` 类型。SVG 不收（可能带脚本）。
  - 推文的图片取原图尺寸（`name=orig`），头像取普通尺寸。
- 推文渲染成统一的 HTML：作者头像、名字、@用户名、发布时间、全文、图片、引用的推文、串推按顺序排。视频只存封面图和视频的原链接，不下载视频。
- 详情弹窗加“阅读”标签页，显示存档的 HTML。原有的纯文本保留，用于搜索。
- 加“导出”：下载单个 HTML 文件，图片内联成 data URI，离线能打开。
- “重新抓取”会重新下载图片。删除条目时一并删除图片文件。
- 旧条目只有纯文本，不自动补。用户点“重新抓取”才补。

## 数据

迁移 `20261010xxxxxx_m17_b140_readlater_archive.sql`，只加不删：

- `read_items` 加列：`content_html TEXT NOT NULL DEFAULT ''`、`kind TEXT NOT NULL DEFAULT 'page'`（`page`、`tweet`）、`meta_json TEXT NOT NULL DEFAULT '{}'`（作者、发布时间、点赞数、抓取用的是哪一步）。
- 新表 `read_assets`：`item_id`、`hash`、`mime`、`size`、`src_url`、`created_at`，主键 `(item_id, hash)`。
- 设置项（`Settings`）：`readlater.x.cookie`（加密）、`readlater.x.query_id`、`readlater.x.fxtwitter`（开关）、`readlater.x.verified_at`。

## 接口

改 `api/modules/readlater.yaml`：

- `ReadItem` 加 `kind`、`meta`、`has_html`。详情带 `content_html`，列表不带。
- `GET /readlater/{id}/assets/{hash}`：图片。`Cache-Control: private, max-age=31536000, immutable`。
- `GET /readlater/{id}/export`：单文件 HTML。
- `GET /readlater/x-auth`：返回 `{configured, verified_at, status}`。
- `PUT /readlater/x-auth`：保存 Cookie，要提权。
- `DELETE /readlater/x-auth`：清除，要提权。
- `POST /readlater/x-auth/test`：测试。
- 隐藏内容锁着时，上面这些都跟 `/readlater` 一样回 404。

## 验收

- 存一条公开推文链接，几秒后出现作者、全文和图片。图片地址是本站的，断网也能显示。
- 没填 Cookie 时，长推文被公开接口截断，状态里写明“内容可能不完整”。填了 Cookie 后重新抓取，拿到完整文字。
- Cookie 不出现在任何接口返回、日志、审计和错误信息里。重定向到别的域名时不带 Cookie。
- 存一篇带图的普通文章，详情里“阅读”标签页有图有排版。原站图片删除后依然能看。
- 导出的 HTML 文件断网打开，图片都在。
- 带 `<script>`、`onerror`、`javascript:` 链接的网页，存档后这些都被去掉。
- 图片超过大小限制时，保留原图地址，条目不算失败。
- 内网地址的图片不下载。
- 删除条目后图片文件也删除。
- 手机（390px）整页不横向滚动，图片不超出屏幕。

## 不确定的地方

- 开发环境连不上 `x.com`，推文接口返回的字段是照已知的格式写的，没有用真实推文调过。上线后第一次要用真实推文试一遍，不对就按实际返回改解析，把样例存进测试。这条要记到“已知问题”。
- 公开接口和 GraphQL 接口都不是 X 的正式接口，以后可能失效。设计上每一步独立，哪一步坏了不影响其他步。
