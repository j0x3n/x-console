# B81 增量备份

用户 2026-10-01 问：备份能不能增量？删掉的也删掉？像 git 那样有版本管理？

能。现在每次备份是一个完整的 `tar.gz`，文件多了每次都要传一遍。改成按内容分块存，每次只传新的块，每次备份是一个“快照”，可以回到任意一个快照。

## 怎么存

在备份目标（S3、WebDAV、Google Drive，B63、B69 已有）下面建一个目录 `x-console-repo/`：

```
x-console-repo/
  config.json          仓库版本、加密参数（随机盐，密钥由主密钥派生）
  blobs/ab/abcdef...   内容块，文件名是内容的 SHA-256，压缩后加密
  snapshots/2026-10-01T03-00-00Z.json   一次快照：数据库块的列表、每个文件的路径→块列表、大小、时间
```

- **文件**：按内容切块（固定 4 MB 一块就够，不用滚动哈希），已经存在的块不再上传。
- **数据库**：先 `VACUUM INTO` 得到一份一致的副本，再按 4 MB 切块。表没变的部分块哈希一样，不会重复上传。
- **删掉的文件**：新快照里没有它，就是删掉了。旧快照还引用着它的块，所以能恢复到删之前。
- **加密**：块用 AES-256-GCM 加密，密钥从主密钥派生（和现在的设置加密一样，换了主密钥就解不开，界面上写清楚）。
- **清理旧快照**：按“保留规则”删快照文件，然后删掉没有任何快照引用的块（“删掉的也删掉”指的就是这里：文件删了以后，等引用它的快照都过期了，它的块才从备份里真正删掉）。
- **一致性**：上传顺序是先块后快照文件，中途断了不会留下坏快照。清理块之前先读一遍所有快照，只删没人引用的块；同时只能有一个备份或清理在跑（在仓库里写一个锁文件，带时间，超过 6 小时算失效）。

## 界面（设置 → 备份）

- “自动备份”卡片加“备份方式”：`完整包`（现在的方式）和`增量`（新的，默认）。改成增量后第一次会传全部，以后只传变化。
- 保留规则：最近 N 次（默认 7）、每天保留 N 天（默认 14）、每周保留 N 周（默认 8）、每月保留 N 月（默认 12）。满足任意一条就保留。
- “快照”列表（增量时显示，替代备份文件列表）：每行时间、新增和改动的文件数、删掉的文件数、这次上传了多少、快照总大小。点开看变化明细（新增、改动、删除的文件路径，最多 200 条）。每行“恢复到这里”（危险操作，要输入“恢复”确认，和现在一样）。
- 顶部概要：快照数、仓库总大小、最近一次备份的时间和结果、去重后比完整包省了多少。
- “检查备份”按钮：读一遍所有快照，检查每个块都在（不下载内容，只查存在和大小），结果写在卡片里。

## 契约（`api/modules/backup.yaml`，已改）

- `BackupSettings` 和 `BackupSettingsInput` 加 `mode`（`full` 或 `incremental`）和 `retention`（`{ last, daily, weekly, monthly }`）。原来的 `keep` 只对 `full` 有效。
- 新接口：
  - `GET /backups/snapshots`：快照列表 `BackupSnapshot[]`（新的在前）和仓库概况 `BackupRepoStats`。
  - `GET /backups/snapshots/{snapshotId}/changes`：和上一个快照相比的变化，`BackupSnapshotChange[]`。
  - `POST /backups/snapshots/{snapshotId}/restore`：恢复，请求和现在的 `RestoreInput` 一样，要“始终验证”（`RequireStrictElevated`）。
  - `POST /backups/check`：检查仓库，后台进行，结果在 `/backups/job` 里（`kind: check`）。
- `BackupJob.kind` 加 `check`、`prune`。

## 后端（待做）

1. 新包 `modules/backup/repo`：仓库读写（块、快照、锁、清理），存储接口用 B63、B69 已有的远端抽象（S3、WebDAV、Google Drive）。写单元测试，用内存存储。
2. 自动备份按 `mode` 走两条路。手动“立即备份”也一样。
3. 恢复：下载快照引用的块，拼回数据库和文件，再走现在的“解包 → 停进程 → 重启时换数据库”。
4. 每次备份后按保留规则清理，清理是单独一步（`prune`），失败不影响这次备份的结果。
5. 性能：上传前先列出仓库里已有的块（S3 `ListObjects` 按前缀分页；WebDAV、Google Drive 也一样），存在内存的集合里，一次备份只列一次。块上传并发 4 个。
6. 测试：第二次备份没变化时只上传一个快照文件；改一个文件只传它的块；删一个文件后新快照里没有它，旧快照还能恢复它；清理后没人引用的块被删；断在半路不留坏快照；换主密钥后给出明确错误。

## 验收

- 改成增量后连着备份两次，第二次只花几秒，上传量接近 0。
- 删掉云盘里一个文件再备份，快照明细里显示“删除 1 个”；恢复到上一个快照能找回它。
- 快照过期后，备份目录里它独有的块被删掉，仓库变小。
