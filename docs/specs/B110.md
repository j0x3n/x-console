# B110 到 B112 AI 额度：Claude、Codex、Grok 的额度重置，DeepSeek 余额，多账号

用户 2026-10-06 提的，参考 [yetone/magpie](https://github.com/yetone/magpie) 的做法（`internal/provider/` 下的 `subscription_usage.go`、`grok_usage.go`、`balance.go`、`claude_usage_cli.go`、`account.go`）。

用户确认：Claude、Codex、Grok 的账号都登录在已经装了 X Console 代理的机器上。

拆成三个任务，各一个提交：

- **B110** 后端和代理：代理读额度，服务端存账号、定时读取、提供接口。
- **B111** 前端：“AI 额度”页和今日页的卡片。
- **B112** 通知：额度快用完、余额不足时通知。

## 要什么

- 每个账号显示：服务名、备注名、套餐、每个额度窗口的已用百分比和重置时间。
- Claude、Codex：5 小时和每周两个窗口，Claude 还有按模型的每周窗口。
- Grok：当前周期（日、周或月）的已用百分比和周期结束时间。有按量付费上限时再显示一个窗口。
- DeepSeek：余额，按币种分开写。没有重置时间。
- 同一个服务可以加多个账号。每个账号单独读取，单独显示错误，一个出错不影响别的。
- 重置时间显示成倒计时（“2 小时 14 分后重置”），鼠标悬停显示具体时间。
- 窗口的重置时间已经过了，就当作已用 0%，并标注“已重置，等待下次读取”。
- 机器离线时显示上一次读到的数字，变灰，写“机器离线，数据是 12 分钟前的”。
- 读取失败时写出原因，不显示成 0。

## 数据来源（照 magpie，没有用真实账号验证过）

这些接口只有 DeepSeek 是官方公开的。其余是内部接口或命令输出，厂商改版就会失效，所以每种读法都要写测试，出错信息要说清楚是哪一步失败。

### DeepSeek（服务端读，不经过代理）

- `GET https://api.deepseek.com/user/balance`，`Authorization: Bearer <API Key>`。
- 返回 `{"is_available":true,"balance_infos":[{"currency":"CNY","total_balance":"110.00",...}]}`。每个币种一条。
- API Key 用 `Secrets.Seal` 加密存储，接口永远不返回 Key，只返回“已设置”。

### Codex（代理读）

- 读账号目录下的 `auth.json`，默认目录 `~/.codex`（环境变量 `CODEX_HOME` 可改）。字段：`tokens.access_token`、`tokens.refresh_token`、`tokens.account_id`、`tokens.id_token`。
- `account_id` 为空时，从 `id_token` 的声明 `https://api.openai.com/auth` 里的 `chatgpt_account_id` 取。
- `GET https://chatgpt.com/backend-api/wham/usage`，请求头 `Authorization: Bearer <access_token>` 和 `chatgpt-account-id: <account_id>`。
- 返回里用到：`plan_type`，`rate_limit.primary_window` 和 `rate_limit.secondary_window`（各有 `used_percent`、`limit_window_seconds`、`reset_at`、`reset_after_seconds`），`credits`（`has_credits`、`unlimited`、`balance`）。
- 窗口名按 `limit_window_seconds` 取：18000 秒叫“5 小时”，整天数叫“N 天”。
- 访问令牌离过期不到 5 分钟时要先刷新：`POST https://auth.openai.com/oauth/token`，JSON 体 `{"client_id":"app_EMoamEEZ73f0CkXaXp7hrann","grant_type":"refresh_token","refresh_token":...,"scope":"openid profile email"}`。
- **刷新令牌用一次就换新**。刷新后必须把新令牌写回同一个 `auth.json`，其他字段保持原样，文件权限 0600，写之前加文件锁，先写临时文件再改名。代理不能自己另存一份，否则机器上的 Codex 命令行会因为令牌失效而掉线。
- 刷新失败时报“Codex 登录已失效，请在这台机器上运行 `codex login`”，不要改文件。

### Grok（代理读）

- 读账号目录下的 `auth.json`，默认 `~/.grok`（环境变量 `GROK_HOME` 可改）。内容是一个对象，值里有 `key`、`email`、`expires_at`。取按键名排序后第一个有 `key` 的。
- `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`，`Authorization: Bearer <key>`。
- 返回 `config.creditUsagePercent`、`config.currentPeriod.{type,end}`（`type` 是 `USAGE_PERIOD_TYPE_DAILY/WEEKLY/MONTHLY`）、`config.billingPeriodEnd`、`config.onDemandCap.val`、`config.onDemandUsed.val`。
- **代理不写这个文件**。`key` 离过期不到 5 分钟时，用 `GROK_HOME=<账号目录>` 运行 `grok models`（超时 30 秒），让命令行自己刷新，再重新读文件。还是过期就报“Grok 登录已失效，请在这台机器上运行 `grok login`”。
- 风险最高：magpie 已经把 Grok 内置支持挪到了插件里，说明这个接口变动过。实现时留一个 `baseURL` 变量，方便测试和以后改地址。

### Claude（代理读）

- magpie 不直接请求 Anthropic。它运行 Claude Code 自己的 `/usage` 命令，再解析文字。我们照做：
  `claude -p /usage --output-format json --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence`
  在一个临时空目录里运行，标准输入给空，环境变量加 `DISABLE_TELEMETRY=1`、`DISABLE_ERROR_REPORTING=1`、`DISABLE_AUTOUPDATER=1`，去掉 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`（它会让 `/usage` 不请求，只显示一小时内的旧数据）。超时 60 秒。
- 命令输出是 JSON，文字在 `result` 字段。每行形如：
  `Current session: 13% used · resets Oct 1 at 3:30pm (Asia/Shanghai)`
  `Current week (all models): 4% used · resets Oct 3 at 2pm (Asia/Shanghai)`
  `Current week (Fable): 0% used`
  正则：`^Current (session|week(?: \(([^)]+)\))?):\s*([0-9.]+)% used(?:\s*·\s*resets (.+))?$`。`session` 叫“5 小时”，`week (all models)` 叫“7 天”，按模型的叫“7 天 · 模型名”。
- 重置时间文字没有年份，括号里是时区。按括号里的时区解析，跨年时往后推一年。解析不出来就只显示百分比，不显示倒计时。
- 输出里有 401、403、`not logged in`、`signed out`、`sign-in expired`、`usage limit`、`hit your limit` 之类的字样，当作账号错误，把那一行原文（截取前 200 字符）放进错误信息。
- 多个 Claude 账号：每个账号一个配置目录，运行命令时设 `CLAUDE_CONFIG_DIR=<账号目录>`，默认目录 `~/.claude`。**这一点 magpie 没有做过，是我们的推断，开工后第一件事是在真实机器上用两个账号各试一次**。不行的话，Claude 先只支持每台机器一个账号，规格改回来。
- 找 `claude` 可执行文件的办法，复用 `internal/agent/coding` 里已有的。
- `/usage` 是启动一个进程，比较重。同一个账号成功读取之后 5 分钟内不再读，手动刷新也一样（返回上一次的结果并标明时间）。

## 协议（B110）

`backend/pkg/protocol` 加一个文件 `methods_quota.go`，只加不改，记到“接口变更记录”：

- 能力 `CapQuota = "quota"`。代理只在这台机器能读至少一种账号时声明（找到 `claude`、`codex` 的登录目录或 `grok` 任一个）。
- 方法 `MethodQuotaRead = "quota.read"`，参数 `QuotaReadParams{Kind string, Home string}`，`Kind` 是 `claude`、`codex`、`grok`，`Home` 空表示默认目录。
- 结果 `QuotaReading{User, Plan, Credits, Windows []QuotaWindow}`。
  `QuotaWindow{Name, UsedPercent float64, ResetsAt *time.Time, SpanSecs int64, Model string, Aside bool}`。`Aside` 表示按量付费这类用完了也不停账号的窗口。
- 错误码：`CodeQuotaSignedOut`（没登录或登录失效，信息里写该运行什么命令）、`CodeQuotaUnavailable`（接口不可用或解析失败）。
- 结果里**不能有任何令牌**，也不能带 `auth.json` 的原文。

代理端新包 `backend/internal/agent/quota`，`claude.go`、`codex.go`、`grok.go` 各一个，在 `cmd/agent/main.go` 里只加一行注册。三个服务的基础地址都是包级变量，测试里指向假服务器。

安全限制：

- `Home` 必须是绝对路径，用 `filepath.Clean` 处理，代理只读里面固定的文件名（`auth.json`）或把它设成环境变量传给命令，不读目录里的别的文件。
- 路径里有 `..` 或不是绝对路径，返回 `bad_params`。
- 代理只用这些令牌请求上面写的三个固定域名，不接受服务端传来的地址。

## 服务端（B110）

新模块 `backend/internal/server/modules/quotas`，接口定义 `api/modules/quotas.yaml`，在 `app/modules.go` 里只加一行。

数据库（迁移只加不删）：

- `quota_accounts`：`id`、`kind`（`claude`、`codex`、`grok`、`deepseek`）、`name`、`host_id`（`deepseek` 为空）、`home`（空表示默认目录）、`api_key`（加密，只 `deepseek` 用）、`sort_order`、`created_at`。
- `quota_readings`：每个账号一行最新结果。`account_id`、`ok`、`error`、`plan`、`user`、`credits`、`balance_json`、`windows_json`、`read_at`。
- 同一个 `kind` + `host_id` + `home` 不能重复，`deepseek` 同一个 Key 不能重复（比较加密前的值的哈希，不要存明文哈希以外的东西）。

接口：

- `GET /quotas`：全部账号和最新结果。
- `POST /quotas`、`PATCH /quotas/{id}`、`DELETE /quotas/{id}`：增、改、删。增和改要 `auth.RequireElevated`，因为会让代理读那个目录。删除也要，因为会连带删掉读取记录。
- `POST /quotas/{id}/refresh`：立即读一次。上一次读取成功且在 5 分钟内，返回上一次结果；上一次失败的，30 秒后可以再读（用户修好登录后不用等 5 分钟）。读取失败不返回错误，错误写在账号的 `error` 里。
- `POST /quotas/reorder`：账号顺序。
- `GET /quotas/hosts`：能读额度的机器（声明了 `CapQuota` 的在线代理），给“添加账号”下拉用。
- 错误：账号不存在 404，`Home` 不合法、机器不存在或不能读额度 400，重复账号 409，没提升权限 403。机器离线、登录失效这类读取问题不是接口错误，写在账号的 `status`、`errorCode`、`error` 里。`errorCode` 取值：`offline`、`signed_out`、`unavailable`、`unsupported`、`host_missing`。

定时读取，用 `Scheduler.Every`：

- DeepSeek、Codex、Grok 每 5 分钟，Claude 每 15 分钟。
- 每个账号单独超时（DeepSeek 20 秒，代理读取 90 秒）、单独记错误。机器离线时不记成错误，只保留上一次结果并标 `stale`。
- 读取并发限制 4 个，避免同一台机器同时起很多 `claude` 进程；同一台机器上同时只跑一个 `claude`。
- 日志里不写 Key 和令牌，错误信息里也不写。

## 前端（B111）

新页面 `web/src/features/quotas`，路径 `/quotas`，导航里放在“集成”组，名称“AI 额度”，图标用 `Gauge`。复制最像的现有页面（路由器、仓库页）再改，用现成的 `StatStrip`、`StatCard`、`Dialog`、`EmptyState`，样式见 `docs/07-design.md`。

- 顶栏页面按钮：“添加账号”（主要按钮）、“全部刷新”。
- 概要条：账号数、最紧张的窗口（剩余最少的那个，写账号名和剩余百分比）、最近一次重置（最早要重置的窗口和倒计时）、出错的账号数。
- 主体按服务分组（Claude、Codex、Grok、DeepSeek），每个账号一张卡片：
  - 标题：备注名，右侧机器名（或“DeepSeek”）、套餐。
  - 每个窗口一行：名称、进度条（显示已用）、“剩余 87%”、倒计时。剩余少于 20% 进度条变黄，少于 5% 变红。
  - DeepSeek 卡片：余额大字，多币种用 `·` 隔开。
  - 卡片右上角：刷新图标按钮、更多菜单（编辑、删除）。删除用 `useConfirm`，写明“删除账号 X？只删除这里的记录，不会影响机器上的登录。”
  - 出错时卡片里显示错误原因，有上次结果时仍显示数字并变灰。
  - 底部灰字：“12 分钟前读取”。
- “添加账号”弹窗：服务类型；Claude、Codex、Grok 选机器（`GET /quotas/hosts`）、填备注名、账号目录（可空，占位写默认目录）；DeepSeek 填备注名和 API Key。添加和修改时要提升权限（`withElevation`）。
- 弹窗里写清楚：每个账号要在那台机器上用单独的目录登录，比如 `CODEX_HOME=~/.codex-work codex login`。各服务一行说明。
- 今日页（`features/overview`）加一张卡片“AI 额度”：每个账号一行，显示名称、最紧张窗口的剩余百分比和倒计时，最多 6 行，多了显示“查看全部”。接口 404、501 或没有账号时不显示这张卡片。
- 新增词条放进 `features/quotas/i18n.ts`，同一个英文键不能和别的模块冲突。

## 通知（B112）

- 窗口剩余百分比降到 10% 以下、降到 0 时各通知一次。窗口重置后（`ResetsAt` 已过，新读到的已用百分比下降）清掉记录，下个周期再通知。
- DeepSeek 账号可以设“余额低于”（数字，币种用该账号第一个币种），默认不设。低于时通知一次，余额回升到阈值以上后清掉记录。
- 可选：“已重置”通知，默认关。
- 走现有 `notify`，开关放在设置 → 通知里，每类一个。记录放新表 `quota_notify_state`（`account_id`、`window`、`event`、`period_end`、`sent_at`），按 `account_id`、`window`、`event`、`period_end` 去重。
- 读取失败不通知。连续 3 次失败（Claude 连续 2 次）通知一次“额度读取失败”，恢复后清掉。

## 测试

- 代理：Codex、Grok 用假 HTTP 服务器测解析和刷新，包括令牌快过期时写回 `auth.json` 且其他字段不变、刷新失败时文件不变。Claude 用假的 `claude` 脚本输出样例文字测解析，包括带年份和不带年份的重置时间、各时区、账号错误字样。`Home` 不合法的各种情况。
- 服务端：模块集成测试（外部测试包），用假代理和假 DeepSeek 服务器。覆盖增删改、重复账号、提升权限、`refresh` 的 5 分钟限制、机器离线时保留上次结果、一个账号出错不影响别的。
- 前端：页面渲染测试（空、加载、出错、离线变灰、多账号、手机宽度）。
- 端到端：补一条主流程，添加 DeepSeek 账号（假服务器）后页面显示余额。

## 验收标准

- 假服务器返回样例时，四种服务的卡片数字、套餐、重置倒计时都对。
- 同一台机器上两个 Codex 账号（不同 `CODEX_HOME`）各自显示，互不影响。
- 刷新 Codex 令牌后，`auth.json` 里除令牌外的字段不变，权限仍是 0600。
- 接口返回、日志、错误信息里都搜不到令牌和 API Key。
- 代理关机后，卡片变灰并显示上次结果和读取时间。
- 添加、修改账号不提升权限会被拒绝。
- B112：同一个窗口在同一个周期内，剩余 10% 和 0 各只通知一次，重置后能再通知。
- 全部后端和前端检查通过，1360px 和 390px 截图没有横向溢出。

## 已知风险

- Codex、Grok、Claude 的读法都不是官方公开接口，随时可能失效。每次失效都会在卡片上显示出错原因，需要改代码修。
- 读取 Claude 额度要启动命令行，每次占用几秒 CPU。
- Codex 的刷新令牌写回逻辑如果出错，会让机器上的 Codex 掉线，要用户重新登录。这是最需要仔细测试的一处。
