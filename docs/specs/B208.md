# B208 网站自动化经过已连接的机器上网

2026-10-15 用户提的。原来 B208 只打算用家里的 Windows 电脑当出口，现在改成任何一台已连接的机器都能当出口，Linux 和 Windows 都行。

## 为什么做

用户在网站自动化里登录江苏政务服务网（`www.jszwfw.gov.cn`，登录后跳到 `wsdj.jszwfw.gov.cn:32080`）。登录是在接管页面里手动完成的，登录一完成就被拦，页面只显示 Forbidden 和一个 trace-id。浏览器跑在国外服务器上，网站看到的是境外机房 IP。最可能的原因是网站按 IP 风控。

用户有一台 Unraid 上的虚拟机，和用户在同一个内网，已经装了代理连到面板。让浏览器的流量经过这台机器出去，网站看到的就是用户家里的 IP。

## 要什么

1. 网站自动化任务的“更多设置”里，出口有三种选法：
   - 服务器直接访问（默认，和现在一样）。
   - 经过一台已连接的机器。下拉框里列出支持出口的机器，不在线的标“离线”。
   - 填代理地址（现在的“出口代理”）。
   三种只能选一种。
2. 选了机器以后，这个任务的浏览器的全部网络请求都经过那台机器出去。浏览器本身仍在服务器上，接管页面、登录状态、记下的步骤都不变。
3. 那台机器离线时，到点的检查不跑。状态不变，状态说明写“出口机器 xxx 不在线，等它上线再检查”，不算出错，不发出错通知。下一次照常按间隔再试。
4. 出口只能连公网地址。目标域名解析出来是内网、本机、链路本地、CGNAT、组播或未指定地址时拒绝，免得网页借这个出口访问用户内网里的设备。
5. 代理的配置文件里写 `"disableEgress": true` 就关掉出口功能。关掉以后这台机器不出现在下拉框里，服务端连过来也拒绝。
6. 代理版本太旧（不认识新方法）时，报“这台机器的代理太旧，先更新代理”。

## 怎么做

### 协议（`pkg/protocol`）

- 新方法 `net.dial`，是一个流（stream），参数 `NetDialParams{Host string, Port int}`。代理连上目标以后，流里的数据原样转发，两边任一方关闭就结束。
- 新能力 `egress`。代理没关掉出口时在 Hello 里报这个能力。

### 代理（`internal/agent`）

- 新包 `internal/agent/egress`。做法参考 `netproxy`：用 `net.Dialer` 的 `Control` 在 DNS 解析之后检查真实连接的 IP，只放行公网地址。允许的判断做成可替换的函数，测试里能放行 127.0.0.1。
- 连接超时 10 秒。端口 1 到 65535 都允许。
- `cmd/agent/main.go` 只加行：注册 `net.dial`，按配置决定报不报 `egress` 能力。
- `config.Config` 加 `DisableEgress bool json:"disableEgress,omitempty"`。
- Windows 上不起子进程，不涉及 `nowindow`。

### 服务端（`modules/watchers`）

- 新文件 `egress.go`：一个 HTTP 代理，只在设置了环境变量时启动。
  - `XC_BROWSER_EGRESS_LISTEN`：监听地址，比如 `:8091`。不设就不启动，选了机器的任务报“服务器没有开出口转发”。
  - `XC_BROWSER_EGRESS_URL`：浏览器容器连这个代理用的地址，比如 `http://x-console:8091`。
  - `deploy/docker-compose.yml` 的 x-console 服务加这两个变量，默认 `:8091` 和 `http://x-console:8091`。端口不映射到宿主机，只在 Docker 内部网络上能连。
- 认证：每个任务一个随机密码（32 字节，进程启动后第一次用时生成，只存内存）。传给浏览器的代理地址是 `http://w<任务编号>:<密码>@<XC_BROWSER_EGRESS_URL 的主机>`。浏览器包已经会处理代理的用户名密码（`handleProxyAuth`）。
  - 没带 `Proxy-Authorization` 时回 407，带 `Proxy-Authenticate: Basic realm="x-console"`，浏览器才会发用户名密码。
  - 密码用常量时间比较。每次连接都从数据库读这个任务现在的出口机器，没有出口机器就回 403。
- `CONNECT host:port`：经 `agenthub.Hub.Open` 开 `net.dial` 流，连上后回 `200 Connection Established`，然后双向转发。
- 普通 HTTP 请求（绝对地址的 GET、POST 等）：经 `net.dial` 连 `host:port`（默认 80），把请求改成相对地址，去掉 `Proxy-Authorization`，加 `Connection: close`，写过去，再把响应原样转回。
- 连不上回 502。代理不在线回 502。
- 每个任务同时最多 64 条连接，超过回 503。
- `runner.go`：任务选了出口机器时，`browser.Options.Proxy` 填上面的代理地址。打开浏览器前先看机器在不在线，不在线按“要什么”第 3 条处理。
- 选了出口机器又填了代理地址时，保存回 400：“出口代理和出口机器只能选一个”。改成出口机器时清掉存的代理地址，填代理地址时清掉出口机器。
- X 类型的任务不走浏览器，不能选出口机器。
- 改出口时写审计，和改代理一样。

### 接口（`api/modules/watchers.yaml`）

- `Watcher` 加 `egressAgentId`（可选，string）。
- `WatcherInput`、`WatcherPatch` 加 `egressAgentId`（string，空字符串是去掉）。

### 数据库

- 迁移 `watchers` 加 `egress_agent_id TEXT NOT NULL DEFAULT ''`，只加不删。

### 前端（`features/watchers`）

- `WatcherDialog.tsx` 的“更多设置”：原来的“出口代理”输入框改成“出口”下拉框（服务器直接访问 / 各台支持出口的机器 / 填代理地址），选“填代理地址”时才显示输入框。
- 任务详情页显示出口：机器名，或者“代理”。

## 验收

- 代理单元测试：只放行公网地址，内网和本机地址拒绝；能把流里的数据转给目标，再把回复转回来；关掉出口时不报能力。
- 服务端集成测试（用测试里的代理，放行本机地址）：
  - 不带密码回 407，密码不对回 407，任务没选出口机器回 403。
  - CONNECT 能连到本地的测试服务器，数据往返正确。
  - 普通 HTTP 请求能拿到响应。
  - 选了出口机器又填代理回 400；X 任务选出口机器回 400；改成出口机器后代理被清掉。
  - 出口机器离线时检查不跑，状态说明写明原因，状态不是 error。
- 用真实 Chrome 的测试：浏览器经出口打开本地测试网页，能读到内容。
- 前端测试：选机器以后保存时带 `egressAgentId`，选“填代理地址”才出现输入框。

## 没法在开发环境验证的

- 江苏政务服务网换了出口以后是不是就不拦了。要用户上线后试。
- Unraid 虚拟机上的代理要先更新到新版本才有出口功能。
