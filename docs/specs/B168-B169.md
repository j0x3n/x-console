# B168、B169：页头播放器改版，歌词和封面分开匹配

2026-10-12 用户提的。

## B168：页头播放器改版（前端，Claude 做）

### 要什么

1. 页头默认只有一个播放按钮。有歌在播时，点它展开，带动画显示封面、暂停、下一首。再点收起按钮（页头最右边的小箭头）收回去，只剩播放按钮。展开状态记在本地。
2. 点封面弹出迷你悬浮播放器，比现在的“正在播放”小组件更紧凑：
   - 上半部分：封面、歌名、歌手，下面是进度条、时间、上一首 / 播放暂停 / 下一首、播放模式、音量、定时、全屏。
   - 中间：滚动歌词，当前行高亮，点一行跳过去。
   - 底部一个“播放列表”按钮，点了在播放器里往下展开队列，再点收起。
   - 右上角有固定和关闭。固定后换页面也在，点别处不收起（沿用现在的固定逻辑）。
3. 去掉页头上单独的队列、歌词按钮，以及单独的队列、歌词小组件。它们都并进迷你播放器。
4. 系统媒体控制：Windows 的媒体浮窗能看到进度，能拖进度条跳转。
   - 现在的问题：`setPositionState` 只在 `currentTime - 上次 >= 1` 时调，换歌和往回拖以后“上次”没重置，新歌的大部分时间都不更新进度，系统那边看到的进度是错的。
   - 改成：`loadedmetadata`、`durationchange`、`play`、`pause`、`seeked`、`ratechange` 时都更新一次，播放中每 5 秒校准一次（系统会按播放速度自己往前推）。换歌没有时长时先清空。
   - `seekto` 支持 `fastSeek`，跳完立刻更新进度。

### 验收

- 1360 和 390 宽截图：收起、展开、迷你播放器、迷你播放器展开列表四种状态，没有横向溢出。
- 测试：展开收起、点封面开迷你播放器、列表展开收起、固定后点别处不收起。
- `setPositionState` 在换歌和拖动后会更新（单测里用假的 `navigator.mediaSession`）。

## B169：歌词和封面分开匹配，查得到每个来源的状态（后端，Codex 做）

### 为什么歌词总是匹配不到

代码里网易云、QQ 音乐、LRCLIB 都能出歌词，iTunes 和 MusicBrainz 只出封面。在本地（国内网络）试过，网易云和 QQ 音乐的搜索、歌词接口都正常返回，LRCLIB 超时。用户看到候选里只有 iTunes，说明线上服务器调网易云和 QQ 音乐时失败了，只是失败被静默跳过（`collect` 里只打 Debug 日志）。最可能的原因是服务器在海外：网易云对海外 IP 返回 `abroad: true` 和加密过的 `result`，解析失败；QQ 音乐也可能限制海外访问。现在没有办法看到是哪个来源、因为什么失败。

另一个问题：用户选 iTunes 候选时，后端拿 iTunes 的歌手名（比如 “Jay Chou”）去别的来源找歌词，再按“歌手要有重叠”的规则判断，中文歌手名对不上就找不到。

### 要什么

1. **来源检查**：新接口 `POST /music/sources/check`，body 可选 `{ trackId }`（不给就用固定的测试歌名 “晴天 周杰伦”）。对每个来源（不管开没开）跑一次搜索，返回 `[{ source, enabled, ok, hits, lyricsHits, coverHits, error, ms }]`。`error` 是给人看的中文原因，比如“HTTP 403”“超时”“返回的不是预期格式（可能限制了海外访问）”。只读，不改歌。
2. **网易云海外访问**：请求带 `X-Real-IP` 头（固定一个国内 IP，NeteaseCloudMusicApi 的做法）。返回里有 `abroad: true` 或 `code` 不是 200 时，报明确的错误，不要当成解析失败。
3. **搜索失败要留痕**：`collect` 里来源失败改成 Warn 日志，带来源名和错误。
4. **分开匹配**：`MusicMatchRequest` 加 `parts`，取值 `lyrics`、`cover` 的数组，不传等于两个都要。
   - 带 `candidate`：只从这个候选取 `parts` 里的部分，别的不动。只要歌词时不要去碰封面，反过来也一样。选了只有封面的候选、`parts` 又包含歌词时，不再自动拿它的歌手名去别的来源找歌词（这是现在找不到歌词的原因之一）。
   - 带 `choose`：只找能提供 `parts` 的候选。两个都要时，歌词候选最多 8 个、封面候选最多 8 个，一起放进待确认（同一个候选两样都有时只存一次）。
   - 都不带：自动匹配只找 `parts` 里的部分，`overwrite` 也只换这部分。
   - 应用一个候选后，如果歌还缺另一部分，并且待确认里还有能提供那部分的候选，留着这些候选，`matchState` 保持 `pending`；否则清空候选，变成 `matched`。
5. **评分**：`rank` 给候选打分时，歌词候选按标题和时长为主，歌手对不上的扣分但不排除（中英文歌手名经常对不上）。打分规则写在注释里，加测试。

### 接口约定（前端按这个写）

```yaml
MusicMatchRequest.parts: { type: array, items: { type: string, enum: [lyrics, cover] } }
POST /music/sources/check
  body: { trackId?: integer }
  200: MusicSourceCheck[]
MusicSourceCheck: { source, enabled: boolean, ok: boolean, hits: integer, lyricsHits: integer, coverHits: integer, error: string, ms: integer }
```

### 验收

- `go test ./internal/server/modules/music/...` 通过。测试用本地假服务器：网易云返回 `abroad: true` 时检查结果里 `ok=false` 且原因写清楚；只要封面时不改歌词；只要歌词时不改封面；选了封面后还缺歌词时候选还在、状态是 `pending`。
- `go generate`、`npm run gen:api` 后生成文件已提交。
