# B29 系统日志

用户要求（2026-09-28）：服务器还缺系统日志显示。

## 要什么

- 服务器和电脑详情页加一个标签“日志”，放在“容器”后面。
- Linux：读 systemd journal。Windows：读事件查看器的“系统”和“应用程序”。没有 journal 的 Linux 读 `/var/log/syslog` 或 `/var/log/messages`。
- 可以按级别、服务（Linux 的 unit，Windows 的来源）、时间范围、关键字过滤。
- 可以打开“实时”，新日志自动滚到底部。

## 前端（已完成，提交 B29）

- 服务器和电脑详情页的“日志”标签（`servers/components/SyslogTab.tsx`），放在“容器”后面。
- 标签用 `cap: "syslog"` 加 `preview: true` 注册：代理还没有这个能力时也显示（只对代理接入的机器），接口回 501 时整页显示“日志还没上线”。代理升级、上报 `syslog` 能力后就正常用。SSH 主机不显示。
- 用公共的 `LogViewer`：级别下拉由页面控制，换成 `priority` 参数向服务端查询（错误 3、警告 4、信息 6、调试 7）；服务下拉来自 `/syslog/units`；时间范围 15 分钟、1 小时、今天、7 天；“实时”开关连 `/syslog/follow`。
- 第一次取 1000 条，滚到顶部带 `cursor` 取更早的 500 条，页面最多保留 10000 行。
- 接口回 403 且 `code = syslog_permission` 时，显示“代理没有读取系统日志的权限”和服务端给的说明。

## 契约

`api/modules/hosts.yaml`：`GET /hosts/{hostId}/syslog`、`GET /hosts/{hostId}/syslog/units`、`GET /hosts/{hostId}/syslog/follow`（WebSocket），结构 `SyslogEntry`、`SyslogPage`。现在由 `modules/hosts/pending.go` 回 501。

## 后端（待做，给开发者）

### 1. 代理

- 新能力 `syslog`，新包 `internal/agent/syslog`，在 `cmd/agent/main.go` 里注册（只加一行）。
- 协议方法（写进 `pkg/protocol` 和 `docs/04-agent-protocol.md`）：
  - `syslog.query`：参数 `{since, until, priority, unit, grep, limit, cursor}`，返回 `{items: [{time, priority, unit, pid, message}], cursor}`。`items` 按时间正序。
  - `syslog.units`：返回最近 7 天的 unit 列表，按次数从多到少，最多 300 个。
  - `syslog.follow`：流，参数 `{priority, unit, grep}`，每 200 毫秒或每 200 条推一批。
- Linux 实现：
  - 有 `journalctl` 时用它，全部参数作为独立的参数传给 `exec.Command`，不拼 shell：
    - 查询：`journalctl -o json --no-pager -r -n <limit>`（`-r` 倒序取最近的，返回前翻转），加 `--since`、`--until`（格式 `2006-01-02 15:04:05`，用服务器本地时区）、`-p 0..<priority>`、`-u <unit>`、`-g <grep>`（journald 244 以上才有 `-g`，旧版本在代理里自己过滤）。
    - 翻页：`cursor` 是上一页最早一条的 `__CURSOR`，用 `--cursor=<cursor> -r` 再跳过第一条。
    - 跟随：`journalctl -o json -f -n 0` 加同样的过滤参数，进程随流的 context 结束。
    - units：`journalctl -o json --since "7 days ago" --output-fields=_SYSTEMD_UNIT,SYSLOG_IDENTIFIER`，自己统计。数据多时只看最近 20000 条。
    - `unit` 只允许 `[A-Za-z0-9._@:-]`，最长 128；`grep` 最长 200，其他字符原样传（不经过 shell 所以安全）。
    - JSON 字段：`__REALTIME_TIMESTAMP`（微秒）、`PRIORITY`、`_SYSTEMD_UNIT`（没有时用 `SYSLOG_IDENTIFIER`）、`_PID`、`MESSAGE`（可能是字节数组，要转成字符串）。
  - 没有 `journalctl` 时读 `/var/log/syslog` 或 `/var/log/messages`：从文件末尾往前读，按行解析 `时间 主机 程序[pid]: 内容`，priority 一律 6，只支持时间、unit（程序名）、关键字过滤。跟随用轮询文件大小（每秒一次），文件变小时从头读（被轮转了）。
  - 没权限（journalctl 返回 “No journal files were opened due to insufficient permissions” 或文件读不了）时返回错误码 `syslog_permission`，消息写：“代理没有读取系统日志的权限。在服务器上执行：sudo usermod -aG systemd-journal <代理运行的用户>，然后重启代理。”
- Windows 实现：用 `wevtutil qe System /f:xml /rd:true /c:<limit>` 和 `Application` 两个日志，合并后按时间排序。级别映射：Critical 2、Error 3、Warning 4、Information 6、Verbose 7。`unit` 是事件来源（`Provider Name`）。跟随每 2 秒查一次比上次新的记录（按 `EventRecordID`）。Windows 部分 CI 测不了，写进“已知问题”。

### 2. 服务端

- `GetSyslog`：检查代理在线和能力，调用 `syslog.query`，把错误码 `syslog_permission` 转成 HTTP 403、`code: "syslog_permission"`。不需要提升权限（只读），但要记审计 `host.syslog.read`（只记一次查询，不记翻页）。
- `ListSyslogUnits`：调用 `syslog.units`，结果按机器缓存 10 分钟。
- `FollowSyslog`：参考现有的容器日志跟随（`monitoring` 模块的 `followContainerLogs`）的写法：升级 WebSocket，开代理的流，每批写成一个 JSON 数组文本帧。注意 AGENTS.md 里 coder/websocket 不要用会被取消的 context 写数据。
- 能力没上报时回 501（`httpx.ErrNotLive`，前端显示“还没上线”）。

### 3. 测试

- 代理：把 `journalctl -o json` 的几行样例放进测试数据，测试解析（包括 `MESSAGE` 是字节数组的情况）、参数拼装（每个参数独立，没有 shell）、unit 校验。
- 文本日志解析：几种常见的 syslog 行格式。
- 服务端：假代理返回权限错误时接口回 403 和 `syslog_permission`；没能力回 501。

## 验收

- 在一台有 systemd 的机器上，按服务 `ssh` 过滤、按“只看错误”过滤、按关键字过滤都对。
- 实时模式下在服务器上执行 `logger "xc test"`，1 秒内出现在页面上。
- 10 万行日志翻页和实时滚动时页面不卡。
- 代理没权限时显示提示和命令，不显示“出错了”。
- Windows 交叉编译和 vet 通过。
