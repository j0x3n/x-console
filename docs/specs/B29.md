# B29 系统日志

用户要求（2026-09-28）：服务器还缺系统日志显示。

## 要什么

- 服务器和电脑详情页加一个标签“日志”，放在“容器”后面。
- Linux：读 systemd journal。Windows：读事件查看器的“系统”和“应用程序”。没有 journal 的 Linux 读 `/var/log/syslog` 或 `/var/log/messages`。
- 可以按级别、服务（Linux 的 unit，Windows 的来源）、时间范围、关键字过滤。
- 可以打开“实时”，新日志自动滚到底部。

## 代理

- 新能力 `syslog`，方法：
  - `syslog.query`：参数 `since`、`until`、`priority`（0 到 7，和 journal 一致，Windows 的级别映射过去）、`unit`、`grep`、`limit`（默认 500，最多 5000）、`cursor`（往前翻页）。返回每行：时间、级别、unit 或来源、进程号、内容，和下一页的 `cursor`。
  - `syslog.follow`：流式，参数和上面一样，不带 `until`。
  - `syslog.units`：列出最近 7 天出现过的 unit 或来源，给下拉框用。
- Linux 实现：调用 `journalctl -o json --no-pager`，参数全部作为独立的参数传，不拼 shell 命令。`-u`、`-g` 的值要校验（unit 名只允许字母数字和 `.-_@:`）。没有 `journalctl` 时读文本日志，只支持关键字和时间过滤。
- Windows 实现：`wevtutil qe System /f:xml /rd:true /c:<limit>` 或 Windows API，选一个能在无管理员权限下读“系统”“应用程序”的方式。
- 读日志要 root 或 `systemd-journal` 组。代理没权限时返回明确的错误，前端显示“代理没有读取系统日志的权限”，并给出加组的命令。
- 更新 `docs/04-agent-protocol.md` 的能力列表。

## 界面

- 工具栏：级别下拉（全部、错误及以上、警告及以上、信息及以上、调试）、服务下拉（可以搜索）、时间范围（15 分钟、1 小时、今天、7 天、自定义）、关键字、“实时”开关。
- 列表用等宽字体，一行一条：时间（`HH:mm:ss`，悬停看完整时间）、级别标签（错误用 `danger`，警告用 `warn`）、服务名、内容。内容太长时折叠，点开看全文。
- 用虚拟列表，只渲染看得到的行。页面里最多保留 10000 行，超出丢掉最旧的。
- 实时模式下，用户往上滚时暂停自动滚动，底部出现“有 N 条新日志，回到底部”。
- 滚到顶部时加载更早的一页。
- 这个日志查看组件放到 `components/log/LogViewer.tsx`，B28 的容器日志和 B31 的云盘日志文件也用它。

## 验收

- 在一台有 systemd 的机器上，按 unit `ssh` 过滤、按错误级别过滤、按关键字过滤都对。
- 实时模式下 `logger "xc test"`，1 秒内出现在页面上。
- 10 万行日志翻页和实时滚动时，页面不卡（滚动时帧率不低于 50，用 Chrome 性能面板看一次，截图附在提交说明里）。
- 代理没权限时显示提示，不显示“出错了”。
- Windows 交叉编译和 vet 通过。Windows 实现没法在 CI 里测，记到“已知问题”。
