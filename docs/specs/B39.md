# B39 AI：Responses 接口、图片和文件附件、快速模型思考强度

用户 2026-09-30 提出，让 Claude 直接写。

## 要什么

- 供应商可以选用哪种接口：`chat`（Chat Completions，原来的做法）或 `responses`（Responses 接口）。每个供应商在设置里手动选，默认 `chat`。
- AI 助手浮窗可以上传附件：图片（PNG、JPEG、WebP、GIF）和文本、代码文件。图片交给模型看，文本文件把内容放进消息。
- 快速模型也能单独设置思考强度，和 Agent 模型分开。

## 接口

- `AiProvider`、`AiProviderInput`、`AiProviderPatch` 加 `apiStyle`：`chat` 或 `responses`。迁移给 `ai_providers` 加列 `api_style`，默认 `chat`。
- `AiModelSettings`、`AiModelSettingsInput` 加 `fastReasoningEffort`（`off`、`low`、`medium`、`high`，默认 `off`）。原来的 `reasoningEffort` 只管 Agent 模型。
- `POST /ai/attachments`：multipart，字段 `file`。回 `{id, name, mime, size, kind}`，`kind` 是 `image` 或 `text`。
  - 图片按内容判断类型，最大 10 MB。
  - 文本文件最大 512 KB，必须是 UTF-8。
  - 其他类型回 415。
- `GET /ai/attachments/{id}`：下载，给前端显示缩略图。带 `nosniff`。
- `SendAiMessage` 请求体加 `attachmentIds`（最多 10 个）。只能用还没发出去的附件，发出后归到这个对话。
- 消息里的块：图片是 `{type: "image", attachmentId, name, mime}`，文件是 `{type: "file", attachmentId, name}`。
- 删除对话时一起删它的附件。24 小时还没发出去的附件每天清理。

## 调用层

- `llm.Config` 加 `APIStyle`。`responses` 时走 `POST {baseUrl}/responses`：
  - `instructions` 放系统提示，`input` 放历史。用户消息的内容是 `input_text` 和 `input_image`（data URL）；工具调用是 `function_call`，结果是 `function_call_output`。
  - 流式读 `response.output_text.delta`、`response.output_item.done`（完整的工具调用）、`response.completed` 和 `response.incomplete`（用量、是否截断）。
  - 思考强度放 `reasoning.effort`，JSON 输出放 `text.format`。接口回 400 说不认识时，和原来一样去掉重试。
  - `store: false`。
- Chat Completions 带图片时，用户消息的内容改成文本加 `image_url`（data URL）。
- 模型规格明确写着不支持图片输入时，带图片的消息回 400 `model_without_images`。规格未知的照常发。

## 验收

- 用假服务器测 `responses`：文字流、工具调用、工具结果回传、截断、用量。
- 带图片的消息两种接口都把图片发出去；文本文件的内容出现在发给模型的消息里。
- 快速模型设了思考强度，调用时带上；Agent 模型不受影响。
- 前端：供应商表单能选接口；模型设置里快速模型有思考强度；浮窗能选附件、显示缩略图和文件名、可以删掉再发。
