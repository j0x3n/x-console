# B24 统一文件存储和 S3，B25 整站导出导入和自动备份

用户要求（2026-09-28）：

- 站内所有文件分类放到一个目录下，方便备份。
- 云盘的“S3 同步”改成 S3 存储。这个 S3 用于整站文件的存储和读取，不只是云盘。
- 设置里加整站数据导出、导入，并能自动备份到 S3。

## 前端（已完成，提交 B24-B25）

- 设置里“云盘同步”标签换成“存储”（`/settings/storage`，`features/storage/StorageTab.tsx`），新增“备份”标签（`/settings/backup`，`features/backup/BackupTab.tsx`）。
- 存储：存储位置卡片（当前位置、切换按钮、搬迁进度、停止、重试、“切换成功后删除原位置的文件”），S3 设置卡片（`features/storage/S3Fields.tsx` 是公共的输入框），用量卡片（按模块、S3 时的本机缓存上限）。
- `GET /storage` 回 404 或 501 时，页面上方提示“新的存储设置还没上线”，下面照旧显示云盘原来的 S3 同步（`features/drive/S3SettingsTab.tsx`）。后端做完、确认线上可用后，删掉 `S3SettingsTab.tsx` 和它在 `StorageTab` 里的引用。
- 备份：导出和恢复卡片（导出、上传、进度、下载），自动备份卡片，备份列表（下载、恢复、删除）。恢复要在确认框里输入“恢复”，并且要提升权限。恢复完成后页面自动刷新。`GET /backups` 回 404 或 501 时整页显示“备份还没上线”。
- 搬迁和导出进行中时，前端每 1.5 到 2 秒轮询一次状态。

## B24 后端（给开发者）

### 1. 基础包 `internal/server/files`

```go
package files

type Info struct {
    Key     string
    Size    int64
    ModTime time.Time
}

type Store interface {
    Put(ctx context.Context, key string, r io.Reader, size int64) error
    Get(ctx context.Context, key string) (io.ReadCloser, Info, error)
    // GetRange 读 [offset, offset+length)。length < 0 表示读到结尾。云盘的 Range 请求和日志查看要用。
    GetRange(ctx context.Context, key string, offset, length int64) (io.ReadCloser, Info, error)
    Stat(ctx context.Context, key string) (Info, error)
    Delete(ctx context.Context, key string) error
    // List 按 key 的字典序列出前缀下的全部文件。
    List(ctx context.Context, prefix string) iter.Seq2[Info, error]
    Copy(ctx context.Context, from, to string) error
}

var ErrNotFound = errors.New("files: not found")
```

- key 用 `/` 分隔，第一段是模块名，比如 `drive/blobs/ab/abcdef…`、`notes/attachments/123`。不允许 `..`、空段、开头的 `/`，不合法时返回错误。
- 两个实现：
  - `Local{Root}`：`Root` 是 `data/files`。`Put` 先写到同目录的临时文件再 `rename`，写一半断电不会留下坏文件。目录权限 0700，文件 0600。
  - `S3{Client, Bucket, Prefix}`：用已经在依赖里的 `minio-go/v7`。key 前面加 `Prefix`。`Put` 用 `PutObject`，大文件自动分片。
- `Scoped(store, "notes")` 返回一个只能读写 `notes/` 下的 `Store`，模块拿到的都是它。
- `Manager`：持有当前的 `Store`，切换时原子替换。模块每次调用都通过 `Manager` 取当前的 `Store`，不要把 `Store` 存在自己的字段里。
- S3 模式下的本机缓存：`Cached{Remote, Dir, Limit}`，读的时候先查 `data/files-cache/`，没有就从 S3 下载一份再返回。每次读更新文件的访问时间，超出 `Limit` 时后台删最久没读的。写的时候直接写 S3，同时写缓存。
- `module.Deps` 加字段 `Files *files.Manager`（基础代码改动，在 `docs/tasks.md` 的“接口变更记录”记一笔），模块用 `d.Files.For("notes")` 取自己的 `Store`。

### 2. 目录和旧文件迁移

```
data/
  x-console.db
  files/
    drive/blobs/<hash[:2]>/<hash>     原 data/drive/blobs/
    drive/thumbnails/<hash>.jpg       原 data/drive/thumbnails/
    drive-versions/<fileId>/<versionId>   B31 用
    notes/attachments/<id>            原 data/notes/attachments/<id>
    projects/<issueId>/<name>         B36 用
  files-cache/                        只在用 S3 时有
  backups/                            数据库和整站备份
```

- 启动时（`app.New` 里、模块启动前）检查旧目录 `data/drive/`、`data/notes/attachments/`，存在就 `os.Rename` 到新位置（同一个卷里是瞬间完成的）。跨卷失败时逐个复制再删除。完成后写一条 `Info` 日志。
- 云盘和笔记改用 `d.Files`：`drive/module.go` 的 `blobPath`、缩略图路径，`notes/attachments.go` 的 `attachmentPath`。数据库里存的是 hash 和 id，不存路径，所以不用改数据。
- 写测试：用旧目录结构启动，文件都能读到，旧目录已经不在。

### 3. 存储设置和切换（新模块 `modules/storage`）

按 `docs/03-backend.md` 的步骤新建模块，`api/gen.go` 指向 `api/modules/storage.yaml`，在 `app/modules.go` 加一行。

设置存储：

| 键 | 内容 |
| --- | --- |
| `storage.backend` | `"local"` 或 `"s3"`，默认 local |
| `storage.s3` | `{endpoint, region, bucket, prefix, accessKeyId, pathStyle}` 普通 JSON |
| `storage.s3_secret` | `secretAccessKey`，用 `SetSecret` 加密 |
| `storage.cache_limit` | 字节数，默认 1 GB |
| `storage.migration` | 最近一次搬迁的状态，结构同 `StorageMigration` |

旧配置迁移：第一次启动时如果 `storage.s3` 没有、云盘的旧 S3 配置有，就复制过来（包括加密的密钥）。存储位置保持 local，不自动切换。

接口：

- `GET /storage`：`usage` 用 `List` 按模块统计，结果缓存 10 分钟（本机模式直接走文件系统很快，S3 模式要列对象，所以要缓存）。`localPath` 是 `data/files` 的绝对路径。
- `PUT /storage/s3`：`auth.RequireElevated`。当前用的就是 S3 时，先用新配置跑一遍测试（写、读、删一个 `.x-console-test` 文件），失败回 400 不保存。成功后 `Manager` 换成新的客户端。
- `POST /storage/s3/test`：请求体里没给的字段用已保存的。回 `{ok, message}`，message 用中文，比如“连接正常”“桶不存在”“密钥不对”。
- `POST /storage/switch`：`auth.RequireElevated`。
  1. 检查：目标和当前一样回 400；目标是 s3 但没配置回 412；已有搬迁在跑回 409。
  2. 起一个后台 goroutine（用 `context.WithoutCancel` 派生，并保存 cancel 函数给取消用）。
  3. 先 `List` 源的全部文件，算出 `totalFiles`、`totalBytes`。
  4. 逐个复制：目标已有同名同大小的跳过（重试时就不重复搬）。每搬一个更新进度，每秒最多写一次 `storage.migration`，并发 `storage.progress` 事件。
  5. 搬迁期间有新文件写入：`Manager` 在搬迁期间“双写”（同时写源和目标），这样搬完不会漏。
  6. 全部完成后再 `List` 一遍目标核对数量和大小，一致才把 `storage.backend` 改成目标，`Manager` 切换。
  7. `deleteSource` 为 true 时切换后删源文件；为 false 时保留。
  8. 失败：`state=failed`，`error` 写第一个出错的 key 和原因。不切换，不删任何东西。
  9. 审计：`storage.switch`，记目标、文件数、结果。
- `POST /storage/switch/cancel`：取消 context，`state=canceled`。
- `PUT /storage/cache`：保存上限，立即按新上限清理一次。

### 4. 去掉云盘原来的 S3 同步

- 新的存储上线、线上确认可用之后，在下一个版本删掉 `drive.yaml` 的 `/drive/s3*` 和 `drive/s3.go`（分两次部署，见 AGENTS.md 的“保持稳定”）。前端同时删 `S3SettingsTab.tsx`。
- 这个版本里旧的同步照常工作，互不影响。

### 5. 测试

- `files` 包：`Local` 的全部方法；key 校验；`Scoped` 不能读写别的模块；`Cached` 超出上限会删最旧的。
- `S3` 实现：用 `httptest` 起一个假 S3（minio-go 能对它发请求），或者 CI 里起 MinIO 容器。至少覆盖 Put、Get、GetRange、List、Delete。
- 搬迁：本机 → 假 S3，中途让第 3 个文件失败，状态是 failed、没切换；修好后重试，已经搬过的跳过，最后切换成功。搬迁中上传的新文件两边都有。

## B25 后端（给开发者）

新模块 `modules/backup`，契约 `api/modules/backup.yaml`。

### 1. 备份包格式

`x-console-<YYYYMMDD>-<HHMM>-<版本>.tar.gz`，版本来自构建时注入的版本号（没有时写 `dev`）。包里：

```
manifest.json
x-console.db          VACUUM INTO 出来的一致副本（store.Backup 已有）
files/...             files.Store 里的全部文件，路径就是 key
```

`manifest.json`：

```json
{ "format": 1, "version": "sha-8fed186", "createdAt": "2026-09-28T03:00:00Z",
  "files": 972, "bytes": 3300000000, "dbSha256": "…", "migration": "20260929000100" }
```

`migration` 是数据库里最新迁移的版本号，恢复时用来判断是不是比当前新。

### 2. 导出 `POST /backups/export`

- `auth.RequireElevated`。同时只能有一个任务（导出、恢复、自动备份共用一个锁），否则 409。
- 后台 goroutine：先 `store.Backup` 出数据库到临时文件，再用 `archive/tar` + `compress/gzip` 流式写到 `data/backups/<名字>.tar.gz.part`，写完改名去掉 `.part`。不要把文件读进内存。
- 进度写到内存里的 `BackupJob`，`GET /backups/job` 读它。`step` 写中文，比如“正在备份数据库”“正在打包文件（120/800）”。
- 完成后 `backupId` 是文件名，发事件 `backup.created`。
- 本机只保留最近 5 份手动导出和 5 份恢复前备份，多的删掉（自动备份放在 S3，不占本机）。

### 3. 列表、下载、删除

- `GET /backups`：本机 `data/backups/` 下的 `.tar.gz` 加上 S3 的 `backups/` 前缀下的。`kind` 从文件旁边的 `<名字>.json`（写包的时候一起写，内容就是 manifest 加 kind）读，没有就按 `manual`。
- `GET /backups/{id}/download`：`auth.RequireElevated`。`id` 只允许 `[A-Za-z0-9._-]+`，防止路径穿越。本机的用 `http.ServeContent`，S3 的由服务端边读边转发。
- `DELETE /backups/{id}`：`auth.RequireElevated`，审计 `backup.delete`。

### 4. 上传 `POST /backups/upload`

- `auth.RequireElevated`，最大 20 GB（`http.MaxBytesReader`）。
- 流式写到 `data/backups/uploaded-<时间>.tar.gz.part`，写完打开读 `manifest.json` 校验 `format` 和必需文件，不对就删掉并回 400“不是 X Console 的备份文件”。

### 5. 恢复 `POST /backups/{id}/restore`

- `auth.RequireElevated`，`confirm` 必须是“恢复”，否则 400。
- 读 manifest：`migration` 比当前数据库最新迁移还新时回 400“备份来自更新的版本，请先升级”。
- 后台任务：
  1. 先按导出的流程备份一次当前数据，`kind=pre-restore`。
  2. 解包到 `data/restore-tmp/`，校验 `dbSha256`。
  3. 进入维护状态：新请求回 503“正在恢复数据，请稍候”（在路由最外层加一个检查），等正在处理的请求结束（最多 10 秒）。
  4. 关掉数据库连接，用解出来的 db 替换 `data/x-console.db`，删掉 `-wal`、`-shm`。
  5. 文件：清空当前 `files.Store`（本机直接换目录；S3 模式逐个上传解出来的文件并删掉多余的）。
  6. 重新打开数据库、跑迁移（备份可能来自旧版本）。
  7. 逐个读取加密的设置，解不开的键记到 `secretsUnreadable`。
  8. 退出维护状态，发事件 `backup.restored`。
- 实现上最简单可靠的做法是第 4 步后让进程以特定退出码退出，由 Docker 重启服务，启动时发现 `data/restore-tmp/` 就完成后面的步骤。两种做法选一种，写进 `docs/06-deploy.md`。
- 审计：`backup.restore`，记来源文件名、结果。

### 6. 自动备份

- 设置键 `backup.settings`（普通 JSON），自定义 S3 的密钥放 `backup.s3_secret`（加密）。
- 调度器每分钟检查一次：到了设定的时间（服务器时区）且今天（或本周）还没备份过，就跑一次，`kind=auto`。
- 目标：`target=storage` 时用 B24 的 S3 配置，key 前缀 `backups/`；`custom` 时用自己的 S3。存储用的是本机磁盘、又选了 `storage` 时，保存设置回 400“存储设置里还没有 S3”。
- 包先生成在本机临时目录，上传成功后删掉本机的。上传后按 `keep` 删 S3 上最旧的 `auto` 备份。
- 每次结果写进 `lastRuns`（最多 10 条）。失败时发通知 `backup.failed`（普通优先级）。
- `POST /backups/run`：立即跑一次，和定时的逻辑一样。

### 7. 测试

- 导出后解包，manifest、数据库、文件都在，数据库能打开并查到数据。
- 在一个新的临时数据目录里恢复这份备份，登录后数据一样；用不同主密钥恢复时 `secretsUnreadable` 列出了令牌。
- 上传一个随便的 gzip 回 400。
- `id` 带 `../` 回 400。
- 自动备份：把时间函数调到设定时间，跑一次，假 S3 里有文件；保留 2 份时第 3 份会删掉最旧的。

### 验收（B24 和 B25 一起）

- 新装的实例只有 `data/x-console.db`、`data/files/`、`data/backups/`。
- 旧数据目录启动后，云盘文件和笔记图片都能打开。
- 在界面上切到 S3（MinIO），进度走完后上传一个文件，S3 里能看到；切回本机，文件都在。
- 导出一份、在另一台机器（同一个主密钥）上传并恢复，登录后数据和文件都在。
- 自动备份设成每天 03:00，保留 3 份，连续 4 天后 S3 上只有 3 份。
