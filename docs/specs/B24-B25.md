# B24 统一文件存储和 S3，B25 整站导出导入和自动备份

用户要求（2026-09-28）：

- 站内所有文件分类放到一个目录下，方便备份。
- 云盘的“S3 同步”改成 S3 存储。这个 S3 用于整站文件的存储和读取，不只是云盘。
- 设置里加整站数据导出、导入，并能自动备份到 S3。

## 现在的情况

- 云盘文件在 `data/drive/`，笔记附件在 `data/notes/attachments/<id>`。各模块自己拼路径。
- 云盘有“S3 同步”：本地是主，定时同步一份到 S3（`modules/drive` 里）。
- 数据库只在部署前由 `remote-deploy.sh` 备份（B19），界面上没有导出导入。

## B24 统一文件存储

### 目录

所有文件放在 `data/files/` 下，按模块分：

```
data/
  x-console.db
  files/
    drive/        云盘
    notes/        笔记附件和图片
    projects/     项目和 Issue 里粘贴的图片、附件（B36 用）
    drive-versions/  云盘文本文件的历史版本（B31 用）
    ai/           AI 对话里的附件（以后用）
  backups/        数据库和整站备份
```

### 接口

- 新增基础包 `internal/server/files`：

  ```go
  type Store interface {
      Put(ctx, key string, r io.Reader, size int64) error
      Get(ctx, key string) (io.ReadCloser, Info, error)   // 支持 Range 的另一个方法 GetRange
      Stat(ctx, key string) (Info, error)
      Delete(ctx, key string) error
      List(ctx, prefix string) iter.Seq2[Info, error]
      Copy(ctx, from, to string) error
  }
  ```

  `key` 形如 `notes/123/photo.png`，第一段是模块名。模块只能写自己那一段，`files.For(d, "notes")` 返回一个限定了前缀的 `Store`。
- 两个实现：`local`（`data/files/` 下的普通文件）和 `s3`（任意兼容 S3 的服务，用 `minio-go`，已有依赖就用已有的）。
- 通过 `module.Deps` 注入，模块不再自己拼 `DataDir` 路径。这是基础代码改动，记到接口变更记录。

### 存储位置设置

- 设置里原“云盘同步”标签改名“存储”。内容：存储位置选“本机磁盘”或“S3”，S3 的地址、区域、桶、前缀、Access Key、Secret Key（加密存储，接口不回明文）、“测试连接”按钮。
- 从本机切到 S3：点“切换”后后台把 `data/files/` 全部上传到 S3，显示进度，全部成功后才切换。失败可以重试，不丢文件。从 S3 切回本机同理。
- 用 S3 时本机保留一个大小有限的缓存目录（默认 1 GB，放缩略图和最近读的文件），可以在设置里改。
- 原来的“S3 同步”功能去掉。旧配置自动迁到新设置，用户不用重填。

### 旧文件迁移

- 启动时发现旧目录（`data/drive/`、`data/notes/attachments/`）就移到新目录，数据库里存的路径同步改。只移一次，移完写一条日志。
- 迁移只加不删：数据库里旧的路径列先保留不用，下个版本再删（见 AGENTS.md）。

### 验收

- 新装的实例只有 `data/x-console.db`、`data/files/`、`data/backups/` 三项。
- 用旧数据目录启动，云盘和笔记图片都还在，能打开，旧目录已经空了。
- 用 MinIO（CI 里起一个容器，或者用假 S3）测：切到 S3 后上传云盘文件、笔记贴图，S3 里有对应的 key；本地缓存不超过设定大小；切回本机后文件都在。
- S3 的 Secret Key 在数据库里是加密的，接口只回打码的值。

## B25 整站导出导入和自动备份

### 导出

- 设置 → 新标签“备份”。
- “导出全部数据”：生成一个 `.tar.gz`，里面是数据库一致的副本（`VACUUM INTO`，B19 已有）和 `files/` 全部文件，外加 `manifest.json`（版本号、导出时间、文件数、大小）。
- 大文件用流式打包，不在内存里拼。生成后给下载链接，链接 1 小时有效。
- 导出前要提升权限（`auth.RequireElevated`）。导出包里的令牌和密钥是加密的，要用同一个主密钥（`XC_MASTER_KEY`）才能解开。界面上写清楚这一点，并提醒单独保存主密钥。

### 导入

- “从备份恢复”：上传一个导出包，或者从 S3 的备份列表里选一个。
- 先校验 `manifest.json` 和版本。版本比当前新时拒绝。
- 恢复前自动再做一次当前数据的备份。
- 恢复会替换全部数据。二次确认弹窗里要输入“恢复”两个字才能点确认。要提升权限。
- 恢复后服务重新加载（进程内重开数据库，或者退出让容器重启），前端提示“已恢复，正在重新加载”。

### 自动备份到 S3

- 开关、频率（每天、每周）、时间（默认凌晨 3 点）、保留份数（默认 14）。
- 用 B24 的 S3 配置，放在桶里的 `backups/` 前缀下。也可以单独填另一个 S3（比如存储用本机磁盘，备份用 S3）。
- 列表显示最近的备份：时间、大小、结果。失败时发一条通知。
- 备份文件名：`x-console-20260928-0300-<版本号>.tar.gz`。

### 验收

- 导出一份，在一个全新实例（同一个主密钥）里导入，登录后数据、文件、令牌都能用。
- 用不同主密钥导入时，数据能导入，但界面提示哪些令牌要重新填写，不会报 500。
- 自动备份在测试里把时间调短，能看到 S3 里按保留份数滚动。
- 导出、导入都记审计日志。
