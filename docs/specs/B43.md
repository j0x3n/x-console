# B43 远程 AI 操作：API 令牌和 MCP 接口

用户 2026-09-30 提出：让别的 AI 能远程操作 X Console，比如添加项目卡片、添加提醒、写笔记。

## 做法

用 MCP（Model Context Protocol）。这是现在各家 AI 客户端通用的“给 AI 接工具”的协议：Claude Code、Claude Desktop、Codex CLI、Cursor、Cherry Studio 都能直接连一个远程 MCP 地址。X Console 提供一个 MCP 地址，AI 连上以后就能看到“新建提醒”“新建笔记”这些工具并调用。

后端已经有现成的底子：内置 AI 助手用的动作注册表（`internal/server/actions`）。每个动作有名字、说明、JSON Schema 格式的参数、读写级别，已经有 `notes.create`、`reminders.create`、`projects.create_issue` 等 40 多个。MCP 接口只是把这个注册表按协议暴露出去，不用给每个模块单独写一遍。以后模块加了新动作，内置助手和外部 AI 同时能用。

外部 AI 不能用登录 Cookie，所以要先加 API 令牌。

## 1. API 令牌

- 新表 `api_tokens(id, name, prefix, token_hash, access, modules, expires_at, created_at, last_used_at, last_used_ip, revoked_at)`：
  - 令牌格式 `xc_` 加 32 字节随机数的 base62。只在创建时显示一次。
  - 库里只存 SHA-256 哈希和前 8 位（`prefix`，列表里给用户认）。
  - `access`：`read`（只读）、`write`（读写，不含删除）、`write_delete`（读写和删除）。
  - `modules`：允许的模块列表，JSON 数组，空数组表示全部。
  - `expires_at` 可以为空（不过期），界面默认 90 天。
- 创建、吊销令牌要调用 `auth.RequireElevated`，写审计日志。
- 认证：`auth.Middleware` 认 `Authorization: Bearer xc_…`。这是基础代码改动，要小、要向后兼容，记到“接口变更记录”：
  - 令牌只对 `/api/v1/mcp` 有效，访问其他接口回 401。以后要开放 REST 再单独排任务。
  - 用令牌得到的会话永远不是提升权限状态，`RequireElevated` 一律失败。
  - 令牌请求不走 CSRF 检查（没有 Cookie）。
  - 每个令牌每分钟最多 60 次调用，超出回 429。连续 10 次认证失败的 IP 封 15 分钟，复用 `auth/ratelimit.go`。
  - 更新 `last_used_at`、`last_used_ip`，同一分钟内只写一次库。

## 2. MCP 接口

- 地址 `POST /api/v1/mcp`，用 Streamable HTTP 传输，无状态（不需要会话、不需要 SSE 推送）。用官方 Go SDK `github.com/modelcontextprotocol/go-sdk`，或者自己按协议写 JSON-RPC，二选一，选定后写进 `docs/03-backend.md`。
- 支持 `initialize`、`tools/list`、`tools/call`、`ping`。
- `tools/list`：从 `actions.Registry.List()` 取，按令牌过滤：
  - `dangerous` 的动作（执行命令、关机、HA 危险服务等）一律不给。
  - `read` 令牌只给 `Effect == read` 的。
  - `write` 令牌不给 `Destructive` 的。
  - 不在 `modules` 里的不给。
  - 工具名把 `.` 换成 `_`（有的客户端不认点号），比如 `reminders_create`。说明文字用动作的 `Title` 和 `Description`。
- `tools/call`：再按同样规则检查一遍（不能信客户端），然后执行 `Action.Run`。
  - 审计日志的 actor 写 `token:<令牌名>`，用 `audit.WithActor`。
  - 返回：成功时把结果转成 JSON 文本放进 `content`，同时放 `structuredContent`；出错时 `isError: true`，文字写清楚原因。
- 另外暴露两个只读的“资源”可以不做，第一步只做工具。

## 3. 需要补的动作

外部 AI 常用的动作先补齐（放在各自模块里，不在 MCP 里写业务逻辑）：

- 项目：看板、列表、卡片的增改查和移动，卡片评论，检查清单条目（B46 做完后接上）。
- 日历：`calendar.list_events`、`calendar.create_event`。
- 笔记：已有，确认 `notes.search` 能按标签、按时间范围查。
- 提醒、习惯：已有。
- 每个动作的 `Description` 要写清楚参数格式，比如时间用 RFC 3339、带时区。外部 AI 只能看到这段文字。

## 4. 界面

设置里加“远程访问”页签：

- 令牌列表：名字、前 8 位、权限、模块、创建时间、上次使用（时间和 IP）、过期时间、吊销按钮（`useConfirm`）。
- 新建：名字、权限三选一、模块多选（默认全部）、有效期（30 天、90 天、1 年、不过期）。创建后弹窗显示完整令牌和复制按钮，写明“关掉以后看不到”。
- 下面是接入说明，把地址和令牌自动填好，每段有复制按钮：
  - Claude Code：`claude mcp add --transport http xconsole https://<域名>/api/v1/mcp --header "Authorization: Bearer <令牌>"`
  - Codex CLI：`~/.codex/config.toml` 里加 `[mcp_servers.xconsole]`，`url` 填地址，`bearer_token_env_var` 填环境变量名。
  - Cursor 等用 JSON 配置的客户端：`{"mcpServers":{"xconsole":{"url":"…","headers":{"Authorization":"Bearer …"}}}}`
- 最近 50 次调用记录：时间、令牌、工具、结果（成功或报错），从审计日志读。

## 第二步（另排任务，这次不做）

claude.ai 网页版和 ChatGPT 的“自定义连接器”要求 OAuth 2.1 登录，不能填固定令牌。要支持它们，需要在 X Console 上实现 OAuth 授权页（登录后点“允许”），签发和上面同样权限模型的令牌。等第一步用顺了再做。

## 安全

- 令牌能做的事严格小于登录用户：不能执行命令、不能关机、不能改设置、不能读保险库、不能管理令牌。
- 令牌泄露后果：在权限范围内增删改数据。所以默认 90 天过期，建议按用途分开建（比如一个只读给手机上的 AI，一个读写给电脑上的 Claude Code）。
- MCP 地址要公网能访问，云端 AI 才连得上。只在本地电脑用 Claude Code 的话，走内网地址也行。

## 验收

- 令牌：创建要提升权限；库里没有明文；吊销、过期后回 401；用令牌访问 `/api/v1/notes` 回 401。
- `tools/list` 按三种权限和模块过滤正确，`dangerous` 永远不出现。
- `tools/call` 调一个不在列表里的工具回错误，不执行。
- 用 `write` 令牌通过 MCP 建一条提醒，提醒页能看到，审计日志 actor 是 `token:<名字>`。
- 端到端：测试里用 MCP 客户端（Go SDK 自带的客户端即可）连上，列工具、建笔记、查笔记。
- 限流回 429。
