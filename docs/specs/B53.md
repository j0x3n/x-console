# B53 邮件：收 Gmail 和阿里企业邮箱，新邮件实时通知

用户 2026-10-01 提的：想查收 Google 邮箱和绑定域名的阿里企业邮箱，最好能实时收到 Gmail 的新邮件通知。用户原来想的是挂着 Gmail 网页拦截浏览器通知。

做法：服务器用 IMAP 连邮箱，用 IDLE 命令等新邮件。邮箱有新邮件时主动告诉服务器，一般几秒内就到，再走现有的通知渠道推送。不需要开着浏览器。网页拦截别的网站的通知做不到，要写浏览器扩展，还得一直开着 Gmail 标签页，不采用。

下面是原来的规格。

### 1. 依赖

- `github.com/emersion/go-imap/v2`（`imapclient`）：连接、登录、IDLE、取邮件、改标记。
- `github.com/emersion/go-message`（`mail` 包）：解析邮件正文和附件。加 `import _ "github.com/emersion/go-message/charset"`，国内邮件常见的 GBK、GB2312 编码才能正确解码。

### 2. 迁移

`backend/internal/server/store/migrations/20261001000700_m16_b53_mail.sql`：

```sql
-- +goose Up
CREATE TABLE mail_accounts (
    id           INTEGER PRIMARY KEY,
    name         TEXT     NOT NULL,
    email        TEXT     NOT NULL,
    provider     TEXT     NOT NULL,          -- gmail、aliyun、other
    imap_host    TEXT     NOT NULL,
    imap_port    INTEGER  NOT NULL DEFAULT 993,
    username     TEXT     NOT NULL,
    password_enc TEXT     NOT NULL,          -- m.d.Secrets.Seal
    notify       INTEGER  NOT NULL DEFAULT 1,
    uid_validity INTEGER  NOT NULL DEFAULT 0, -- 收件箱的 UIDVALIDITY，变了要重新同步
    last_uid     INTEGER  NOT NULL DEFAULT 0, -- 已经同步到的最大 UID
    last_sync_at DATETIME,
    created_at   DATETIME NOT NULL
);

CREATE TABLE mail_messages (
    id              INTEGER PRIMARY KEY,
    account_id      INTEGER  NOT NULL REFERENCES mail_accounts (id) ON DELETE CASCADE,
    uid             INTEGER  NOT NULL,
    message_id      TEXT     NOT NULL DEFAULT '', -- 邮件头的 Message-ID
    from_name       TEXT     NOT NULL DEFAULT '',
    from_address    TEXT     NOT NULL DEFAULT '',
    subject         TEXT     NOT NULL DEFAULT '',
    snippet         TEXT     NOT NULL DEFAULT '',
    date            DATETIME NOT NULL,
    unread          INTEGER  NOT NULL DEFAULT 1,
    flagged         INTEGER  NOT NULL DEFAULT 0,
    has_attachments INTEGER  NOT NULL DEFAULT 0,
    body_json       TEXT,                         -- 第一次打开时取正文，存 to、cc、html、text、attachments
    UNIQUE (account_id, uid)
);
CREATE INDEX mail_messages_date ON mail_messages (account_id, date DESC);

-- +goose Down
DROP TABLE mail_messages;
DROP TABLE mail_accounts;
```

`sqlc.yaml` 加 mail 模块（共享文件只加行），查询写在 `modules/mail/queries.sql`。

### 3. 账号接口

- `POST /mail/accounts`、`PATCH`（改服务器、登录名、密码时）、`DELETE` 先调 `auth.RequireElevated`。
- 保存前先连一次：TLS 连 `host:port`，登录，`SELECT INBOX`，超时 20 秒。失败回 400，文字按情况写：连不上服务器、TLS 握手失败、用户名或密码不对（Gmail 加一句“Gmail 要用应用专用密码”）、没开 IMAP。成功才保存。
- `provider` 是 gmail、aliyun 时服务器用固定值（`imap.gmail.com`、`imap.qiye.aliyun.com`，端口 993），忽略请求里的；other 必须填。
- 密码用 `m.d.Secrets.Seal` 加密存，接口永远不返回。审计记 `mail.account.create`、`mail.account.update`、`mail.account.delete`，不记密码。
- `GET /mail/accounts` 的 `status`、`lastError`、`idle` 来自内存里每个账号的连接状态（见下），`unread` 是本地表里未读数。

### 4. 同步和 IDLE

每个账号一个后台 goroutine（模块实现 `module.Starter`，`Start` 时为所有账号启动，增删改账号时启停对应的那个）：

1. 连接、登录、`SELECT INBOX`。看服务器的 CAPABILITY 有没有 `IDLE`，记到状态里。
2. `UIDVALIDITY` 和存的不一样时，清掉这个账号的本地邮件，`last_uid` 归零。
3. 第一次同步只取最近 200 封（按 UID 从大到小）；之后取 `UID > last_uid` 的。取 `ENVELOPE`、`FLAGS`、`INTERNALDATE`、`BODYSTRUCTURE` 和正文前 2 KB（`BODY.PEEK[TEXT]<0.2048>`，生成 `snippet`；`PEEK` 不会把邮件标成已读）。存进 `mail_messages`，更新 `last_uid`。
4. 已有邮件的已读、星标变化：每次同步时对最近 500 封取一次 `FLAGS` 更新本地，别的设备上读过的邮件这里也会变成已读。
5. 支持 IDLE 时进入 IDLE。收到 `EXISTS`（新邮件）或 `FETCH`（标记变化）就退出 IDLE，做一次第 3、4 步，再进 IDLE。每 25 分钟主动退出再进一次，Gmail 大约 30 分钟会断开空闲连接。
6. 不支持 IDLE 时每 60 秒做一次第 3、4 步。
7. 出错断开后按 10 秒、30 秒、1 分钟、5 分钟递增重试，状态设成 `error`，`lastError` 写原因。登录失败（密码不对）时不再自动重试，等用户改密码。
8. `POST /mail/accounts/{id}/sync`：通知那个 goroutine 马上同步一次，接口立刻回 202。

每次有变化时发事件 `m.d.Bus.Publish("mail.updated", map[string]any{"accountId": id})`，前端会自动刷新。连接状态变化时也发一次。

### 5. 新邮件推送

- 第 3 步里拿到的新邮件，账号 `notify` 开着、邮件是未读、并且 `INTERNALDATE` 在 10 分钟内（避免第一次同步时把旧邮件全推一遍）时推送。
- `m.d.Notify.Send`：`Kind: "mail.new"`，标题“发件人：主题”，正文是 `snippet` 前 100 字，`Link: "/mail?m=<id>"`，`Source: "mail"`。
- 一次来了超过 3 封时合成一条：“个人 Gmail 收到 5 封新邮件”，正文列前 3 个主题。

### 6. 邮件接口

- `GET /mail/messages`：按 `date` 倒序，`before` 翻页，`q` 用 `LIKE` 匹配 `from_name`、`from_address`、`subject`。
- `GET /mail/messages/{id}`：`body_json` 为空时连 IMAP 用 `BODY.PEEK[]` 取整封邮件，最多 25 MB，用 go-message 解析：`text/html` 放 `html`（超过 2 MB 截断），`text/plain` 放 `text`，没有纯文字时从 HTML 去标签生成。附件和内嵌图片列进 `attachments`（带 `Content-ID` 的是内嵌图片）。附件内容不存数据库，存到 `m.d.Files.For("mail")` 下的 `<账号 id>/<uid>/<序号>`，存完写 `body_json`。
- `PATCH /mail/messages/{id}`：用 `UID STORE` 改服务器上的 `\Seen`、`\Flagged`，成功后改本地。
- `GET /mail/messages/{id}/attachments/{index}`：从文件存储读，`Content-Disposition: attachment`。内嵌图片（有 `contentId`）用 `inline`，并且只允许图片类型，其他类型一律 `attachment`。加 `X-Content-Type-Options: nosniff`。
- `GET /mail/summary`：未读总数、每个账号的未读数和状态、最近 5 封未读。
- 删除账号时一起删文件存储里这个账号的目录。

### 7. 测试

- 用 go-imap v2 自带的内存服务器（`imapserver` 和 `imapmemserver`）起假邮箱：
  - 添加账号：密码不对时回 400 且不保存；对的时候保存，`GET` 不返回密码。
  - 同步：先放 3 封，同步后列表有 3 封；再放 1 封，IDLE 收到后几秒内列表变成 4 封，并且推送了一条通知。
  - 已读：`PATCH unread=false` 后，假服务器上这封有 `\Seen`。
  - GBK 编码的主题和正文能正确显示。
  - `UIDVALIDITY` 变了时本地重新同步。
- 删除账号后 `mail_messages` 和文件都删掉。
