# B60 AI 操作机器要经过 Agent；AI 浮窗加权限、模型和思考程度

用户 2026-10-01 提的：

- 面板 AI 没分配 Agent 也能在机器上执行命令，要限制。
- 创建 Agent 时可以选它的运行环境，比如“我的 Windows 电脑”。面板 AI 要操作某台机器时，必须找到绑定了这台机器的 Agent，交给它去做；没有就不做。机器详情的 Agent 标签（B33）照常能用。
- AI 浮窗里加权限选择（手动、写入、全部允许），以及模型和思考程度选择。设置 → AI 里的是默认值。

前后端都待做。前端和后端可以分给两个人，接口以本文“契约”一节为准。

## 现状

- 机器相关的 AI 动作在 `backend/internal/server/modules/hosts/actions.go`：`hosts.exec`（执行命令）、`hosts.service_action`、`hosts.power`（这三个是 `actions.Dangerous`）、`hosts.clipboard_set`、`hosts.open`（`actions.Write`）。面板 AI（`modules/ai`）的工具列表里有它们，只靠每步确认挡着。
- Agent（`modules/aiagents`，B47）有 `runnerAgentId`（“默认机器”），但新建 Agent 的弹窗（`web/src/features/aiagents/AgentDialog.tsx`）只列能跑 Claude Code 或 Codex 的机器，选不了一台普通的 Windows 电脑。
- 机器详情的 Agent 标签（B33）是 `/ai/host-agent/{hostId}/conversations`，有自己的权限 `HostAgentPermission`（`confirm | read_auto | all_auto`）。

## 做法

### 1. Agent 绑定机器

- `AiAgent` 加 `hostIds: string[]`：这个 Agent 能操作的机器（代理 id）。可以多选，可以为空。和原来的 `runnerAgentId`（编码任务在哪台机器上跑）是两件事，不要合并。
- 新建和编辑 Agent 的弹窗加一项“能操作的机器”，列出所有服务器和电脑（`/hosts`，不限 kind），多选，带在线状态。说明写“面板 AI 只能通过这里勾选的 Agent 操作这些机器”。
- Agent 卡片上显示绑定的机器名，最多 3 个，多了写“等 N 台”。

### 2. 面板 AI 操作机器的规则

- 面板 AI 的工具列表里去掉 `hosts.exec`、`hosts.service_action`、`hosts.power`、`hosts.clipboard_set`、`hosts.open`。读机器状态的（`hosts.list`、`hosts.metrics` 这类 `Read` 动作）保留。
- 新增一个动作 `agents.operate_host`（`Effect: Dangerous`），参数 `{host, request}`：`host` 是机器 id 或名称，`request` 是要做的事（自然语言）。执行时：
  1. 找所有 `enabled` 并且 `hostIds` 里有这台机器的 Agent。
  2. 一个都没有：返回错误“这台机器没有绑定 Agent，不能操作。可以在 Agent 页面给一个 Agent 勾选这台机器”。不执行任何命令。
  3. 有多个时，选会话里上次用过的；没用过就选第一个，并在结果里写明用了哪个 Agent。
  4. 用这个 Agent 的模型、说明和权限，在那台机器上开一个 B33 的机器会话（`hostId` 就是这台机器），把 `request` 作为第一条消息发进去，等这一轮结束，把最后的回复和执行过的命令列表返回给面板 AI。会话的权限取面板 AI 当前会话的权限档（见下）。
  5. 结果里带上机器会话的链接（`/servers/<id>/agent?c=<会话 id>` 或 `/pc?...` 对应的地址），面板里能点过去看全过程。
- 机器详情的 Agent 标签不变，在那里直接对话照常可以执行。
- `hosts.*` 这些动作本身不删，机器会话（B33）和自动化还要用。只是不再出现在面板 AI 的列表里。在 `actions` 包里加一个过滤：调用方是面板 AI 时排除这 5 个名字（看 `modules/ai` 现在是怎么组装工具列表的，在那里过滤最简单）。

### 3. 权限档

面板 AI 的会话加 `permission`，三档：

| 档 | 英文值 | 效果 |
| --- | --- | --- |
| 手动 | `manual` | 所有写入、删除、危险动作都要你点确认（现在的做法） |
| 写入 | `write` | 普通写入自动执行；删除和危险动作（包括 `agents.operate_host`）仍要确认 |
| 全部允许 | `all` | 全部自动执行。切到这一档要提升权限（`auth.RequireElevated`）；只在内存里生效，服务重启或会话 2 小时没有新消息后回到 `manual` |

- 新会话默认 `manual`，可以在设置 → AI 里改默认（只能选 `manual` 或 `write`，`all` 不能当默认）。
- `agents.operate_host` 开的机器会话：面板是 `manual` 时机器会话用 `confirm`，`write` 用 `read_auto`，`all` 用 `all_auto`。

### 4. 模型和思考程度

- 会话加 `model`（`providerId:modelId`，和 B47 内置 Agent 的写法一样）和 `effort`（沿用 B32 的思考程度取值）。不传时用设置 → AI 里对应用途的默认值。
- 每次请求模型时按会话的值走。ai 模块现在通过 context 覆盖模型选择（B47 用过），照着做。

## 契约（待改，后端先写）

`api/modules/aiagents.yaml`：

- `AiAgent`、`AiAgentInput`、`AiAgentPatch` 加 `hostIds`（字符串数组）。

`api/modules/ai.yaml`：

- `Conversation` 加 `permission`（`AiPermission`：`manual | write | all`）、`model`（字符串，可选）、`effort`（可选，用 B32 已有的思考程度类型）。
- `POST /ai/conversations` 的请求体加 `permission`、`model`、`effort`，都可选。
- 新接口 `PATCH /ai/conversations/{conversationId}/settings`：请求 `{permission?, model?, effort?}`，返回 `Conversation`。`permission: all` 要提升权限，不够时回 403 `elevation_required`（前端的 `withElevation` 会自动弹验证）。只对面板 AI 的会话有效，机器会话回 400（机器会话继续用原来的 `/permission` 接口）。
- `ModelSettings`（`/ai/model-settings`）加 `defaultPermission`（`manual | write`）。

## 实现时的调整（2026-10-01）

- `Conversation` 原来已经有 `permission`（机器会话用的 `HostAgentPermission`），面板的权限档改叫 `panelPermission`，另有 `panelPermissionUntil`（全部允许的到期时间）、`model`、`effort`。
- 新对话的默认权限：设置里没选过时，沿用原来的“所有写操作都先确认”开关，开着是手动，关着是写入，这样老用户的体验不变。设置 → AI 里那个开关换成了“新对话的默认权限”下拉框。
- 手动档：所有写入都要确认。写入档：普通写入自动，删除和高危要确认。全部允许：都不确认。
- `agents.operate_host` 只给面板 AI（`PanelOnly`），远程 AI、Agent、自动化都没有。机器会话的地址：服务器 `/servers/<id>/agent?c=<会话 id>`，电脑 `/pc/agent?c=<会话 id>`，Agent 标签按 `c` 打开那个会话。
- Agent 绑定新的机器要提升权限。

## 验收

- 没有任何 Agent 勾选你的 Windows 电脑时，让面板 AI“在电脑上打开记事本”，它回答这台机器没有绑定 Agent，电脑上什么都没发生。
- 给一个 Agent 勾选这台电脑后再问，面板 AI 弹确认，确认后交给这个 Agent 执行，回复里能点进去看执行过程。
- 浮窗里切到“写入”，让它新建一条笔记，不再弹确认；让它删除笔记，仍然弹确认。
- 浮窗里换一个模型，下一条回复用的是新模型（设置 → AI 用量里能看到）。
