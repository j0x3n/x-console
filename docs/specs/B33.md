# B33 服务器的 Agent 标签

用户要求（2026-09-28）：服务器详情加一个“Agent”标签。输入提示词，AI 在这台服务器上完成要做的操作。AI 运行在面板上，不在客户端上。

依赖 B32（Agent 模型）。

## 和“Agent 任务”的区别

- “Agent 任务”（原编码任务）是在客户端机器上启动 Claude Code 或 Codex 这类命令行工具。
- 本任务的 Agent 跑在面板进程里，用 B32 的 Agent 模型。它通过已有的代理能力（执行命令、读写文件、服务、进程、容器）操作目标机器。目标机器上不用装任何 AI 工具。

## 界面

- 服务器和电脑详情页加标签“Agent”，放在最后。
- 布局和 AI 浮窗的对话一样：上面是对话，下面是输入框。复用 `features/assistant` 的消息和动作卡片组件，不重写。
- 左侧（宽屏）或顶部下拉（窄屏）是这台机器的历史会话。
- 每一步操作显示成一张卡片：要执行的命令或动作、为什么要做、结果（输出可以折叠，超过 200 行只显示首尾）。
- 输入框上方有“权限”下拉：
  - **每步确认**（默认）：每条命令都要点“执行”。
  - **只读自动**：判断为只读的命令（见下）自动执行，其他的要确认。
  - **全部自动**：全部自动执行。选它时要提升权限，并且只在本次会话有效，关掉页面就回到默认。
- 运行中可以随时点“停止”。

## 工具

给模型的工具只针对当前这台机器：

| 工具 | 做什么 | 类别 |
| --- | --- | --- |
| `run_command` | 执行一条命令，参数：命令、工作目录、超时（默认 60 秒，最多 10 分钟） | 按命令判断 |
| `read_file` | 读文件，最多 256 KB，可以指定行范围 | 只读 |
| `write_file` | 写文件，写之前自动备份原文件到 `/tmp/xc-agent-backup/` | 写 |

- 备份安全（2026-09-30 加）：备份文件只给属主读写（0600），需要代理有 `files.private` 能力。旧代理只能备份本来就所有人可读的文件，其他文件回错误“代理版本太旧”，不写入。`/tmp/xc-agent-backup` 如果已经存在但不是普通目录（比如符号链接），取消写入。Windows 用当前用户的 TEMP，不受这两条限制。
| `list_dir` | 列目录 | 只读 |
| `system_info` | 系统、资源、磁盘、网络概况 | 只读 |
| `list_processes` / `list_services` / `list_containers` | 列表 | 只读 |
| `service_action` / `container_action` | 启停重启 | 写 |

- 只读命令的判断用白名单：命令的第一个词在列表里（`ls`、`cat`、`head`、`tail`、`grep`、`find`、`df`、`du`、`free`、`uptime`、`ps`、`top -b -n1`、`ss`、`netstat`、`ip`、`systemctl status`、`journalctl`、`docker ps`、`docker logs`、`docker inspect` 等），并且整条命令里没有 `>`、`>>`、`|` 后接写命令、`;`、`&&`、`` ` ``、`$(`。判断不出来的一律当写操作。
- 高危命令（`rm -rf /`、`mkfs`、`dd of=/dev/`、`shutdown`、`reboot`、`:(){`、改防火墙清空规则等）即使选了“全部自动”也要确认，确认要提升权限（`auth.RequireElevated`）。
- 所有工具最终都走代理已有的能力和 `contracts.Hosts`，不新开执行通道。代理对命令执行的原有限制保持不变。
- 系统提示词里写入这台机器的系统、架构、主机名、当前资源，让模型少走一步。

## 数据

- 会话和消息存在 AI 模块已有的对话表里，加一列 `host_id`（迁移只加列）。AI 浮窗的历史列表不显示带 `host_id` 的会话。
- 每条执行过的命令记审计日志，actor 写 `ai:host-agent`，内容包括命令、机器、结果码。

## 验收

- 假模型测试：模型要求执行 `df -h`，在“只读自动”下直接执行；要求 `rm -rf /tmp/x`，停下来等确认；拒绝后模型收到“用户拒绝了”并继续。
- 高危命令在“全部自动”下也要确认，且没有提升权限时不能执行。
- 真实环境：在一台服务器上让它“看看为什么磁盘快满了”，它能一步步用 `df`、`du` 找到大目录并说明。
- 停止按钮能中断正在跑的命令（代理那边的进程也被结束）。
- 审计日志里能看到每条命令。

## 契约

都在 `api/modules/ai.yaml`，和 B32 一起加的：

- `GET/POST /ai/host-agent/{hostId}/conversations`：这台机器的会话列表和新建。新会话的权限是 `confirm`。
- `PUT /ai/conversations/{conversationId}/permission`：`{mode: confirm | read_auto | all_auto}`。
- `Conversation` 加 `hostId`、`permission`。`PendingAction` 加 `effect`（`read | write | dangerous`）。
- 发消息、停止、确认、拒绝都用 `/ai/conversations` 下已有的接口。
- 工具名（给模型的）：`host__run_command`、`host__read_file`、`host__write_file`、`host__list_dir`、`host__system_info`、`host__list_processes`、`host__list_services`、`host__list_containers`、`host__service_action`、`host__container_action`。前端按这些名字显示中文标题，改名要两边一起改。
- `modules/ai/pending.go` 里这几个接口先回 501。
- 远端日志（`api/modules/hosts.yaml`）：`GET /hosts/{hostId}/files/range?path=&offset=&length=`（最多 1 MB，响应头 `X-File-Size`），`GET /hosts/{hostId}/files/follow?path=&offset=`（WebSocket，帧是 `HostFileFollowFrame`，和云盘的一样）。`modules/hosts/pending.go` 先回 501。

### 1. 迁移

```sql
-- +goose Up
ALTER TABLE ai_conversations ADD COLUMN host_id TEXT;
ALTER TABLE ai_pending_actions ADD COLUMN effect TEXT;
CREATE INDEX ai_conversations_host ON ai_conversations(host_id, updated_at DESC) WHERE host_id IS NOT NULL;
```

- 文件名 `20260929000300_m12_b33_host_agent.sql`，时间排在 B32 那个之后。
- 权限不存库：`confirm` 是默认，`all_auto` 只在内存里（见第 4 步）。`read_auto` 存在内存里就够了，服务重启后回到 `confirm`，前端每次打开会重新读。

### 2. 接口

- `GET /ai/conversations` 加条件 `host_id IS NULL`，AI 浮窗不显示机器的会话。
- `GET /ai/host-agent/{hostId}/conversations`：机器不存在回 404（用 `contracts.Hosts` 或 hosts 模块的查询确认）。按 `updated_at` 倒序，最多 50 条。每条带 `hostId` 和当前 `permission`。
- `POST`：建会话，写 `host_id`。
- `GET /ai/conversations/{id}` 返回的 `conversation` 带 `hostId`、`permission`；`pendingActions` 带 `effect`。
- `PUT permission`：会话没有 `host_id` 回 400 `not_host_conversation`。`all_auto` 要 `auth.RequireElevated`，其他两个不要。回 `{mode}`。发 `ai.permission_changed` 事件。

### 3. 工具 `hostagent/tools.go`

- 机器的会话只给这 10 个工具，不给 `d.Actions.List()` 里的面板动作（避免 Agent 去改笔记、提醒）。
- 每个工具的参数都加一个可选的 `reason`（字符串，“为什么要做这一步”），在工具说明里要求模型填。前端会显示。
- 实现都走代理已有的方法，通过 `d.Agents.Call(ctx, hostID, method, params, &out)`：

| 工具 | 代理方法 | 说明 |
| --- | --- | --- |
| `run_command` | `exec.run` | 参数 `command`、`cwd`、`timeout`（秒，默认 60，最大 600）。结果是 `{exitCode, stdout, stderr}`，各截到 64 KB，截断时在末尾写明 |
| `read_file` | `files.read` | 最多 256 KB，可选 `startLine`、`endLine`。二进制文件（前 8 KB 里有 0 字节）只回“这是二进制文件” |
| `write_file` | `files.read` + `files.write` | 先把原文件读出来写到 `/tmp/xc-agent-backup/<时间>-<文件名>`（Windows 用 `%TEMP%`），再写新内容。结果里写备份路径 |
| `list_dir` | `files.list` | 最多 500 条 |
| `system_info` | `system.info` + 最近一次指标 | 系统、CPU、内存、磁盘、网络 |
| `list_processes` | `proc.list` | 按 CPU 排序，最多 50 条 |
| `list_services` | `svc.list` | 可选 `filter` |
| `list_containers` | `docker.ps` | 机器没有 docker 能力时回错误“这台机器没有 Docker” |
| `service_action` | `svc.action` | `start`、`stop`、`restart` |
| `container_action` | `docker.action` | `start`、`stop`、`restart` |

- 机器没有对应能力时（`capabilities` 里没有），工具直接回错误，不去调代理。
- 工具出错也作为 `tool_result`（`is_error: true`）回给模型，让它自己换办法，不中断对话。

### 4. 风险判断 `hostagent/classify.go`

- `classify(tool, input) effect`：
  - `read_file`、`list_dir`、`system_info`、`list_*` 是 `read`。
  - `write_file`、`service_action`、`container_action` 是 `write`。
  - `run_command` 按命令判断，见下。
- 只读命令：整条命令去掉首尾空格后，不含 `>`、`<`（heredoc）、`;`、`&&`、`||`、`` ` ``、`$(`、换行。允许用 `|` 串起来，但每一段的第一个词都要在白名单里。白名单：`ls`、`cat`、`head`、`tail`、`grep`、`egrep`、`find`（不能带 `-delete`、`-exec`、`-ok`）、`df`、`du`、`free`、`uptime`、`ps`、`top`（要带 `-b`）、`ss`、`netstat`、`ip`（只允许 `addr`、`route`、`link` 后面不跟 `set`、`add`、`del`）、`wc`、`sort`、`uniq`、`awk`（不含 `system(`）、`sed`（不带 `-i`）、`stat`、`file`、`which`、`whoami`、`id`、`hostname`、`uname`、`date`、`lsblk`、`mount`（不带参数）、`env`、`printenv`、`journalctl`、`systemctl`（只允许 `status`、`list-units`、`is-active`、`is-enabled`、`show`）、`docker`（只允许 `ps`、`logs`、`inspect`、`images`、`stats --no-stream`）。Windows 上加 `Get-*` 开头的 PowerShell 命令、`dir`、`type`、`ipconfig`、`tasklist`。判断不出来的一律是 `write`。
- 高危命令是 `dangerous`：`rm` 带 `-r` 且路径是 `/`、`/*`、`~`、`/etc`、`/usr`、`/var`、`/home` 这类顶层目录；`mkfs`；`dd` 且 `of=/dev/`；`shutdown`、`reboot`、`poweroff`、`halt`、`init 0`、`init 6`；fork 炸弹 `:(){`；`iptables -F`、`nft flush`、`ufw disable`；`chmod -R 777 /`、`chown -R` 到顶层目录；`> /dev/sd`。用正则写成一张表，每条写一个测试。
- 放在 `hostagent` 包里，是纯函数，测试用表驱动覆盖上面每一条和一些绕过写法（多空格、绝对路径 `/bin/rm`、`sudo rm`）。`sudo` 开头的命令去掉 `sudo` 再判断，判断结果至少是 `write`。

### 5. 执行和确认

- 在现有的 `generate()` 循环里，机器会话的工具调用按下面决定要不要停下来等确认：

| 权限 | read | write | dangerous |
| --- | --- | --- | --- |
| `confirm` | 等确认 | 等确认 | 等确认，确认要提升权限 |
| `read_auto` | 自动 | 等确认 | 等确认，确认要提升权限 |
| `all_auto` | 自动 | 自动 | 等确认，确认要提升权限 |

- 等确认时写 `ai_pending_actions`，同时写 `effect`。确认接口（`ApproveAiAction`）里，`effect` 是 `dangerous` 时要 `auth.RequireElevated`，没有提升回 403（前端已经用 `withElevation` 包了）。
- `all_auto` 存在 `Module` 的内存里：`map[conversationID]time.Time`（设置的时间）。超过 2 小时没有新消息自动失效，服务重启全部失效。
- 停止：`StopAiReply` 取消这一轮的 context。`d.Agents.Call` 的 context 取消后，确认代理那边的 `exec.run` 会结束进程。如果现在不会，在代理的 `exec` 包里补上：收到取消就杀掉整个进程组（Linux 用 `Setpgid` 加 `syscall.Kill(-pid, SIGKILL)`，Windows 用 job object 或 `taskkill /T /F`）。这一步要改 `internal/agent/exec`，在“接口变更记录”里记一笔。
- 系统提示词：在 B32 的系统提示词后面加一段机器信息（名称、主机名、系统、架构、CPU 核数、内存、磁盘占用、是否在线），并说明“你只能通过工具操作这台机器；先看再改；改文件前说明原因；每一步都填 reason”。
- 机器离线时，工具回错误“机器离线”，模型会告诉用户。

### 6. 审计

- 每次执行（不管自动还是确认后）记一条审计：action `ai.host_agent.exec`，actor 写 `ai:host-agent`，target 是机器 id，内容包括工具名、命令或路径、退出码、耗时，不存完整输出。
- 改权限记 `ai.host_agent.permission`。

### 7. 远端日志（hosts 模块和代理）

- 代理：`FilesReadParams` 加可选的 `Offset`、`Length`（`int64`，`omitempty`）。`Length` 大于 0 时只读这一段（`Seek` 后读 `Length` 字节）。旧代理不认这两个字段会从头读整个文件，所以加一个新能力 `files.range`（`protocol.CapFilesRange`），在 `capabilities()` 里上报。
- `GET /hosts/{id}/files/range`：机器没有 `files.range` 能力回 501（前端会显示“还没上线”）。调 `files.read` 带 `Offset`、`Length`，把 `FileHeader.Size` 写进 `X-File-Size`。`length` 超过 1 MB 回 400。权限和现有的 `GET files/content` 一样（登录即可，不用提升）。
- `GET /hosts/{id}/files/follow`：WebSocket。每秒调一次 `files.list` 的父目录（或者给代理加一个 `files.stat`，二选一，选简单的），比较大小：变大就用 `files.read` 读新增部分推过去，一帧最多 256 KB；变小先推 `{type: "reset"}`，再从 0 开始。写 WebSocket 时不要用会被取消的 context（`AGENTS.md` 的规则）。连接断开或机器离线就停。和云盘的 `follow.go` 共用解码和分帧的代码，放到 `internal/server/httpx` 或一个小的公共包里，在“接口变更记录”记一笔。
- 测试：假代理返回一个 3 MB 的文件，读最后 1 MB 和前面一段；实时模式追加一行能收到；文件变小收到 `reset`；没有 `files.range` 能力回 501。代理端 `files` 包测 `Offset`、`Length`。
