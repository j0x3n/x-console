# B33 服务器的 Agent 标签

用户要求（2026-09-28）：服务器详情加一个“Agent”标签。输入提示词，AI 在这台服务器上完成要做的操作。AI 运行在面板上，不在客户端上。

依赖 B32（Agent 模型）。

## 和“Agent 任务”的区别

- “Agent 任务”（原编码任务）是在客户端机器上启动 Claude Code 或 Codex 这类命令行工具。
- 本任务的 Agent 跑在面板进程里，用 B32 的 Agent 模型。它通过已有的代理能力（执行命令、读写文件、服务、进程、容器）操作目标机器。目标机器上不用装任何 AI 工具。

## 界面

- 服务器和电脑详情页加标签“Agent”，放在最后。
- 布局和 AI 浮窗的对话一样：上面是对话，下面是输入框。复用 `features/assistant` 的消息和动作卡片组件，不重写。
- 左侧（宽屏）或顶部下拉（窄屏）是这台机器的历史会话。
- 每一步操作显示成一张卡片：要执行的命令或动作、为什么要做、结果（输出可以折叠，超过 200 行只显示首尾）。
- 输入框上方有“权限”下拉：
  - **每步确认**（默认）：每条命令都要点“执行”。
  - **只读自动**：判断为只读的命令（见下）自动执行，其他的要确认。
  - **全部自动**：全部自动执行。选它时要提升权限，并且只在本次会话有效，关掉页面就回到默认。
- 运行中可以随时点“停止”。

## 工具

给模型的工具只针对当前这台机器：

| 工具 | 做什么 | 类别 |
| --- | --- | --- |
| `run_command` | 执行一条命令，参数：命令、工作目录、超时（默认 60 秒，最多 10 分钟） | 按命令判断 |
| `read_file` | 读文件，最多 256 KB，可以指定行范围 | 只读 |
| `write_file` | 写文件，写之前自动备份原文件到 `/tmp/xc-agent-backup/` | 写 |
| `list_dir` | 列目录 | 只读 |
| `system_info` | 系统、资源、磁盘、网络概况 | 只读 |
| `list_processes` / `list_services` / `list_containers` | 列表 | 只读 |
| `service_action` / `container_action` | 启停重启 | 写 |

- 只读命令的判断用白名单：命令的第一个词在列表里（`ls`、`cat`、`head`、`tail`、`grep`、`find`、`df`、`du`、`free`、`uptime`、`ps`、`top -b -n1`、`ss`、`netstat`、`ip`、`systemctl status`、`journalctl`、`docker ps`、`docker logs`、`docker inspect` 等），并且整条命令里没有 `>`、`>>`、`|` 后接写命令、`;`、`&&`、`` ` ``、`$(`。判断不出来的一律当写操作。
- 高危命令（`rm -rf /`、`mkfs`、`dd of=/dev/`、`shutdown`、`reboot`、`:(){`、改防火墙清空规则等）即使选了“全部自动”也要确认，确认要提升权限（`auth.RequireElevated`）。
- 所有工具最终都走代理已有的能力和 `contracts.Hosts`，不新开执行通道。代理对命令执行的原有限制保持不变。
- 系统提示词里写入这台机器的系统、架构、主机名、当前资源，让模型少走一步。

## 数据

- 会话和消息存在 AI 模块已有的对话表里，加一列 `host_id`（迁移只加列）。AI 浮窗的历史列表不显示带 `host_id` 的会话。
- 每条执行过的命令记审计日志，actor 写 `ai:host-agent`，内容包括命令、机器、结果码。

## 验收

- 假模型测试：模型要求执行 `df -h`，在“只读自动”下直接执行；要求 `rm -rf /tmp/x`，停下来等确认；拒绝后模型收到“用户拒绝了”并继续。
- 高危命令在“全部自动”下也要确认，且没有提升权限时不能执行。
- 真实环境：在一台服务器上让它“看看为什么磁盘快满了”，它能一步步用 `df`、`du` 找到大目录并说明。
- 停止按钮能中断正在跑的命令（代理那边的进程也被结束）。
- 审计日志里能看到每条命令。
