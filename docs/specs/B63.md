# B63 备份到网盘：WebDAV 和 Google Drive

用户 2026-10-01 提的：能不能集成谷歌云盘等网盘用于备份。用户确认先做 WebDAV 和 Google Drive，OneDrive 不做。服务器在国外，能连 Google。

2026-10-01 前后端都已做完（Claude，在 `develop` 上）。和下面写法不同的地方：

- 没有用 `golang.org/x/oauth2` 和 `google.golang.org/api/drive/v3`，直接用 `net/http` 调 Google 的接口，少两个大依赖，测试也好假。
- WebDAV 和 Google Drive 目录里直接放备份文件，不再套一层 `backups/`（备份模块里的 `flat` 做转换）。
- Google Drive 的文件名就是 key，同名文件以最新的为准。上传完新文件才删旧的同名文件。
- `GET /backups/gdrive/auth` 的返回多了 `redirectUri`。点“授权”时前端先只保存客户端 ID、密钥和文件夹名（不改备份位置和开关），再跳到 Google。
- 改了客户端 ID 会清掉原来的授权；改了文件夹名，下次按新名字找或新建文件夹。
- 回调靠一次性的 `state` 校验（10 分钟有效，用一次就作废），存在内存里，服务重启后要重新点授权。

## 现状

- 备份模块 `backend/internal/server/modules/backup/`（B25）。自动备份的目标在设置里：`target` 是 `storage`（用“存储”里的 S3）或 `custom`（单独填一个 S3）。
- 上传、列出、清理旧备份都通过 `files.Store` 接口（`backend/internal/server/files/files.go`：`Put`、`Get`、`GetRange`、`Stat`、`Delete`、`List`、`Copy`）。`auto.go` 的 `remoteFor` 按设置返回一个 `files.Store`。
- 所以新目标只要各写一个 `files.Store` 的实现，再在 `remoteFor` 里多两个分支。

## 做法

### WebDAV

- 一次实现能接很多家：坚果云、Nextcloud、群晖、alist（alist 又能挂百度网盘、阿里云盘、OneDrive 等）。
- 填：地址（比如 `https://dav.jianguoyun.com/dav/`）、用户名、密码（坚果云要用“应用密码”）、目录（默认 `x-console-backups`）。
- 实现用标准的 WebDAV 方法：`PUT` 上传，`GET`（带 `Range`）下载，`PROPFIND`（`Depth: 1`）列目录和取大小时间，`DELETE` 删除，`MKCOL` 建目录，`COPY` 复制。可以用 `github.com/studio-b12/gowebdav`，也可以自己写，代码量不大。
- 上传大文件：先传到 `<名字>.part`，传完再 `MOVE` 成正式名字，这样中途失败不会留下半个文件冒充备份（对应 `files.Store` 里“读者看不到写了一半的文件”的要求）。

### Google Drive

- 自己部署的面板没法共用一个 Google 应用，用户要在 Google Cloud 里自己建一个 OAuth 客户端：
  1. 在 Google Cloud 控制台建一个项目，启用 Google Drive API。
  2. 配置 OAuth 同意屏幕（外部、测试用户填自己的 Gmail）。
  3. 建一个“Web 应用”类型的 OAuth 客户端，已获授权的重定向 URI 填 `<面板地址>/api/v1/backups/gdrive/callback`。
  4. 把客户端 ID 和密钥填到面板，点“授权”，在 Google 页面同意。
- 只申请 `https://www.googleapis.com/auth/drive.file` 权限：面板只能看到它自己建的文件，看不到网盘里的其他东西。
- 备份放在网盘根目录下一个文件夹里（默认 `X Console 备份`），文件夹 id 记下来。
- 用 `golang.org/x/oauth2` 和 `google.golang.org/api/drive/v3`。上传用可续传上传（resumable upload）。
- 注意：Google 同意屏幕是“测试”状态时，refresh token 7 天就过期。设置页要提示把同意屏幕“发布”成正式版（个人用，不需要 Google 审核也能发布，只是授权时会有“未经验证的应用”提示，点继续即可）。refresh token 失效时，自动备份失败并推送通知“Google Drive 授权过期，请重新授权”。

## 契约（待改，`api/modules/backup.yaml`）

- `BackupSettings.target` 的取值加 `webdav`、`gdrive`。
- `BackupSettings` 加：
  - `webdav: {url, username, password?, folder}`。返回时没有 `password`，改成 `passwordSet: boolean`。保存时 `password` 不传表示不改。
  - `gdrive: {clientId, clientSecret?, folderName, authorized: boolean, account?: string}`。返回时没有 `clientSecret`，有 `secretSet`；`authorized` 和 `account`（授权的 Google 账号邮箱）只读。
- 新接口：
  - `POST /backups/target/test`：用请求体里的设置（和保存时一样的结构）试一次：建目录、写一个小文件、读回来、删掉。返回 `{ok, message}`。
  - `GET /backups/gdrive/auth`：返回 `{url}`，前端打开这个 Google 授权地址。`state` 参数用一次性随机值，存 10 分钟。要提升权限。
  - `GET /backups/gdrive/callback`：Google 跳回来的地址。校验 `state`，用 `code` 换 token，存 refresh token，然后 302 到 `/settings/backup?gdrive=ok`（失败时 `?gdrive=error&message=...`）。这个地址不用登录 cookie 也要能用（加进 `app.go` 的公开路径列表，靠 `state` 校验），但 `state` 必须是当前登录用户刚刚生成的。
  - `DELETE /backups/gdrive/auth`：撤销授权（调 Google 的 revoke 接口，删掉本地 token）。

## 后端（待做）

1. `backend/internal/server/files/webdav.go`：`files.Store` 的 WebDAV 实现，带单元测试（用 `golang.org/x/net/webdav` 起一个内存 WebDAV 服务测 `Put`、`Get`、`GetRange`、`List`、`Delete`、`.part` 改名）。
2. `backend/internal/server/files/gdrive.go`：`files.Store` 的 Google Drive 实现。`key` 是文件名（备份目录是平的，不用处理多级目录）。`List` 用 `files.list`，查询条件 `'<文件夹 id>' in parents and trashed = false`。`GetRange` 用 `alt=media` 加 `Range` 头。测试用 `httptest` 假一个 Drive API。
   - 这两个是基础代码（`backend/internal/server/files`），按 AGENTS.md 的要求在 PR 里说明，在“接口变更记录”里记一笔。
3. `modules/backup/auto.go` 的 `remoteFor`：按 `target` 返回对应的 Store。WebDAV 密码、Google 的 client secret 和 refresh token 都用 `m.d.Settings.SetSecret` 加密存。
4. 手动导出的备份文件，在备份列表里照旧；`GET /backups` 列出远端备份时，来源写 `webdav` 或 `gdrive`（`BackupItem` 的来源枚举加这两个值）。从远端恢复、下载照旧走 `files.Store`。
5. 授权接口和回调见契约。审计记 `backup.gdrive.authorize`、`backup.gdrive.revoke`、`backup.settings`（不记密码和密钥）。
6. 测试：WebDAV 和 Google Drive 两种目标下，自动备份能上传、按 `keep` 清理旧的、能从远端恢复；Google token 失效时自动备份记失败并发通知；回调的 `state` 不对时拒绝。

## 验收

- 选 WebDAV 填坚果云，点测试成功，立即备份一次，坚果云里出现备份文件。
- 选 Google Drive，按步骤建好 OAuth 客户端，授权后立即备份一次，Google Drive 的“X Console 备份”文件夹里出现文件。设 `keep` 为 2，备份 3 次后只剩 2 个。
- 从 Google Drive 上的备份恢复成功。
