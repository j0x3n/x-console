# M1 今日（首页）

状态：待做（任务 B2）。第一轮只做前端，第二轮补后端。

## 目标

打开面板第一眼看到今天要关心的事。

2026-09-27 用户要求参考初版（提交 `3215f0f`，`src/features/today/`）的“今日”页。侧边栏第一项从“概览”改名为“今日”。

## 依赖

- B10 先做。今日页用 B10 新增的 `StatStrip`、`Section` 和统一后的 `PageHeading`。
- 数据全部来自各模块已有的接口。只有布局接口是新的。

## 版式

照初版“今日”：

- 顶部：大字问候，下面一行概况，右侧是日期和时间。
  - 问候按本地时间分四段：早上好（5 到 11 点）、中午好（11 到 13 点）、下午好（13 到 18 点）、晚上好（其余）。后面接用户名，用户名取 `GET /auth/status` 的 `username`。
  - 概况一句话，只列有数据的项，比如“今天 3 个待办，2 个提醒，服务器全部在线”。有服务器离线或告警时改成“1 台服务器离线”。
  - 时间每分钟刷新，用 `features/calendar` 的 `useNow`。
- 一排概要卡片（`StatStrip`），见下面“概要卡片”。
- 下面两栏：
  - 左栏宽，放“今日待办”和“待你决定”。
  - 右栏窄，放“日程”“习惯”“智能家居”“天气”“最近动态”。
- 宽度小于 1100px 时单列，顺序和编辑模式里的顺序一致。
- 390px 下不能横向滚动。

## 概要卡片

| 卡片 | 大数字 | 说明行 | 迷你图 | 点击去哪 |
| --- | --- | --- | --- | --- |
| 今日待办 | 今天到期的未完成 Issue 数 | “逾期 N 个” | 无 | /projects |
| 提醒 | 今天的提醒数 | 下一条的时间和标题 | 无 | /reminders |
| 习惯 | 今天完成几项 / 共几项 | 最长连续天数 | 环 | /habits |
| 服务器 | 在线数 / 总数 | 告警数，没有就写“一切正常” | 无 | /servers |
| 编码任务 | 运行中的数量 | “N 个等你确认” | 无 | /coding |
| 下一项日程 | 开始时间 | 标题 | 无 | /calendar |

某个模块没数据或出错时，这张卡片显示“—”和一句原因，不影响别的卡片。

## 分区

| 分区 | 数据来源（已有接口） | 内容 | 点击去哪 |
| --- | --- | --- | --- |
| 今日待办 | `GET /issues?due=today`、`GET /issues?due=overdue` | 逾期的在前，标红。每条显示编号、标题、项目、优先级。最多 8 条，多了显示“查看全部” | Issue 详情 `/projects/:key/:number` |
| 待你决定 | `GET /coding/tasks?status=review`，逾期 Issue 不重复放 | 等你确认的编码任务：仓库、标题、改动文件数。按钮“查看改动” | `/coding/:taskId` |
| 日程 | `GET /calendar/events?from=今天0点&to=明天0点`（`useCalendarEvents`） | 时间轴列表，正在进行的高亮 | /calendar |
| 习惯 | `GET /habits/today`（`useHabitsToday`） | 每个习惯一行，能直接打卡（`useCheckin`）和撤销（`useUndoCheckin`） | /habits |
| 智能家居 | `GET /ha/favorites`（`useHAFavorites`） | 收藏的实体，开关类能直接切换（`useCallService`） | /home |
| 天气 | `GET /weather` | 当前温度、天气、今天最高最低 | 无 |
| 最近动态 | `GET /audit?limit=10`、`GET /notifications?limit=10` | 两者按时间合并，取前 10 条 | 通知有链接时跳过去 |

所有分区都用 B10 的 `Section`，标题右侧显示数量。

## 前端要做的事

只改 `web/src/features/overview/`，另外两处小改动见下面。

1. `routes.tsx`：用 `TodayPage` 替换 `ComingSoon`。页面标题用新的英文键 `Today page`，中文“今日”。不能用 `Today`，它已经是“今天”。
2. `app/nav.ts`：第一项的 `label` 从 `Overview` 改成 `Today page`，图标换成 `Sun`。这是基础代码，改动只有一行，在 `docs/tasks.md` 的“接口变更记录”里记一笔。
3. `api.ts`：本模块要的查询放这里。
   - 其他模块已有的 hooks 直接引用：`useHabitsToday`、`useCheckin`、`useUndoCheckin`、`useReminders("today")`、`useHosts`、`useTasks`、`useCalendarEvents`、`useHAFavorites`、`useCallService`、`useNotifications`。
   - 没有现成 hook 的自己写：`useDueIssues(due)`、`useWeather()`、`useAuditRecent()`、`useDashboardLayout()`、`useSaveDashboardLayout()`。query key 用 `["overview", ...]` 开头。天气的 key 用 `features/calendar/api.ts` 里已有的 `["calendar","weather"]`，这样早报页和今日页共用缓存。
4. 每张卡片、每个分区一个组件，放在 `components/`。
5. 错误边界：新写一个 `CardBoundary`（放在本模块）。子组件抛错时只显示“这块加载失败”和“重试”按钮，点重试重置边界并重新请求。
6. 空状态：
   - 没配置集成时显示一句话和“去设置”按钮。判断依据：HA `GET /ha/status` 的 `configured` 为 false；天气接口返回 412；没有日历；没有主机；没有习惯。
   - 有配置但今天没数据时显示“今天没有 X”。
7. 编辑模式：
   - 页头右上角“编辑布局”按钮。进入后每个分区显示拖动把手和显示开关，页头按钮变成“完成”和“恢复默认”。
   - 桌面用拖动排序，手机用上移下移按钮。拖动用原生 HTML5 拖放，不加新依赖。
   - 两栏各自排序，不能把分区拖到另一栏。
   - 点“完成”时调用 `PUT /dashboard/layout`。
8. 布局接口没上线时（返回 404）：
   - 用默认布局显示，页面照常能用。
   - 编辑模式照常能改，改完先存在 `localStorage` 的 `xc.dashboard.layout`，读取时要 try/catch。
   - 编辑模式顶部显示一行提示：“布局同步功能还没上线，现在只存在这台设备上”。
   - 接口上线后，以服务端为准。服务端没有布局而本地有时，把本地的上传一次。
9. 刷新：进入页面时拉一次。页面停留时，编码任务和服务器每 30 秒刷新一次，其余用各模块已有的刷新方式。
10. 中文词典写在本模块的 `i18n.ts`，注意全局词典规则。

## 接口

### 已有接口够用

上面表里的数据都有现成接口，不用改后端。几个要注意的地方：

- `GET /issues` 的 `due` 只接受 `today`、`week`、`overdue`。今日待办要调两次。
- `GET /weather` 在没设置位置时返回 412，前端按“去设置”处理，跳到早报设置。
- `GET /coding/tasks` 的 `status` 可以传多个，`review` 就是“等你确认”。
- `Host.activeAlerts` 已经有告警数，不用再调告警接口。

### 缺的接口：布局

第一轮写好契约 `api/modules/dashboard.yaml`，跑 `npm run gen:api`。后端第二轮做。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/dashboard/layout` | 返回 `DashboardLayout`。没存过时返回默认布局，不返回 404 |
| PUT | `/dashboard/layout` | 整体替换，返回保存后的 `DashboardLayout` |

```yaml
DashboardLayout:
  type: object
  required: [version, cards]
  properties:
    version: { type: integer, description: 目前是 1 }
    cards:
      type: array
      items: { $ref: "#/components/schemas/DashboardCard" }
DashboardCard:
  type: object
  required: [id, visible, column, order]
  properties:
    id: { type: string, description: 分区 id，比如 todo、decisions、agenda、habits、home、weather、activity }
    visible: { type: boolean }
    column: { type: string, enum: [main, side] }
    order: { type: integer }
```

- 概要卡片那一排固定显示，不参与布局。
- 前端遇到不认识的 `id` 直接忽略。布局里缺的分区按默认位置补上，默认显示。

### 第二轮的后端

- 新建 `modules/dashboard`，存在 `settings` 的 `dashboard.layout` 键。
- PUT 时校验：`id` 不能重复，`column` 只能是两个值，`cards` 最多 50 条。不认识的 `id` 保留，不报错。
- 写集成测试：没存过时返回默认布局；保存后能读回；重复 id 返回 400。
