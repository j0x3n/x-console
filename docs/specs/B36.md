# B36 项目：二级分类、检查清单、截止到分钟、粘贴图片、工具栏合并

用户要求（2026-09-28）：

1. 项目内支持二级分类。
2. Issue 编辑时可以加子功能勾选框，和 Trello 的检查清单一样。
3. 截止日期精确到分钟，到期时弹出站内通知。
4. 内容里可以粘贴图片。站内所有文件分类放在一个目录下方便备份（B24 已经定了目录）。
5. 看板上方的名称缩写、显示方式、分组这些，都合并到搜索那一行。

## 1. 二级分类

用户原话是“项目内支持二级分类”。按下面理解，验收时和用户确认：**一个项目里的 Issue 可以归到分类下，分类最多两级**。比如项目“X Console”下有“后端 / 服务器”“后端 / 云盘”“前端 / 设置页”。

- 新表 `project_categories(id, project_id, parent_id, name, position)`。`parent_id` 为空是一级，一级下面可以有二级，不能再往下。
- `issues` 加列 `category_id`，可以为空。
- 项目设置里管理分类：新建、改名、拖动排序、删除（删除时里面的 Issue 变成“未分类”，二次确认）。
- 侧边栏里项目的二级菜单显示一级分类（`registerNavChildren`，最多 5 条）。
- 看板和列表的工具栏加“分类”筛选，选一级时包含它下面的二级。
- “分组”下拉加一项“按分类分组”。
- Issue 卡片上显示分类名（小字，`一级 / 二级`）。
- 新建和编辑 Issue 时可以选分类，下拉按两级缩进显示。

如果用户的意思是“项目列表分组”（项目本身分两级），改成：`projects` 加 `group_id`，项目列表按分组显示。开工前先确认。

## 2. 检查清单

- 一个 Issue 可以有多个检查清单，每个清单有标题和若干条目。条目：文字、是否完成、顺序。
- 新表 `issue_checklists(id, issue_id, title, position)`、`issue_checklist_items(id, checklist_id, text, done, position, done_at)`。
- Issue 详情里，描述下面显示清单：
  - 标题旁边显示进度 `3/5` 和一条进度条。
  - 勾选条目立即保存。点文字可以编辑，回车保存并新建下一条。拖动排序。
  - “隐藏已完成的条目”开关。
  - 清单和条目都可以删除，删除清单要二次确认。
- 看板卡片上显示总进度 `☑ 3/5`，全部完成时变成 `ok` 颜色。
- Issue 的“更多”菜单里有“添加检查清单”。
- 条目可以“转成 Issue”：新建一个 Issue，标题用条目文字，原条目删掉。
- 事件：`issue.checklist_changed`，前端据此刷新。

## 3. 截止时间精确到分钟

- `issues` 加列 `due_at`（UTC 时间，可以为空）。原 `due_date` 先保留（迁移只加不删）：迁移时把已有的 `due_date` 写成当天 23:59（服务器时区）的 `due_at`。接口里新增 `dueAt`，`dueDate` 标记为废弃，下个版本删。
- 编辑界面：日期加时间（`datetime-local`），可以只选日期（这时时间默认 23:59）。
- 列表和卡片上：今天到期的显示“今天 18:00”；已过期的用 `danger` 颜色，写“已过期 2 小时”。
- 到期提醒：
  - 每分钟检查一次，到期且没完成的 Issue 发一条通知（`issue.due`，站内和已开的推送渠道都发），每条 Issue 只发一次；改了截止时间后重新算。
  - Issue 里可以选“提前提醒”：不提醒、到期时（默认）、提前 15 分钟、1 小时、1 天。
  - 通知点开跳到这个 Issue。
  - 站内通知的弹出和声音走已有的通知中心，不单独做。
- 排序“截止日期”和筛选“今天到期 / 7 天内 / 已过期”改用 `due_at`。

## 后端（待做，给开发者）

按下面的顺序做，每一步都能单独测。新代码放在 `modules/projects/` 下，按功能分文件：`categories.go`、`checklists.go`、`due.go`。公共上传是新模块 `modules/files/`。每做完一部分，把对应的函数从 `pending.go` 删掉。

### 1. 迁移 `20260929000100_m5_b36_categories_checklists_due.sql`

时间要晚于当时最新的迁移，文件名里的时间按实际改。

```sql
CREATE TABLE project_categories (
  id INTEGER PRIMARY KEY,
  project_id INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  parent_id INTEGER REFERENCES project_categories(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  position REAL NOT NULL DEFAULT 0
);
CREATE INDEX project_categories_project ON project_categories(project_id, parent_id, position);

ALTER TABLE issues ADD COLUMN category_id INTEGER REFERENCES project_categories(id) ON DELETE SET NULL;
ALTER TABLE issues ADD COLUMN due_at TEXT;            -- UTC，RFC 3339
ALTER TABLE issues ADD COLUMN due_remind TEXT NOT NULL DEFAULT 'at_due';
ALTER TABLE issues ADD COLUMN due_notified_at TEXT;   -- 已经为哪个 due_at 发过提醒
CREATE INDEX issues_due_at ON issues(due_at) WHERE due_at IS NOT NULL;

CREATE TABLE issue_checklists (
  id INTEGER PRIMARY KEY,
  issue_id INTEGER NOT NULL REFERENCES issues(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  position REAL NOT NULL DEFAULT 0
);
CREATE TABLE issue_checklist_items (
  id INTEGER PRIMARY KEY,
  checklist_id INTEGER NOT NULL REFERENCES issue_checklists(id) ON DELETE CASCADE,
  text TEXT NOT NULL,
  done INTEGER NOT NULL DEFAULT 0,
  position REAL NOT NULL DEFAULT 0,
  done_at TEXT
);
CREATE INDEX issue_checklist_items_list ON issue_checklist_items(checklist_id, position);
```

- 先确认库里打开了外键（`PRAGMA foreign_keys`），没打开的话 `ON DELETE` 不生效，删除时要自己删。
- 已有的 `due_date` 转成 `due_at`：Go 里做（SQL 拿不到服务器时区）。启动时如果有 `due_date` 不为空、`due_at` 为空的行，按 `Scheduler.Location()` 的当天 23:59 算出 UTC 写进去。只跑一次，可以用 settings 里的一个标记。
- `due_date` 列不删（迁移只加不删）。接口里 `dueDate` 继续返回，值是 `due_at` 在服务器时区的日期。概览页（`features/overview`）还在用 `dueDate`，下个版本改完再删。
- 旧客户端只发 `dueDate` 时：写 `due_date`，同时把 `due_at` 设成那天 23:59。两个都发时以 `dueAt` 为准。

### 2. 分类 `categories.go`

- `GET` 按树的顺序返回：一级按 `position`，每个一级后面跟它的二级。`issueCount` 是直接归在这个分类的 Issue 数，一条 `GROUP BY` 算出来。
- `POST`：`name` 去掉首尾空格，1 到 40 个字。`parentId` 必须是同一项目的一级分类，否则 400 `invalid_parent`（不允许第三级）。新分类放在同级最后，`position` 用现有 `sortorder.go` 的算法。
- `PATCH`：改名同样校验。有 `afterId` 或 `beforeId` 时，两个都必须是同级的分类，按 `sortorder.go` 的 `between` 算新 `position`，太挤时重排这一级。
- `DELETE`：一个事务里，先把这个分类和它的二级分类下的 Issue 的 `category_id` 置空，再删分类（二级跟着删）。回 204。
- 分类属于另一个项目时一律回 404。
- 事件：`project_category.changed`，数据带 `projectId`。前端按 `project_category.` 前缀刷新。
- 已归档的项目不能改分类，回 409 `project_archived`（和改 Issue 一致）。

### 3. Issue 的新字段

- `Issue` 返回 `categoryId`、`dueAt`、`dueRemind`、`checklistDone`、`checklistTotal`。清单进度在列表查询里用子查询一次算出来，不要每个 Issue 查一次。
- `CreateIssue`、`UpdateIssue`：`categoryId` 必须是这个 Issue 所在项目的分类，否则 400 `invalid_category`。`UpdateIssue` 里 `categoryId: null` 清除，`dueAt: null` 清除截止时间（同时清 `due_date`）。
- `dueAt` 改了就把 `due_notified_at` 置空，这样改时间后会重新提醒。`dueRemind` 改了也置空。
- `GET /issues?categoryId=`：一级分类包含它的二级；0 表示 `category_id IS NULL`。
- `due=today|week|overdue` 和 `sort=due` 改用 `due_at`。“今天”“7 天内”按服务器时区的日期边界算，`overdue` 是 `due_at < now` 且未完成。
- Linear 同步（`contracts.go` 的 `issue.synced`）只写 `due_date` 时，同样补 `due_at`。

### 4. 检查清单 `checklists.go`

- 所有接口先用 `key` 取 Issue（不存在 404），清单和条目必须属于这个 Issue，否则 404。
- `GET`：清单按 `position`，每个清单的 `items` 也排好。一次查出所有条目，在 Go 里分组。
- 新清单放最后。新条目不传 `afterId` 放最后，传了放在它后面（它和下一条中间）。
- `PATCH` 条目：`done` 从 false 改 true 时写 `done_at`，改回 false 清空。`checklistId` 要挪到同一个 Issue 的另一个清单。`afterId`、`beforeId` 按目标清单算位置。
- `convert`：一个事务里，用条目文字建 Issue（同项目、同分类、`todo`、优先级 0），删掉条目。建 Issue 走现有的创建逻辑，编号、事件、审计都一样。回 201 和新 Issue。
- 每个写操作后发 `issue.checklist_changed`（数据带 `key`），同时更新 Issue 的 `updated_at`。前端按 `issue.` 前缀刷新，看板卡片的进度也会跟着变。
- 长度：清单标题 1 到 200 字，条目 1 到 500 字。一个 Issue 最多 20 个清单，一个清单最多 200 条，超过回 400 `too_many`。

### 5. 到期提醒 `due.go`

- `Start` 里 `Scheduler.Every("projects.due", time.Minute, ...)`。
- 每次查：`due_at IS NOT NULL`、`due_remind != 'none'`、状态不是 done 或 canceled、`due_notified_at` 为空或不等于当前 `due_at`、提醒时间 `due_at - 提前量 <= now`。项目已归档的跳过。
- 提前量：`at_due` 0，`15m` 15 分钟，`1h` 1 小时，`1d` 24 小时。
- 每条发一次 `Notify.Send`：`Kind: "issue.due"`，`Title` 写“XC-12 快到期了”（提前提醒）或“XC-12 到期了”，`Body` 是 Issue 标题和截止时间（服务器时区，`1月2日 18:00`），`Link: "/projects/XC/12"`，`Source: "projects"`。站内通知和已开的推送渠道由 `notify` 处理，弹出和声音走现有通知中心。
- 发完把 `due_notified_at` 写成这次的 `due_at`。先写库再发，发失败记日志，不重发（避免重复）。
- 服务器停了一段时间后启动：过期超过 1 天的不补发，只写 `due_notified_at`。
- 同时实现 B37 要的 `contracts.ReminderSource`（等 B37 定下接口再做，这里先留一个 `Upcoming` 查询函数）。

### 6. 公共上传 `modules/files/`（新模块）

- 在 `app/modules.go` 末尾加一行 `files.New`。按 `api/modules/files.yaml` 生成代码（照其他模块的 `//go:generate`）。
- 表 `uploaded_files(id, scope, name, mime, size, sha256, owner_kind, owner_id, created_at)`。`owner_*` 为空表示还没被认领。
- 存储：B24 的 `files.Store` 做好后用 `d.Files.For(scope)`，key 是 `uploads/<id>`，缩略图 `uploads/<id>.thumb.jpg`。B24 没做完时先写到 `data/files/<scope>/uploads/<id>`，写临时文件再 `rename`，目录 0700、文件 0600，B24 做的时候一起迁过去。
- `POST /files?scope=`：`http.MaxBytesReader` 限 20 MB（超了回 413）。用 `http.DetectContentType` 看前 512 字节，只收 png、jpeg、gif、webp，其他回 415 `unsupported_type`（不看文件名和客户端给的类型）。文件名只留 `filepath.Base`，去掉控制字符，最长 100 字。回 201 和 `UploadedFile`，`url` 是 `/api/v1/files/<id>`。
- `GET /files/{id}`：要登录（走默认的认证中间件，不加进 `PublicPaths`）。`Content-Type` 用存的 mime，加 `X-Content-Type-Options: nosniff`、`Cache-Control: private, max-age=31536000, immutable`（内容不会变）。`thumb=1` 且图片宽或高超过 1600 像素时返回缩略图：第一次请求时用 `golang.org/x/image/draw` 缩到 1600 以内，存成 JPEG（质量 85），以后直接读。GIF 不缩。
- `DELETE /files/{id}`：删记录和文件，回 204。
- 认领：`contracts` 加 `Files` 接口，`Claim(ctx, ownerKind string, ownerID int64, markdown string) error`，从 Markdown 里找 `/api/v1/files/(\d+)`，把还没归属的这些文件记到这个 owner 名下。已经归属别人的不改。注册表键 `files.files`，在“接口变更记录”记一笔。
- 调用方：项目保存 Issue 描述、评论、项目描述时 `Claim("issue", id, ...)`、`Claim("comment", id, ...)`、`Claim("project", id, ...)`；日程、提醒、Agent 任务同样在保存备注时调用。模块拿不到 `Files` 时跳过，不报错。
- 删除：`Files` 接口再加 `DeleteOwned(ctx, ownerKind, ownerID)`。删 Issue 时删它和它的评论的文件；删评论、删日程、删提醒同样处理。
- 清理：每天一次，删掉创建超过 24 小时还没被认领的文件。
- 审计：`files.upload` 记 scope、大小、类型。

- 旧客户端只发 `dueDate` 能用，`due_at` 是当天 23:59；只发 `dueAt` 时 `dueDate` 也对。
- 清单：建两个清单共 5 条，勾 3 条，列表里的 Issue 是 `3/5`；挪到另一个清单；转 Issue 后原条目没了、新 Issue 在同一分类。
- 到期提醒：用假时钟，到点只发一次；改时间后再发一次；`none` 不发；`1h` 提前 1 小时发。
- 上传：非图片回 415，超过 20 MB 回 413，没登录回 401；认领后删 Issue 文件没了；24 小时没认领的被清掉。
- 端到端：`web/scripts/e2e.mjs` 加一条：建分类、建 Issue 选分类和截止时间、加清单勾一条、贴一张图，刷新后都在（AGENTS.md 要求新功能补一条主流程）。
