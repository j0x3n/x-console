# M4 编码任务

状态：已完成。依赖 M3 的代理、M5 的 contracts.Issues、M13 的 contracts.GitHub（可选）。

## 流程

1. 代理上报可用的仓库和执行器。
2. 你选仓库、执行器、基础分支，写需求，点开始。也可以在 Issue 页点“交给编码助手”，需求自动带上 Issue 标题和描述。
3. 服务端排队。运行中的任务数不超过上限（默认 2，可配置，所有机器合计）。
4. 代理在 `<仓库>/.x-console/worktrees/<任务id>` 建 worktree 和分支 `xc/<任务id>-<短名>`，在里面启动执行器。代理第一次用这个仓库时，会在 `.git/info/exclude` 里加一行 `/.x-console/`，主工作区不会多出未跟踪文件。
5. 执行器的输出实时回传，服务端存库并推给浏览器。
6. 执行器退出后，代理算出改动文件，任务进入“待你决定”（退出码不是 0 时是“失败”，worktree 同样保留）。
7. 你选：提交、提交并推送、建 PR、丢弃。建 PR 通过 M13。
8. 提交后删除 worktree，保留分支。丢弃时删除 worktree 和本地分支。取消、超时、代理断线时，代理停掉执行器后马上删除 worktree 和分支。

## 执行器

| 执行器 | 默认启动命令 |
| --- | --- |
| Claude Code | `claude -p --output-format stream-json --verbose --permission-mode acceptEdits`，已用 Claude Code 2.1 的 `--help` 核实 |
| Codex | `codex exec --json --full-auto -`，开发机上没装 codex，参数按 0.4x 版的文档写，没实测 |

- 需求从标准输入传给执行器，避免命令行转义和长度限制。参数里写了 `{prompt}` 时改为替换进参数。
- 输出按行解析 JSON。解析不了的行当纯文本。stderr 的每一行是 `text` 事件，`data.stream` 为 `stderr`。
- 统一转成事件：`{kind: "text"|"tool"|"status"|"error"|"done", text, data, exitCode, at}`。
  - 工具调用：`{kind: "tool", text: "Edit: a.go", data: {id, name, input}}`；工具结果：`{kind: "tool", text: 输出, data: {id, result: true, isError}}`。前端按 id 配对并折叠显示。
  - 状态：`data.code` 是 `worktree_ready`（带 `baseCommit`、`branch`）、`started`（带 `pid`）、`session_started`、`result`、`canceled`、`timeout`、`plan`。
  - 结束：`{kind: "done", exitCode, data: {reason: "exited"|"timeout"|"canceled"|"start_failed", baseCommit, files, error}}`。
- 执行器路径和参数在代理配置里可改（`config.Coding`，见下）。
- 工作目录是 worktree。代理只接受 `xc/` 开头的分支名，丢弃时不会误删你自己的分支。
- 超时默认 60 分钟。取消或超时先发中断信号，10 秒后强杀。Linux 上执行器是单独的进程组，整组一起停；Windows 上放进作业对象（kill-on-close），中断发 Ctrl+Break，强杀时结束整个作业，作业建不起来时用 `taskkill /T /F`。

代理配置示例（`config.json` 里的 `coding`，都可省略）：

```json
"coding": {
  "roots": ["~/code", "D:\\work"],
  "depth": 3,
  "executors": {
    "claude": {"path": "C:\\Users\\me\\.local\\bin\\claude.exe", "extraArgs": ["--model", "opus"]},
    "codex": {"args": ["exec", "--json", "--sandbox", "workspace-write", "-"], "env": {"CODEX_HOME": "D:\\codex"}}
  }
}
```

能力 `coding`：Windows 上总是上报（桌面代理，即使还没装执行器，页面也能提示缺什么）；其他系统在 PATH 或配置里找到 claude、codex 之一时才上报。

## 代理端方法（`methods_coding.go`，实现放 `internal/agent/coding`）

代理不保存任务状态，每个方法都带仓库路径、任务 id 和分支。

| 方法 | 类型 | 说明 |
| --- | --- | --- |
| `coding.executors` | 请求 | 检测 claude、codex 是否可用及版本（运行 `--version`） |
| `coding.repos` | 请求 | 扫描根目录（默认用户目录下的 `code`、`projects`、`src`，深度 3），返回路径、名称、当前分支、默认分支、远端地址。`depth: -1` 只检查给的目录本身，登记仓库时用它确认是仓库根目录 |
| `coding.run` | 流 | 参数：任务 id、仓库路径、执行器、需求、基础分支、分支名、超时秒数。代理每块数据发一行 JSON 事件，最后是 `done`。服务端发 `{"op":"cancel"}` 取消 |
| `coding.diff` | 请求 | 改动文件列表和统一 diff（限制 2 MB）。worktree 在时比较 worktree（含未跟踪文件），提交后比较分支 |
| `coding.commit` | 请求 | 提交全部改动（执行器自己做的提交也算），删除 worktree，返回 commit sha。没有 git 身份时用 `X Console <x-console@localhost>` |
| `coding.push` | 请求 | `git push --set-upstream origin <分支>` |
| `coding.discard` | 请求 | 删除 worktree 和分支，可以重复调用 |

## 后端 `modules/coding`

### 表

| 表 | 列 |
| --- | --- |
| `coding_repos` | id、agent_id、path、name、default_branch、remote_url、github_repo（owner/name，从远端解析）、created_at |
| `coding_tasks` | id、repo_id、issue_key、executor、prompt、base_branch、branch、base_commit、status、exit_code、error、commit_sha、pr_url、changed_files（JSON）、timeout_minutes、created_at、started_at、finished_at、updated_at |
| `coding_task_events` | id、task_id、seq、at、kind、text、data |

状态：`queued` → `running` → `review`（等你决定）/ `failed` / `canceled` → `committed` → `pushed` → `pr_opened`；`review`、`failed`、`canceled`、`committed` 可以 → `discarded`。

- 提交：`review` 或 `failed`。推送：`committed`。建 PR：`committed` 或 `pushed`（没推送时先推送）。
- 代理离线时排队的任务继续等，代理上线后自动开始。运行中代理断线，任务标记失败：“代理断开了连接，任务中止。”
- 服务重启时，还在“运行中”的任务标记失败：“服务重启了，任务被中断。”
- 取消后服务端最多等 30 秒让代理收尾，超时就直接断开并记为已取消。

### 接口

| 方法 | 路径 |
| --- | --- |
| GET | `/coding/executors?agentId=` |
| GET | `/coding/repos`；POST `/coding/repos`（`{agentId, path}`，代理先确认是仓库根目录）；DELETE `/coding/repos/{id}`（有排队或运行中的任务时 409） |
| GET | `/coding/repos/discover?agentId=&root=` |
| GET/POST | `/coding/tasks`（列表可按 `status`（可多个）、`repoId`、`issueKey` 筛选，不分页，最多 500 条，运行中和排队的在前） |
| GET | `/coding/tasks/{id}` |
| GET | `/coding/tasks/{id}/events?after=&limit=` |
| POST | `/coding/tasks/{id}/cancel` |
| GET | `/coding/tasks/{id}/diff` |
| POST | `/coding/tasks/{id}/commit`（`{message?, push?}`）、`/push`、`/pr`（`{title?, body?, draft?}`）、`/discard`（都要提升权限） |
| GET/PUT | `/coding/settings`（并发上限、默认超时；GET 还返回只读的 `prAvailable`） |

GitHub 模块没启用时，`/pr` 返回 501 `feature_unavailable`，前端不显示“建 PR”，改为提示去接 GitHub。

### 事件

`coding_task.created`、`coding_task.updated`（状态变化）、`coding_task.output`（`{taskId, events:[...]}`，200 毫秒合并一次，事件带 seq）、`coding_repo.created`、`coding_repo.deleted`、`coding_settings.updated`。

### 对外

- 提供 `contracts.Coding`。
- 动作：`coding.launch`（write，输入 repoId、executor（默认 claude）、prompt、baseBranch、issueKey）、`coding.list_tasks`（read，输入 status 数组、limit）。
- 通知：`coding_task.review`（完成待决定）、`coding_task.failed`（高优先级）。取消不发通知。
- 有 Issue 时：开始时把 Issue 改成 in_progress，并 `AttachLink(kind: coding_task, url: /coding/<id>, ref: <id>)`；建 PR 后再 `AttachLink(kind: pull_request, ref: owner/repo#号)` 并改成 in_review。
- 审计：`coding_task.create`、`.cancel`、`.commit`、`.push`、`.pr`、`.discard`，`coding_repo.create`、`.delete`，`coding.settings`。

## 前端 `features/coding`

- `/coding` 任务列表：状态筛选（全部、进行中、等你决定、已完成、失败或取消），运行中的在最上面。
- 新建任务弹窗（`/coding?new=1`，从 Issue 进来带 `&issue=XC-1`）：选仓库、执行器（显示代理检测到的版本）、基础分支、需求。
- `/coding/:id` 任务详情：左边实时输出（工具调用折叠显示），右边状态和操作按钮。完成后显示改动文件列表和 diff 查看器。
- `/coding/repos` 仓库管理：从代理扫描、登记、按路径登记、删除；运行设置（并发上限、默认超时）。
- 命令面板命令：“新建编码任务”、“管理编码仓库”。
- Issue 详情页的“交给编码助手”是一个链接，打开新建任务弹窗并带上 Issue 编号。

## 验收

- 用一个假执行器脚本（`internal/agent/coding/testdata/fake-claude.sh`，输出 stream-json 并改文件）跑通：排队、运行、实时输出、diff、提交、推送、丢弃。
