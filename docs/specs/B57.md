# B57 隐藏内容：AI 不提隐藏，整个模块可以隐藏

用户 2026-10-01 提的：

- AI 弹窗里显示“隐藏内容我看不到”。用户要的是别人看面板完全不知道还有隐藏内容。
- 解锁后，设置里可以选左栏任意模块完全隐藏。对 MCP 就提示不存在。

用户确认的做法：

- 锁定时，被隐藏的模块从左栏、今日页、命令面板、搜索里全部消失。直接输网址打开，显示普通的“页面不存在”。
- 这个模块的接口回 404，和不存在的接口一样。MCP 和 AI 的工具列表里也没有它，硬调用只回“没有这个工具”。
- 隐藏了哪些模块，名单本身只有解锁后能看到。锁定时服务端只告诉前端能用哪些模块。
- 解锁后这些模块正常显示。

## 已完成

### AI 不再提隐藏内容（后端）

- `modules/ai/worker.go` 的系统提示词删掉“隐藏内容不可访问”。原因：模型读到这句会照着告诉用户。
- `modules/notes/actions_extra.go` 里 `notes.get`、`notes.delete` 的说明去掉 “excluding hidden notes”。工具查数据时本来就用 `auth.WithoutVault` 过滤掉了隐藏内容，模型不需要知道。

### 隐藏模块的设置（前后端）

- 契约 `api/modules/vault.yaml`：
  - `GET /vault/modules`、`PUT /vault/modules`：读写被隐藏的模块。没解锁时回 404。
  - `GET /app/modules`：这个会话能用的模块。没解锁时不含被隐藏的，解锁后全部返回。名字里不带 vault，返回内容也不提隐藏。
  - 模块名 `ModuleId`：`projects coding notes reminders habits drive calendar servers pc monitoring home automations github`，和前端路由第一段一样。今日页不能隐藏。
- 后端 `modules/vault/modules.go`：设置键 `vault.hidden_modules`，内容是模块名数组。保存时记审计 `vault.modules`。测试 `modules/vault/modules_test.go`。
- 前端：
  - `app/modules.ts`：`useModules()` 读 `/app/modules`，缓存键 `["app","modules"]`。锁定和解锁时隐藏内容模块会重置别的缓存，这个列表跟着重新拉。接口回 404、501 或出错时全部能用。还没拿到结果时可隐藏的模块先不显示，避免闪一下。
  - 左栏（`Sidebar`）、命令面板（页面跳转和各模块注册的命令，按命令分组认模块）、顶栏标题、路由出口（`Layout` 的 `ModuleGate`，被隐藏的显示“页面不存在”）、今日页（卡片、顶部概要、问候下面的概况）都按它过滤。
  - 设置 → 安全加“隐藏的模块”卡片（`features/vault/HiddenModulesCard.tsx`），只在解锁时渲染，锁定时整张卡片不存在。
  - 端到端测试：设隐藏密码，隐藏 GitHub，锁定后左栏没有 GitHub，打开 `/github` 显示页面不存在，`/vault/modules` 回 404。

## 后端（待做，给开发者）

上面只做了设置和前端的显示。锁定时被隐藏模块的接口、AI 工具、MCP 还能用，要补上。

### 1. 读隐藏名单的公共函数

在 `contracts` 里加一个接口，vault 模块实现并注册（照 `contracts.Renewals` 的写法）：

```go
// HiddenModules tells whether a sidebar module is hidden for this request.
// It is false whenever the vault is unlocked.
type HiddenModules interface {
    Hidden(ctx context.Context, module string) bool
}
```

实现：`auth.VaultUnlocked(ctx)` 为真时返回 false；否则读 `vault.hidden_modules`。名单每次都读设置太慢的话，在内存里缓存，`PUT /vault/modules` 时清掉。在 `docs/tasks.md` 的“接口变更记录”里记一笔。

### 2. 接口回 404

`app/app.go` 挂载模块的循环改成按组挂，给每个模块套一个中间件：

```go
for _, m := range a.modules {
    api.Group(func(g chi.Router) {
        g.Use(hiddenGate(d, sidebarModuleOf(m.Name())))
        m.Mount(g)
    })
}
```

`hiddenGate`：模块属于某个可隐藏的左栏模块、并且这个请求下它被隐藏时，直接回 `httpx.ErrNotFound`，和 `api.NotFound` 完全一样。

后端模块名和左栏模块的对应：

| 左栏模块 | 后端模块 |
| --- | --- |
| projects | projects |
| coding | coding、aiagents |
| notes | notes |
| reminders | reminders（只拦 `/reminders` 开头的；`/notify` 是通知设置，所有模块共用，不能拦） |
| habits | habits |
| drive | drive（`/files` 是公共上传接口，属于 files 模块，不拦） |
| calendar | calendar |
| servers、pc | hosts。两个都隐藏时整个拦；只隐藏一个时，在 hosts 模块里按 `kind`（server、pc）过滤列表，打开被隐藏那类的主机回 404 |
| monitoring | monitoring |
| home | homeassistant |
| automations | automations |
| github | github、linear |

`/events`（WebSocket）推的事件里带模块名前缀（`note.updated` 这类），被隐藏模块的事件不要推给锁定的会话，否则前端会去请求再拿到 404。

### 3. AI 和 MCP 的工具

- 动作目录（`actions` 包）里每个动作名的前缀就是后端模块名（`notes.get`）。列工具和执行工具时，用上面的对应表过滤：被隐藏模块的动作不出现在列表里；按名字硬调用时，回和名字不存在时一样的错误。
- 注意 AI 助手、自动化、MCP 都走这个目录，三处都要过滤。MCP 的会话没有 vault 解锁状态，所以被隐藏的模块对 MCP 总是不存在。
- 今日页的“最近动态”（dashboard 的活动接口）、命令面板的搜索、早报（brief）汇总时，跳过被隐藏的模块。

### 4. 测试

- 隐藏 notes 并锁定后：`GET /notes` 回 404，错误码 `not_found`；解锁后回 200。
- 隐藏 notes 后，AI 工具列表里没有 `notes.*`，调用 `notes.get` 的错误和调用不存在的工具一样。
- 只隐藏 pc：`GET /hosts?kind=pc` 是空列表，`GET /hosts/{pc 的 id}` 回 404，服务器照常。
- `/notify/*` 和 `/files` 不受影响。
