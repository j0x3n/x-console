# B70 仓库页：改名、多仓库、提交、CI 步骤、Forgejo

## 后端实现差异（2026-10-02）

- 新增 `github_cache_v2`，主键为账号、仓库、对象类型、对象编号。旧表的唯一约束无法只加索引解除，因此保留旧表并一次幂等复制缓存、PR 关联和 CI 状态。新缓存以 JSON 保存 API 数据，旧 API 路径和默认 GitHub 账号保持兼容。
- `repos` 输入改成可选，字段名不变。显式 `watches: []` 表示取消全部关注。旧配置只在 watches 设置键不存在时转换。
- Forgejo/Gitea 按接口能力探测，不按原规格的版本下限判断。Forgejo v12 才新增 runs API；Gitea 1.23 只有 actions/tasks。这里请求 actions/runs，明确 404/501 时使用默认分支提交状态。403、超时和 5xx 不降级。jobs 单独探测，不支持时回 501。提交状态用持久负数运行编号，不与真实运行冲突。
- jobs 未传账号且同名仓库有多个账号时回 400。多个 workflow 对同一 SHA 的结果合并；只取各 workflow 最新运行。Issue 概况读取全仓库，旧 Issue 列表仍只显示本人创建或被指派的打开 Issue。

## 做法

### 1. 改名和位置

- 左栏“集成”组里的 GitHub 挪到“主要”组，排在“Agent”后面，名字“仓库”（英文键 `Repositories`），图标 `FolderGit2`。
- 地址还是 `/github`，模块名、接口路径都不变，省得改后端和隐藏模块的配置。
- 设置标签“Git 与 GitHub”改叫“Git 与仓库”（英文键 `Git & repositories`），地址 `/settings/git` 不变。

### 2. 设置 → Git 与仓库

两栏。左栏：“Git 账号”“同步状态”上下排。右栏：“关注的仓库”。窄屏一栏。

- **Git 账号**：和 B62 一样。列表去掉左边的空白（`.xc-list` 是 `ul`，没清掉默认缩进）。每行前面的图标按类型区分：GitHub 用 `Github`，Forgejo 用 `GitBranch`。
- **关注的仓库**（原“GitHub 页面”卡片）：
  - 上面一个下拉框选账号，GitHub 和 Forgejo 账号都列出来。
  - 下面是这个账号能访问的仓库（`GET /github/available-repos?connectionId=`），可以搜索、多选。
  - 已选的仓库按账号分组显示成标签，每个标签前面有账号类型的小图标。可以单个去掉。
  - 换账号不会清掉别的账号下已选的仓库。保存时一起提交。
- **同步状态**：照旧。GitHub 的剩余额度只在有 GitHub 账号时显示。

### 3. 仓库页（`/github`）

```
┌ 概要：PR · 默认分支 CI · Issue · API 额度 ────────────────────────┐
├ 左：仓库列表（搜索）          │ 右：所选仓库（或“全部仓库”）          │
│   全部仓库        12          │  标题：颜色块 owner/name  账号  打开↗ │
│   ● x-console  PR 3  ✓        │  标签页：PR · 提交 · CI · Issue        │
│   ● blog       PR 0  ✗        │  列表                                  │
└───────────────────────────────┴────────────────────────────────────────┘
```

- **左栏仓库列表**（`GET /github/repos`）：每行一个颜色块（按仓库名算固定颜色）、仓库名（owner 灰字）、账号类型小图标、打开的 PR 数、默认分支最新 CI 状态的图标。CI 失败的排前面，其余按最近推送排。顶部有搜索框，仓库多时按 owner 分组，组可以折叠。宽度 260px，窄屏变成顶部一个下拉框。
- 选“全部仓库”时，右边的列表按仓库分组，每组的标题行带颜色块和仓库名，一眼能分开。选了某个仓库时只显示这个仓库，标题行显示仓库名、账号、默认分支、“在 GitHub 打开”。
- 选中的仓库记在地址栏 `?repo=<connectionId>:<owner/name>`，标签页记在 `?tab=`。
- **提交**标签（新）：默认分支最近 30 个提交（`GET /github/commits`）。每行：提交信息第一行、短 sha（等宽）、作者、时间、这个提交的 CI 状态图标。点 sha 打开网页。“全部仓库”时显示所有关注仓库最近的提交，按时间混排，每行前面带仓库颜色块和名字。
- **CI** 标签：每条运行可以展开，展开后列出 job 和步骤（`GET /github/runs/{runId}/jobs`）：
  - 每个 job 一行：状态图标、名称、用时；正在跑的 job 显示“第 3 / 8 步：Run tests”和一条进度条。
  - 展开 job 列出步骤：做完的打勾，失败的打叉，正在跑的转圈，没开始的灰圈，每步后面写用时。
  - 运行还没结束时，展开状态下每 5 秒重新取一次 jobs，结束后停止。这是唯一允许轮询的地方，因为 GitHub 不推步骤进度。
  - 运行行本身显示“进行中 · 第 3 / 8 步”。
- PR 和 Issue 标签照旧，加上仓库颜色块。
- 左栏二级菜单：列出关注的仓库（最多 5 个，CI 失败的在前），前面是 CI 状态点，点了跳到 `/github?repo=...`。

### 4. Forgejo

- Forgejo / Gitea 账号下的仓库和 GitHub 一样关注、同步、显示。
- Forgejo 没有 GitHub 那样的额度，同步间隔固定 60 秒。
- Forgejo 的 CI：有 Actions 接口（Forgejo 7 以上、Gitea 1.23 以上的 `/repos/{owner}/{repo}/actions/runs`）就用它；没有时用提交状态（`/repos/{owner}/{repo}/commits/{ref}/status`）当成一条“运行”，没有步骤，展开时显示“这个服务器不提供步骤详情”。

## 契约（`api/modules/github.yaml`，已改）

- `GitHubConfig` 加 `watches: RepoWatch[]`；`GitHubConfigInput` 加 `watches`。`RepoWatch = { connectionId, repo }`。传了 `watches` 时以它为准，原来的 `repos` 和 `connectionId` 不再用（标成 `deprecated`，读的时候后端把旧数据换算成 `watches` 返回）。
- `GET /github/available-repos` 加参数 `connectionId`，不传时用旧的 `github.connection_id`。
- 新接口 `GET /github/repos`：关注的仓库和它们的概况，`WatchedRepo[]`。
- 新接口 `GET /github/commits?repo=&connectionId=&limit=`：不传 repo 时返回所有关注仓库的最近提交，按时间倒序。
- 新接口 `GET /github/runs/{runId}/jobs?connectionId=&repo=`：一条运行的 job 和步骤，`GitHubJob[]`。
- `GitHubPull`、`GitHubRun`、`GitHubIssue` 加 `connectionId`、`forge`（`github` 或 `forgejo`）。`GitHubRun` 加 `headSha`、`stepsDone`、`stepsTotal`、`currentStep`（进行中时有）。
- `/github/pulls`、`/github/runs`、`/github/issues` 加参数 `connectionId`，和 `repo` 一起定位一个仓库。

## 后端（待做）

1. 配置：设置键 `github.watches`（JSON 数组）。启动时如果没有它，用旧的 `github.repos` 和 `github.connection_id` 生成一份（迁移只加不删）。最多 100 个。
2. 同步：按 `watches` 里的每个账号分别同步。GitHub 走原来的逻辑；Forgejo 用 Gitea 的 API（`/api/v1/repos/{owner}/{repo}/pulls`、`/issues`、`/commits`、`/actions/runs`、`/actions/runs/{id}/jobs`）。账号令牌从 `contracts.GitAccounts.Credentials` 取（B62 已有）。
3. 缓存表加 `connection_id` 列（迁移新加列，默认填旧的 `github.connection_id`），主键或唯一索引带上它。
4. `GET /github/repos`：每个关注的仓库一行：`connectionId`、`forge`、`repo`、`url`、`defaultBranch`、`private`、`description`、`openPulls`、`openIssues`、`pushedAt`、`ci`（默认分支最新一条运行的 `status`、`conclusion`）、`lastCommit`（`sha`、`message`、`author`、`at`）。从缓存出，不现查。
5. 提交：同步时每个仓库拉默认分支最近 30 个提交（GitHub `GET /repos/{o}/{r}/commits?sha=<默认分支>&per_page=30`，带 ETag）。每个提交的 CI 状态从已有的 runs 按 `head_sha` 对上，对不上就是 `none`。存缓存表 `github_commits`。
6. 步骤：`/github/runs/{runId}/jobs` 现查（GitHub `GET /repos/{o}/{r}/actions/runs/{id}/jobs`），结果在内存缓存 5 秒。运行列表的 `stepsDone`、`stepsTotal`、`currentStep` 只给进行中的运行，同步时顺便取（只取进行中的，省额度）。
7. 额度：GitHub 的额度逻辑不变。每个 GitHub 账号单独算额度，`/github/status` 返回第一个 GitHub 账号的额度。
8. 测试：假 GitHub 服务和假 Gitea 服务各一个，测两个账号同时关注、同名仓库不混、提交和 CI 状态对上、jobs 接口、旧配置迁移成 `watches`。

## 验收

- 设置页两栏，没有空白；加一个 Forgejo 账号后能搜到它的仓库并关注。
- 仓库页左边列出全部关注的仓库，选一个只看它；“全部仓库”时每组有颜色块和名字。
- 提交标签能看到最近的提交和 CI 状态。
- 一条正在跑的 CI 展开后能看到当前第几步，做完的步骤打勾。
- 左栏里“仓库”在“Agent”下面。
