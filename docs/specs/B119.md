# B119 身体数据：自动同步和趋势

用户 2026-10-10 让按《功能扩展建议》的顺序做，这是第五条（建议里的第 5 条）。来源是 `/mnt/project-files/x-console-suggestions/功能扩展建议.md`。

## 现状和缺口

B97 已经有按日手填的体重、腰围、睡眠、步数，页面上有体重折线和七天均值。缺这几样：

- 没有静息心率。
- 只能手填。手机快捷指令或 Home Assistant 没有地方推数据。
- 只有体重有趋势，睡眠、步数、心率看不出变化。
- AI 只能一天一天查，不能问“最近三个月体重怎么变”。

这条是补全习惯模块，不是新模块。数据继续存在原来的按日记录里，不加迁移。

## 要什么

- 每天多一项“静息心率”（次/分），和体重、睡眠、步数放在同一个表单里。
- 自动同步：设置里生成一个上报令牌，手机快捷指令、Home Assistant 或脚本每天 POST 一次，写进当天的记录。
- 趋势：体重、睡眠、静息心率、步数各一张折线（步数用柱状），可选 30、90、180 天。每项显示最近一次、范围内平均、最低、最高、和范围开头相比的变化。只用记录过的值，没记的日子不补零。
- 动作目录：`habits.body_trend`（读，某段时间的四项序列和统计）、`habits.body_record`（写，记某天的数）。AI 能回答“最近三个月体重怎么变”，也能说“今天体重 72.5”就记下。

## 数值范围

| 项 | 范围 | 说明 |
| --- | --- | --- |
| 体重 | 30–250 kg | 已有 |
| 腰围 | 40–200 cm | 已有 |
| 睡眠 | 0–24 小时 | 已有 |

## 上报接口

`POST /api/v1/habits/body/report`，不需要登录会话，用 `Authorization: Bearer <令牌>` 校验。和路由器上报（B114）同一种做法。

请求体是 JSON，字段都可选，至少要有一个指标：

```json
{ "date": "2026-10-10", "weight": 72.4, "sleep": 7.5, "restingHr": 58, "steps": 8123, "waist": 80 }
```

- 数值可以写数字，也可以写数字字符串，因为 iOS 快捷指令常发字符串。
- `date` 不填就是今天（服务器时区）。不能比明天晚，不能早于 2000 年。
- 没写、写 `null` 或写空字符串的字段不改。上报不会清除已有的数。要清除只能在页面里改。
- 有不认识的字段、数值越界、不是数字，整条请求回 400，什么都不写。
- 成功回 204。令牌不对回 401，不透露有没有开启。
- 请求体最多 4 KB。

## 令牌

- `POST /habits/body/push/token`：生成令牌，要提升权限。旧令牌立即作废。令牌只在这次回复里出现，面板只存它的 SHA-256。回复里带上报地址和一条可以直接复制的 curl 示例。
- `GET /habits/body/push`：状态，已开启与否、创建时间、上次收到上报的时间和日期、上报地址。
- `DELETE /habits/body/push`：关闭，令牌作废。
- 上报地址用 `XC_PUBLIC_URL`，没配置时用请求的 Host。
- 写入记审计 `habit.body.report`（记成功和数据被拒绝的情况，不记令牌；令牌不对的请求不记，免得被刷满日志）。成功后发事件 `habit.personal_updated`，页面自动刷新。

## 页面

- “个人计划 › 记录”：表单加“静息心率”。原来的“体重趋势”卡片换成“身体趋势”：指标分段选择（体重、睡眠、静息心率、步数）和范围分段选择（30、90、180 天），下面是图和统计数字。历史表加心率一列。
- “个人计划 › 设置”：加“自动同步”卡片。没开启时显示“生成上报令牌”按钮。开启后显示上次收到上报的时间，一个“重新生成”和一个“关闭”按钮。新令牌只显示一次，旁边有示例命令和一段 iOS 快捷指令的步骤说明。
- 手机（390px）不横向滚动。

## 备份

`PersonalDayInput` 加可选字段 `restingHr`。导出、导入照常带上。旧备份没有这个字段，导入后心率为空。

## 验收

- 在记录页填静息心率，刷新后还在，历史表里能看到。
- 生成令牌后，用 curl 带令牌上报体重、睡眠、心率、步数，当天的记录里是这些值；再只报体重，其他三项不变。
- 令牌错误回 401；越界的心率回 400 且当天记录不变；重新生成后旧令牌回 401；关闭后回 401。
- 趋势：有多天数据时图和统计数字对得上，切换指标和范围有变化。只有一天数据时提示“至少记两天才有趋势”。
- `habits.body_trend` 返回的平均、最低、最高和页面一致。`habits.body_record` 越界时报错。
- 备份导出再导入，心率不丢。

## 实现记录

- 后端：`habits/body.go`。令牌的哈希存在设置里（键 `habits.body_push`），同时记创建时间和上次上报。上报、令牌、趋势的测试在 `body_test.go`。
- 前端：`BodyTrend.tsx`（趋势）、`BodySync.tsx`（设置里的自动同步卡片）、`personal.ts` 的 `bodySeries`。体重趋势原来的 `WeightChart` 删了，七日均值还在计划概览里用。
- 趋势的结束日是页面选中的那天，不是今天，和原来的体重图一致。
- 没做：腰围没有单独的趋势（还是只在历史表里）；上报的值不区分来源，手填和自动写进同一个字段，后写的覆盖先写的。
- 没验证：真实的 iOS 快捷指令和 Home Assistant 没连过，只用 curl 的写法测了接口。
