# B118 每日时间线和日记

用户 2026-10-10 让按《功能扩展建议》的顺序做，这是第四条（建议里的第 4 条）。来源是 `/mnt/project-files/x-console-suggestions/功能扩展建议.md`。

## 为什么要加

要回答“上周三我干了什么”“那台服务器是哪天出的问题”，现在要翻五六个页面。早报讲今天要做的事，这个记已经发生的事。各模块的数据已经在库里，缺的是按日期汇总，还有一个地方写几句自己的话。

## 要什么

新模块 `journal`，页面叫“每日时间线”，地址 `/journal?date=YYYY-MM-DD`，不带日期是今天。

- 每天一页，上面自动列出当天发生的事，按时间排。
- 下面是日记：自己写的 Markdown，一天一篇，可以不写。
- 能按日期往回翻：前一天、后一天、回到今天、选日期，页面上还有最近两周的日期条，有日记或有记录的日子带标记。
- 能搜索：搜日记正文，也搜时间线上的标题和说明，结果按日期从新到旧列出，点一条跳到那一天。
- 概要卡片：代码（提交和 PR 的数量）、卡片和 Agent 任务（完成数）、专注（分钟）、习惯和训练（次数）。其他类型只在时间线里出现。

## 当天会列出什么

每个模块提供自己那部分，规则见“接口”。第一版有这些来源：

| 来源 | 内容 | 隐藏模块 |
| --- | --- | --- |
| 项目 | 完成的卡片（`completed_at` 在当天） | `projects` |
| Agent 任务 | 结束的任务：成功、失败、等审查，带提交号和 PR 链接 | `coding` |
| 专注 | 当天开始的专注，写分钟数和关联的卡片 | `calendar` |
| 习惯 | 习惯打卡（同一习惯一天合成一条，写次数）和训练记录 | `habits` |
| GitHub | 缓存里的提交（作者是自己的）、自己开的 PR 和合并的 PR | `github` |
| 日程 | 当天的日程（含重复日程的当天发生） | `calendar` |
| 告警 | 服务器告警：触发时间、恢复时间 | `servers` |
| 电脑时间 | 一条汇总：用了多久，哪类最多（只在 B116 有数据时） | `screentime` |
| 稍后读 | 存下的链接和读完的链接 | `readlater` |
| 笔记 | 当天新建的笔记 | `notes` |

没做：邮件、云盘、提醒、Home Assistant。要加的话在对应模块里再提供一个来源就行。

已知限制：

- GitHub 来源只用模块已经缓存的数据，每个仓库的分支最近 30 个提交。在电脑上提交很多时，几天前的提交可能已经不在缓存里。时间线会把读到的存下来，所以只要这个模块在跑，读到过的不会丢。
- 一个模块第一次启动时回填最近 90 天，只能回填到各来源的库里还有的数据。

## 隐私和隐藏内容

- “每日时间线”加进可隐藏的模块（`vault.yaml` 的 `ModuleId` 加 `journal`），默认不隐藏。日记是私人内容，设了隐藏密码的用户可以勾上。
- 时间线里每一条记着它来自哪个模块。隐藏内容锁着时，来自隐藏模块的条目不显示，也不计入概要和搜索。比如隐藏了“电脑时间”，时间线里就没有那一条。
- 采集在后台跑，不看隐藏状态，读取时才按当时的状态过滤。

## 接口

见 `api/modules/journal.yaml`。

- `GET /journal/days/{day}`：当天的时间线、日记和概要。当天和前两天的数据在返回前会先刷新一次（30 秒内刷新过就不再刷）。
- `PUT /journal/days/{day}/diary`：写日记，内容为空就删除这一天的日记。最多 20000 个字。
- `GET /journal/recent?days=14`：最近几天每天的条目数和有没有日记，最多 366 天。
- `GET /journal/search?q=`：搜索，最多 100 条。
- 写操作记审计。事件 `journal.updated`（日记改了）和 `journal.collected`（时间线有新内容）。
- 动作目录：`journal.day`（某天的时间线和日记）、`journal.search`，只读。AI 能回答“上周三我干了什么”。

### 提供来源（`contracts/journal.go`）

```go
const ActivitySourcePrefix = "journal.sources."

type Activity struct {
    Ref     string    // 在这个来源里唯一，比如 "issue:12"
    Module  string    // 对应的可隐藏模块，比如 "projects"
    Kind    string    // card、task、commit、pr、focus、habit、workout、event、alert、screen、link、note
    At      time.Time
    Title   string    // 一行
    Detail  string    // 可选，一行
    Link    string    // 站内路径，或 http 开头的外部链接
    Minutes int       // 有时长的才填：专注、电脑时间
}

type ActivitySource interface {
    // Activity 返回 [from, until) 之间发生的事。
    Activity(ctx context.Context, from, until time.Time) ([]Activity, error)
}
```

模块用 `module.Provide[contracts.ActivitySource](d.Registry, contracts.ActivitySourcePrefix+"projects", src)` 注册，键的最后一段是来源名。来源不检查隐藏状态，也不依赖时间线模块。

## 采集

- 时间线模块自己存一份：表 `journal_items`。这样缓存过期或来源数据被清掉后，历史还在，搜索也只查这一张表。
- 每 10 分钟采集最近三天（从前天 0 点到明天 0 点，用服务器时区）。启动时如果还没回填过，在后台采集最近 90 天，分段取，每段 30 天，做完记下标记。
- 对每个来源：取到数据后，在一个事务里先删掉这个来源在这个时间段内的旧条目，再写入新条目。某个来源出错，就保留它的旧条目，别的来源照常。
- 每个来源每次最多取 2000 条，标题最多 200 个字，说明最多 500 个字。
- 日期按采集时的服务器时区算，存在 `day` 列。以后改时区，旧条目保持原来的日期。

## 数据

- `journal_items`：`id`、`day`、`at`、`module`、`source`、`ref`、`kind`、`title`、`detail`、`link`、`minutes`。`(source, ref)` 唯一，`day, at` 有索引。
- `journal_diary`：`day`（主键）、`body`、`updated_at`。
- 迁移 `20261010000300_m18_b118_journal.sql`，只加不删。

## 验收

- 当天完成一张卡片、结束一个 Agent 任务、打一次习惯卡，打开 `/journal`，这三条按时间出现在时间线里，概要卡片的数字对得上。
- 写一段日记，刷新后还在；清空后这一天不再有日记标记。
- 往前翻到有记录的一天，能看到当天的内容；没有任何记录的一天显示“这一天没有记录”，日记框仍然能写。
- 搜日记里的一个词和时间线里卡片标题里的一个词，都能找到并跳到那天。
- 隐藏“电脑时间”后锁上隐藏内容：时间线里没有电脑时间那一条，搜索也搜不到；`/journal` 本身也隐藏时接口回 404。
- 手机（390px）整页不横向滚动。

## 实现记录

- 后端：`modules/journal/`。采集、日记、搜索、动作都在这里；日程和告警两个来源也放在这里（`sources.go`），其他来源在各自模块的 `activity.go`。
- 前端：`web/src/features/journal/`。日期条显示最近两周，有记录或有日记的日子带标记。日记在点保存、编辑框失焦、按 Ctrl+Enter、切换日期前保存。
- 测试：`journal_test.go` 用假来源测采集、替换、出错保留旧条目、限流、回填、日记、搜索、隐藏；`sources_test.go` 用真实数据测每个模块的来源。
- 做了没做的：
  - GitHub 来源只读缓存里的提交（每个分支最近约 30 个）和 PR，而且要已经知道自己的登录名。
  - 回填只能回到各来源库里还有的数据。
  - 日期按采集时的时区定，以后改时区旧条目不动。
  - 没做邮件、云盘、提醒、Home Assistant。
  - 各来源用本地数据库插入的数据验证，没有连真实的 GitHub、服务器告警。
