# B245、B246 笔记表格在手机上和导出图片里的显示：检查记录

2026-10-17，Claude Opus 5.5。本地起服务端和前端，用 Chromium 实际打开和导出。

## 做了什么

- 造了一篇黄色背景的笔记，内容是用户截图里的“珍珠耳饰需求表”：6 列 3 行，单元格里有长句和加粗。下面再放一张 2 列的小表格。
- 390 宽打开阅读模式，截一张；把表格往右滑 220px，再截一张。
- 打开“更多 → 导出图片”，分别用“卡片”和“加宽表格”导出。
- 1360 宽再打开同一篇，看电脑上有没有变化。

## 结果

- 390 宽：其余列最少 6 个字宽，不再一行一两个字。右边还有列时边缘淡出，滑到最右边淡出消失。往右滑时第一列固定在左边，底色是笔记的黄色。
- 第一次截图发现固定列左边漏出一条底下的字，原因是合并边框不跟着固定列走。已改成手机上每格自己画边框，再截图没有漏字。
- 页面没有报错，整页没有横向溢出。
- 导出“卡片”：每行一块，第一列做小标题，其余是“表头：内容”，宽 1080。2 列的小表格照常画成表格。
- 导出“加宽表格”：图片宽 800（2160 像素），表格完整，最后一列没有被裁掉。第一次表头“珍珠尺寸”折成两行，已改成加宽时表头不换行。
- 原来的问题（400 宽里 6 列挤在一起、表头叠在一起、最后一列被裁掉）两种模式下都没有了。2 列以内的表格在原来的 400 宽里，表头也会换行，不再叠在一起。
- 弹窗在 390 宽下，“卡片 / 加宽表格”和范围选项排在同一行，没有挤乱。
- 1360 宽阅读模式的表格和以前一样。

## 没验证的

- 固定列的底色在卡片、弹窗、彩色笔记、便签里分别设了，只实际看了彩色笔记。别的页面（项目、日记、AI 对话）的表格没逐个在手机上看。底色不对时，表现是固定列的底色和周围不一样。
- 例子里第一列是序号“#”，固定它帮助不大。第一列是名称时才有用。
- 没在真机 iPhone 上试 `position: sticky` 和 `mask-image`，用的是无头 Chromium。
