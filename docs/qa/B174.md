# B174 检查记录

日期：2026-10-13。负责人：Codex。分支：`develop`。

## 实现

- 歌手为空时，标题必须通过 `titlesMatch`，双方时长必须已知，差值不超过 2000 ms。先确定歌手，再判断其他来源的歌词和封面。无法确定时保留待确认候选。
- 匹配和用户采用候选都补空的歌手、专辑、专辑歌手、年份。已有字段保留。`manual = 1` 不补信息。标题、曲目号、碟号不补。
- 网易云读取歌曲或专辑的 `publishTime`。QQ 音乐读取 `publictime`。iTunes 读取 `releaseDate` 和 `collectionArtistName`。MusicBrainz 读取专辑发行日期 `date`。LRCLIB 不推断年份和专辑歌手。无效日期不写年份。
- iTunes 没有封面的搜索结果也能用于补信息。五个来源在歌手为空时都能正常查询。
- `POST /music/fill-albums` 处理歌手、专辑、年份任意一项缺失的歌曲。排除手动编辑和跳过匹配的歌曲。只缺专辑歌手的歌不纳入批量处理。请求和 `music.album_progress` 事件结构不变。与后台匹配互斥时仍返回 `409`。
- 批量不下载歌词和封面，不修改匹配状态，不保存候选。查不到的歌可以再次补全。
- 开启写回后，同步歌手、专辑、专辑歌手和年份标签。仍先写副本，读回标签和音频属性，验证成功后替换文件并更新 sha。
- 新候选的年份和专辑歌手保存到现有设置存储。采用另一部分后保留剩余候选的信息。采用完、跳过或移除歌曲时清理。扫描时也清理云盘外键删除留下的记录。没有新增迁移。
