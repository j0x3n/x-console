# B243 分享链接可以允许编辑：检查记录

2026-10-17，Claude Opus 5.5。本地起服务端和前端，用 Chromium 实际操作。

## 做了什么

- 在分享弹窗里勾上“打开链接的人可以编辑”，不设密码。弹窗里出现“没设密码，拿到链接的人都能改”，链接下面的说明多了“可以编辑”。
- 用一个没登录的浏览器打开链接，点“编辑”，在正文末尾加一行，填称呼“小王”，点“保存”。

## 结果

- 访客页面保存后回到只读页面，显示新内容。
- 自己这边读到的正文有新加的那行，附件地址还是原来的 `/api/v1/notes/attachments/<id>`，没变成公开地址。
- 访客编辑页在 1360 和 390 宽都没有横向溢出。
- 后端测试覆盖了：没开编辑回 403，有密码不带访问码回 401，`baseUpdatedAt` 不对回 409 且笔记不变，关掉编辑后再保存回 403，附件地址往返不变，10 分钟内两次保存只发一条通知，改“允许编辑”要二次验证。
- 前端测试覆盖了：没开编辑时没有“编辑”按钮，保存时带上开始编辑时的修改时间和称呼，409 时提示并能载入最新内容、自己写的放在下面。自动保存的暂停和继续单独测了。

## 没验证的

- 访客保存时自己正好在打字（有没保存的修改），顶部出现“这篇笔记在别处被改过”的提示，这条只有自动保存的单元测试，没有在浏览器里同时开两边试过。
- 通知只在测试里看了通知列表，没连 Telegram、Bark 这些真实渠道。
