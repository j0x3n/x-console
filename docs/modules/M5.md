# M5 项目

负责批次：1（任务卡 A，已完成）。Linear 同步在批次 2 由任务卡 H 做。

## 数据

迁移文件：`store/migrations/20260927174300_m5_projects.sql`。

| 表 | 列 |
| --- | --- |
| `projects` | id、key（2 到 5 个大写字母，如 XC）、name、description、color、icon、archived_at、next_number、created_at、updated_at |
| `issues` | id、project_id、number、title、description（Markdown）、status、priority（0 无、1 紧急、2 高、3 中、4 低）、due_date、milestone_id、sort_order（浮点，看板内排序）、external_source、external_id、created_at、updated_at、completed_at |
| `labels` | id、project_id（空表示全局）、name、color |
| `issue_labels` | issue_id、label_id |
| `milestones` | id、project_id、name、due_date、created_at |
| `issue_links` | id、issue_id、kind、title、url、ref、created_at |
| `issue_comments` | id、issue_id、body、created_at（先做简单评论，用于记录进展） |

状态固定为：`backlog`、`todo`、`in_progress`、`in_review`、`done`、`canceled`。Issue 的 key 是 `<项目 key>-<number>`。

实现说明：

- `due_date` 是本地日期，存成 `YYYY-MM-DD` 文本，接口里是 `format: date`。“今天”按服务器时区（`XC_TZ`）算。
- 新建 Issue 默认状态 `todo`，放在这一列最上面。编号用 `next_number`，只增不减，删除后不会复用。
- `completed_at` 在进入 done 或 canceled 时写入，回到其他状态时清空。
- `(external_source, external_id)` 有唯一索引（external_id 为空的不算）。
- 写数据的事务用 `BEGIN IMMEDIATE`。先读后写的普通事务在多连接下会直接报 `SQLITE_BUSY`。

## 接口

契约：`api/modules/projects.yaml`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/projects` | GET 默认只返回未归档的，`?archived=true` 只返回已归档的。每个项目带 `issueCount`、`openCount` |
| GET/PATCH/DELETE | `/projects/{projectId}` | DELETE 改为归档。PATCH `archived: false` 恢复 |
| GET | `/issues` | 过滤：projectId、status（可多个）、priority、labelId、milestoneId、due、q。排序：updated、priority、due、manual |
| POST | `/projects/{projectId}/issues` | 已归档的项目不能建 |
| GET/PATCH/DELETE | `/issues/{key}` | PATCH 可以改任意字段。`dueDate`、`milestoneId` 传 `null` 表示清除，`labelIds` 整体替换 |
| POST | `/issues/{key}/move` | 看板拖动：`{status, afterKey?, beforeKey?}`，服务端算 sort_order |
| GET/POST | `/issues/{key}/comments` | |
| DELETE | `/issues/{key}/comments/{commentId}` | |
| GET/POST | `/issues/{key}/links` | 同一种类、同一个 url 只存一次 |
| DELETE | `/issues/{key}/links/{linkId}` | |
| GET/POST | `/projects/{projectId}/labels` | 列表包括全局标签。POST `global: true` 建全局标签 |
| PATCH/DELETE | `/projects/{projectId}/labels/{labelId}` | |
| GET/POST | `/projects/{projectId}/milestones` | |
| PATCH/DELETE | `/projects/{projectId}/milestones/{milestoneId}` | 删除后，Issue 上的里程碑清空 |

`GET /issues` 的细节：

- 不带 projectId 时，不包含已归档项目的 Issue。
- `due=today` 今天到期；`week` 今天起 7 天内；`overdue` 已过期且没完成。
- `q` 搜标题，也能直接匹配 key（`XC-12`）或编号（`12`、`#12`）。
- `priority` 排序时紧急在前，无优先级最后。
- 分页用 `limit`（默认 200，最多 1000）和 `cursor`。游标是偏移量，因为排序不一定按 id。前端看板一次取完一个项目的全部 Issue。

`move` 的规则：`afterKey` 是落点上方的 Issue，`beforeKey` 是落点下方的。只传一个时，服务端自己找另一边的邻居；都不传表示放到这一列最后。新位置取两个邻居的中点，间隔小于 1e-6 时整列重新编号（间隔 1024）。前端 `logic.ts` 用同样的算法做乐观更新。

## 事件

| 主题 | 数据 |
| --- | --- |
| `project.created`、`project.updated`、`project.archived` | Project |
| `issue.created`、`issue.updated`、`issue.deleted` | Issue |
| `issue.status_changed` | `{key, from, to}`，PATCH 和 move 都会发 |
| `issue.synced` | Issue。IssueSync.Upsert 发这个，不发 created/updated，避免同步把改动推回去 |
| `issue_comment.created`、`issue_comment.deleted` | `{issueKey, data}` |
| `issue_link.created`、`issue_link.deleted` | `{issueKey, data}` |
| `label.created/updated/deleted`、`milestone.created/updated/deleted` | Label、Milestone |

## 对外

- 提供 `contracts.Issues`：`Create` 默认状态 todo；`AttachLink` 同一种类同一个 url 不重复；`ListDue(until)` 返回截止日期不晚于 until 当天的未完成 Issue（不含已归档项目），日期近的在前。
- 提供 `contracts.IssueSync`：
  - `Upsert` 按 `(ExternalSource, ExternalID)` 找 Issue。有就更新标题、描述、状态、优先级、截止日期，不换项目；没有就在 `ProjectID` 里新建。`UpdatedAt` 按传入的值写。
  - `Link` 把外部编号写到已有 Issue 上，不改 `updated_at`。编号已被别的 Issue 用了会返回 409。
  - `ChangedSince` 返回 `updated_at` 晚于 since 的 Issue，包括还没关联外部编号的本地 Issue。
- 动作：

| 名称 | 效果 | 输入 |
| --- | --- | --- |
| `projects.list` | read | `{}` |
| `projects.list_issues` | read | `projectKey?`、`status?[]`、`due?`、`q?`、`limit?`（默认 50） |
| `projects.get_issue` | read | `key`；返回 `{issue, links, comments}` |
| `projects.create_issue` | write | `projectKey` 或 `projectId`、`title`、`description?`、`status?`、`priority?`、`dueDate?` |
| `projects.update_issue` | write | `key` 和要改的字段；`dueDate: ""` 表示清除 |

## 前端 `features/projects`

- `/projects`：项目卡片（进度条、未完成数）、已归档项目切换、“我的未完成 Issue”（跨项目，快到期的在前）。
- `/projects/:projectKey`：看板和列表切换，偏好存在 localStorage。筛选栏：状态（列表视图）、优先级、标签、里程碑、搜索，都在前端筛。列表可按状态、优先级分组或不分组，可按手动顺序、最近更新、优先级、截止日期排序。右上角可以编辑项目、管理标签和里程碑、归档。
- `/projects/:projectKey/:number`：Issue 详情页。标题点击或按 `E` 编辑；描述用 textarea 编辑，可切换预览，`⌘/Ctrl + Enter` 保存；右侧属性面板；下方是关联和评论。
- 看板拖动用浏览器原生拖放，乐观更新，失败回滚并提示。手机上看板横向翻页，拖动不可用，可在详情页改状态。
- 键盘：`C` 新建，`J/K` 上下，`Enter` 打开，`E` 编辑标题，`1-6` 改状态，`Esc` 取消选中（详情页里返回项目）。焦点在输入框或有弹窗时不生效。
- “交给编码助手”按钮已经放好，置灰并提示编码模块还没上线。M4 接入时把它改成调用 `POST /coding/tasks`。
- 命令面板：“新建 Issue”“新建项目”“跳到 Issue…”（弹出输入框），另外每个项目和已加载的 Issue 都注册成跳转命令，输入 `XC-12` 就能找到。
- Markdown 用模块自带的小解析器（`mdparse.ts` + `Markdown.tsx`），不引入新依赖，不用 innerHTML。备忘模块也用它。

## 验收

- 新建项目、建 Issue、拖动看板、改状态后刷新仍正确。
- 两个浏览器窗口同时打开，一边改，另一边 1 秒内更新（事件推送）。
- key 在项目内连续递增，删除后不复用。
- 列表 500 条 Issue 时滚动流畅（行用 `content-visibility: auto`；后端测试里 500 条一次取出）。
