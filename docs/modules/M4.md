# M4 编码任务

负责批次：2（任务卡 E）。依赖 M3 的代理、M5 的 contracts.Issues、M13 的 contracts.GitHub（可选）。

## 流程

1. 代理上报可用的仓库和执行器。
2. 你选仓库、执行器、基础分支，写需求，点开始。也可以在 Issue 页点“交给编码助手”，需求自动带上 Issue 标题和描述。
3. 服务端排队。运行中的任务数不超过上限（默认 2，可配置）。
4. 代理在 `<仓库>/.x-console/worktrees/<任务id>` 建 worktree 和分支 `xc/<任务id>-<短名>`，在里面启动执行器。
5. 执行器的输出实时回传，服务端存库并推给浏览器。
6. 执行器退出后，代理算出改动文件和 diff，任务进入“待你决定”。
7. 你选：提交、提交并推送、建 PR、丢弃。建 PR 通过 M13。
8. 完成后清理 worktree（提交并推送后保留分支，丢弃时删除分支）。

## 执行器

| 执行器 | 启动命令（起点，开发时用 `--help` 核实参数） |
| --- | --- |
| Claude Code | `claude -p <需求> --output-format stream-json --verbose --permission-mode acceptEdits` |
| Codex | `codex exec --json <需求>`，按需加沙箱和自动批准参数 |

- 输出按行解析 JSON。解析不了的行当纯文本。
- 统一转成事件：`{kind: "text"|"tool"|"status"|"error", text, data}`。
- 执行器路径和额外参数在代理配置里可改（`config.Coding`）。
- 在 worktree 里运行，工作目录不能跳出 worktree。
- 超时默认 60 分钟。取消时先发中断信号，10 秒后强杀。

## 代理端方法（`methods_coding.go`，实现放 `internal/agent/coding`）

| 方法 | 类型 | 说明 |
| --- | --- | --- |
| `coding.executors` | 请求 | 检测 claude、codex 是否可用及版本 |
| `coding.repos` | 请求 | 扫描配置的根目录（默认用户目录下的 `code`、`projects`、`src`，深度 3），返回 git 仓库路径、名称、当前分支、默认分支、远端地址 |
| `coding.run` | 流 | 参数：任务 id、仓库路径、执行器、需求、基础分支、分支名、超时。流里发 JSON 行事件，结束时发 `{kind:"done", exitCode}` |
| `coding.diff` | 请求 | 改动文件列表和统一 diff（限制 2 MB） |
| `coding.commit` | 请求 | 提交信息。返回 commit sha |
| `coding.push` | 请求 | 推送分支 |
| `coding.discard` | 请求 | 删除 worktree 和分支 |

## 后端 `modules/coding`

### 表

| 表 | 列 |
| --- | --- |
| `coding_repos` | id、agent_id、path、name、default_branch、remote_url、github_repo（owner/name，从远端解析）、created_at |
| `coding_tasks` | id、repo_id、issue_key、executor、prompt、base_branch、branch、status、exit_code、error、commit_sha、pr_url、created_at、started_at、finished_at |
| `coding_task_events` | id、task_id、seq、at、kind、text、data |

状态：`queued` → `running` → `review`（等你决定）/ `failed` / `canceled` → `committed` / `pushed` / `pr_opened` / `discarded`。

### 接口

| 方法 | 路径 |
| --- | --- |
| GET | `/coding/executors?agentId=` |
| GET | `/coding/repos`；POST `/coding/repos`（从代理扫描结果里登记）；DELETE `/coding/repos/{id}` |
| GET | `/coding/repos/discover?agentId=` |
| GET/POST | `/coding/tasks` |
| GET | `/coding/tasks/{id}` |
| GET | `/coding/tasks/{id}/events?after=` |
| POST | `/coding/tasks/{id}/cancel` |
| GET | `/coding/tasks/{id}/diff` |
| POST | `/coding/tasks/{id}/commit`、`/push`、`/pr`、`/discard`（都要提升权限） |
| GET/PUT | `/coding/settings`（并发上限、默认超时） |

### 事件

`coding_task.created`、`coding_task.updated`（状态变化）、`coding_task.output`（`{taskId, events:[...]}`，200 毫秒合并一次）。

### 对外

- 提供 `contracts.Coding`。
- 动作：`coding.launch`（write）、`coding.list_tasks`（read）。
- 通知：`coding_task.review`（完成待决定）、`coding_task.failed`。
- 有 Issue 时：开始时把 Issue 改成 in_progress，并 `AttachLink(kind: coding_task)`；建 PR 后再 `AttachLink(kind: pull_request)` 并改成 in_review。

## 前端 `features/coding`

- 任务列表：状态筛选，运行中的在最上面。
- 新建任务弹窗：选仓库、执行器、基础分支、需求。
- 任务详情：左边实时输出（工具调用折叠显示），右边状态和操作按钮。完成后显示改动文件列表和 diff 查看器。
- 仓库管理：从代理发现、登记、删除。
- 命令面板命令：“新建编码任务”。
- Issue 详情页的“交给编码助手”按钮由 M5 放置，调用 `POST /coding/tasks` 带 `issueKey`。

## 验收

- 用一个假执行器脚本（测试里放一个输出 stream-json 的脚本）跑通：排队、运行、实时输出、diff、提交、丢弃。
- 超时和取消能停掉子进程，worktree 被清理。
- 同时提交 3 个任务、上限为 2 时，第 3 个排队，前一个结束后自动开始。
- 代理离线时任务标记失败，原因写清楚。
