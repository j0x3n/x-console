# M13 开发者集成：GitHub 与 Linear

负责批次：2（任务卡 H）。

## GitHub

- 设置：`github.token`（细粒度 PAT，加密），`github.repos`（关注的仓库列表 owner/name）。
- 用 REST API，`net/http` 直接调就行，也可以用 `github.com/google/go-github`。
- 每 5 分钟同步关注仓库的：打开的 PR（标题、作者、状态、检查结果、评审状态）、最近的 workflow runs、分配给你或你创建的 Issue。存缓存表。
- 接口：`GET/PUT /github/config`、`GET /github/pulls`、`GET /github/runs`、`GET /github/issues`、`POST /github/sync`。
- CI 从成功变失败时发通知（kind `github.ci_failed`）。
- 提供 `contracts.GitHub`（CreatePR）。
- 关联：PR 标题或分支名里出现 Issue key（如 `XC-12`）时，调用 `contracts.Issues.AttachLink`。编码任务分支 `xc/<任务id>-...` 能对应到编码任务。
- 动作：`github.list_pulls`（read）、`github.create_pr`（write）。
- 前端 `features/github`：PR 列表（按仓库分组，带检查状态）、CI 运行、Issue。设置页加“GitHub”标签。

## Linear 同步

- 设置：`linear.api_key`（加密），映射：Linear 团队 ↔ 本地项目。
- 用 Linear GraphQL API。
- 同步字段：标题、描述、状态（按状态类型映射：backlog、unstarted→todo、started→in_progress、completed→done、canceled→canceled）、优先级（Linear 的 0-4 和本地一致）、截止日期。
- 方向：双向。以 `updated_at` 较新的一方为准。本地 `issues.external_source = 'linear'`、`external_id = Linear issue id`。
- 触发：每 5 分钟拉一次 Linear 的更新；本地 `issue.updated` 事件触发推送（有 external_id 的才推）。
- 冲突和错误写日志，并在设置页显示最近一次同步结果。
- 接口：`GET/PUT /linear/config`、`GET /linear/teams`（配置时选择用）、`POST /linear/sync`、`GET /linear/status`。
- 读写本地 Issue 只通过 `contracts.IssueSync`（M5 已实现），不要跨模块直接写表。

## 验收

- 用 httptest 模拟 GitHub 和 Linear API。
- GitHub：同步后 PR 列表正确；CI 变红发通知；带 `XC-12` 的 PR 出现在 Issue 的关联里。
- Linear：本地改状态推到 Linear；Linear 改标题拉回本地；两边都改时以较新的为准。
