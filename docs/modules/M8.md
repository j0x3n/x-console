# M8 习惯与健康

负责批次：1（任务卡 B）。依赖 M7 的通知投递（同一任务卡）。

## 数据

| 表 | 列 |
| --- | --- |
| `habits` | id、name、icon、color、unit（杯、分钟、次）、daily_target、remind_mode（none/interval/times）、remind_interval_minutes、remind_window（`09:00-21:00`）、remind_times（JSON，如 `["08:00","20:00"]`）、ha_entity_id（可选，这个 HA 实体变化时自动打卡）、archived_at、sort_order、created_at |
| `habit_logs` | id、habit_id、at、amount、source（web/telegram/webpush/ha/ai/automation）、note |
| `workout_plans` | id、weekday（1-7）、title、items（JSON：动作名、组数、次数、重量） |
| `workout_logs` | id、date、plan_id、items（JSON：实际完成的组）、duration_minutes、note |

## 规则

- “今天”按 `Config.Location` 算。
- 间隔提醒：在 remind_window 内，从上次打卡或上次提醒起过了 interval 分钟就提醒。当天达标后不再提醒。
- 定时提醒：到 remind_times 的时间点提醒，已达标就跳过。
- 提醒走 `notify.Send`，kind `habit.reminder`，按钮“+1 {unit}”（action `habit.checkin:<id>:1`）和“跳过”。
- 连续天数：从昨天往前数达标的天数，今天达标再加 1。
- HA 联动：启动时和保存习惯时，对 ha_entity_id 调用 `contracts.HomeAssistant.WatchEntity`（取不到就跳过）。订阅 `ha.state_changed`，实体匹配且状态变化时打卡 1 次。M9 在同一批次开发，按 contracts 里的格式对接，测试里自己往总线发假事件。
- 健身：每天 8 点（可配置）如果当天有计划，发通知列出计划。

## 接口

| 方法 | 路径 |
| --- | --- |
| GET/POST | `/habits` |
| GET/PATCH/DELETE | `/habits/{id}` |
| GET | `/habits/today` |
| POST | `/habits/{id}/checkin`（`{amount?, note?}`） |
| DELETE | `/habits/logs/{logId}`（撤销打卡） |
| GET | `/habits/{id}/stats?days=30` |
| GET/PUT | `/workouts/plans` |
| GET/POST | `/workouts/logs` |

## 对外

- 提供 `contracts.Habits`。
- 动作：`habits.today`（read）、`habits.checkin`（write）、`workouts.log`（write）。
- 事件：`habit.checked_in`、`habit.goal_reached`。

## 前端 `features/habits`

- 今日视图：每个习惯一张卡，显示进度环和“+1”按钮，打卡后可以撤销。
- 习惯编辑：名称、单位、目标、提醒方式。
- 统计：连续天数、30 天热力图、每天次数柱状图。
- 健身标签：本周计划表（可编辑），今天的计划，记录训练。

## 验收

- 喝水目标 8 杯、每 60 分钟提醒、窗口 9 点到 21 点：模拟时间推进时，提醒只在窗口内发，达标后停止。（提醒逻辑写成接收“当前时间”参数的纯函数，测试里直接传时间。）
- 通知上点“+1”后，今日进度加 1。
- 跨午夜时，进度按用户时区清零。
