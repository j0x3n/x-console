# M8 习惯与健康

负责批次：1（任务卡 B）。依赖 M7 的通知投递（同一任务卡）。

## 数据

| 表 | 列 |
| --- | --- |
| `habits` | id、name、icon、color、unit（杯、分钟、次）、daily_target、remind_mode（none/interval/times）、remind_interval_minutes、remind_window（`09:00-21:00`）、remind_times（JSON，如 `["08:00","20:00"]`）、ha_entity_id（可选，这个 HA 实体变化时自动打卡）、archived_at、sort_order、created_at |
| `habit_logs` | id、habit_id、at、amount、source（web/telegram/webpush/ha/ai/automation）、note |
| `workout_plans` | id、weekday（1-7）、title、items（JSON：动作名、组数、次数、重量） |
| `workout_logs` | id、date、plan_id、items（JSON：实际完成的组）、duration_minutes、note |

## 规则

- “今天”按 `Config.Location` 算。
- 间隔提醒：在 remind_window 内，从上次打卡或上次提醒起过了 interval 分钟就提醒。当天达标后不再提醒。
- 定时提醒：到 remind_times 的时间点提醒，已达标就跳过。
- 提醒走 `notify.Send`，kind `habit.reminder`，按钮“+1 {unit}”（action `habit.checkin:<id>:1`）和“跳过”。
- 连续天数：从昨天往前数达标的天数，今天达标再加 1。
- HA 联动：启动时和保存习惯时，对 ha_entity_id 调用 `contracts.HomeAssistant.WatchEntity`（取不到就跳过）。订阅 `ha.state_changed`，实体匹配且状态变化时打卡 1 次。M9 在同一批次开发，按 contracts 里的格式对接，测试里自己往总线发假事件。
- 健身：每天 8 点（可配置）如果当天有计划，发通知列出计划。

## 对外

- 提供 `contracts.Habits`。

- 事件：`habit.checked_in`、`habit.goal_reached`。

## 前端 `features/habits`

- 今日视图：每个习惯一张卡，显示进度环和“+1”按钮，打卡后可以撤销。
- 习惯编辑：名称、单位、目标、提醒方式。
- 统计：连续天数、30 天热力图、每天次数柱状图。
- 健身标签：本周计划表（可编辑），今天的计划，记录训练。

## 实现说明（批次 1）

和上面规格不同或补充的地方：

- **多出的列**：`habits.last_reminded_at`（上次提醒时间，间隔提醒要用）、`habits.quiet_until`（通知上点“跳过”后，当天不再提醒）。`workout_logs.created_at`。
- **提醒规则**是纯函数 `shouldRemind(state, now, loc)`（`logic.go`）：
  - 间隔：在时段内，从“时段开始、今天最后一次打卡、上次提醒”里最晚的那个算起，过了间隔就提醒。时段为空表示全天，不支持跨午夜。间隔 5 到 1440 分钟。
  - 定时：到点提醒一次，最多晚 1 小时（服务重启后不补发太久以前的）。
  - 两种都在当天达标后停止。调度器每分钟跑一次。
- **按钮**：`habit.checkin:<id>:<数量>`；“跳过”是 `habit.skip:<id>`，效果是当天不再提醒。打卡来源按按钮来路记为 `telegram` 或 `webpush`。
- **HA 联动**：只跟踪有习惯关联的实体。先用 `State` 取一次当前状态做基准；之后状态和上次不同才打卡。`unavailable`、`unknown` 忽略。事件的 payload 按 `contracts.HAState` 解析，也接受同样字段的 JSON 结构。
- **健身提醒设置**：`habits.workout_notify = {enabled, time}`，默认开启、08:00。接口 `GET/PUT /workouts/settings`。每天最多发一次，晚于设定时间 2 小时就不发。通知 kind `workout.plan`，链接 `/habits/workout`。
- **新增接口**：`DELETE /workouts/logs/{logId}`、`GET /workouts/settings`、`PUT /workouts/settings`。`GET /habits?archived=true` 包含已归档的。
- **`POST /habits/{id}/checkin`** 返回 `{log, today}`，today 是这个习惯的最新进度。归档的习惯不能打卡（409）。
- **统计**：`GET /habits/{id}/stats?days=30` 返回 `streak`、范围内的 `bestStreak`、`reachedDays`、`total` 和每天的 `{date, amount, reached}`。连续天数最多往回看一年。
- **动作** `habits.checkin` 可以用 `habitId` 或 `name` 指定习惯；来源在自动化里记 `automation`，否则记 `ai`。
- **事件**：`habit.created`、`habit.updated`、`habit.deleted`、`habit.checked_in`、`habit.goal_reached`、`habit.log_deleted`、`workout.logged`、`workout.log_deleted`、`workout.plans_updated`。
- **前端**：`/habits`（今天）、`/habits/stats`、`/habits/workout`；`/habits?new=1` 打开新建弹窗。每周计划在界面上每天一条，服务端同一天有多条时合并显示。

## 验收

- 喝水目标 8 杯、每 60 分钟提醒、窗口 9 点到 21 点：模拟时间推进时，提醒只在窗口内发，达标后停止。（提醒逻辑写成接收“当前时间”参数的纯函数，测试里直接传时间。）
- 通知上点“+1”后，今日进度加 1。
- 跨午夜时，进度按用户时区清零。
