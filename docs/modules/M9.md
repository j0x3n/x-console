# M9 Home Assistant

负责批次：1（任务卡 D）。状态：已实现，包括第二步“通过代理访问”。

代码：后端 `backend/internal/server/modules/homeassistant/`，代理端 `backend/internal/agent/netproxy/`，协议 `backend/pkg/protocol/methods_proxy.go`，前端 `web/src/features/home/`。

## 连接

- 设置键：`ha.url`（如 `http://homeassistant.local:8123`，去掉末尾的 `/`）、`ha.token`（长期访问令牌，`Settings.SetSecret` 加密存）、`ha.agent_id`（空表示直连）。
- 面板服务器在公网，HA 在家里。两种接法：
  1. **服务器直接访问**：HA 有公网地址（Nabu Casa 或自己的反向代理）时直接填。反向代理必须转发 WebSocket。
  2. **通过家里的代理**：HA 只在内网时，选一台和 HA 在同一个网络、已配对的代理。服务端通过代理的 `http.proxy` 和 `ws.proxy` 访问 HA，地址填内网地址。
- 用 HA 的 WebSocket API（`/api/websocket`）：`auth` → `subscribe_events`（`state_changed`）→ `get_states` 取全量 → 之后 `call_service` 调服务。先订阅再取全量，两者之间的变化不会丢；取全量期间收到的更新按 `last_updated` 取较新的。
- 每 30 秒发一次 `ping`，10 秒没有 `pong` 就断开重连。
- 断线自动重连，间隔 1 秒起步翻倍，最长 1 分钟；一次连接保持超过 1 分钟后间隔重置为 1 秒。
- 令牌被拒（`auth_invalid`）后**不再重试**，直到配置改变。原因：HA 开了 IP 封禁时，连续登录失败会封掉服务器的 IP。
- 保存配置后立即断开并按新配置重连，同时清空缓存。
- 代理模式下，代理重新上线（`agent.online` 事件）时跳过等待，马上重连。
- 内存里保存全部实体的最新状态。断线时保留缓存（页面显示最后一次的状态），重连后用新的全量替换。断线期间收藏或被关注的实体有变化时，重连后补发 `ha.state_changed`。

## 代理转发（第二步）

协议定义在 `pkg/protocol/methods_proxy.go`，能力常量 `proxy`（`protocol.CapProxy`），Linux 和 Windows 都有。

| 方法 | 类型 | 参数 → 结果 |
| --- | --- | --- |
| `http.proxy` | 请求/响应 | `HTTPProxyParams{method, url, header, body, timeoutSeconds}` → `HTTPProxyResult{status, header, body}`。不跟随重定向，响应体最大 8 MB，超时默认 15 秒、最长 60 秒 |
| `ws.proxy` | 流 | `WSProxyParams{url, header}`。双向的数据帧都是 WebSocket 文本消息 |

- **只转发到内网**：代理只连回环、私有网段（10/8、172.16/12、192.168/16、fc00::/7）、链路本地和 100.64.0.0/10（Tailscale）。检查在 DNS 解析之后、真正建连时做（`net.Dialer.Control`），所以域名解析到公网地址也会被拒；不走环境变量里的 HTTP 代理。被拒时返回错误码 `forbidden_target`。
- **分帧**：一条 WebSocket 消息可能比一个协议帧大（大家庭的 `get_states` 有几 MB），所以按 256 KB 切块。每块第一个字节是标志：`0` 表示后面还有，`1` 表示这条消息结束。单条消息最大 64 MB。工具函数 `protocol.WSProxySplit` 和 `protocol.WSProxyJoiner`。
- 服务端的实现是 `homeassistant/agent.go` 里的 `viaAgent`，和直连共用同一个 `transport` 接口。
- 选代理时校验：代理存在、没吊销、上次连接时上报了 `proxy` 能力。

## 接口

契约 `api/modules/homeassistant.yaml`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/ha/config` | `{url, mode, agentId, hasToken, token}`，`token` 打码成 `••••••••` 加最后 4 位 |
| PUT | `/ha/config` | `{url, token?, mode, agentId?}`。**需要提升权限**（改地址会把已存的令牌发到新地址）。`token` 留空表示不改。`url` 为空表示删除整个配置 |
| POST | `/ha/test` | 先用 REST 读 `/api/config`，再走一遍 WebSocket 认证。不带请求体测已保存的配置；带请求体测表单的值，**需要提升权限**。返回 200 `{ok, message?, version?, locationName?}`，失败原因在 `message` |
| GET | `/ha/status` | `{configured, connected, mode, version?, entityCount, error?, connectedAt?}` |
| GET | `/ha/states?domain=&q=` | 缓存里的全部状态，按 entityId 排序。`q` 匹配 entityId 和 friendly_name |
| GET | `/ha/states/{entityId}` | 单个状态。不存在 404；没连上且缓存里没有 503 `ha_unavailable` |
| POST | `/ha/services/{domain}/{service}` | `{entityId?, data?}`，`entityId` 放进 `target.entity_id`，`data` 是 `service_data`。成功 204。危险服务**需要提升权限** |
| GET/PUT | `/ha/favorites` | PUT 整体替换 `{items: [{entityId, alias?}]}`，数组顺序就是显示顺序，最多 200 个 |

错误：未配置 412 `integration_not_configured`；没连上 503 `ha_unavailable`；HA 返回的错误映射成 404 `ha_not_found`、400 `ha_invalid`、502 `ha_error`；超时 504 `ha_timeout`。

**危险服务**（`isDangerous`）：`lock.*`、`alarm_control_panel.*`、`cover` 的 `open_cover`、`open_cover_tilt`、`set_cover_position`、`set_cover_tilt_position`、`toggle`、`toggle_cover_tilt`；以及目标实体是门锁、安防面板，或对 cover 实体调 `turn_on`/`toggle` 的通用服务（如 `homeassistant.turn_on`）；`homeassistant.*` 按区域、设备、楼层、标签批量操作时也算。脚本和场景里做了什么无法判断，按普通写操作处理。

## 事件

- `ha.state_changed`：数据是 `contracts.HAState`，只转发收藏实体和用 `WatchEntity` 注册过的实体。其余实体变化只更新内存。
- 其他模块用 `contracts.HomeAssistant.WatchEntity(entityID)` 注册需要转发的实体（M8 习惯、M12 自动化）。注册只在内存里，模块应在 `Start` 里注册。
- `ha.connection_changed`：`{connected}`。连上、断开时发；断开状态下错误原因变化时也会再发一次 `{connected: false}`，方便前端刷新状态。

## 对外

- 提供 `contracts.HomeAssistant`：`State` 读缓存；`CallService(domain, service, data)` 的目标实体放在 `data["entity_id"]`，调用方自己负责确认和提升权限。
- 动作（一个动作的 Effect 是固定的，所以调服务拆成两个）：

| 动作 | Effect | 说明 |
| --- | --- | --- |
| `ha.list_entities` | read | `{domain?, q?}` → `[{entityId, name, state, unit}]` |
| `ha.get_state` | read | `{entityId}` → `HAState` |
| `ha.call_service` | write | `{domain, service, entityId?, data?}`。遇到危险服务返回 403 `dangerous_service` |
| `ha.call_dangerous_service` | dangerous | 同上，接受任何服务，包括开锁、撤防、开车库门 |

审计动作：`ha.config`、`ha.favorites`、`ha.call_service`（目标是 `domain.service`）。

## 前端 `features/home`

- 收藏：大按钮卡片，手机上两列。灯、开关、风扇等点一下切换；场景、脚本点一下执行；按钮点一下按下；传感器显示读数和单位。门锁、窗帘不做一键操作，只显示状态。“编辑”里可以上移、下移、取消收藏。
- 全部设备：按域分组（常用的域在前），可按名称或 id 搜索，可按类型筛选，星标加入或取消收藏，每行有开关、执行、开锁、打开和关闭等按钮。开锁和开门会弹出验证码框。
- 实时更新：`useServerEvent("ha.", ...)` 收到 `ha.state_changed` 直接写进 Query 缓存；`ha.connection_changed` 整体刷新。非收藏实体没有事件，调用服务后隔一会刷新一次列表。
- 未配置时显示设置引导；断线时显示提示和原因，列表显示最后一次的状态。
- 设置页“Home Assistant”标签：地址、令牌、连接方式（服务器直接访问 / 通过家里的代理）、代理选择（只列出有 `proxy` 能力的代理）、测试连接、状态卡片。
- 命令面板：“打开智能家居”“Home Assistant 设置”。
