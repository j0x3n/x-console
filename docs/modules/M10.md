# M10 运维监控

负责批次：2（任务卡 F）。依赖 M2 的 hosts 模块和代理。

## 实现概览

| 部分 | 位置 |
| --- | --- |
| 后端模块 | `backend/internal/server/modules/monitoring`（一个模块，名字 `monitoring`，四个部分都在这里） |
| 接口契约 | `api/modules/monitoring.yaml` |
| 迁移 | `backend/internal/server/store/migrations/20260927210000_m10_ops.sql` |
| 代理方法 | `backend/pkg/protocol/methods_docker.go` |
| 代理功能包 | `backend/internal/agent/docker` |
| 前端 | `web/src/features/monitoring`，Docker 标签在 `DockerTab.tsx`，由 `features/servers/tabs.tsx` 引用 |

定时逻辑都写成带当前时间参数的纯函数（`logic.go`），测试直接调用：
`nextState`、`expiryDue`、`isDue`、`downsample`、`reminderDue`、`advance`、`renewUntil`、`monthlyCost`。

后台任务：

| 名称 | 间隔 | 做什么 |
| --- | --- | --- |
| `monitoring.check` | 15 秒 | 检查到了间隔的监控。同一个监控同时只会检查一次 |
| `monitoring.subscriptions` | 30 分钟 | 自动续期、发续费提醒。重复运行不会重复发 |
| `monitoring.cleanup` | 1 小时 | 删除 30 天前的监控结果 |

## 四个部分

### 1. Docker

- 代理端方法（`methods_docker.go`，实现 `internal/agent/docker`，用 net/http 通过 unix socket 调 Docker Engine API，不引入 SDK）：
  - `docker.ps`（`{all}`）、`docker.action`（start/stop/restart/remove，remove 带 force）、`docker.stats`（空 id 表示所有运行中的容器，并行采样）、`docker.images`。
  - `docker.logs` 是流：代理去掉 Docker 的 8 字节多路复用头，把 stdout 和 stderr 合在一起发文本；`follow` 时一直发，任何一方关流就停。TTY 容器直接转发。
- socket 路径：`DOCKER_HOST=unix://...`，没有就是 `/var/run/docker.sock`。
- 代理启动时 `/_ping` 能通才上报 `docker` 能力。Windows 上 Docker Desktop 用命名管道，所以一般没有这个能力。
- 服务端接口（在 monitoring 模块里，不在 hosts 里）：

| 接口 | 说明 |
| --- | --- |
| `GET /hosts/{hostId}/docker/containers?all=` | 容器列表 |
| `POST /hosts/{hostId}/docker/containers/{containerId}/{action}` | stop 和 remove 要提升权限；四种操作都写审计 `docker.container.<action>`，成功后发 `docker.container.changed` |
| `GET /hosts/{hostId}/docker/containers/{containerId}/logs?tail=` | 最近的日志行（最多 5000 行、4 MB） |
| `GET /hosts/{hostId}/docker/containers/{containerId}/logs/follow?tail=` | WebSocket，文本帧是日志文本 |
| `GET /hosts/{hostId}/docker/stats` | 运行中容器的资源占用 |
| `GET /hosts/{hostId}/docker/images` | 本地镜像 |

- SSH 主机和没有 docker 能力的机器返回 501 `unsupported`；容器不存在返回 404。
- 前端：服务器详情页的“容器”标签（`tabs.tsx` 一行，懒加载 `features/monitoring/DockerTab.tsx`）。列表合并了资源占用，日志弹窗实时跟随。

### 2. 脚本库

| 表 | 列 |
| --- | --- |
| `scripts` | id、name、description、shell（bash/sh/powershell）、body、default_host_ids（JSON）、timeout_seconds（默认 300，最多 1800）、created_at、updated_at |
| `script_runs` | id、script_id、host_id、host_name、started_at、finished_at、exit_code、stdout、stderr、error、triggered_by（user/automation/ai） |

- 执行通过 `contracts.Hosts.Exec`，要提升权限。可以一次选多台机器（最多 50 台）并行跑。
- `POST /scripts/{id}/run` 立即返回 202 和每台机器的运行记录（状态 running），在后台执行。每台跑完发 `script_run.finished`。开始时发 `script_run.started`。
- 命令：`sh` 和 `powershell` 直接交给代理的 shell（Linux 是 `/bin/sh -c`，Windows 是 PowerShell）；`bash` 包成 `bash -c '<脚本>'`。脚本最长 64 KB。
- 输出每路保留 256 KB。机器不在线等没能执行的情况，`exit_code` 为空，原因写在 `error`。
- 服务重启时，还没结束的运行标成失败（“服务重启，运行被中断”）。
- 改脚本内容或 shell 也要提升权限（和执行一样敏感）；只改名字、说明、默认机器不用。
- 接口：`/scripts` CRUD，`POST /scripts/{id}/run`（`{hostIds}`，不填用默认机器），`GET /scripts/{id}/runs`（游标分页），`GET /script-runs/{id}`。
- 审计：`script.create/update/delete/run`，每台机器还有 hosts 模块写的 `host.exec`。

### 3. 网站、证书、域名

| 表 | 列 |
| --- | --- |
| `monitors` | id、kind（http/tls/domain）、name、target、interval_seconds、expected_status（0 表示 200 到 399）、keyword、timeout_ms、enabled、last_status（unknown/up/down）、last_checked_at、last_error、consecutive_failures、expires_at、expiry_notified（JSON）、created_at |
| `monitor_results` | id、monitor_id、at、ok、status_code、latency_ms、error、detail（JSON：expiresAt、daysLeft、subject、issuer、registrar） |

- 默认间隔：http 60 秒，tls 6 小时，domain 1 天。最小：http 30 秒，tls 5 分钟，domain 1 小时。
- http：GET 目标，检查状态码和可选关键词（读前 1 MB）。每次检查新建连接。
- tls：握手取证书，按系统根证书在检查时刻验证。证书无效或过期算失败，但到期时间照样记录。剩 14 天、7 天、3 天各提醒一次。
- domain：RDAP `GET <base>/domain/<域名>`，读 `events` 里的 `expiration`，也记下注册商。base 默认 `https://rdap.org`，可以用设置键 `monitoring.rdap_url` 改。剩 30 天、7 天各提醒一次。
- 到期提醒按“到期时间”记账：第一次检查就只剩 5 天时只发一条（7 天那档），14 天那档不会再补发。证书或域名续期后（到期时间变了）重新开始。
- 三种监控都按同一个规则告警：连续失败 2 次发 `monitor.down`（高优先级通知），之后第一次成功发 `monitor.up`。改了目标会清空状态。
- 结果保留 30 天。`GET /monitors/{id}/results?range=24h|7d|30d` 超过 500 个点时按时间合并，返回可用率和平均耗时。
- 接口：`/monitors` CRUD，`POST /monitors/{id}/check`，`GET /monitors/{id}/results`。
- 事件：`monitor.down`、`monitor.up`、`monitor.expiring`，还有 `monitor.checked`（每次检查）和 `monitor.created/updated/deleted`。
- 通知链接：网站是 `/monitoring?monitor=<id>`，证书和域名是 `/monitoring/certs?monitor=<id>`。

### 4. 订阅与续费

| 表 | 列 |
| --- | --- |
| `subscriptions` | id、name、category（server/domain/saas/other）、amount、currency、cycle（monthly/yearly/custom_days）、cycle_days、next_renewal（本地日期 YYYY-MM-DD）、remind_days_before（JSON，默认 `[7,1]`）、reminded（这次续费已提醒的天数）、url、note、auto_renew、archived_at、created_at、updated_at |
| `subscription_events` | id、subscription_id、at、kind（created/reminded/renewed/updated）、detail |

- 每 30 分钟检查一次，按用户时区算“今天”。提醒只在本地 9 点以后发，不会半夜打扰。
- 按 remind_days_before 发 `subscription.due` 通知，每个天数只发一次；改了续费日期就重新计。
- 过了续费日且是自动续费的，把 next_renewal 往后推整周期（月底对齐，1 月 31 日加一个月是 2 月 28 日），记一条 renewed 历史，发 `subscription.renewed`。
- 不是自动续费的过期后保持原样，列表里显示“已过期 N 天”。前端“已续费”按钮把日期推一个周期。
- 接口：`/subscriptions` CRUD（`?archived=true` 看已归档，PATCH `{archived}` 归档或取消），`GET /subscriptions/summary`（未归档的按币种折算每月和每年，另有按分类），`GET /subscriptions/{id}/events`（历史）。
- 折算：年付除以 12；每 N 天按一年 365.25 天折算。不做汇率换算。

## 动作

| 名称 | 效果 | 说明 |
| --- | --- | --- |
| `scripts.list` | read | 脚本列表 |
| `scripts.run` | dangerous | `script` 是 id 或名字，`hosts` 是机器 id 或名字（不填用默认机器）。等所有机器跑完（最多 10 分钟）再返回结果。actor 含 automation 时记为 automation，否则记为 ai |
| `monitors.list` | read | 监控列表，可按 kind 过滤 |
| `subscriptions.list` | read | 未归档的订阅和支出汇总 |

## 前端 `features/monitoring`

标签页：网站（`/monitoring`）、证书与域名（`/monitoring/certs`）、脚本（`/monitoring/scripts`）、订阅（`/monitoring/subscriptions`）。每个都是列表 + 新建弹窗（`?new=1`）+ 详情弹窗（`?monitor=`、`?script=`、`?subscription=`）：

- 网站和证书详情：响应时间曲线、正常/失败色带、最近 20 次检查、立即检查、暂停、编辑、删除。证书和域名还显示到期时间、剩余天数、签发机构或注册商。
- 脚本详情：脚本内容、运行记录（展开看输出）、执行弹窗（选机器，需要再次验证）。
- 订阅：顶部按币种的每月、每年支出；详情里有历史、已续费、归档。

## 验收

- http 监控用 httptest 模拟宕机和恢复，各收到一次通知。（`TestHTTPMonitorDownAndUp`）
- 证书用本地 TLS 服务器测试 14/7/3 天提醒各一次、续期后重新提醒。（`TestTLSMonitorExpiry`）
- 域名用假 RDAP 服务器。（`TestDomainMonitorRDAP`）
- 脚本在两台假代理上并行执行，结果分别记录。未提升权限时拒绝。（`TestScriptsRunInParallel`、`TestScriptRunOnOfflineHost`）
- 订阅续费提醒在提前 7 天和 1 天各发一次，不重复发。（`TestSubscriptionReminders`）
- Docker 代理包用临时目录里 unix socket 上的假 Docker API 测试；设置 `XC_TEST_DOCKER_SOCKET`（和 `XC_TEST_DOCKER_CONTAINER`）时还会连真实 Docker 测试。（`internal/agent/docker`）
