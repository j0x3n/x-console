# M2 服务器 与 M3 本机

负责批次：1（任务卡 C）。M10 的 Docker 页面在这之上做。

两个模块共用一个后端模块 `modules/hosts`，前端分成 `features/servers`（kind=server）和 `features/pc`（kind=desktop）。

## 代理端方法

写在 `pkg/protocol/methods_hosts.go`，实现放 `internal/agent/{metrics,proc,svc,pty,files,exec,clipboard,power}`，公共小工具在 `internal/agent/rpcutil`。指标用 gopsutil。`app.open` 和 `power.action` 一起放在 `power` 包。

| 方法 / 事件 | 类型 | 说明 |
| --- | --- | --- |
| `metrics`（事件） | 事件 | 每 10 秒一次：CPU%、每核 CPU%、内存已用/总量、交换区、每个挂载点的磁盘用量、网络收发速率、磁盘读写速率、load1/5/15、开机时长、进程数 |
| `system.info` | 请求 | 用 gopsutil 补全 `protocol.SystemInfo` |
| `proc.list` | 请求 | 参数：排序字段、条数。返回 pid、名称、用户、CPU%、内存、命令行、启动时间 |
| `proc.kill` | 请求 | pid、信号（Windows 只支持结束） |
| `svc.list` | 请求 | systemd 单元或 Windows 服务：名称、描述、状态、是否开机启动 |
| `svc.action` | 请求 | start、stop、restart、enable、disable |
| `svc.logs` | 请求 | 最近 N 行（journalctl -u / Windows 事件日志可以先返回 unsupported） |
| `pty.open` | 流 | 参数：shell（可空）、cols、rows、cwd。Linux 用 creack/pty，Windows 用 ConPTY |
| `files.list` | 请求 | 路径下的条目：名称、类型、大小、修改时间、权限 |
| `files.read` | 流 | 下载。代理先发一块 JSON `FileHeader`（名称、大小、修改时间），再分块发送内容，每块 64 KB |
| `files.write` | 流 | 上传。参数带 `size`。服务端正好发 `size` 字节；代理写到同目录的临时文件，改名到位后回一块 JSON `FileEntry` 作为确认。流提前结束时删掉临时文件 |
| `files.remove` / `files.mkdir` / `files.rename` | 请求 | |
| `exec.run` | 请求 | 命令、超时（默认 60 秒，最长 30 分钟）、工作目录。Linux 用 `/bin/sh -c`，Windows 用 PowerShell。返回退出码、stdout、stderr（各最多 1 MB）、是否超时、是否截断 |
| `clipboard.get` / `clipboard.set` | 请求 | 只在 desktop。文本 |
| `power.action` | 请求 | lock、sleep、shutdown、restart。只在 desktop |
| `app.open` | 请求 | 打开程序或网址。只在 desktop |

能力：`metrics`、`processes`、`files`、`exec` 总是上报；`pty` 在能开终端时上报（Windows 需要 ConPTY）；`services` 在 Linux 上只有 systemd 在运行时才上报；`clipboard`、`power` 和新增的 `open`（`protocol.CapOpen`，对应 `app.open`）只在 Windows 上报。

错误码：除标准码外，文件和服务操作会返回 `not_found`、`permission_denied`、`exists`，服务端转成 404、403、409。

### 终端流的格式

代理和服务端之间的流里，每块数据第一个字节是类型：

- `0`：终端数据
- `1`：窗口大小，后面是 JSON `{"cols":120,"rows":32}`

代理发给服务端的输出块也以 `0` 开头。

浏览器和服务端之间的 WebSocket：二进制帧是终端数据，文本帧是 JSON 控制消息 `{"type":"resize","cols":..,"rows":..}`。终端结束时服务端正常关闭 WebSocket；代理报错时用 1011 关闭，原因里带错误信息。

浏览器拿不到 WebSocket 握手的 403，所以前端打开终端前先查 `/auth/status`，没提升就走 `withElevation` 弹框。服务端仍然在升级前检查。

## 后端 `modules/hosts`

### 表

迁移文件 `20260927020000_m2_hosts.sql`。

| 表 | 列 |
| --- | --- |
| `host_metrics_1m` | host_id（代理 id 或 `ssh:<id>`）、at、cpu、mem_used、mem_total、disk_json、net_rx、net_tx、load1。主键 (host_id, at) |
| `host_metrics_1h` | 同上，按小时汇总 |
| `ssh_hosts` | id、name、address、port、username、auth（key/password）、secret（加密的 JSON：密码，或私钥和私钥密码）、host_key（第一次连上时记下的主机公钥）、created_at |
| `alert_rules` | id、host_id（空表示所有）、metric（cpu/memory/disk/offline）、op（gt/lt）、threshold、duration_seconds、severity（warning/critical）、enabled、created_at |
| `alert_events` | id、rule_id（规则删了置空）、host_id、host_name、metric、severity、value、message、fired_at、resolved_at |

内存里为每台机器保留最近 1 小时的原始数据（环形缓冲，360 条）。样本时间用服务端收到的时间。定时任务：

| 任务 | 间隔 | 做什么 |
| --- | --- | --- |
| `hosts.rollup` | 1 分钟 | 把最近两个完整分钟写成 1m 行；把上一小时和当前小时的 1m 行汇总成 1h 行。都是 upsert，重复跑没关系 |
| `hosts.alerts` | 15 秒 | 检查所有启用的规则 |
| `hosts.ssh_metrics` | 1 分钟 | 通过 SSH 读 /proc 和 df，得到基础指标 |
| `hosts.cleanup` | 1 小时 | 1m 保留 7 天，1h 保留 90 天，已恢复的告警保留 90 天 |

曲线：`1h` 用内存里的原始数据（代理 10 秒一个点，SSH 主机 1 分钟一个点），服务端刚重启时退回 1m 数据；`24h` 用 1m 数据按 5 分钟取平均；`7d` 用 1h 数据。

### 接口

`{id}` 是 agent id，SSH 主机用 `ssh:<数字>`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/hosts?kind=` | 所有机器及最新指标 |
| GET | `/hosts/{id}` | 详情：系统信息、最新指标、能力 |
| GET | `/hosts/{id}/metrics?range=1h\|24h\|7d` | 曲线数据 |
| GET | `/hosts/{id}/processes` | |
| POST | `/hosts/{id}/processes/{pid}/kill` | 要提升权限 |
| GET | `/hosts/{id}/services` | |
| POST | `/hosts/{id}/services/{name}/{action}` | stop、disable 要提升权限 |
| GET | `/hosts/{id}/services/{name}/logs?lines=200` | |
| GET（WS） | `/hosts/{id}/terminal?cols=&rows=` | 要提升权限（在升级前检查） |
| GET | `/hosts/{id}/files?path=` | |
| GET | `/hosts/{id}/files/content?path=` | 下载 |
| PUT | `/hosts/{id}/files/content?path=` | 上传，要提升权限 |
| DELETE | `/hosts/{id}/files?path=&recursive=` | 要提升权限 |
| POST | `/hosts/{id}/files/mkdir` | 新建文件夹 |
| POST | `/hosts/{id}/files/rename` | 移动或改名，目标不能存在，要提升权限 |
| POST | `/hosts/{id}/exec` | 要提升权限 |
| GET/PUT | `/hosts/{id}/clipboard` | |
| POST | `/hosts/{id}/power` | shutdown、restart 要提升权限 |
| POST | `/hosts/{id}/open` | |
| CRUD | `/ssh-hosts` | 新建、修改、删除要提升权限。修改时密码或私钥留空表示不改；地址或端口变了会清掉记住的主机指纹 |
| POST | `/ssh-hosts/test` | 不保存，试连一次，返回主机指纹。要提升权限 |
| POST | `/ssh-hosts/{sshId}/test` | 用保存的信息试连一次 |
| CRUD | `/alert-rules` | |
| GET | `/alerts?since=&hostId=&active=&limit=` | 告警历史，默认最近 7 天 |

SSH 主机只支持：终端、exec、基础指标（通过 exec 读 /proc，1 分钟一次）。用 `golang.org/x/crypto/ssh`，每台主机保持一条连接，断了自动重连。主机指纹第一次连接时记下，之后不一致就拒绝连接（返回 `ssh_host_key_changed`）。其他接口对 SSH 主机返回 501 `feature_unavailable`。1 分钟内（150 秒）有过成功的 SSH 操作就算在线。

所有高危操作写审计：`host.process.kill`、`host.service.<动作>`、`host.terminal`、`host.exec`、`host.file.upload/download/delete/rename/mkdir`、`host.clipboard.set`（只记长度）、`host.power.<动作>`、`host.open`、`host.ssh.*`、`host.alert_rule.*`。

| 主题 | 数据 |
| --- | --- |
| `host.metrics` | `{hostId, sample}`，sample 是接口里的 `MetricsSample`。每台机器最多 9 秒一次 |
| `host.alert.fired` / `host.alert.resolved` | `AlertEvent` |
| `host.process.killed` | `{hostId, pid}` |
| `host.service.changed` | `{hostId, name, action}` |

| `host.alert_rule.created/updated/deleted` | 告警规则 |

### 对外

- 提供 `contracts.Hosts`。
- 注册动作：`hosts.list`（read）、`hosts.get_metrics`（read）、`hosts.service_action`（dangerous）、`hosts.exec`（dangerous）、`hosts.clipboard_set`（write）、`hosts.power`（dangerous）、`hosts.open`（write）。参数里的 `host` 可以是 id，也可以是机器名；剪贴板、电源和打开不写 `host` 时用第一台在线的电脑。动作本身不检查提升权限，由调用方负责。
- 告警触发时调用 `Notify.Send`，kind 为 `host.alert`，优先级 high；规则级别是 critical 时用 urgent，免打扰时段也会送达。恢复只发事件，不发通知。
- 指标规则只在机器在线、最新样本不超过 3 分钟时判断；没有数据时保持原状态。离线规则从最后在线时间算起。规则停用或删除后，它的未恢复告警自动恢复。

## 前端

- `features/servers`：列表页（卡片，显示 CPU/内存/磁盘小条和在线状态，页头有告警和 SSH 主机入口），详情页标签：概览（曲线）、进程、服务、终端、文件、告警。标签定义在 `features/servers/tabs.tsx`，按能力显示，新标签加一行，例如 `{ id: "docker", label: "Containers", cap: "docker", component: DockerTab }`。
- `features/pc`：只显示 kind=desktop 的机器（通常只有一台，直接进详情）。额外有剪贴板和快捷操作卡片。
- 终端用 `@xterm/xterm` 和 `@xterm/addon-fit`。
- 实时指标用 `useServerEvent("host.metrics", ...)` 写进 Query 缓存。
- 曲线用模块里的 `MetricChart`（SVG，单纵轴，悬停十字线和提示，离线时段断开）。两种曲线颜色经过色觉检查。终端标签按需加载，xterm.js 不进主包。

## 验收

- 本地起服务端和一个 Linux 代理，列表 10 秒内出现数据。
- 终端能跑 `top`，调整窗口大小后显示正常。关闭页面后代理端 shell 进程退出。
- 未提升权限时打开终端、结束进程返回 403 elevation_required，前端弹出验证框，验证后自动继续。
- `GOOS=windows go build ./cmd/agent` 通过。Windows 专属实现有单元测试（能在 Linux 上跑的部分）。
- 断开代理后页面显示离线和最后在线时间，离线告警规则能触发通知。
