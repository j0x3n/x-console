# M7 提醒与通知

负责批次：1（任务卡 B）。

## 两部分

1. **通知投递**：给 M0 的 `notify.Service` 注册渠道和路由规则。
2. **提醒**：用户自己建的提醒，到点发通知。

## 渠道

实现 `notify.Channel`，在 `New` 里 `d.Notify.RegisterChannel(...)`，路由器 `d.Notify.SetRouter(...)`。

| 渠道 | 配置（存 settings，令牌加密） | 实现要点 |
| --- | --- | --- |
| `webpush` | VAPID 公私钥（首次启动自动生成）、订阅列表 | 用 `github.com/SherClockHolmes/webpush-go`。前端注册 service worker 后把订阅发给服务端。订阅失效（404/410）时删除 |
| `telegram` | bot token、chat id、webhook 密钥 | 发消息用 `sendMessage`，按钮用 inline keyboard，`callback_data` 放 action id。回调入口 `POST /integrations/telegram/webhook`（公开路径），校验 `X-Telegram-Bot-Api-Secret-Token`。回调里调用 `d.Notify.HandleAction`，然后 `answerCallbackQuery` 并编辑原消息显示结果。设置页提供“注册 webhook”按钮 |
| `bark` | 服务器地址（默认 https://api.day.app）、device key | GET 或 POST 推送。链接参数带 `XC_PUBLIC_URL + link` |
| `serverchan` | SendKey | POST `https://sctapi.ftqq.com/<key>.send` |

站内通知已经由 M0 存库，不算渠道。

## 路由规则

表 `notification_routes`：id、kind_pattern（如 `host.alert*`、`*`）、min_priority、channels（JSON 数组）、enabled、sort_order。

- 按 sort_order 找第一条匹配的规则，发到它的渠道。都不匹配就只留站内。
- 免打扰：settings 里 `notify.quiet_hours = {start:"23:00", end:"07:30"}`。期间只有 urgent 发外部渠道，其余只留站内。
- 时间按 `Config.Location` 算。

## 提醒

| 表 | 列 |
| --- | --- |
| `reminders` | id、title、body、link、rrule（空表示一次性）、dtstart、next_at、last_fired_at、snoozed_until、done_at、enabled、created_at |

- 用 `github.com/teambition/rrule-go` 计算下次时间，时区用 `Config.Location`。
- 调度器每 30 秒扫一次 `next_at <= now` 的提醒：发通知（kind `reminder.due`，按钮“完成”“10 分钟后”），然后算下一次。
- 按钮 action id：`reminder.done:<id>`、`reminder.snooze:<id>:10`。
- 服务重启后不补发太久以前的提醒：超过 1 小时的只补发一次，并在正文写“错过的提醒”。

## 前端

- `features/reminders`：今天、即将到来、已完成三个标签。新建弹窗：标题、时间、重复（常用选项 + 自定义 RRULE）、链接。
- 设置页加“通知”标签：各渠道配置和测试按钮、路由规则表、免打扰时段。
- Web Push：`web/public/sw.js` 处理 push 和 notificationclick（点击打开 link，按钮调用 `POST /notify/actions`）。PWA manifest 在任务卡 J 做，这里只需要 service worker 和订阅流程。
- 需要一个 `POST /notify/actions` 接口（登录后可用），body `{actionId}`，让 Web Push 按钮也能回调。

## 实现说明（批次 1）

和上面规格不同或补充的地方：

- **渠道配置的存法**：每个字段一个设置键 `<渠道>.<字段>`，令牌类字段用 `SetSecret` 加密。
  - `telegram.bot_token`（密）、`telegram.chat_id`、`telegram.api_base`（默认 `https://api.telegram.org`）、`telegram.webhook_secret`（密，注册 webhook 时生成）
  - `bark.device_key`（密）、`bark.server`（默认 `https://api.day.app`，用 `POST /push` JSON 接口）
  - `serverchan.send_key`（密）、`serverchan.api_base`（空时按 key 自动选：`sctp<uid>t...` 用 `https://<uid>.push.ft07.com/send/<key>.send`，其他用 `https://sctapi.ftqq.com/<key>.send`）
  - `webpush.subject`（VAPID 联系人，可空）、`webpush.vapid`（密，启动时自动生成）
  - 所有外部地址都能改，测试就是这样指向 httptest 假服务器的。
- **Web Push 订阅列表**放在表 `webpush_subscriptions`（不在 settings 里），推送返回 404/410 时删掉。
- **改令牌要提升权限**：`PUT /notify/channels/{name}` 里只要带了令牌字段就要求 `RequireElevated`。令牌字段传空字符串表示删除。返回时令牌打码成 `••••` 加后 4 位。
- **新增接口**：`GET /notify/channels`（全部渠道），`GET /reminders/{id}`。`DELETE /notify/webpush/subscriptions` 用查询参数 `?endpoint=`。
- **默认路由**：迁移里插一条 `*`、最低 normal、发到全部四个渠道。路由器会跳过还没配置好的渠道，所以配好哪个就用哪个。
- **免打扰**：`notify.quiet_hours = {enabled, start, end}`，多了 `enabled`，默认关闭。
- **按钮来源**：Telegram 回调时 actor 是 `telegram`；`POST /notify/actions` 时 actor 是 `webpush:<用户名>`。别的模块（习惯）据此记录打卡来源。
- **Telegram 回调**只接受配置的 `chat_id` 发来的按钮；成功后 `answerCallbackQuery`，再用 `editMessageText` 在原文后加“已处理：<按钮名>”并去掉按钮。
- **提醒状态** `status`：`scheduled` 等待到点、`pending` 已到点没处理、`snoozed` 稍后提醒、`done` 一次性已完成、`ended` 重复规则已结束。另外返回 `dueAt`（考虑稍后提醒后的下一次时间）。
- **完成重复提醒**：已到点（pending/snoozed）的算确认；还没到点就跳到下一次。
- **稍后提醒**：一次性提醒改成到时再提醒；重复提醒如果下一次落在稍后时间之前，那一次跳过。
- **重复规则**：`FREQ=SECONDLY` 和间隔小于 5 分钟的 `MINUTELY` 会被拒绝。重复提醒的第一次从 `max(at, 现在)` 算起，不会补一堆过去的。
- **范围**：`today` = 已到点未处理的 + 今天内要提醒的；`upcoming` = 其余未结束的（含已暂停的）；`done` = 已完成或已结束，最多 100 条。
- **事件**：`reminder.created`、`reminder.updated`、`reminder.deleted`、`reminder.due`，`notify.channel_updated`、`notify.subscription_removed`。
- **`notify.send` 动作**输入 `{title, body?, link?, priority?, kind?}`，kind 默认 `notify.message`，source 是调用方的 actor。
- **`contracts.Reminders.Upcoming`** 会展开重复提醒在时间窗内的每一次（每条最多 50 次）。
- **前端**：`/reminders?tab=upcoming|done`，`/reminders?new=1` 打开新建弹窗。设置页 `/settings/notifications`。service worker 只在用户点“开启浏览器推送”时注册。

## 验收

- 建一个 1 分钟后的提醒，到点收到站内通知和 Telegram（测试里用假 Telegram 服务器）。
- 点 Telegram 的“完成”按钮后，提醒状态变成已完成，原消息被编辑。
- 每天 9 点的重复提醒，完成今天那次后，下次时间是明天 9 点。
- 免打扰期间普通通知不发 Bark，紧急通知照发。
