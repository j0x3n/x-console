# M7 提醒与通知

负责批次：1（任务卡 B）。

## 两部分

1. **通知投递**：给 M0 的 `notify.Service` 注册渠道和路由规则。
2. **提醒**：用户自己建的提醒，到点发通知。

## 渠道

实现 `notify.Channel`，在 `New` 里 `d.Notify.RegisterChannel(...)`，路由器 `d.Notify.SetRouter(...)`。

| 渠道 | 配置（存 settings，令牌加密） | 实现要点 |
| --- | --- | --- |
| `webpush` | VAPID 公私钥（首次启动自动生成）、订阅列表 | 用 `github.com/SherClockHolmes/webpush-go`。前端注册 service worker 后把订阅发给服务端。订阅失效（404/410）时删除 |
| `telegram` | bot token、chat id、webhook 密钥 | 发消息用 `sendMessage`，按钮用 inline keyboard，`callback_data` 放 action id。回调入口 `POST /integrations/telegram/webhook`（公开路径），校验 `X-Telegram-Bot-Api-Secret-Token`。回调里调用 `d.Notify.HandleAction`，然后 `answerCallbackQuery` 并编辑原消息显示结果。设置页提供“注册 webhook”按钮 |
| `bark` | 服务器地址（默认 https://api.day.app）、device key | GET 或 POST 推送。链接参数带 `XC_PUBLIC_URL + link` |
| `serverchan` | SendKey | POST `https://sctapi.ftqq.com/<key>.send` |

站内通知已经由 M0 存库，不算渠道。

## 路由规则

表 `notification_routes`：id、kind_pattern（如 `host.alert*`、`*`）、min_priority、channels（JSON 数组）、enabled、sort_order。

- 按 sort_order 找第一条匹配的规则，发到它的渠道。都不匹配就只留站内。
- 免打扰：settings 里 `notify.quiet_hours = {start:"23:00", end:"07:30"}`。期间只有 urgent 发外部渠道，其余只留站内。
- 时间按 `Config.Location` 算。

## 提醒

| 表 | 列 |
| --- | --- |
| `reminders` | id、title、body、link、rrule（空表示一次性）、dtstart、next_at、last_fired_at、snoozed_until、done_at、enabled、created_at |

- 用 `github.com/teambition/rrule-go` 计算下次时间，时区用 `Config.Location`。
- 调度器每 30 秒扫一次 `next_at <= now` 的提醒：发通知（kind `reminder.due`，按钮“完成”“10 分钟后”），然后算下一次。
- 按钮 action id：`reminder.done:<id>`、`reminder.snooze:<id>:10`。
- 服务重启后不补发太久以前的提醒：超过 1 小时的只补发一次，并在正文写“错过的提醒”。

## 接口

| 方法 | 路径 |
| --- | --- |
| GET/POST | `/reminders`（GET 支持 `range=today|upcoming|done`） |
| GET/PATCH/DELETE | `/reminders/{id}` |
| POST | `/reminders/{id}/done`、`/reminders/{id}/snooze`（`{minutes}`） |
| GET/PUT | `/notify/channels/{name}`（配置，返回时令牌打码） |
| POST | `/notify/channels/{name}/test` |
| GET/PUT | `/notify/routes` |
| GET/PUT | `/notify/quiet-hours` |
| GET | `/notify/webpush/vapid-public-key` |
| POST/DELETE | `/notify/webpush/subscriptions` |
| POST | `/integrations/telegram/webhook`（公开） |
| POST | `/notify/telegram/register-webhook` |

## 前端

- `features/reminders`：今天、即将到来、已完成三个标签。新建弹窗：标题、时间、重复（常用选项 + 自定义 RRULE）、链接。
- 设置页加“通知”标签：各渠道配置和测试按钮、路由规则表、免打扰时段。
- Web Push：`web/public/sw.js` 处理 push 和 notificationclick（点击打开 link，按钮调用 `POST /notify/actions`）。PWA manifest 在任务卡 J 做，这里只需要 service worker 和订阅流程。
- 需要一个 `POST /notify/actions` 接口（登录后可用），body `{actionId}`，让 Web Push 按钮也能回调。

## 验收

- 建一个 1 分钟后的提醒，到点收到站内通知和 Telegram（测试里用假 Telegram 服务器）。
- 点 Telegram 的“完成”按钮后，提醒状态变成已完成，原消息被编辑。
- 每天 9 点的重复提醒，完成今天那次后，下次时间是明天 9 点。
- 免打扰期间普通通知不发 Bark，紧急通知照发。
